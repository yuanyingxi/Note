# 1. 什么是反射？

**反射是指程序在运行时获取类的信息，并动态创建对象、调用方法或访问字段的机制。**

普通情况下，我们直接编写代码，明确指定要创建的对象和调用的方法：

```java
User user = new User();
user.sayHello();
```

使用反射时，可以在运行时获取 `User` 类的信息，再通过反射 API 创建对象、查找方法并调用：

```java
Class<?> clazz = Class.forName("User");
Object user = clazz.getDeclaredConstructor().newInstance();
```

其中，`Class.forName("User")` 根据类的完整名称获取对应的 `Class` 对象。

**反射的核心价值：** 让程序不必在编写代码时就固定所有类和方法，而是可以**根据运行时获取的信息动态操作它们**。

# 2. 反射的底层原理
## 2.1 反射是如何实现的？

反射的核心是：**Java 程序运行时，可以通过** `Class` **对象获取类的信息，并进一步操作类的构造方法、成员变量和成员方法。**

可以分为三个阶段理解：

**第一步：编译阶段**

**Java 源码文件 `Person.java` 经过编译后，生成字节码文件 `Person.class`。**

```java
public class Person {
    private String name;

    public Person() {}

    public void say() {}
}
```

`.class` 文件中包含了**类的结构信息**，例如**字段、构造方法、成员方法**等信息。

**第二步：类加载阶段**

**JVM 加载 `Person.class`，并为这个类建立运行时所需的相关信息。**

在类加载过程中，**JVM 会创建或获取对应的 `Class` 对象**，用于表示这个类。

通过 `Class` 对象，可以进一步获取：

- `Field[]`：类声明的成员字段信息。
    
- `Constructor[]`：类声明的构造方法信息。
    
- `Method[]`：类声明的方法信息。
    

注意：这些数组是通过反射 API 查询得到的，并不是简单地把 `.class` 文件中的内容原样存放在数组里。

**第三步：运行阶段**

**程序可以通过 `Class` 对象动态获取类的信息，并使用反射 API 操作类的成员。**

例如：

```java
Class<?> cls = Class.forName("Person");

// 获取无参构造方法并创建对象
Object obj = cls.getDeclaredConstructor().newInstance();

// 获取 say 方法
Method method = cls.getDeclaredMethod("say");

// 调用 say 方法
method.invoke(obj);
```

这里不需要直接写 `new Person()` 或 `obj.say()`，而是通过运行时获取的类信息完成对象创建和方法调用。

## 2.2 反射涉及的几个核心概念

| 概念             | 含义                                |
| -------------- | --------------------------------- |
| `Person.java`  | Java 源码文件，供开发者编写代码                |
| `Person.class` | 编译生成的字节码文件，供 JVM 加载和执行            |
| `Class` 对象     | 在运行时表示 `Person` 这个类，可以通过它获取类的结构信息 |
| `Field`        | 表示类中的字段，例如 `name`                 |
| `Constructor`  | 表示类的构造方法，例如 `Person()`            |
| `Method`       | 表示类的方法，例如 `say()`                 |

**特别注意：** `Class` **对象不是类加载器。**

- **类加载器（ClassLoader）**：负责查找并加载类的字节码。
    
- `Class` **对象**：表示运行时的类，可以通过它获取类信息并使用反射 API。
    

可以简单理解为：类加载器负责把类加载进 JVM，`Class` 对象则提供了程序在运行时了解和操作这个类的入口。

## 2.3 为什么反射可以在运行时获取类的信息？

因为 **JVM 加载类时，会建立该类的运行时表示，并保留反射所需的类结构信息。**

例如：

```java
Class<?> cls = Person.class;

Field field = cls.getDeclaredField("name");
Method method = cls.getDeclaredMethod("say");
```

程序通过 `Class` 对象查询字段和方法的信息，再根据需要读取字段、调用方法或创建对象。

这就是反射能够在运行时动态操作类的基础。

## 2.4 总结

反射的基本过程可以概括为：

```text
Person.java 源码
       |
       | 编译
       v
Person.class 字节码
       |
       | 类加载器加载
       v
JVM 中的类信息及对应的 Class 对象
       |
       | 反射 API
       v
获取字段、构造方法、成员方法等信息
       |
       v
动态创建对象、访问字段、调用方法
```

**一句话记忆：** **编译阶段**生成 **`.class` 字节码**，**类加载阶**段建立**运行时的类信息**，**运行时**再通过 `Class` 对象和反射 API 动态操作类。

# 3. 反射的核心 API

Java 反射主要涉及 `Class`、`Constructor`、`Method` 和 `Field`。

|API|作用|
|---|---|
|`Class`|表示类的信息，可以获取构造方法、普通方法和字段等信息|
|`Constructor`|表示构造方法，可以调用构造方法创建对象|
|`Method`|表示方法，可以获取方法信息并调用方法|
|`Field`|表示字段，可以获取字段信息、读取或修改字段值|

## 3.1 获取 `Class` 对象

`Class` 对象可以理解为程序在运行时了解一个类的入口。

常见的获取方式有三种：

```java
// 方式一：通过类名获取
Class<?> c1 = User.class;

// 方式二：通过已有对象获取
User user = new User();
Class<?> c2 = user.getClass();

// 方式三：通过类的完整名称获取
Class<?> c3 = Class.forName("com.example.User");
```

其中：

- `User.class`：直接通过类名获取。
    
- `user.getClass()`：通过已有对象获取它所属的类。
    
- `Class.forName()`：根据类的完整名称动态加载类，并获取对应的 `Class` 对象。
    

注意：`Class.forName()` 中的类名通常需要包含包名，例如 `com.example.User`。

## 2.2 使用 `Constructor` 创建对象

普通方式：

```java
User user = new User();
```

反射方式：

```java
Class<?> clazz = User.class;

Object user = clazz.getDeclaredConstructor().newInstance();
```

这里的执行过程是：

1. 获取 `User` 对应的 `Class` 对象。
    
2. 使用 `getDeclaredConstructor()` 获取无参构造方法。
    
3. 使用 `newInstance()` 调用构造方法，创建对象。
    

如果需要调用有参数的构造方法，可以指定参数类型：

```java
Object user = User.class
        .getDeclaredConstructor(String.class)
        .newInstance("小明");
```

这里获取的是参数类型为 `String` 的构造方法，并传入 `"小明"`。

注意：`getDeclaredConstructor()` 可以获取当前类声明的构造方法，包括 `private` 构造方法，但获取到不代表一定有权限调用。访问权限和模块限制仍然可能影响调用。

## 3.3 使用 `Method` 调用方法

假设有以下类：

```java
class User {
    public String sayHello(String name) {
        return "你好，" + name;
    }
}
```

普通调用：

```java
User user = new User();
String result = user.sayHello("小明");
```

反射调用：

```java
User user = new User();

Method method = User.class.getMethod(
        "sayHello", String.class
);

Object result = method.invoke(user, "小明");
System.out.println(result); // 你好，小明
```

主要步骤：

1. 使用 `getMethod()` 查找名称为 `sayHello`、参数类型为 `String` 的公开方法。
    
2. 使用 `invoke()` 调用该方法。
    
3. 第一个参数 `user` 表示调用哪个对象的方法，后面的参数是传给该方法的实际参数。
    
4. `invoke()` 的返回值类型是 `Object`，需要时可以进行类型转换。
    

注意：

- `getMethod()` 获取公开方法，包括从父类继承的公开方法。
    
- `getDeclaredMethod()` 获取当前类自己声明的方法，包括 `private` 方法，但不包含继承来的方法。
    

## 3.4 使用 `Field` 访问字段

假设有一个私有字段：

```java
class User {
    private String name = "小明";
}
```

可以通过反射读取：

```java
Field field = User.class.getDeclaredField("name");
field.setAccessible(true);

User user = new User();
Object value = field.get(user);

System.out.println(value); // 小明
```

主要步骤：

1. 使用 `getDeclaredField()` 获取指定字段。
    
2. 使用 `setAccessible(true)` 尝试允许反射访问该字段。
    
3. 使用 `get(user)` 获取该对象中对应字段的值。
    

注意：反射访问私有字段受到 Java 模块封装和访问权限等限制，`setAccessible(true)` 不保证任何情况下都能成功。

# 4. 反射的实际应用场景
## 4.1 Spring 框架创建和管理对象

**在 Spring 项目中，常见的 `Controller`、`Service` 等组件通常由 Spring 容器创建并管理；使用 MyBatis 时，`Mapper` 接口通常由 MyBatis 生成代理对象，再交由 Spring 管理。**

反射是这些框架实现相关功能时使用的技术之一。

例如：

- **Controller**：Spring 根据组件扫描、注解等信息发现控制器，并创建和管理对应对象。
    
- **Service**：Spring 创建和管理业务层对象，并根据依赖关系注入所需的其他对象。
    
- **Mapper**：MyBatis 通常为 Mapper 接口生成代理对象，通过代理机制执行数据库操作。
    
- **其他场景**：Spring 还可以通过反射等机制处理依赖注入、读取注解信息，以及调用相关方法。
    

**注意：** 并不是所有对象都由反射创建。普通 Java 对象可以直接使用 `new` 创建；框架也可能结合构造方法调用、代理、工厂方法等机制完成对象创建。

**反射的价值在于：框架可以在运行时获取类的信息，并根据配置和注解动态创建、管理或操作对象。**

## 4.2 根据配置文件动态创建对象

假设配置文件中保存了类名：

```java
className=com.example.User
```

程序可以读取配置中的类名，再通过反射获取对应的 `Class` 对象并创建实例。

```java
String className = "com.example.User";

Class<?> clazz = Class.forName(className);
Object object = clazz.getDeclaredConstructor().newInstance();
```

这样，创建哪个类的对象就可以由配置决定，而不必在代码中直接写死具体的类名。

前提是目标类及其依赖可以正常加载，且构造方法能够被合法调用。

## 4.3 ORM 框架进行对象与数据库记录的映射

**ORM（对象关系映射）框架用于建立数据库记录与 Java 对象之间的对应关系。**

例如，数据库中的 `user` 表有一条记录：

|id|name|
|---|---|
|1|小明|

Java 中有对应的 `User` 类：

```java
class User {
    private Integer id;
    private String name;
}
```

ORM 框架可以将数据库记录中的 `id = 1`、`name = "小明"` 映射到 `User` 对象的对应属性中。

```java
User user = userMapper.selectById(1);
```

执行查询后，框架返回一个 `User` 对象，其中的 `id` 为 `1`，`name` 为 `"小明"`。

**反射的作用：** 框架可以在运行时获取 `User` 类的字段、构造方法或 setter 方法等信息，从而将查询结果填充到对象中。

例如，MyBatis 可以根据查询结果与字段映射关系，将数据库列的值设置到 Java 对象的对应属性中。

注意：ORM 框架不一定全部依靠反射完成映射，还可能使用构造方法、setter 方法、代理或其他机制。

# 5. 反射的优点和缺点
## 5.1 优点

- **灵活性高**：可以根据运行时的类名、方法名等信息动态操作类。
    
- **便于框架开发**：适合实现通用组件、依赖注入、ORM 映射等功能。
    
- **减少硬编码**：可以通过配置决定具体使用哪个类或方法。
    

## 5.2 缺点

- **类型检查较弱**：部分错误只能在运行时发现，例如类名或方法名错误。
    
- **代码理解难度较高**：方法调用关系不一定能从普通代码中直接看出来。
    
- **存在额外开销**：动态查找、访问检查和调用会带来一定成本，实际影响取决于使用方式和 JDK 版本。
    
- **受到访问限制**：反射不能保证随意访问所有私有成员，Java 模块封装等机制可能阻止访问。
    

**使用原则：** 普通业务代码优先使用直接调用；只有在需要动态处理类、方法或字段时，再考虑使用反射。

# 6. 总结

1. **反射是什么：** **程序在运行时获取类的信息，并动态创建对象、调用方法或访问字段。**
    
2. **核心 API：** `Class` 获取类的信息，`Constructor` 创建对象，`Method` 调用方法，`Field` 访问字段。
    
3. **常见应用：** Spring 对象管理、配置驱动的对象创建、ORM 映射和 JDBC 驱动加载等。
    
4. **主要优势：** 灵活，可以根据运行时信息决定操作哪个类或方法。
    
5. **主要限制：** 代码更复杂，部分错误只能在运行时发现，并且受到访问权限和模块封装限制。
    

**一句话记忆：反射就是让程序在运行时，能够像编写代码时一样了解并操作类的结构。**
