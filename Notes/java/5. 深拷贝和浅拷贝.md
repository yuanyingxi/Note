# 1. 什么是浅拷贝和深拷贝？

在 Java 中，拷贝对象是指根据一个已有对象，创建另一个对象副本。

**浅拷贝和深拷贝的核心区别：拷贝对象内部的引用类型字段时，是否也复制其引用指向的对象。**

### 1.1 浅拷贝（Shallow Copy）

浅拷贝会创建一个新的对象，并复制原对象的字段值。

- 基本类型字段：复制具体的值。
    
- 引用类型字段：复制对象的引用，不会复制引用指向的对象。
    

因此，原对象和拷贝对象是两个不同的对象，但它们内部的引用类型字段可能指向同一个对象。

### 1.2 深拷贝（Deep Copy）

深拷贝不仅会创建一个新的对象，还会复制其内部需要独立存在的引用类型对象。

- 基本类型字段：复制具体的值。
    
- 引用类型字段：创建对应的对象副本，而不是继续共享原对象。
    

深拷贝通常需要递归处理内部对象，确保需要独立的对象状态不会因为共享引用而相互影响。

### 1.3 示例：理解两者的区别

假设有两个类：

```
class Address {
    String city;

    Address(String city) {
        this.city = city;
    }
}

class Person {
    String name;
    Address address;

    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }
}
```

创建一个对象：

```
Address address = new Address("北京");
Person person1 = new Person("小明", address);
```

此时，`person1` 内部的 `address` 引用指向一个 `Address` 对象。

**浅拷贝：**

```
Person person2 = new Person(person1.name, person1.address);
```

这里创建了新的 `Person` 对象，但没有创建新的 `Address` 对象。

```
person1 ──→ Person 对象1 ──┐
                           ├──→ 同一个 Address 对象
person2 ──→ Person 对象2 ──┘
```

修改地址：

```
person2.address.city = "上海";

System.out.println(person1.address.city); // 上海
```

因为两个 `Person` 对象共享同一个 `Address` 对象，所以修改其中一个对象的地址，也会影响另一个对象看到的地址。

**深拷贝：**

如果创建 `person2` 时，同时复制 `Address` 对象：

```
Person person2 = new Person(
    person1.name,
    new Address(person1.address.city)
);
```

此时两个对象拥有独立的 `Address` 对象。

```
person1 ──→ Person 对象1 ──→ Address 对象1（北京）

person2 ──→ Person 对象2 ──→ Address 对象2（北京）
```

再修改 `person2.address.city`，不会影响 `person1.address.city`。

注意：这里的示例通过手动创建 `Address` 对象实现了相应的深拷贝效果，并不是 Java 自动完成的。

### 1.4 浅拷贝与深拷贝的对比

|对比项|浅拷贝|深拷贝|
|---|---|---|
|是否创建新的外层对象|是|是|
|基本类型字段|复制值|复制值|
|引用类型字段|复制引用|复制需要独立的对象|
|内部对象是否共享|可能共享|对需要独立复制的对象不共享|
|实现难度|通常较简单|通常较复杂|

注意：深拷贝并不意味着必须复制整个对象图中的每个对象。实际实现还需要考虑不可变对象、循环引用以及多个字段指向同一对象等情况。

## 2. Java 中如何实现浅拷贝？

### 2.1 使用 `Object` 的 `clone()` 方法

Java 的 `Object` 类提供了 `clone()` 方法。

默认的 `clone()` 实现属于浅拷贝：它会创建一个新的对象，并复制字段值，但不会自动复制引用类型字段指向的对象。

使用 `clone()` 通常需要实现 `Cloneable` 接口，并重写 `clone()` 方法。

```
class Person implements Cloneable {
    String name;
    Address address;

    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    @Override
    public Person clone() {
        try {
            return (Person) super.clone();
        } catch (CloneNotSupportedException e) {
            throw new AssertionError(e);
        }
    }
}
```

使用：

```
Person person1 = new Person(
    "小明",
    new Address("北京")
);

Person person2 = person1.clone();
```

此时：

- `person1` 和 `person2` 是两个不同的 `Person` 对象。
    
- `person1.name` 和 `person2.name` 是两个独立的引用字段，但如果它们指向同一个 `String` 对象，也没有问题，因为 `String` 是不可变的。
    
- `person1.address` 和 `person2.address` 指向同一个 `Address` 对象。
    

### 2.2 `Cloneable` 接口有什么作用？

`Cloneable` 是一个标记接口，本身没有定义需要实现的方法。

它的作用是告诉 `Object.clone()`：当前对象允许被克隆。

如果没有实现 `Cloneable`，调用 `super.clone()` 通常会抛出 `CloneNotSupportedException`。

注意：**实现** `**Cloneable**` **并不会自动实现深拷贝。** 上面的代码仍然只是浅拷贝。

## 3. Java 中如何实现深拷贝？

常见方法有三种：手动递归复制、重写 `clone()` 实现递归复制、序列化与反序列化。

### 3.1 方法一：手动复制对象

根据对象的字段逐一创建副本，并继续复制其中需要独立存在的引用类型对象。

```
class Address {
    String city;

    Address(String city) {
        this.city = city;
    }
}

class Person {
    String name;
    Address address;

    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    public Person deepCopy() {
        return new Person(
            this.name,
            new Address(this.address.city)
        );
    }
}
```

调用：

```
Person person2 = person1.deepCopy();
```

这里通过新建 `Person` 和 `Address` 对象，让它们拥有独立的可变状态。

优点：

- 实现逻辑清晰。
    
- 不依赖序列化机制。
    
- 可以控制哪些字段需要复制。
    

缺点：

- 需要手动处理对象中的引用字段。
    
- 对象结构复杂时，代码量会增加。
    
- 如果新增了引用类型字段，需要及时更新复制逻辑。
    

### 3.2 方法二：重写 `clone()`，递归复制引用字段

可以先使用 `super.clone()` 创建浅拷贝，再单独复制引用类型字段。

```
class Person implements Cloneable {
    String name;
    Address address;

    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    @Override
    public Person clone() {
        try {
            Person copy = (Person) super.clone();

            // 单独复制引用类型对象
            copy.address = new Address(this.address.city);

            return copy;
        } catch (CloneNotSupportedException e) {
            throw new AssertionError(e);
        }
    }
}
```

这里的执行过程是：

1. `super.clone()` 创建新的 `Person` 对象，完成浅拷贝。
    
2. 创建新的 `Address` 对象，并赋给副本的 `address` 字段。
    
3. 返回最终的副本对象。
    

如果 `Address` 内部还有其他需要独立复制的引用类型字段，也需要继续处理。

优点：可以利用 `clone()` 快速创建外层对象。

缺点：需要逐层处理引用类型字段，结构复杂时容易遗漏，代码维护也比较麻烦。

### 3.3 方法三：使用序列化和反序列化

序列化是把对象转换为字节流的过程；反序列化则是根据字节流重新构建对象的过程。

通过先序列化，再反序列化，可以创建一个独立的对象副本。

```
import java.io.*;

class Address implements Serializable {
    private static final long serialVersionUID = 1L;

    String city;

    Address(String city) {
        this.city = city;
    }
}

class Person implements Serializable {
    private static final long serialVersionUID = 1L;

    String name;
    Address address;

    Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }
}
```

实现深拷贝：

```
static <T extends Serializable> T deepCopy(T obj)
        throws IOException, ClassNotFoundException {

    ByteArrayOutputStream buffer = new ByteArrayOutputStream();

    try (ObjectOutputStream out = new ObjectOutputStream(buffer)) {
        out.writeObject(obj);
    }

    try (ObjectInputStream in = new ObjectInputStream(
            new ByteArrayInputStream(buffer.toByteArray()))) {
        @SuppressWarnings("unchecked")
        T copy = (T) in.readObject();
        return copy;
    }
}
```

调用：

```
Person person2 = deepCopy(person1);
```

使用这种方式时，需要注意：

- 对象图中需要被序列化的对象都必须支持序列化，否则可能抛出 `NotSerializableException`。
    
- 对象及其可达引用对象会根据 Java 序列化机制进行处理。
    
- 序列化和反序列化有额外的时间与内存开销。
    
- `transient` 字段不会按普通实例字段的方式序列化，因此反序列化后可能无法保留原值。
    
- Java 原生反序列化不应直接处理不可信输入。
    

优点：对于符合序列化要求的对象结构，可以减少手动复制每个字段的工作。

缺点：开销较大，并且受到序列化规则和对象结构的限制。

---

## 4. 序列化和反序列化一定是深拷贝吗？

在合适的条件下，通过 Java 原生序列化再反序列化，可以实现深拷贝效果，但不能简单地认为任何序列化机制都一定会深拷贝。

需要注意：

1. Java 原生序列化会维护对象引用关系，同一个对象被多个字段引用时，反序列化后通常仍会保留这种共享关系。
    
2. 如果某些字段被标记为 `transient`，这些字段不会按普通实例字段的方式保存。
    
3. 自定义序列化逻辑可能改变对象的复制行为。
    
4. JSON 等其他序列化方案是否能实现深拷贝，取决于序列化框架、类型处理和对象结构。
    

因此，判断是否实现深拷贝，应该检查复制后需要独立的可变对象是否仍然共享，而不是只看是否使用了序列化。

## 5. 常见面试问题

### 5.1 浅拷贝创建的新对象和原对象是同一个吗？

不是。浅拷贝会创建一个新的外层对象，但其中的引用类型字段可能仍然指向原对象所引用的对象。

### 5.2 为什么浅拷贝会相互影响？

因为两个外层对象的引用字段可能指向同一个可变对象。通过任意一个引用修改该对象，另一方也会看到修改后的状态。

### 5.3 `clone()` 默认是深拷贝还是浅拷贝？

默认是浅拷贝。若要实现深拷贝，需要重写 `clone()` 并进一步复制需要独立存在的引用类型字段。

### 5.4 实现 `Cloneable` 就能实现深拷贝吗？

不能。`Cloneable` 只是标记接口，不会自动递归复制内部对象。

### 5.5 深拷贝有哪些常见实现方式？

1. 手动创建对象副本，逐个复制字段。
    
2. 重写 `clone()`，递归复制引用类型字段。
    
3. 使用序列化与反序列化，在满足相关条件时创建独立副本。
    

### 5.6 深拷贝一定比浅拷贝好吗？

不一定。

- 如果多个对象共享某个不可变对象，通常没有必要复制它。
    
- 如果需要独立修改对象内部的状态，深拷贝更合适。
    
- 深拷贝会增加时间、内存和维护成本，应根据实际需求选择。
    

---

## 6. 本节总结

- **浅拷贝：** 创建新的外层对象，但引用类型字段复制的是引用，内部对象可能共享。
    
- **深拷贝：** 对需要独立存在的内部对象也进行复制，避免共享可变状态。
    
- `**Object.clone()**`**：** 默认执行浅拷贝。
    
- `**Cloneable**`**：** 标记接口，不会自动实现深拷贝。
    
- **深拷贝的常见方式：** 手动复制、递归 `clone()`、序列化与反序列化。
    
- **判断标准：** 重点看复制后内部需要独立的可变对象是否仍被共享。
