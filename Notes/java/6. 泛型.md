# 1. 什么是泛型？

**泛型就是在定义类、接口或方法时，使用类型参数表示具体的数据类型，在使用时再指定实际类型。**

例如：

```java
List<String> names = new ArrayList<>();
```

其中：

- `List`：集合接口。
    
- `String`：指定集合中存储的元素类型。
    
- `List<String>`：表示元素类型为 `String` 的列表。
    

泛型主要解决两个问题：

1. **类型安全**：在编译阶段检查类型错误，减少运行时类型转换异常。
    
2. **代码复用**：一份代码可以适用于多种数据类型，无须为每种类型重复编写代码。
    

# 2. 为什么需要泛型？
## 2.1 不使用泛型的问题

```java
List list = new ArrayList();

list.add("小明");
list.add(100);

String name = (String) list.get(0);
String age = (String) list.get(1); // 运行时抛出 ClassCastException
```

不使用泛型时：

- 集合可以放入不同类型的对象。
    
- 取出元素时通常需要手动进行类型转换。
    
- 如果转换的目标类型不正确，就可能在运行时抛出 `ClassCastException`。
    

## 2.2 使用泛型

```java
List<String> names = new ArrayList<>();

names.add("小明");
// names.add(100); // 编译错误

String name = names.get(0);
```

使用泛型后：

- 编译器会检查添加的元素是否符合指定类型。
    
- 取出元素时通常不需要手动强制转换。
    
- 可以更早发现类型错误，提高代码的安全性和可读性。

# 3. 泛型类

**泛型类是在定义类时声明类型参数，使类中的属性和方法能够使用该类型。**

```java
class Box<T> {
    private T value;

    public void set(T value) {
        this.value = value;
    }

    public T get() {
        return value;
    }
}
```

这里的 `T` 是类型参数，可以在使用时指定具体类型：

```java
Box<String> stringBox = new Box<>();
stringBox.set("Hello");

String str = stringBox.get();

Box<Integer> integerBox = new Box<>();
integerBox.set(100);

Integer num = integerBox.get();
```

同一个 `Box<T>` 类可以用于存储不同类型的数据，无须分别定义 `StringBox`、`IntegerBox` 等类。

常见的类型参数命名：

|符号|常见含义|
|---|---|
|`T`|Type，类型|
|`E`|Element，集合元素|
|`K`|Key，键|
|`V`|Value，值|
|`R`|Return，返回值类型|

这些只是约定俗成的命名，并非 Java 关键字。

# 4. 泛型方法

泛型方法是在方法上声明类型参数，使方法能够处理不同类型的数据。

```java
public static <T> T identity(T value) {
    return value;
}
```

使用：

```java
String str = identity("Hello");
Integer num = identity(100);
```

其中：

- `<T>`：声明该方法的类型参数。
    
- `T`：表示参数和返回值使用同一个类型参数。
    
- Java 通常可以根据传入的参数推断 `T` 的实际类型。
    

注意：泛型类和泛型方法不是同一个概念。泛型类在类上声明类型参数，泛型方法则在方法上声明类型参数；普通类也可以定义泛型方法。

# 5. 泛型接口

泛型接口是在定义接口时声明类型参数，实现接口时可以指定具体类型。

```java
interface Converter<T> {
    T convert(String value);
}

class IntegerConverter implements Converter<Integer> {
    @Override
    public Integer convert(String value) {
        return Integer.valueOf(value);
    }
}
```

这里 `IntegerConverter` 指定了 `T` 为 `Integer`，因此实现方法的返回类型必须是 `Integer`。

# 6. 泛型的类型擦除

**Java 泛型主要通过类型擦除（Type Erasure）实现。**

## 6.1 什么是类型擦除？

Java 编译器在编译泛型代码时，会进行类型检查，并在生成字节码时擦除大部分泛型类型参数信息。

通常：

- 没有指定上界的类型参数，会被擦除为 `Object`。
    
- 指定了上界的类型参数，会被擦除为其上界。
    
- 必要时，编译器会插入类型转换。
    

例如：

```java
List<String> names = new ArrayList<>();
List<Integer> numbers = new ArrayList<>();

System.out.println(names.getClass() == numbers.getClass());
// true
```

`List<String>` 和 `List<Integer>` 在运行时使用的都是同一个 `ArrayList` 类，不会因为泛型参数不同就生成两个独立的 `ArrayList` 类。

## 6.2 类型擦除是否意味着所有泛型信息都消失了？

不是。

类、字段和方法声明中的部分泛型信息可以保存在 `.class` 文件的 `Signature` 属性中，并可通过反射读取。

但不能仅凭一个普通的 `new ArrayList<String>()` 对象，直接获知它的泛型参数是 `String`。

## 6.3 类型擦除带来的限制

**限制一：不能直接使用基本数据类型作为泛型参数。**

```java
List<int> numbers;       // 编译错误
List<Integer> numbers;   // 正确
```

泛型类型参数必须是引用类型。需要使用包装类表示基本数据类型，例如 `Integer`、`Double`。

**限制二：不能直接通过类型参数创建对象。**

```java
class Box<T> {
    // T value = new T(); // 编译错误
}
```

因为运行时无法直接通过被擦除的类型参数确定应该创建什么类型的对象。

**限制三：不能直接创建具体类型的泛型数组。**

```java
// T[] array = new T[10]; // 编译错误
```

这是因为泛型类型擦除与 Java 数组的运行时类型检查机制存在冲突。

# 7. 泛型的不变性
## 7.1 什么是泛型的不变性？

虽然 `Integer` 是 `Number` 的子类，但 `List<Integer>` 不是 `List<Number>` 的子类。

```java
List<Integer> integers = new ArrayList<>();

// 编译错误
// List<Number> numbers = integers;
```

## 7.2 为什么不允许这样赋值？

先理解：**两个变量可以引用同一个列表对象。**

假设 Java 允许上面的赋值：

```java
List<Integer> integers = new ArrayList<>();
List<Number> numbers = integers;
```

此时，`integers` 和 `numbers` 指向的是同一个列表，并不是各自拥有一个列表。

可以简单理解为：

```text
integers ──┐
           ├──> 同一个列表
numbers ───┘
```

接下来执行：

```java
numbers.add(3.14);
```

虽然是通过 `numbers` 添加元素，但实际修改的是两个变量共同引用的那个列表。

因此，通过 `integers` 查看这个列表时，也能看到刚刚添加的 `Double` 对象。

这就产生了问题：`integers` 声明为 `List<Integer>`，按照泛型的约定，列表中应该只能存放 `Integer`，但现在却出现了 `Double`。

为了避免这种类型安全问题，Java 禁止将 `List<Integer>` 直接赋值给 `List<Number>`。

## 7.3 总结

- `Integer` 是 `Number` 的子类，但 `List<Integer>` 不是 `List<Number>` 的子类。
    
- `List<Integer>` 和 `List<Number>` 是两种不同的泛型类型。
    
- 泛型默认具有不变性，**即泛型参数之间存在继承关系，不代表对应的泛型类型也存在继承关系**。
    

**核心原因：** 如果允许这种赋值，就可能通过 `List<Number>` 向原本声明为 `List<Integer>` 的同一个列表添加其他类型的元素，从而破坏泛型的类型安全。

# 8. 泛型通配符

通配符 `?` 表示某个**未知类型**，可以配合上下界限制允许的类型范围。

## 8.1 无界通配符 `<?>`

表示泛型参数是某个未知类型。

```java
public static void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}
```

`List<String>`、`List<Integer>` 等都可以传入该方法。

由于元素的具体类型未知，不能直接向其中添加普通元素（`null` 除外）。

## 8.2 上界通配符 `<? extends T>`

**表示未知类型是 `T` 本身或 `T` 的某个子类。**

```java
List<? extends Number> numbers;
```

可以接收：

```java
List<Integer>
List<Double>
List<Number>
```

适合从集合中读取数据：

```java
public static double sum(List<? extends Number> numbers) {
    double total = 0;

    for (Number number : numbers) {
        total += number.doubleValue();
    }

    return total;
}
```

读取出来的元素可以作为 `Number` 使用。

但不能安全地添加 `Integer`、`Double` 等普通元素，因为编译器无法确定列表的实际元素类型。

## 8.3 下界通配符 `<? super T>`

表示未知类型是 `T` 本身或 `T` 的某个父类。

```java
List<? super Integer> numbers;
```

可以接收：

```java
List<Integer>
List<Number>
List<Object>
```

适合向集合中写入 `Integer`：

```java
public static void addNumbers(List<? super Integer> numbers) {
    numbers.add(10);
    numbers.add(20);
}
```

读取时，只能保证得到的元素至少可以作为 `Object` 使用，因为集合的实际元素类型可能是 `Integer`、`Number` 或 `Object`。

## 8.4 `extends` 和 `super` 的区别

|类型|含义|适合的操作|
|---|---|---|
|`<? extends T>`|T 或 T 的子类|读取 T 类型的数据|
|`<? super T>`|T 或 T 的父类|写入 T 类型的数据|
|`<?>`|未知类型|通用读取，不适合添加普通元素|

记忆口诀：**PECS（Producer Extends, Consumer Super）**

- 主要从集合中**读取数据**，即集合是**数据提供者**（Producer），优先考虑 **`extends`**。
    
- 主要向集合中**写入数据**，即集合是**数据消费者**（Consumer），优先考虑 **`super`**。
    

这是一条实用的设计原则，不代表 `extends` 只能读取、`super` 只能写入。

## 8.5 `T` 和 `?` 的区别

`T` **是类型参数，**`?` **是通配符，表示某个未知类型。**

```java
// T：声明一个类型参数
public static <T> void print(T value) {
    System.out.println(value);
}

// ?：表示未知的泛型类型
public static void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}
```

主要区别：

|对比|`T`|`?`|
|---|---|---|
|含义|类型参数，可以用一个名称表示某个类型|通配符，表示未知类型|
|使用方式|通常需要先声明，例如 `<T>`|可以直接使用|
|能否重复引用同一个类型参数|可以，例如参数和返回值都使用 `T`|单独使用时，不会为其他位置提供可直接引用的类型名称|
|典型用途|定义泛型类、泛型接口和泛型方法|接收不同泛型类型的对象|

**使用 `T` 还是 `?` 关键是需不需要明确地关联和使用具体类型。**

- 用 `T`：需要在多个位置使用同一个类型，让它们的类型保持一致。
    
- 用 `?`：不关心具体类型，只需要接收或处理不同类型的泛型对象。
    

例如：

```java
// 使用 T：返回值类型与列表元素类型保持一致
public static <T> T getFirst(List<T> list) {
    return list.get(0);
}

// 使用 ?：不关心列表元素的具体类型，只负责打印
public static void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}
```

简单记忆：

- `T`：我要用一个类型参数，并且可能在多个位置重复使用它。
    
- `?`：我不需要知道具体的类型，只需要接受符合泛型约束的对象。

# 9. 总结

1. **泛型的作用**：提高类型安全性、减少强制类型转换、提高代码复用性。
    
2. **泛型的形式**：可以用于类、接口和方法。
    
3. **类型擦除**：Java 泛型主要在编译阶段进行类型检查，运行时会擦除大部分类型参数信息。
    
4. **泛型不变性**：`List<Integer>` 不是 `List<Number>` 的子类。
    
5. **通配符**：`<?>` 表示未知类型，`<? extends T>` 适合读取，`<? super T>` 适合写入。
    
6. **基本数据类型**：不能直接作为泛型参数，需要使用包装类，例如 `Integer`。
