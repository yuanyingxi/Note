# 1. 什么是 Java 多线程？
## 1.1 基本概念

**线程（Thread）是 CPU 调度执行任务的基本单位之一。** 一个 Java 程序可以创建多个线程，让它们分别执行不同的任务。

例如，一个应用程序可以同时执行以下任务：

- 线程 A：处理用户请求。
    
- 线程 B：读取文件。
    
- 线程 C：执行后台任务。
    

多线程可以提高程序的并发处理能力，但不代表所有任务都会因此执行得更快。

### 1.2 线程之间的内存关系

同一个 Java 进程中的多个线程通常共享进程的资源，但每个线程也有自己的执行状态。

|资源|线程之间的关系|
|---|---|
|堆内存中的对象|可以被多个线程共享|
|类的静态变量|可以被多个线程访问|
|局部变量|通常属于各自线程的栈帧|
|程序计数器、线程栈|每个线程独立维护|

例如：

```
class Counter {
    static int count = 0;

    public static void main(String[] args) {
        // 多个线程都可以访问 Counter.count
    }
}
```

`count` 是静态变量，多个线程可以访问它。如果多个线程同时修改它，就可能出现线程安全问题。

## 2. 使用多线程需要注意什么？

主要有三个问题：

1. **线程安全**：多个线程同时操作共享数据，可能产生错误结果。
    
2. **线程间通信**：线程需要交换数据或等待其他线程完成任务。
    
3. **线程管理成本**：创建和销毁线程会消耗系统资源，通常需要合理使用线程池。
    

## 3. Java 内存模型 JMM

### 3.1 什么是 JMM？

JMM（Java Memory Model，Java 内存模型）规定了多线程环境下，共享变量的读写操作应当满足哪些可见性和顺序规则。

JMM 是一种抽象的内存模型，不应将它的“主内存”和“工作内存”直接等同于物理内存、JVM 堆或 CPU 缓存。

理解 JMM，主要关注三个问题：

- 原子性
    
- 可见性
    
- 有序性
    

### 3.2 原子性

**原子性**指一个操作或需要整体保护的一组操作，不会被其他线程的并发操作破坏其整体效果。

例如：

```
count++;
```

虽然只有一行代码，但通常包含读取、加一、写回三个步骤。

假设 `count` 初始值为 0，两个线程同时执行：

1. 线程 A 读取 `count = 0`。
    
2. 线程 B 读取 `count = 0`。
    
3. 线程 A 写入 `1`。
    
4. 线程 B 也写入 `1`。
    

最终结果是 1，而不是预期的 2。这就是丢失更新。

常见解决方案：

- 使用 `synchronized` 或 `Lock` 保护整个操作。
    
- 使用 `AtomicInteger` 等原子类执行相应的原子操作。
    

### 3.3 可见性

**可见性**指一个线程对共享变量的修改，能够按照 Java 内存模型规定的同步关系被其他线程观察到。

例如：

```
private static boolean stopped = false;

public void run() {
    while (!stopped) {
        // 执行任务
    }
}
```

如果一个线程把 `stopped` 改成 `true`，另一个线程不一定能及时观察到这次修改。

可以使用 `volatile`：

```
private static volatile boolean stopped = false;
```

`volatile` 能为该变量提供相应的可见性和有序性保证。

注意：`volatile` 不能保证 `count++` 这样的复合操作具有原子性。

### 3.4 有序性

**有序性**指多线程环境下，操作之间应当满足规定的先后关系。

为了提高性能，编译器和处理器可能对指令进行重排序，只要不破坏规定的程序语义。

但在多线程环境中，如果没有适当的同步措施，其他线程观察到的结果可能不符合预期。

Java 通过 JMM 的规则来保证必要的顺序关系。

### 3.5 happens-before 规则

`happens-before` 是 Java 内存模型中描述操作之间可见性和顺序保证的规则。

常见规则：

|规则|含义|
|---|---|
|`volatile` 规则|对某个 `volatile` 变量的写，happens-before 后续对该变量的读|
|锁规则|对同一把锁的解锁，happens-before 后续对该锁的加锁|
|线程启动规则|调用线程的 `start()`，happens-before 被启动线程中的操作|
|线程结束规则|线程中的操作，happens-before 另一个线程成功通过 `join()` 等待它结束后的操作|
|传递性|如果 A happens-before B，B happens-before C，那么 A happens-before C|

注意：happens-before 规定的是必须满足的可见性和顺序保证，并不意味着底层指令一定按照源码顺序执行。

## 4. Java 线程与操作系统线程的关系

需要区分平台线程和虚拟线程。

### 4.1 平台线程（Platform Thread）

传统 Java 线程通常采用一对一映射：

**一个 Java 平台线程对应一个操作系统线程。**

特点：

- 线程调度主要由操作系统负责。
    
- 每个线程需要占用一定的栈空间和系统资源。
    
- 线程数量过多时，可能增加内存消耗和上下文切换开销。
    

### 4.2 虚拟线程（Virtual Thread）

Java 21 正式发布了虚拟线程。

虚拟线程由 JVM 管理，可以将大量虚拟线程调度到较少的载体平台线程上执行，属于 M 调度模型。

特点：

- 创建和管理成本通常低于平台线程。
    
- 适合大量存在阻塞等待的任务，例如许多并发的 I/O 请求。
    
- 不会自动加快 CPU 密集型计算。
    
- 仍然受到内存、CPU 和外部服务处理能力的限制。
    

因此，不能简单地说 Java 线程永远等于操作系统线程。

## 5. 如何保证多线程安全？

多线程安全通常关注三个方面：

|方面|含义|常见解决方式|
|---|---|---|
|原子性|避免并发操作产生不完整或丢失的更新|原子类、锁|
|可见性|确保其他线程能观察到共享变量的修改|`volatile`、锁|
|有序性|确保必要的操作顺序得到保证|`volatile`、锁、happens-before 规则|

这些方式各有适用范围，需要根据具体的共享数据和操作选择，不能认为使用 `volatile` 就能解决所有线程安全问题。

## 6. 线程的创建方式

Java 中常见的线程创建和任务提交方式有以下几种。

### 6.1 继承 Thread 类

```
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("执行任务");
    }
}

// 创建并启动线程
MyThread thread = new MyThread();
thread.start();
```

特点：

- 实现简单。
    
- 因为已经继承了 `Thread`，不能再继承其他类。
    

### 6.2 实现 Runnable 接口

```
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("执行任务");
    }
}

Thread thread = new Thread(new MyTask());
thread.start();
```

特点：

- 将任务逻辑与线程对象分离。
    
- 任务类仍然可以继承其他类。
    
- 多个线程可以使用同一个 `Runnable` 对象，但如果共享可变数据，仍需考虑线程安全。
    

### 6.3 实现 Callable 接口

`Callable` 与 `Runnable` 类似，但 `call()` 方法可以返回结果，也可以抛出异常。

通常可以配合 `FutureTask` 使用：

```
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

Callable<Integer> task = () -> 100;

FutureTask<Integer> futureTask = new FutureTask<>(task);

Thread thread = new Thread(futureTask);
thread.start();

Integer result = futureTask.get();
System.out.println(result); // 100
```

这里：

- `Callable<Integer>`：定义一个返回整数结果的任务。
    
- `FutureTask`：包装任务，并保存执行结果。
    
- `get()`：获取任务结果。如果任务尚未完成，调用线程可能需要等待。
    

### 6.4 使用线程池

实际开发中，通常会使用线程池管理任务，而不是每次都手动创建线程。

```
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

ExecutorService executor = Executors.newFixedThreadPool(10);

executor.submit(() -> {
    System.out.println("执行任务");
});

executor.shutdown();
```

这里创建了一个固定大小为 10 的线程池，并提交了一个任务。

线程池的主要作用：

- 重用线程，减少频繁创建和销毁线程的开销。
    
- 控制并发执行的线程数量。
    
- 配合任务队列管理待执行任务。
    

注意：线程池的大小和队列容量仍需要合理配置。配置不当也可能造成任务积压或资源耗尽。

## 7. start() 和 run() 的区别

### 7.1 start()

`start()` 会启动一个新线程，由新线程执行 `run()` 中的任务。

```
Thread thread = new Thread(() -> {
    System.out.println("执行任务");
});

thread.start();
```

### 7.2 run()

直接调用 `run()` 只是普通的方法调用，不会启动新线程。

```
thread.run();
```

此时，任务会在当前调用线程中执行。

### 7.3 注意事项

同一个 `Thread` 对象只能成功调用一次 `start()`。线程结束后，不能通过再次调用该对象的 `start()` 来重新启动它。

## 8. 如何停止线程？

Java 通常采用**协作式取消**：向线程发出停止请求，由线程在适当的位置检查请求并自行退出。

### 8.1 使用标志位

```
private volatile boolean running = true;

public void run() {
    while (running) {
        // 执行任务
    }
}

public void stopTask() {
    running = false;
}
```

`volatile` 用于确保线程能够观察到标志位的修改。

适合能够定期检查标志位的任务。但如果线程正在长时间阻塞，仅修改标志位不一定能立即让它退出。

### 8.2 使用 interrupt()

`interrupt()` 用于向线程发出中断请求。

```
Thread worker = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        // 执行任务
    }
});

worker.start();
worker.interrupt();
```

线程通过检查中断状态，决定是否退出任务。

### 8.3 使用 Future.cancel(true)

对于线程池中的任务，可以使用 `Future.cancel(true)` 尝试取消任务，并在适用情况下向执行任务的线程发出中断请求。

但任务能否及时停止，仍取决于任务是否正确响应中断。

### 8.4 注意事项

- `interrupt()` 不是强制杀死线程。
    
- `Thread.stop()` 已废弃，不应使用，因为它可能使共享数据处于不一致状态。
    
- 如果线程在 `sleep()`、`wait()` 或 `join()` 等可中断等待中收到中断，通常会抛出 `InterruptedException`，并清除中断标志。
    
- 捕获 `InterruptedException` 后，如果当前方法不能继续完成任务，通常应结束任务或向上抛出异常；如果需要在当前层处理并保留中断请求，可以恢复中断标志。
    

## 9. interrupt() 为什么可能抛出 InterruptedException？

`interrupt()` 本身并不会在任意代码位置强行抛出异常，具体行为取决于线程当前的状态。

|线程正在做什么|中断后的常见行为|
|---|---|
|正常执行代码|设置中断状态，线程需要检查或响应|
|执行 `sleep()`、`wait()`、`join()`|结束相应等待并抛出 `InterruptedException`，同时清除中断状态|
|执行 `LockSupport.park()`|可以使等待返回，但通常不抛出 `InterruptedException`，也不清除中断状态|
|等待进入 `synchronized`|不能靠中断直接取消监视器锁的等待|
|使用 `ReentrantLock.lock()` 等待|普通 `lock()` 不响应中断取消等待；可中断等待可使用 `lockInterruptibly()`|

两个方法的区别：

- `isInterrupted()`：检查当前线程对象的中断状态，不清除状态。
    
- `Thread.interrupted()`：检查当前线程的中断状态，并清除状态。
    

## 10. Java 线程的六种状态

Java 在 `Thread.State` 中定义了六种线程状态。

|状态|含义|
|---|---|
|`NEW`|线程对象已创建，但尚未启动|
|`RUNNABLE`|处于可运行状态，可能正在运行，也可能等待 CPU 调度|
|`BLOCKED`|等待获取或重新获取 `synchronized` 的监视器锁|
|`WAITING`|无限期等待其他线程执行某种操作|
|`TIMED_WAITING`|在指定时间内等待|
|`TERMINATED`|线程已经执行结束|

注意：

- Java 的 `RUNNABLE` 同时涵盖了操作系统层面的就绪和运行情况。
    
- `BLOCKED` 特指等待进入或重新进入 `synchronized` 监视器的状态。
    
- 等待 `ReentrantLock` 时，线程可能处于 `WAITING` 或 `TIMED_WAITING`，具体取决于等待方式。
    
- `getState()` 返回的是某一时刻的状态，不能单独用于精确控制线程执行顺序。
    

## 11. sleep() 和 wait() 的区别

两者都可以让当前线程暂时无法继续执行，但用途不同。

|对比项|`Thread.sleep()`|`Object.wait()`|
|---|---|---|
|所属类|`Thread`|`Object`|
|是否需要持有锁才能调用|不需要|必须持有对应对象的监视器锁|
|是否释放已持有的锁|不释放|释放调用对象的监视器锁|
|常见状态|`TIMED_WAITING`|`WAITING` 或 `TIMED_WAITING`|
|主要用途|暂停一段时间|配合锁实现线程协作|

例如：

```
synchronized (lock) {
    Thread.sleep(1000);
}
```

线程休眠期间仍然持有 `lock`，其他线程不能进入需要同一把锁的同步代码块。

而：

```
synchronized (lock) {
    lock.wait();
}
```

线程调用 `wait()` 后会释放 `lock`，让其他线程有机会获取这把锁并修改相关条件。

注意：`wait()` 只释放调用对象的监视器锁，不会释放当前线程持有的其他锁。

## 12. sleep() 会释放 CPU 吗？

调用 `Thread.sleep()` 后，线程会暂停执行并进入 `TIMED_WAITING` 状态，不再继续占用 CPU 执行该线程的任务。

但要区分两件事：

- **释放 CPU 执行机会**：线程休眠后，操作系统可以把 CPU 分配给其他可运行线程。
    
- **释放锁**：`sleep()` 不会自动释放线程已经持有的锁。
    

另外，休眠时间到达只意味着线程可以再次参与调度，不代表它一定会立即运行。

## 13. BLOCKED 和 WAITING 的区别

两者都表示线程暂时无法继续执行，但等待原因不同。

### BLOCKED

线程正在等待获取 `synchronized` 使用的监视器锁。

例如，线程 A 已持有 `lock`，线程 B 也想进入 `synchronized (lock)`，那么线程 B 可能进入 `BLOCKED` 状态。

### WAITING

线程正在无限期等待某种事件，例如：

- 调用 `Object.wait()` 等待通知。
    
- 调用 `Thread.join()` 等待另一个线程结束。
    
- 调用 `LockSupport.park()` 等待许可或其他唤醒条件。
    

**记忆重点：** `BLOCKED` 主要是等待进入 `synchronized` 监视器；`WAITING` 则可能是在等待通知、线程结束或其他协作条件。

## 14. wait() 状态下的线程如何恢复执行？

调用 `wait()` 后，线程可以通过以下情况结束等待：

- 其他线程调用同一个对象的 `notify()` 或 `notifyAll()`。
    
- 线程收到中断请求，等待操作抛出 `InterruptedException`。
    
- 带超时的 `wait()` 到达等待时间。
    
- 发生虚假唤醒。
    

但**结束等待不代表立即继续执行**。线程还需要重新获取原先释放的监视器锁。

例如：

```
synchronized (lock) {
    while (!ready) {
        lock.wait();
    }

    // ready 为 true 后继续执行
}
```

这里使用 `while` 检查条件，而不是 `if`，是因为线程被唤醒后，条件可能仍然不满足，也可能发生虚假唤醒。

## 15. notify() 和 notifyAll() 的区别

两者都用于通知等待在同一个对象监视器上的线程。

|方法|作用|
|---|---|
|`notify()`|通知一个等待线程|
|`notifyAll()`|通知所有等待线程|

注意：

1. 调用它们时必须持有对应对象的监视器锁。
    
2. 调用通知方法不会立即释放锁。
    
3. 被通知的线程还需要重新竞争锁。
    
4. `notify()` 不保证选择最先等待的线程。
    
5. 被唤醒的线程仍然必须重新检查条件，因此通常应将 `wait()` 放在 `while` 循环中。
    

如果多个线程等待不同条件，而无法确定 `notify()` 选择的线程是否能够继续工作，使用 `notifyAll()` 通常更稳妥。

## 16. 线程间通信的方式

### 16.1 共享变量

多个线程通过共享变量传递状态或数据。

例如，使用 `volatile` 变量发布一个简单的状态变化：

```
private volatile boolean ready = false;
```

一个线程修改 `ready`，其他线程可以按照 `volatile` 的可见性规则观察到修改。

但 `volatile` 不能保证复合操作的原子性，也不能替代所有线程同步机制。

### 16.2 wait()、notify() 和 notifyAll()

通过对象监视器锁配合等待与通知，实现线程协作。

常见于生产者和消费者之间的协调。

### 16.3 Lock 和 Condition

`Condition` 配合 `Lock` 提供等待与通知功能。

|方法|作用|
|---|---|
|`await()`|等待条件满足|
|`signal()`|通知一个等待线程|
|`signalAll()`|通知所有等待线程|

调用 `await()` 前需要持有对应的锁；等待时会释放该锁，恢复执行前需要重新获取它。

### 16.4 BlockingQueue

`BlockingQueue` 是线程安全的阻塞队列。

例如：

- `put()`：队列满时，插入操作可以等待。
    
- `take()`：队列为空时，获取操作可以等待。
    

它适合生产者和消费者模式，能将线程间的数据传递与部分等待协调交给队列处理。

### 16.5 常见并发工具类

|工具类|主要作用|
|---|---|
|`CountDownLatch`|让一个或多个线程等待其他任务完成|
|`CyclicBarrier`|让一组线程相互等待，直到所有参与者到达屏障|
|`Semaphore`|限制同时访问某类资源的线程数量|

这些工具解决的问题不同，不应互相混淆。

## 17. Go 协程和 Java 线程的区别

Go 使用 goroutine，Java 主要提供平台线程和虚拟线程。

|对比项|Java 平台线程|Java 虚拟线程|Go goroutine|
|---|---|---|---|
|调度方式|主要由操作系统调度|由 JVM 调度到载体线程|由 Go 运行时调度|
|与操作系统线程的关系|通常一对一|大量虚拟线程可映射到较少的平台线程|大量 goroutine 可映射到较少的操作系统线程|
|资源开销|相对较高|通常较低|通常较低|
|适用场景|通用并发任务|大量阻塞等待的任务|大量并发任务|

注意：

- 虚拟线程与 goroutine 的调度思路有相似之处，但两者的实现并不完全相同。
    
- 虚拟线程和 goroutine 都不是无限制的资源。
    
- 轻量级并发模型不能自动提升 CPU 密集型任务的执行速度。
    

## 18. 本章总结

学习 Java 多线程时，可以按以下顺序建立知识体系：

1. **线程基础**：线程是什么、线程共享哪些资源。
    
2. **JMM**：理解原子性、可见性、有序性，以及 happens-before。
    
3. **线程创建与管理**：掌握 `Thread`、`Runnable`、`Callable`、`FutureTask` 和线程池的基本用途。
    
4. **线程生命周期**：理解六种线程状态，以及 `start()`、`sleep()`、`wait()`、`interrupt()` 的作用。
    
5. **线程间通信**：掌握共享变量、等待与通知、`Condition`、`BlockingQueue` 等方式。
    
6. **并发工具**：理解 `CountDownLatch`、`CyclicBarrier`、`Semaphore` 的适用场景。
    
7. **线程模型**：区分平台线程、虚拟线程和 Go goroutine。
    

其中，JMM、线程状态、中断机制、`sleep()` 与 `wait()` 的区别，以及线程间通信，是后续学习并发安全、锁和线程池的重要基础。
