# 1. Object 类有哪些常用方法？

`Object` 是 Java 中所有类的**根父类**。如果一个类没有显式继承其他类，就会默认继承 `Object`。即使显示继承了其他的类，仍然**间接继承 `Object`**。

`Object` 提供了对象比较、哈希计算、字符串转换、对象克隆和线程同步等相关方法。

## 1.1 常用方法一览

| 方法                              | 作用                         |
| ------------------------------- | -------------------------- |
| `equals(Object obj)`            | 判断两个对象是否相等，默认比较**对象身份**    |
| `hashCode()`                    | 返回对象的**哈希码**，供哈希集合等使用      |
| `toString()`                    | 返回对象的**字符串表示**             |
| `getClass()`                    | 获取对象运行时的**实际类型**           |
| `clone()`                       | 创建当前对象的**浅拷贝**             |
| `wait()`                        | 使当前线程等待，并释放当前对象的监视器锁       |
| `wait(long timeout)`            | 最多等待指定时间                   |
| `wait(long timeout, int nanos)` | 按指定的毫秒和纳秒参数等待              |
| `notify()`                      | 唤醒一个等待当前对象监视器的线程           |
| `notifyAll()`                   | 唤醒所有等待当前对象监视器的线程           |
| `finalize()`                    | 历史上用于垃圾回收前的清理回调，现已过时，不推荐使用 |

## 1.2 对象比较与信息获取
### 1.2.1 equals()

默认情况下，`Object` 的 `equals()` 与 `==` 比较引用时的效果相同。

如果希望按照对象的业务内容判断是否相等，可以重写该方法。

具体区别见后面的第 2 节。

### 1.2.2 hashCode()

返回对象的哈希码，常用于 `HashMap`、`HashSet` 等哈希集合中。

如果两个对象通过 `equals()` 判断为相等，它们必须具有相同的哈希码。

具体关系见第 3 节。

### 1.2.3 toString()

返回对象的字符串表示，常用于日志输出和调试。

默认实现通常返回：

```text
类名@哈希码的十六进制表示
```

例如：

```java
class User {
    private int id = 1;
}

User user = new User();
System.out.println(user);
```

默认输出可能类似：

```text
User@1b6d3586
```

这里的哈希码不是对象内存地址的保证。

实际开发中，可以重写 `toString()`，让输出更容易理解：

```java
@Override
public String toString() {
    return "User{id=" + id + "}";
}
```

这样打印对象时，就能直接看到相关字段的信息。

### 1.2.4 getClass()

返回对象运行时的**实际类型对应的 `Class` 对象**，常用于**反射**。

例如：

```java
Animal animal = new Dog();

System.out.println(animal.getClass());
```

即使变量的声明类型是 `Animal`，实际创建的对象是 `Dog`，因此获取到的是 `Dog` 对应的 `Class` 对象。

注意：`getClass()` 是 **`final`** 方法，不能被子类重写。

## 1.3 对象克隆：clone()

`clone()` 用于根据已有对象创建一个副本。`Object` 默认提供的是**浅拷贝**，即**复制对象自身的字段值，但不会递归复制字段引用的其他对象**。

使用时通常需要实现标记接口 `Cloneable`，并重写 `clone()` 方法。

```java
class Product implements Cloneable {
    private String name;

    @Override
    public Product clone() throws CloneNotSupportedException {
        return (Product) super.clone();
    }
}
```

如果没有实现 `Cloneable`，调用 `Object` 的 `clone()` 实现会抛出 `CloneNotSupportedException`。

注意：实现 `Cloneable` 本身并不会自动提供深拷贝。如果对象包含引用类型字段，浅拷贝后的两个对象仍可能共享这些字段所引用的对象。

## 1.4 线程同步：wait()、notify() 和 notifyAll()

这三个方法主要用于**多线程之间的协调**，需要配合当前对象的**监视器锁**使用。

| 方法            | 作用                                |
| ------------- | --------------------------------- |
| `wait()`      | **释放**当前对象的**监视器锁**，并**等待**其他线程通知 |
| `notify()`    | 唤醒**一个**正在等待该对象监视器的线程             |
| `notifyAll()` | 唤醒**所有**正在等待该对象监视器的线程             |

例如：

```java
synchronized (lock) {
    while (!condition) {
        lock.wait();
    }

    // 条件满足后执行
}
```

这里需要注意：

- 调用这些方法的线程必须持有对应对象的监视器锁，否则会抛出 `IllegalMonitorStateException`。
    
- `wait()` 会释放对应的监视器锁，使其他线程有机会进入同步代码。
    
- `notify()` 和 `notifyAll()` 不会立即释放锁，等待线程被唤醒后仍需要重新竞争锁。
    
- 使用 `wait()` 等待条件时，通常应该使用 `while` 循环重新检查条件，因为线程可能出现虚假唤醒。

# 2. == 与 equals() 有什么区别？

两者的区别主要在于比较规则。

## 2.1 \==：比较基本类型的值或引用身份

对于**基本数据类型**，`==` 比较的是**数值是否相等**。

```java
int a = 10;
int b = 10;

System.out.println(a == b); // true
```

对于**引用类型**，`==` 比较的是两个引用**是否指向同一个对象**。

```java
String a = new String("hello");
String b = new String("hello");

System.out.println(a == b); // false
```

虽然两个字符串的内容相同，但它们是分别创建的两个对象，因此引用**身份不同**。

## 2.2 equals()：默认比较身份，可以重写为比较内容

`equals()` 是 `Object` 中定义的方法。

**如果一个类没有重写 `equals()`，那么它的默认行为与比较引用的 `==` 相同。**

不过，**很多类重写了该方法**，用于按照对象的**实际内容**判断**是否相等**。

例如：

```java
String a = new String("hello");
String b = new String("hello");

System.out.println(a.equals(b)); // true
```

`String` 重写了 `equals()`，因此这里比较的是字符串内容，而不是是否为同一个对象。

## 2.3 为什么字符串有时使用 == 也会返回 true？

Java 使用字符串常量池管理字符串字面量。

```java
String a = "hello";
String b = "hello";

System.out.println(a == b); // true
```

**这两个变量通常引用常量池中的同一个字符串对象**，因此 `==` 返回 `true`。

但这不代表 `==` 比较字符串内容。它仍然比较引用身份，只是两个引用恰好指向同一个对象。

## 2.4 两者的区别总结

| 对比     | `==`           | `equals()`            |
| ------ | -------------- | --------------------- |
| 基本数据类型 | 比较数值           | 不能直接用于基本类型，需通过包装等方式调用 |
| 引用类型   | 比较是否为同一个对象     | 默认比较对象身份，也可以被重写为比较内容  |
| 能否重写   | 不能重写运算符        | 可以重写方法                |
| 典型用途   | 判断两个引用是否指向同一对象 | 判断两个对象在业务意义上是否相等      |

实际开发中，如果需要比较字符串或对象的内容，通常使用 `equals()`，而不是 `==`。

# 3. equals() 和 hashCode() 有什么关系？

`equals()` 用于判断两个对象是否相等，`hashCode()` 用于提供哈希码，帮助哈希集合定位对象。

两者需要遵守以下约定。

## 3.1 两者的基本关系

**规则一：如果两个对象通过 equals() 判断为相等，它们的 hashCode() 必须相同。**

```java
a.equals(b) == true
    ==> a.hashCode() == b.hashCode()
```

**规则二：两个对象的 hashCode() 相同，不代表它们一定相等。**

不同对象可能产生相同的哈希码，这种情况称为哈希冲突。

```java
对象 A ──> hashCode = 100
对象 B ──> hashCode = 100

哈希码相同
    |
    v
仍然需要比较对象是否相等
```

**规则三：如果重写了 equals()，通常也必须重写 hashCode()。**

否则，业务上相等的两个对象可能产生不同的哈希码，导致哈希集合无法按照预期识别它们。

## 3.2 为什么重写 equals() 时必须考虑 hashCode()？

以 `HashSet` 为例，假设业务规定：两个用户的 `id` 相同，就认为它们是同一个用户。

```java
class User {
    private int id;

    public User(int id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) {
            return true;
        }

        if (obj == null || getClass() != obj.getClass()) {
            return false;
        }

        User other = (User) obj;
        return id == other.id;
    }
}
```

现在只重写了 `equals()`，没有重写 `hashCode()`。

```java
Set<User> users = new HashSet<>();

users.add(new User(1));
users.add(new User(1));

System.out.println(users.size());
```

由于 `Object` 默认的 `hashCode()` 不会因为我们重写 `equals()` 而自动改变，两个业务上相等的对象仍可能具有不同的哈希码，导致集合无法按预期将它们识别为同一个元素。

因此，需要同时重写 `hashCode()`：

```java
@Override
public int hashCode() {
    return Integer.hashCode(id);
}
```

这样，两个 `id` 相同的 `User` 对象就会获得相同的哈希码，`HashSet` 再结合 `equals()` 判断它们是否相等。

## 3.3 HashMap 如何利用 `hashCode()` 和 `equals()` 查找元素？

当调用 `map.get(key)` 查找元素时，HashMap 大致会经历以下过程。

### 3.3.1 具体查找流程

假设 HashMap 中已经存入一个键值对，现在使用一个传入的 `key` 查找对应的 value。

```text
传入要查找的 key
        |
        v
调用 key.hashCode()，计算哈希值
        |
        v
对哈希值进行处理，计算桶下标（同一个桶里的对象，哈希值不一定相同）
        |
        v
定位到对应的桶
        |
        v
检查桶中的候选节点
        |
        v
比较节点的哈希值是否相同
        |
        +---- 不同 ----> 检查下一个候选节点
        |
        +---- 相同
               |
               v
       判断 key 是否与节点中的键相等
       （先判断是否为同一个对象，再通过 equals() 判断）
               |
          +----+----+
          |         |
         相等       不相等
          |         |
          v         v
      找到节点    检查下一个候选节点
          |
          v
      返回对应的 value
```

**注：**

- **如果桶中没有匹配的节点，就返回 `null`。**
	
- **先判断是否为同一个对象指先用 `==` 判断两个引用是否指向同一个对象，提高效率。**

### 3.3.2 为什么先比较哈希值，再调用 `equals()`？

因为 `HashMap` 需要先缩小查找范围，再判断键是否真正相等。

- **`hashCode()`**：帮助计算桶下标，定位可能存放键的位置。
    
- **比较哈希值**：检查候选节点的哈希值是否与待查找键的哈希值相同，不同就可以跳过该节点。
    
- **`equals()`**：进一步判断两个键在业务上是否相等。只有判断结果为 `true`，才会匹配到这个键。
    

注意：**同一个桶中的键，哈希值可能相同，也可能不同。** 因为不同的哈希值也可能计算出相同的桶下标，这种情况属于**哈希冲突**。

另外，一个桶中可能存放多个节点。JDK 8 及之后的 HashMap 通常使用链表组织这些节点；当满足一定条件时，也可能将链表转换为红黑树，以改善冲突严重时的查找效率。

### 3.3.3 为什么重写 `equals()` 时通常也要重写 `hashCode()`？

假设有两个不同的用户对象：

```java
User user1 = new User(1001);
User user2 = new User(1001);
```

它们是两个独立的对象，但如果按照用户 ID 判断是否相等，那么：

```java
user1.equals(user2) // true
```

如果只重写 `equals()`，没有重写 `hashCode()`，这两个对象可能产生不同的哈希值，进而定位到不同的桶。

使用 `user2` 查找以 `user1` 为键存入的键值对时，HashMap 可能根本检查不到 `user1`，因此无法正确找到原来的 value。

所以，Java 规定：**如果两个对象通过** `equals()` **判断为相等，它们的** `hashCode()` **必须相同。** 反过来，哈希值相同并不代表对象一定相等，还需要通过 `equals()` 等判断进一步确认。

因此，自定义类如果需要作为 HashMap 的键，并且重写了 `equals()`，通常也必须重写 `hashCode()`。

#### HashMap 的常见业务场景：状态码映射

在后端开发中，数据库可能使用数字保存订单状态，而页面需要展示对应的中文描述。例如：

```java
Map<Integer, String> statusMap = new HashMap<>();

statusMap.put(1, "待支付");
statusMap.put(2, "已支付");
statusMap.put(3, "已取消");

// 根据订单状态查询对应的中文描述
String statusName = statusMap.get(order.getStatus());
```

假设 `order.getStatus()` 返回 `2`，那么 `statusName` 就是 `"已支付"`。

这里，`Map` 将**状态码作为 key，将对应的中文描述作为 value**，可以根据状态码快速查找描述。使用 `HashMap` 时，查找操作的平均时间复杂度为 `O(1)`。

**为什么使用 Map？**

如果使用 `Map`，只需要通过 `get()` 查询映射关系，不必每次都编写 `if-else` 或 `switch` 判断。

不过，`Map` 并不是唯一的选择：

- **状态固定且数量较少**：可以使用 `switch`。
    
- **固定的业务状态需要统一管理**：可以使用 `enum` 枚举，并在枚举中定义状态码和描述。
    
- **映射关系需要动态维护**：例如从数据库读取数据字典，再使用 `Map` 存储或缓存查询结果。
    

**注意：** 上面的 `statusMap` 只负责将状态码转换为文字，并不直接负责执行不同的业务逻辑。此外，如果状态码不存在于 Map 中，`get()` 会返回 `null`，可以使用 `getOrDefault()` 提供默认描述。

```java
String statusName = statusMap.getOrDefault(
        order.getStatus(), "未知状态"
);
```

## 3.4 使用对象作为 HashMap 的 key，需要注意什么？

**不要随意修改参与 equals() 和 hashCode() 计算的字段。**

假设一个用户的 `id` 决定它的相等性和哈希码。如果对象放入 `HashMap` 后修改了 `id`，后续查找时计算出的哈希值可能与插入时不同，从而无法正常找到该键。

因此，**作为哈希集合键的对象，最好使用不可变的身份字段，或者保证参与相等性和哈希计算的字段在使用期间保持不变。**

# 4. 本章总结

- **Object 类**：Java 所有类的根父类，提供对象比较、哈希计算、字符串表示、克隆和线程协调等方法。
    
- **`==` 与 `equals()`**：`==` 对引用类型比较对象身份；`equals()` 默认也是比较身份，但可以重写为比较内容。
    
- **`equals()` 与 `hashCode()`**：两个相等的对象必须具有相同的哈希码；哈希码相同不代表对象一定相等。
    
- **哈希集合**：`HashMap`、`HashSet` 等依赖哈希值定位，并结合相等性判断识别对象。
    
- **资源与线程方法**：`wait()`、`notify()`、`notifyAll()` 用于线程协调；`finalize()` 已过时，不应依赖它释放资源。
