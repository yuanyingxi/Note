# 1. 什么是 Java 异常？

异常是程序运行过程中出现的非正常情况。Java 使用异常机制来表示和处理这些情况，例如文件不存在、数字格式错误、访问空对象等。

Java 的异常体系以 `Throwable` 为根类，主要分为 `Error` 和 `Exception` 两大类。

```text
Throwable
├── Error
│   ├── OutOfMemoryError
│   └── StackOverflowError
│
└── Exception
    ├── IOException
    ├── SQLException
    └── RuntimeException
        ├── NullPointerException
        ├── ArithmeticException
        └── ArrayIndexOutOfBoundsException
```

## 1.1 Error：错误

`Error` 表示比较**严重**的问题，通常与 JVM 运行环境或系统资源有关，一般**不建议程序尝试捕获并继续运行**。

例如：

- `OutOfMemoryError`：内存不足，JVM 无法满足内存分配需求。
    
- `StackOverflowError`：线程栈空间耗尽，常见原因是递归调用过深。
    

## 1.2 Exception：异常

`Exception` 表示**程序可以识别和处理**的异常情况。

根据是否需要**编译器强制检查**，可以分为两类：

| 类型                         | 含义            | 常见例子                                         |
| -------------------------- | ------------- | -------------------------------------------- |
| 受检异常（Checked Exception）    | 编译器要求捕获或声明抛出  | `IOException`、`SQLException`                 |
| 非受检异常（Unchecked Exception） | 编译器不强制要求捕获或声明 | `NullPointerException`、`ArithmeticException` |

其中，`RuntimeException` 及其子类属于非受检异常。

例如：

```java
int num = Integer.parseInt("abc");
```

由于 `"abc"` 不是有效的整数格式，运行时会抛出 `NumberFormatException`，它属于 `RuntimeException` 的子类。

注意：受检异常并不意味着异常一定会发生，非受检异常也不意味着一定无法处理。两者的主要区别在于**编译器是否强制要求处理**。

# 2. Java 有哪些异常处理方式？

Java 常见的异常处理机制包括 `try-catch`、`throw`、`throws`、`finally` 和 `try-with-resources`。

## 2.1 try-catch：捕获并处理异常

`try` 用于包围可能发生异常的代码，`catch` 用于捕获指定类型的异常并进行处理。

```java
try {
    int num = Integer.parseInt("abc");
    System.out.println(num);
} catch (NumberFormatException e) {
    System.out.println("输入的内容不是有效整数");
}

System.out.println("程序继续执行");
```

执行过程：

1. 执行 `try` 中的代码。
    
2. 转换失败，抛出 `NumberFormatException`。
    
3. 跳过 `try` 中异常发生位置之后的剩余代码。
    
4. 进入匹配的 `catch` 处理异常。
    
5. 继续执行整个 `try-catch` 结构后面的代码。
    

如果没有匹配的 `catch`，异常会继续向调用方传播。

**注意：** 如果存在多个 `catch`，应将**范围较小的异常类型放在前面**，**范围较大的父类异常放在后面**，否则可能出现编译错误。

## 2.2 throw 和 throws：主动抛出与声明异常

两者的作用不同：

| 对比    | `throw`         | `throws`         |
| ----- | --------------- | ---------------- |
| 作用    | 实际抛出一个异常对象      | 声明方法可能抛出的异常类型    |
| 使用位置  | 方法体内部           | 方法声明处            |
| 后面跟什么 | 异常对象            | 异常类型             |
| 主要用途  | 发现问题时**主动抛出异常** | 将**异常处理责任交给调用方** |

`throw` **示例：**

```java
public static void checkAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负数");
    }
}
```

当年龄小于 0 时，程序主动抛出 `IllegalArgumentException`，表示传入的参数不合法。

`throws` **示例：**

```java
public static String readFile(String path)
        throws IOException {
    // 读取文件的相关代码
    return "";
}
```

这里的 `throws IOException` 表示该方法可能抛出 `IOException`，由调用方决定捕获处理还是继续声明抛出。

对于受检异常，方法必须捕获处理，或者通过 `throws` 声明后交给调用方处理。

对于 `RuntimeException` 和 `Error`，编译器不强制要求捕获或声明。

## 2.3 finally：执行清理操作

`finally` 用于放置通常需要执行的清理代码，例如释放资源、关闭连接等。

```java
try {
    System.out.println("执行操作");
} catch (Exception e) {
    System.out.println("处理异常");
} finally {
    System.out.println("执行清理操作");
}
```

通常情况下，无论 `try` 中的代码正常执行还是发生异常，**`finally` 都会执行**。

即使 `try` 或 `catch` 中有 `return`，在方法真正返回之前，通常也会先执行 `finally`。

但是，不能认为 `finally` 在任何情况下都一定执行。例如，JVM 被强制终止时，`finally` 可能没有机会运行。

## 2.4 try-with-resources：自动关闭资源

`try-with-resources` 用于自动关闭实现了 `AutoCloseable` 接口的资源，例如文件流、数据库连接等。

```java
try (BufferedReader reader =
         new BufferedReader(new FileReader("test.txt"))) {

    System.out.println(reader.readLine());

} catch (IOException e) {
    System.out.println("文件读取失败");
}
```

当程序离开 `try` 代码块时，Java 会自动关闭其中声明的资源，即使执行过程中发生异常，也会尝试关闭资源。

与手动在 `finally` 中调用 `close()` 相比，这种方式更简洁，也更不容易遗漏资源释放。

**实际开发中，关闭文件流等资源时，通常优先使用** `**try-with-resources**`**。**

# 3. 为什么有些异常不需要使用 throws？

是否需要使用 `throws`，主要取决于异常类型以及方法内部是否已经处理异常。

## 3.1 非受检异常不需要强制声明

```java
public static void test() {
    String str = null;
    System.out.println(str.length());
}
```

这里可能抛出 `NullPointerException`，但编译器不会要求方法使用 `throws` 声明它。

原因是 `NullPointerException` 属于 `RuntimeException` 的子类，属于非受检异常。

### 3.2 受检异常可以在方法内部处理

```java
public static void test() {
    try {
        Thread.sleep(1000);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}
```

`Thread.sleep()` 可能抛出受检异常 `InterruptedException`，但这里已经在方法内部捕获处理，因此不需要再通过 `throws` 声明该异常。

**总结：**

- **受检异常：必须捕获处理，或者声明抛出。**
    
- **非受检异常：编译器不强制要求捕获或声明。**
    
- **已经在方法内部捕获处理的异常：不需要再向外声明该异常。**
    

# 4. try-catch 中的语句是如何执行的？

需要区分正常执行和发生异常两种情况。

## 4.1 没有发生异常

`try` 中的代码按顺序执行完毕，跳过对应的 `catch`，然后执行 `finally`（如果存在），最后继续执行后续代码。

```java
try {
    System.out.println("A");
    System.out.println("B");
} catch (Exception e) {
    System.out.println("C");
} finally {
    System.out.println("D");
}

System.out.println("E");
```

输出：

```
A
B
D
E
```

### 4.2 发生异常

当 `try` 中的代码抛出异常时，异常发生位置之后的剩余代码不会继续执行，而是寻找能够匹配该异常的 `catch`。

```java
try {
    System.out.println("A");
    int num = Integer.parseInt("abc");
    System.out.println("B");
} catch (NumberFormatException e) {
    System.out.println("C");
} finally {
    System.out.println("D");
}

System.out.println("E");
```

输出：

```text
A
C
D
E
```

其中，`B` 不会输出，因为异常发生后，程序跳转到了对应的 `catch`，而由于**异常被捕获**，**所以程序可以继续执行**，输出 `E`。

如果没有匹配的 `catch`，异常会继续向调用方传播，但在控制流正常离开 `try` 时，`finally` 通常仍会执行。

# 5. try 和 finally 都有 return 时，返回什么？

例如：

```java
public static String test() {
    try {
        return "a";
    } finally {
        return "b";
    }
}
```

返回结果是：

```text
b
```

**原因是：`try` 中的 `return "a"` 尚未完成方法返回，就先执行了 `finally`；而 `finally` 中的 `return "b"` 会覆盖原本准备返回的结果。**

**注意：实际开发中应避免在 `finally` 中使用 `return`，因为它可能覆盖原有返回值，还可能掩盖原本抛出的异常。**

# 6. 总结

| 知识点                  | 核心结论                        |
| -------------------- | --------------------------- |
| `Throwable`          | Java 异常体系的根类                |
| `Error`              | 通常表示严重的运行环境或资源问题            |
| `Exception`          | 表示程序可以识别和处理的异常情况            |
| 受检异常                 | 必须捕获处理，或者声明抛出               |
| 非受检异常                | 编译器不强制要求捕获或声明               |
| `try-catch`          | 捕获并处理异常                     |
| `throw`              | 主动抛出异常对象                    |
| `throws`             | 声明方法可能抛出的异常类型               |
| `finally`            | 通常用于执行清理操作                  |
| `try-with-resources` | 自动关闭实现了 `AutoCloseable` 的资源 |

面试时尤其需要掌握：**异常体系的分类、受检异常与非受检异常的区别、`throw` 与 `throws` 的区别，以及 `finally` 的执行规则。**
