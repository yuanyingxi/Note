# 1. Java 的特点

Java 是一种广泛应用于后端开发、企业级应用和 Android 开发等领域的高级编程语言。

## 1.1 平台无关性

Java 的一个重要特点是平台无关性。

Java 源代码通常先编译为与具体操作系统无关的字节码，再由不同平台上的 JVM 执行。

```text
Java 源代码（.java）
        ↓ javac 编译
Java 字节码（.class）
        ↓
   ┌────┼────┐
   ↓    ↓    ↓
Windows Linux macOS
 JVM    JVM   JVM
```

只要目标平台提供兼容的 Java 运行环境，同一份字节码通常就可以在不同操作系统上运行。

这就是 Java 的经典理念：

**一次编写，到处运行（Write Once, Run Anywhere）。**

注意：不同平台需要相应的 JVM，并不是同一个 JVM 软件可以直接运行在所有操作系统上。

## 1.2 面向对象

Java 是一种以面向对象编程为重要特征的语言。

面向对象的核心概念包括：

- **封装**：将数据和操作数据的方法组织起来，通过访问控制保护对象内部状态。
    
- **继承**：子类可以继承父类的成员，并在此基础上扩展功能。
    
- **多态**：同一个父类型引用可以指向不同子类对象，调用方法时表现出不同的行为。
    
- **抽象**：提取共同特征，隐藏不必要的实现细节。
    

面向对象有助于组织复杂程序，提高代码的可维护性和可复用性。

## 1.3 自动内存管理

Java 提供垃圾回收机制（Garbage Collection，GC）。

当某些对象不再被程序访问、无法通过有效的引用链到达时，垃圾回收器可以在适当时机回收它们占用的堆内存。

与 C/C++ 中需要开发者显式管理大量内存释放工作的场景相比，Java 能够减少部分手动内存管理负担。

但要注意：

- GC 不意味着绝对不会发生内存泄漏。
    
- GC 不保证对象一旦不可达就会立即被回收。
    
- 文件、网络连接等外部资源仍然需要妥善关闭。
    

## 1.4 可移植性

Java 的字节码和标准类库设计有助于提高程序的可移植性。

不过，如果程序依赖特定操作系统的文件路径、系统命令、本地动态库或硬件功能，仍然可能需要针对不同平台进行适配。

## 1.5 安全性

Java 提供了多种有助于提高程序安全性的机制，例如：

- 类型检查与字节码验证。
    
- 访问权限控制。
    
- 类加载机制。
    
- 运行时异常检查等。
    

但安全性并不意味着 Java 程序天然没有漏洞。程序仍然需要正确的设计、配置和安全实践。

## 1.6 多线程支持

Java 提供了丰富的并发编程能力，例如：

- `Thread`
    
- `Runnable`
    
- `synchronized`
    
- `volatile`
    
- `java.util.concurrent` 并发工具包
    

这些机制可以帮助开发者编写多线程程序，充分利用多核处理器资源。

## 1.7 丰富的生态系统

Java 具有成熟的开发工具、类库和框架生态，例如：

- Spring、Spring Boot：后端应用开发。
    
- MyBatis、Hibernate：数据持久化。
    
- Maven、Gradle：项目构建与依赖管理。
    
- JUnit：自动化测试。
    

这使 Java 特别适合大型、长期维护的企业级应用。

# 2. Java 的优势和劣势

## 2.1 Java 的优势

| 优势     | 说明                 |
| ------ | ------------------ |
| 平台无关性  | 通过字节码和 JVM 支持跨平台运行 |
| 面向对象   | 便于组织复杂业务逻辑，提高可维护性  |
| 自动内存管理 | GC 可以自动回收符合条件的对象内存 |
| 生态成熟   | 框架、类库、开发工具丰富       |
| 并发支持   | 提供线程、锁和并发工具等机制     |
| 工程化能力强 | 适合大型项目和团队协作        |
| 类型检查   | 静态类型系统有助于发现部分错误    |

## 2.2 Java 的劣势

|劣势|说明|
|---|---|
|内存开销可能较大|JVM 运行环境、对象头和运行时数据结构等都会占用内存|
|启动开销|JVM 启动、类加载和运行时初始化可能增加启动时间|
|语法相对冗长|某些场景需要编写较多样板代码|
|性能并非始终最优|对启动速度、极低延迟或底层控制要求很高的场景，可能需要权衡|
|GC 需要调优|在特定工作负载下，垃圾回收可能带来延迟和资源开销|

### 面试回答

**问：Java 有哪些优缺点？**

答：Java 的主要优势是平台无关性、面向对象特性、自动内存管理、成熟的生态系统以及丰富的并发支持，适合大型企业级应用开发。它的不足包括 JVM 运行环境带来的内存和启动开销、部分语法相对冗长，以及垃圾回收在特定场景下可能引入延迟。但实际性能需要结合具体场景、JVM 实现和优化方式判断，不能简单认为 Java 一定比其他语言慢。

# 3. 为什么 Java 可以跨平台？

## 3.1 核心原因

Java 跨平台的关键在于：

**Java 源代码先编译为平台无关的字节码，再由目标平台上的 JVM 执行字节码。**

完整过程如下：

```text
Java 源代码
  Main.java
      |
      | javac 编译
      v
Java 字节码
  Main.class
      |
      | 由对应平台的 JVM 加载和执行
      |
  ┌───┴────┐
  v        v
Windows   Linux
 JVM       JVM
  |         |
  v         v
操作系统    操作系统
```

## 3.2 为什么不直接编译成机器码？

不同操作系统和处理器可能使用不同的机器指令与运行环境。

如果直接把源代码编译成某一平台的原生机器码，通常就需要针对其他平台重新编译，或者提供专门的兼容层。

Java 采用字节码作为中间表示：

1. `javac` 将 `.java` 源文件编译为 `.class` 字节码。
    
2. 字节码不直接绑定到某一种操作系统的原生指令集。
    
3. 不同平台上的 JVM 负责加载、验证和执行字节码。
    
4. JVM 通过解释执行或 JIT 编译等方式，将字节码落实为目标平台上的实际操作。
    

## 3.3 跨平台的本质

这里需要区分三个概念：

- **Java 源代码**：开发者编写的程序。
    
- **Java 字节码**：Java 编译器生成的中间代码。
    
- **JVM**：负责执行字节码的虚拟机，不同平台通常有相应的 JVM 实现。
    

因此，准确的说法是：

> 跨平台能力来自平台无关的字节码以及不同平台上兼容的 JVM 实现，而不是 JVM 本身跨平台运行。

此外，如果 Java 程序依赖平台专属的本地库或操作系统功能，就不一定能够不加修改地跨平台运行。

### 面试回答

Java 之所以能够跨平台，是因为 Java 源代码经过编译后生成平台无关的字节码，而不是直接生成某个操作系统专用的机器码。不同平台只要具有兼容的 JVM，就可以加载并执行相同的字节码。因此，Java 实现了“一次编写，到处运行”。

# 4. JVM、JRE、JDK 三者的关系

## 4.1 JVM 是什么？

JVM（Java Virtual Machine，Java 虚拟机）是一种用于加载和执行 Java 字节码的虚拟机运行环境。

可以把它理解为一种软件实现的虚拟执行环境，负责在真实操作系统和处理器上执行 Java 字节码。

JVM 的主要职责包括：

- 加载和验证类。
    
- 管理运行时内存。
    
- 执行字节码。
    
- 配合垃圾回收器管理对象内存。
    
- 通过解释器和 JIT 编译器执行、优化代码。
    

注意：JVM 不等于 Java 语言，也不等于整个 Java 开发环境。

## 4.2 JRE 是什么？

JRE（Java Runtime Environment，Java 运行环境）是传统 Java 发行体系中的概念，主要用于运行 Java 程序。

传统概念下，可以理解为：

```text
JRE ≈ JVM + Java 类库及其他运行时组件
```

其中：

- JVM 负责执行字节码。
    
- Java 类库提供集合、输入输出、网络等常用功能。
    
- 其他运行时组件提供程序运行所需的支持。
    

**版本说明：** 从 Java 9 开始，Oracle 不再以过去的方式提供独立的传统 JRE 下载包。不过，JRE 作为描述 Java 运行环境的概念仍然有意义；实际部署也可以通过定制运行时镜像等方式提供运行环境。

## 4.3 JDK 是什么？

JDK（Java Development Kit，Java 开发工具包）是用于开发 Java 程序的工具集合。

它包含运行 Java 程序所需的运行时能力，以及编译、调试和其他开发工具。

常见工具包括：

|工具|作用|
|---|---|
|`javac`|将 Java 源代码编译成字节码|
|`java`|启动 Java 程序|
|`jdb`|调试 Java 程序|
|`javadoc`|生成 API 文档|
|`jar`|创建和处理 JAR 文件|

实际安装 JDK 时，通常就能同时获得编译和运行 Java 程序所需的工具。

## 4.4 三者关系

从传统概念上理解：

```text
JDK：开发工具包
 ├── 开发工具（javac、jdb 等）
 └── Java 运行环境
      ├── JVM
      ├── Java 类库
      └── 其他运行时组件
```

常见的简化记忆方式是：

**JDK > JRE > JVM**

但这是一种传统概念关系图，并不意味着所有现代 Java 发行版都以独立的 JRE 文件夹或安装包呈现。

### 面试回答

JVM 是执行 Java 字节码的虚拟机；JRE 是传统意义上运行 Java 程序所需的环境，包括 JVM 和相关运行时组件；JDK 则是开发 Java 程序的工具包，包含编译器、调试工具等开发工具以及运行时能力。开发 Java 程序通常安装 JDK 即可。

# 5. JVM 和 Java 有什么区别？

Java 和 JVM 不是同一个概念。

|对比维度|Java|JVM|
|---|---|---|
|本质|编程语言及其相关技术体系|虚拟机运行环境|
|主要作用|编写程序、描述程序逻辑|加载和执行字节码|
|典型对象|`.java` 源代码|`.class` 字节码|
|相关职责|语法、类型系统、语言规则等|类加载、内存管理、字节码执行等|

## 5.1 两者如何配合？

```text
开发者编写 Java 源代码
        |
        v
    Main.java
        |
        | javac
        v
    Main.class
        |
        | JVM 加载并执行
        v
    程序运行
```

Java 负责描述程序逻辑；编译器将源代码编译成字节码；JVM 负责加载和执行字节码。

## 5.2 JVM 只能运行 Java 吗？

不一定。

只要某种语言能够编译或转换为符合 JVM 规范的字节码，并且遵循相应运行时约定，就可以借助 JVM 运行。

例如，Kotlin、Scala 和 Groovy 都可以面向 JVM 运行。

因此，JVM 不仅服务于 Java 语言，也构成了 JVM 语言生态的运行基础。

### 面试回答

Java 是编程语言，JVM 是执行 Java 字节码的虚拟机。开发者用 Java 编写源代码，通过编译器生成字节码，再由 JVM 加载和执行。JVM 负责运行时的类加载、字节码执行、内存管理等工作，而且它也能够运行其他编译为 JVM 字节码的语言。

# 6. 为什么 Java 既有编译又有解释？

这是理解 Java 运行机制的关键问题。

Java 中需要区分两个阶段：

1. **编译阶段**：将 Java 源代码编译成字节码。
    
2. **运行阶段**：JVM 通过解释执行和 JIT 编译等方式执行字节码。
    

## 6.1 第一阶段：编译器 javac

开发者编写：

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}
```

保存为：

```text
Main.java
```

执行：

```bash
javac Main.java
```

生成：

```text
Main.class
```

此时完成的是：

```text
.java 源代码
      |
      | javac
      v
.class 字节码
```

`javac` 不是直接把 Java 源代码编译成某个特定操作系统的原生可执行文件，而是生成 JVM 可以加载的字节码。

## 6.2 第二阶段：JVM 执行字节码

JVM 的执行引擎可以通过解释器和 JIT 编译器等机制执行字节码。

### 解释器（Interpreter）

解释器在程序运行时读取 Java 字节码指令，并按照指令的含义执行相应操作。

可以把它理解为：

```text
读取字节码指令
      ↓
解释指令含义
      ↓
执行对应操作
      ↓
继续处理后续指令
```

需要注意：

**解释器并不是逐行读取 `.java` 源代码，也不是先把整个 `.class` 文件完整编译成机器码再执行。**

它主要负责运行时的字节码解释执行。

### JIT 编译器（Just-In-Time Compiler）

JIT 编译器是即时编译器。

程序运行过程中，JVM 可以收集运行时信息，并识别经常执行的代码，也就是通常所说的热点代码（Hot Code）。

当满足相应编译条件时，JIT 可以将热点代码编译成本地机器码，并进行一些运行时优化。

```text
Java 字节码
    |
    v
运行时执行
    |
    v
识别热点代码
    |
    v
JIT 编译
    |
    v
本地机器码
    |
    v
后续执行可使用编译结果
```

这样可以减少热点代码反复解释执行的开销。

注意，JIT 并不是把所有代码在程序启动时一次性编译完成。哪些代码被编译、何时编译以及采用哪些优化，取决于 JVM 实现和运行时情况。

## 6.3 为什么同时使用解释器和 JIT？

两种方式各有特点：

|机制|特点|
|---|---|
|解释执行|可以较快开始执行代码，不必等待所有代码完成即时编译|
|JIT 编译|热点代码编译为本地机器码后，后续执行通常更高效|
|两者结合|兼顾启动阶段的执行效率和长期运行时的性能优化|

如果所有代码都必须先完成本地编译才能开始执行，启动阶段可能需要付出额外开销。

如果所有代码始终只由解释器执行，长期反复执行的热点代码又可能错过 JIT 优化带来的性能收益。

因此，现代主流 JVM 通常结合解释执行和 JIT 编译。

## 6.4 Java 运行流程：七个步骤

```text
第 1 步：编写源代码
        Main.java
             |
             v
第 2 步：javac 编译
        Main.class
             |
             v
第 3 步：JVM 加载和验证字节码
             |
             v
第 4 步：解释器开始执行字节码
             |
             v
第 5 步：JVM 收集运行时信息
             |
             v
第 6 步：识别热点代码，符合条件时由 JIT 编译
             |
             v
第 7 步：后续执行可利用编译后的本地机器码
```

需要补充：这张图是为了便于理解的简化流程。实际 JVM 中，解释执行、热点检测、JIT 编译和优化可能交错发生，并非所有代码都必须严格依次经历每一个步骤。

## 6.5 如何准确理解“普通代码解释，热点代码编译”？

可以这样理解：

- 尚未被 JIT 编译的代码，可以由解释器执行。
    
- JVM 监控运行情况，识别反复执行的热点代码。
    
- 热点代码满足相应条件后，可以被 JIT 编译成本地机器码。
    
- 后续执行时，JVM 可以使用已经生成的机器码。
    

所以，“普通代码一句一句解释，热点代码编译成机器码”是一种便于入门的概括。

更严谨的说法是：

> JVM 可以解释执行尚未编译的字节码，并根据运行时信息对热点代码进行 JIT 编译和优化。两种机制共同参与程序执行。

### 面试回答

Java 先由 `javac` 将源代码编译成平台无关的字节码。运行时，JVM 可以通过解释器执行字节码，并通过 JIT 编译器将符合条件的热点代码编译成本地机器码。解释执行有助于快速启动，JIT 则能够优化热点代码的执行效率，因此现代 JVM 通常采用解释执行与即时编译相结合的方式。

# 7. 编译型语言和解释型语言的区别

## 7.1 编译型语言

典型的编译型执行模式是：程序在运行前先由编译器编译成目标平台的原生机器码，再执行生成的程序。

常见例子包括 C、C++ 和 Rust。

简化流程：

```text
源代码
  |
  | 编译器
  v
原生机器码
  |
  v
运行
```

需要注意，编译型语言也可能涉及中间表示、运行时组件或 JIT 等机制，因此这个流程是典型模式，不是对所有实现的绝对描述。

## 7.2 解释型语言

典型的解释型执行模式是：运行时由解释器处理程序代码或中间表示，而不是要求整个程序预先编译为原生机器码后才能运行。

常见例子包括 Python 的常见实现，以及 JavaScript 的许多运行环境。

简化流程：

```text
源代码
  |
  | 解释器或运行时处理
  v
执行
```

但要注意：

**解释执行不一定意味着解释器直接逐行读取源代码。**

很多解释器会先将源代码转换为中间表示或字节码，再执行这些内容。

例如，常见的 CPython 实现会先将 Python 源代码编译为 Python 字节码，再由其虚拟机解释执行。

## 7.3 核心区别

|对比维度|典型编译型模式|典型解释型模式|
|---|---|---|
|主要执行方式|运行前编译为原生机器码|运行时解释执行代码或中间表示|
|运行前的编译|通常需要|不一定需要编译为原生机器码|
|运行方式|执行编译后的程序|依赖解释器或运行时执行|
|典型例子|C、C++、Rust|Python、部分 JavaScript 运行模式|

这是一种帮助理解的分类方式，并不是严格的二分法。

现代语言和运行时可能同时使用解释、编译、中间表示和 JIT 优化。

## 7.4 Java 属于哪一种？

Java 不能简单地等同于传统的纯编译型语言，也不能简单地说它是一种纯解释型语言。

Java 的典型执行过程是：

```text
Java 源代码
    |
    | javac
    v
Java 字节码
    |
    v
JVM
    |
    ├── 解释执行
    |
    └── JIT 编译为本地机器码
```

Java 的特点是先编译成 JVM 字节码，再由 JVM 在运行时结合解释和即时编译等机制执行。

### 面试回答

编译型和解释型通常是根据程序的主要执行模式来区分的。典型编译型程序会在运行前编译为原生机器码；典型解释型程序则由运行时解释执行源代码或中间表示。现代语言实现可能同时采用编译和解释，因此不能只看有没有编译步骤来判断。Java 先将源代码编译成字节码，再由 JVM 通过解释器和 JIT 编译器执行。

# 8. Python 和 Java 的区别

## 8.1 执行机制

### Java

```text
.java 源代码
     |
     | javac
     v
.class 字节码
     |
     v
JVM
     |
     ├── 解释执行
     └── JIT 编译
```

### Python（以常见的 CPython 实现为例）

```text
.py 源代码
     |
     v
编译为 Python 字节码
     |
     v
CPython 虚拟机解释执行
```

CPython 可能缓存字节码，例如 `.pyc` 文件，但这并不意味着它已经将整个程序编译成原生机器码。

因此，不能把 Python 简单理解为“完全不编译、直接逐行执行源代码”。

## 8.2 主要区别

| 对比维度   | Java                       | Python（以 CPython 为例）                 |
| ------ | -------------------------- | ------------------------------------ |
| 类型系统   | 静态类型语言，变量声明通常具有明确的类型约束     | 动态类型语言，类型在运行时与对象相关                   |
| 主要执行机制 | 字节码 + JVM + 解释器/JIT        | Python 字节码 + CPython 解释执行            |
| 编译步骤   | 通常先使用 `javac` 编译为 `.class` | 运行时通常先编译为 Python 字节码                 |
| 性能     | JVM JIT 对热点代码有较强优化能力       | 常见的 CPython 纯 Python 代码执行通常受解释执行开销影响 |
| 开发效率   | 结构和类型约束明确，工程化能力强           | 语法通常简洁，适合快速开发与脚本任务                   |
| 常见应用   | 企业后端、服务端系统、大型应用            | 数据分析、机器学习、自动化、脚本和 Web 开发             |

## 8.3 如何理解 Java 的静态类型和 Python 的动态类型？

Java 示例：

```java
int age = 20;
age = "hello"; // 编译错误
```

`age` 被声明为 `int`，不能直接赋值为字符串。

Python 示例：

```python
age = 20
age = "hello"  # 合法
```

Python 中，变量名可以先后绑定不同类型的对象。

这里比较的是 Java 和 Python 在常见类型检查方式上的差异，并不意味着 Python 没有类型系统。Python 同样支持类型注解，只是常规运行时不会像 Java 编译器那样强制执行所有静态类型约束。

## 8.4 哪个性能更好？

不能只根据语言名称判断性能。

Java 的 JIT 编译器可以根据运行时信息优化热点代码，因此在长期运行的服务端程序中往往有良好的性能表现。

常见 CPython 对纯 Python 代码的执行通常有较明显的解释执行开销。不过，Python 的 NumPy、PyTorch 等库会将大量计算交给底层优化过的原生代码或专用计算设备，因此实际任务的性能还取决于算法、库实现、数据规模和硬件。

### 面试回答

Java 是静态类型语言，通常先通过 `javac` 编译成 JVM 字节码，再由 JVM 结合解释执行和 JIT 编译运行。Python 是动态类型语言，以 CPython 为例，源代码通常先编译成 Python 字节码，再由虚拟机解释执行。Java 常见于大型企业级后端，Python 则广泛用于数据分析、机器学习和自动化开发。两者的性能和开发效率都需要结合具体场景判断。

# 9. Java 参数传递：值传递还是引用传递？

## 9.1 核心结论

Java 中**只有值传递（Pass by Value），不存在真正的引用传递（Pass by Reference）**。

关键在于：

> 方法调用时，传递的永远是参数值的副本。

区别只是：

- **基本数据类型**：传递的是基本数据本身的值的副本。
    
- **引用类型**：传递的是对象引用的副本。
    

因此，Java 中不存在“把变量本身传进去，让方法可以直接修改原变量”的引用传递。

## 9.2 基本数据类型：传递值的副本

```java
public static void main(String[] args) {
    int num = 10;

    changeValue(num);

    System.out.println(num); // 10
}

public static void changeValue(int a) {
    a = 20;
}
```

执行过程：

```text
num = 10
  |
  | 调用 changeValue(num)
  v
a 得到 num 的值的副本

修改 a = 20 后：

num = 10
a   = 20
```

`a` 和 `num` 是两个独立的变量，因此修改 `a` 不会影响 `num`。

## 9.3 引用类型：传递的是引用的副本

先定义一个类：

```java
class Person {
    String name;

    Person(String name) {
        this.name = name;
    }
}
```

调用方法：

```java
public static void main(String[] args) {
    Person p = new Person("Alice");

    changeName(p);

    System.out.println(p.name); // Bob
}

public static void changeName(Person obj) {
    obj.name = "Bob";
}
```

为什么 `p.name` 会变成 `"Bob"`？

因为调用方法时，没有复制一个新的 `Person` 对象，而是将 `p` 中保存的引用值复制一份，赋值给 `obj`。

```text
p ────────┐
          v
      Person 对象
      name = "Alice"
          ^
          |
obj ──────┘
```

`p` 和 `obj` 都指向同一个对象。

因此：

```java
obj.name = "Bob";
```

修改的是它们共同指向的对象。

所以：

```text
p.name == "Bob"
```

## 9.4 为什么这仍然属于值传递？

假设：

```java
Person p = new Person("Alice");
```

调用：

```java
changeName(p);
```

方法得到的是 `p` 中引用值的副本：

```text
p ─────────→ Person 对象
                ^
                |
obj ────────────┘
```

因此：

> 传递的是引用这个“值”的副本，而不是变量 `p` 本身。

这就是为什么引用类型的参数传递仍然属于值传递。

## 9.5 修改对象内容：会影响原对象

```java
public static void changeName(Person obj) {
    obj.name = "Bob";
}
```

因为 `p` 和 `obj` 指向同一个对象，所以通过 `obj` 修改对象内容后，使用 `p` 访问时也能看到变化。

```text
p ────────→ Person
              name = "Bob"
                ^
                |
obj ────────────┘
```

## 9.6 修改引用的指向：不会影响原引用

这是面试中最关键的例子。

```java
public static void changeReference(Person obj) {
    obj = new Person("Charlie");
}
```

调用：

```java
Person p = new Person("Alice");

changeReference(p);

System.out.println(p.name); // Alice
```

调用方法之前，`p` 和 `obj` 指向同一个对象：

```text
p ────────→ Person("Alice")
                ^
                |
obj ────────────┘
```

执行：

```java
obj = new Person("Charlie");
```

只是让局部变量 `obj` 指向新对象：

```text
p ─────────→ Person("Alice")

obj ───────→ Person("Charlie")
```

`p` 的指向没有改变，因此输出仍然是 `"Alice"`。

## 9.7 修改对象和修改引用的区别

|操作|示例|是否影响调用者的变量|
|---|---|---|
|修改基本类型参数|`a = 20;`|不影响原变量|
|修改引用所指对象的内容|`obj.name = "Bob";`|原变量访问同一对象时能看到变化|
|给引用参数重新赋值|`obj = new Person("Charlie");`|不影响调用者原来的引用|

最重要的区别：

- `obj.name = "Bob"`：修改对象。
    
- `obj = new Person("Charlie")`：修改局部引用变量的指向。
    

## 9.8 面试回答

如果面试官问“Java 是值传递还是引用传递”，可以回答：

Java 中只有值传递，没有引用传递。对于基本数据类型，传递的是实际值的副本；对于引用类型，传递的是对象引用的副本。因此，通过引用副本可以修改原对象的内容，但如果让这个引用副本重新指向另一个对象，并不会影响原来的引用。

记忆口诀：

**Java 的参数传递永远是值传递，只不过引用类型传递的“值”是对象的引用。**
