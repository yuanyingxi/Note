# 1. 什么是序列化和反序列化？

**序列化（Serialization）**：将 **Java 对象**转换成**字节流**的过程，使对象的数据能够被**保存**到文件、网络传输或存储到其他介质中。

**反序列化（Deserialization）**：将**字节流**重新转换成 **Java 对象**的过程。

例如，服务器需要将一个用户对象发送给另一台服务器，但**不同 JVM 之间不能直接共享彼此的 Java 对象**，因此需要先将对象转换成字节流，再由接收方恢复对象。

**原因：Java 对象存在于某个 JVM 的内存中，而不同服务器通常有各自独立的 JVM 和内存空间。它们不能直接访问彼此的对象，但可以通过网络传输数据。**

```text
       JVM A
         |
         v
      Java 对象
         |
         | 序列化
         v
       字节流
         |
         | 网络传输
         v
       字节流
         |
         | 反序列化
         v
      Java 对象
         |
         v
       JVM B
```

需要注意：**传输的并不是原来的 Java 对象本身，而是对象的数据表示。接收方会根据字节流创建一个新的对象。**

# 2. 如何将一个对象从一个 JVM 转移到另一个 JVM？

不同 JVM 之间不能直接共享对象引用，通常需要通过数据传输的方式实现。

常见方式有以下几种：

| 方式       | 实现思路                          | 适用场景           |
| -------- | ----------------------------- | -------------- |
| Java 序列化 | 将对象转换为**字节流**，再通过网络传输         | Java 系统之间的数据传输 |
| 消息队列     | 将对象转换为**消息**，再发送给其他服务         | 异步通信、服务解耦      |
| RPC      | 使用序列化协议传输请求和响应数据              | 分布式服务之间的远程调用   |
| 数据库或缓存   | 将对象转换为数据后存入 MySQL、Redis 等共享存储 | 多个 JVM 共享业务数据  |

例如，两个 Java 服务之间可以使用消息队列传递用户信息。

**具体步骤为：发送方将对象序列化成消息数据，通过网络发送给消息队列服务器；接收方再从消息队列获取消息，通过反序列化恢复数据并处理。**

```text
服务 A
  |
  v
User 对象
  |
  v
序列化为消息
  |
  v
消息队列
  |
  v
服务 B
  |
  v
反序列化
  |
  v
User 对象
```

这里的消息队列并不会直接传输 Java 对象，而是传输经过序列化处理后的消息数据。

实际开发中，不同系统之间通常会使用 JSON、Protocol Buffers（Protobuf）等格式，而不一定使用 Java 原生序列化。

# 3. Java 如何实现序列化和反序列化？

Java 提供了 `ObjectOutputStream` 和 `ObjectInputStream` 两个类，用于实现对象的序列化和反序列化。

## 3.1 Serializable 接口

如果希望使用 Java 原生序列化，通常需要让类实现 `Serializable` 接口。

```java
import java.io.Serializable;

public class User implements Serializable {
    private int id;
    private String name;
}
```

`Serializable` 是一个**标记接口（Marker Interface），本身没有定义任何方法**。

它的作用是告诉 JVM：该类允许参与 Java 原生序列化机制。

如果对象没有实现 `Serializable` 或 `Externalizable`，直接使用 `ObjectOutputStream` 序列化通常会抛出 `NotSerializableException`。

注意：不仅对象自身需要支持序列化，它所引用的对象也需要能够被序列化，否则同样可能出现异常（被 `transient` 排除或通过自定义序列化处理的字段除外）。

## 3.2 ObjectOutputStream：序列化

`ObjectOutputStream` 用于将 Java 对象写入输出流。

常用方法：

|方法|作用|
|---|---|
|`writeObject(obj)`|将对象序列化并写入输出流|
|`flush()`|刷新输出流，确保缓冲数据写出|
|`close()`|关闭流|

例如：

```java
User user = new User();

// 创建输出流
try (ObjectOutputStream out = new ObjectOutputStream(
        new FileOutputStream("user.ser"))) {

    // 序列化对象
    out.writeObject(user);
}
```

执行后，Java 会将对象转换成序列化格式的字节数据，并写入 `user.ser` 文件。

## 3.3 ObjectInputStream：反序列化

`ObjectInputStream` 用于从输入流中读取字节数据，并恢复 Java 对象。

常用方法：

|方法|作用|
|---|---|
|`readObject()`|从输入流读取数据并恢复对象|
|`close()`|关闭流|

例如：

```java
User user;

try (ObjectInputStream in = new ObjectInputStream(
        new FileInputStream("user.ser"))) {

    // 反序列化对象
    user = (User) in.readObject();
}
```

`readObject()` 返回的是 `Object` 类型，因此通常需要进行类型转换。

另外，`readObject()` 可能抛出 `ClassNotFoundException`，因为 JVM 需要找到对应的类才能恢复对象。

## 3.4 Serializable 的完整示例

下面将对象序列化为字节数组，再从字节数组中恢复对象：

```java
import java.io.*;

public class User implements Serializable {

    private static final long serialVersionUID = 1L;

    private int id;
    private String name;

    public User(int id, String name) {
        this.id = id;
        this.name = name;
    }
}
```

**第一步：序列化对象**

```java
User user = new User(1, "Tom");

byte[] bytes;

try (ByteArrayOutputStream bos = new ByteArrayOutputStream();
     ObjectOutputStream out = new ObjectOutputStream(bos)) {

    out.writeObject(user);

    bytes = bos.toByteArray();
}
```

这里使用 `ByteArrayOutputStream` 将序列化后的数据保存到内存中的字节数组。

**第二步：反序列化对象**

```java 
User newUser;

try (ByteArrayInputStream bis = new ByteArrayInputStream(bytes);
     ObjectInputStream in = new ObjectInputStream(bis)) {

    newUser = (User) in.readObject();
}
```

这里通过 `ObjectInputStream` 读取字节数组，恢复出一个新的 `User` 对象。

实际开发中，这些字节数据也可以通过网络发送给另一个 JVM，再由接收方进行反序列化。

# 4. serialVersionUID 有什么作用？

`serialVersionUID` 是 Java 序列化机制中的版本标识，用于**判断序列化数据与当前类定义是否兼容**。

例如：

```java
public class User implements Serializable {

    private static final long serialVersionUID = 1L;

    private int id;
    private String name;
}
```

## 4.1 为什么需要 serialVersionUID？

假设：

1. JVM A 使用旧版本的 `User` 类，将对象序列化并保存。
    
2. 后来 `User` 类发生修改，例如新增字段。
    
3. JVM B 使用修改后的 `User` 类，尝试读取之前的序列化数据。
    

此时，Java 需要判断新旧两个版本的类是否兼容。

如果序列化数据中的 `serialVersionUID` 与当前类的 `serialVersionUID` 不一致，就可能抛出 `InvalidClassException`。

## 4.2 如果不定义 serialVersionUID 会怎么样？

如果没有显式定义，Java 序列化机制会根据类的结构等信息自动计算一个默认的 `serialVersionUID`。

但是，类的结构发生变化时，计算出来的值可能随之变化，导致反序列化失败。

因此，通常建议显式声明：

```java
private static final long serialVersionUID = 1L;
```

这样可以明确控制类的序列化版本标识，避免因为一些不必要的类结构变化导致默认版本号发生变化。

注意：**serialVersionUID 相同不代表任何类结构变化都一定兼容**，它主要用于版本校验，并不能自动解决所有数据结构变化问题。

# 5. transient 和 static 字段会被序列化吗？

Java 默认序列化对象的非静态、非 `transient` 实例字段。

## 5.1 transient：不参与默认序列化

`transient` 用于修饰字段，表示该字段**不参与默认序列化**。

例如：

```java
public class User implements Serializable {

    private int id;

    private transient String password;
}
```

序列化时：

- `id` 会被序列化。
    
- `password` 不会被默认序列化。
    

反序列化后，`password` 会恢复为对应类型的默认值，例如引用类型为 `null`，`int` 为 `0`。

`transient` 常用于排除临时数据、敏感信息或无需持久化的字段。

但需要注意，敏感数据不能仅依赖 `transient` 作为安全措施，还应该避免将敏感信息写入序列化数据。

## 5.2 static：不参与对象序列化

**`static` 修饰的是类变量，属于类本身，而不是某个对象的实例状态。**

例如：

```java
public class User implements Serializable {

    private int id;

    public static String school = "ABC";
}
```

序列化时：

- `id` 会被序列化。
    
- `school` 不会被作为对象字段序列化。
    

因为 `school` 属于类级别的数据，不属于当前对象的实例状态。

# 5.3 总结

|字段类型|默认是否序列化|
|---|---|
|普通实例字段|是|
|`transient` 实例字段|否|
|`static` 字段|否|

# 6. 如何自己实现序列化和反序列化？

如果不使用 Java 原生的 `ObjectOutputStream`，也可以自己设计一套序列化协议。

核心思路是：

**规定对象如何转换成字节流，以及如何根据字节流恢复对象。**

需要考虑以下几个方面。

## 6.1 第一步：确定支持的数据类型

首先确定序列化协议支持哪些数据类型。

例如：

- 基本数据类型：`int`、`long`、`boolean` 等。
    
- 字符串：`String`。
    
- 集合：`List`、`Map` 等。
    
- 自定义对象：例如 `User`。
    

例如，一个 `User` 对象包含：

```java
class User {
    int id;
    String name;
}
```

需要事先约定 `id` 和 `name` 分别如何转换为字节数据。

## 6.2 第二步：设计字节流格式

为了让接收方知道每段数据代表什么，需要设计统一的数据格式。

可以将数据分为消息头和消息体：

```text
消息头：
魔数 | 协议版本 | 消息体长度 | 类型标识

消息体：
字段编号 | 字段类型 | 数据长度 | 字段数据
```

各部分作用：

|字段|作用|
|---|---|
|魔数|用于识别数据是否符合当前协议|
|协议版本|标识序列化协议的版本|
|消息体长度|标识后续数据的长度|
|类型标识|标识当前数据对应的对象类型|
|字段编号|标识对象中的具体字段|
|字段类型|标识字段的数据类型|
|数据长度|标识字段数据占用的字节数|
|字段数据|实际存储的内容|

例如：

```text
User 对象：

字段编号 1：id
字段编号 2：name
```

可以约定：

- `id` 使用固定长度的整数格式。
    
- `name` 使用 UTF-8 编码，并在字符串内容前记录长度。
    

这样，接收方就能按照相同的规则解析数据。

## 6.3 第三步：实现序列化和反序列化

序列化时：

1. 读取对象的各个字段。
    
2. 根据约定的数据类型进行编码。
    
3. 将字段编号、长度和实际数据写入字节流。
    
4. 最终生成完整的字节数组。
    

反序列化时：

1. 读取消息头，检查魔数、协议版本和消息长度。
    
2. 根据字段编号和字段类型解析数据。
    
3. 将解析出来的数据填充到对象字段中。
    
4. 创建并返回恢复后的对象。
    

实现时可以使用：

- `DataOutputStream`：将基本类型数据写入输出流。
    
- `DataInputStream`：从输入流读取基本类型数据。
    
- `ByteBuffer`：按照指定的字节顺序组织和读取二进制数据。
    
- 反射：根据类型信息动态读取和设置对象字段。
    

## 6.4 第四步：考虑版本兼容

实际项目中，对象的字段可能会发生变化，因此需要考虑**协议兼容性**。

例如，旧版本的 `User` 只有：

```java
class User {
    int id;
    String name;
}
```

新版本增加了：

```java
String email;
```

为了保证新旧版本能够兼容，可以：

- 新增字段时分配新的字段编号。
    
- 旧版本遇到无法识别的字段时，根据字段长度跳过。
    
- 新版本读取旧数据时，对缺失字段使用约定的默认值。
    
- 已经使用过的字段编号不要随意复用。
    
- 不要随意修改已有字段的数据类型。
    

## 6.5 第五步：考虑特殊情况

除了基本的数据转换，还需要考虑：

- **空值处理**：区分 `null` 和空字符串。
    
- **对象引用**：同一个对象被多个字段引用时，需要避免重复创建对象。
    
- **循环引用**：例如对象 A 引用 B，而 B 又引用 A，需要防止无限递归。
    
- **数据校验**：限制消息长度、字符串长度和嵌套深度，避免异常数据造成内存消耗或解析错误。
    
- **网络传输**：TCP 是字节流协议，一次读取不一定能获得完整消息，需要根据消息长度处理数据边界。
    

如果自行实现序列化协议，必须保证发送方和接收方遵循相同的数据格式约定。

实际开发中，如果没有特殊需求，通常优先使用成熟的序列化框架，例如 JSON 或 Protobuf，而不是从零开始设计协议。

# 7. Java 如何将对象转换为二进制字节流？

本质上，序列化就是按照一定的**序列化协议**，将对象的数据转换成符合协议格式的字节流。

Java 原生序列化使用对象流完成这一过程：

|类|作用|
|---|---|
|`ObjectOutputStream`|将 Java 对象转换成序列化字节数据|
|`ObjectInputStream`|将序列化字节数据恢复成 Java 对象|

整体过程：

```text
          Java 对象
              |
              v
     ObjectOutputStream
              |
              v
       序列化协议处理
              |
              v
         二进制字节流
              |
        文件 / 网络传输
              |
              v
         二进制字节流
              |
              v
      ObjectInputStream
              |
              v
       反序列化协议解析
              |
              v
          Java 对象
```

需要注意：

1. 序列化后的数据不仅包含字段值，还包含恢复对象所需的类型等相关信息。
    
2. 接收方需要拥有对应的类定义，并满足序列化兼容性要求。
    
3. 不同序列化协议生成的字节流格式不同，不能随意混用。
    

### 常见序列化方案对比

| 方案         | 特点                           | 适用场景               |
| ---------- | ---------------------------- | ------------------ |
| Java 原生序列化 | 与 Java 类型体系关联紧密，使用方便         | Java 内部对象序列化（基本淘汰） |
| JSON       | 可读性好，跨语言支持广泛                 | HTTP 接口、配置和业务数据传输  |
| Protobuf   | 二进制格式，通常体积较小，解析效率较高，需要定义数据结构 | RPC、微服务之间的数据传输     |

实际选择时，需要结合跨语言能力、数据体积、性能和版本兼容性等因素考虑。

# 8. 序列化有哪些安全问题？

Java 原生反序列化需要特别注意安全问题。

**不要直接反序列化不可信来源的字节数据。**

因为反序列化不仅仅是读取字段，还可能涉及对象的重建及相关类的特殊处理逻辑。如果输入数据经过恶意构造，可能触发危险的反序列化行为。

常见防护措施：

- 不要反序列化来源不明的数据。
    
- 对需要反序列化的类型进行限制。
    
- 使用 `ObjectInputFilter` 等机制过滤允许反序列化的类。
    
- 对数据长度、集合大小和嵌套深度进行限制。
    
- 避免在序列化数据中暴露密码等敏感信息。
    

实际开发中，对于跨服务传输，通常优先考虑具有明确数据结构和类型约束的序列化方案。
