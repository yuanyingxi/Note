# 1. Java 8 有哪些主要新特性？

Java 8 是 Java 发展过程中的一个重要版本，引入了 Lambda 表达式、Stream API、Optional、函数式接口等功能，使 Java 的集合处理和异步编程更加方便。

## 1.1 Java 8 新特性概览

| 新特性               | 主要作用                                        |
| ----------------- | ------------------------------------------- |
| Lambda 表达式        | 使用更简洁的语法表示行为，减少匿名内部类的代码                     |
| 函数式接口             | 为 Lambda 表达式提供目标接口类型                        |
| 方法引用              | 使用已有的方法或构造方法，进一步简化 Lambda                   |
| Stream API        | 对集合数据进行过滤、映射、排序、聚合等操作                       |
| Optional          | 显式表示一个值可能不存在，帮助处理空值                         |
| 接口默认方法与静态方法       | 允许接口提供部分方法实现                                |
| CompletableFuture | 支持异步任务、结果处理和任务组合                            |
| 新的日期时间 API        | 通过 `java.time` 提供更加清晰的日期时间处理方式              |
| 并行数组操作            | 通过 `Arrays.parallelSort()` 等方法利用多核 CPU 处理数组 |
| 重复注解与类型注解         | 扩展注解的使用方式                                   |

其中，**Lambda 表达式、Stream API 和 CompletableFuture 是比较重要的面试考点**，需要重点理解。

# 2. Lambda 表达式与函数式接口
## 2.1 什么是 Lambda 表达式？

**Lambda 表达式**是一种简洁地表示行为的语法，通常用于**实现函数式接口（只包含一个抽象方法的接口）**，可以**减少匿名内部类**中的**重复代码**。

例如，需要创建一个线程并执行任务。

传统方式：

```java
Thread thread = new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("执行任务");
    }
});

thread.start();
```

使用 Lambda 表达式：

```java
Thread thread = new Thread(() -> {
    System.out.println("执行任务");
});

thread.start();
```

这里，`Runnable` 是一个函数式接口，它只有一个需要实现的抽象方法 `run()`。

Lambda 表达式中的：
	
```java
() -> {
    System.out.println("执行任务");
}
```

可以理解为提供了 `run()` 方法需要执行的代码。

Lambda 表达式省略了匿名内部类中的部分模板代码，使程序更加简洁。

### 2.1.1 Lambda 表达式的使用要求

**（1）目标类型通常必须是函数式接口**

**函数式接口是指只有一个抽象方法需要实现的接口**，可以使用 `@FunctionalInterface` 注解标记。

例如：

```java
@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}
```

可以使用 Lambda 表达式实现这个接口：

```java
Calculator calculator = (a, b) -> a + b;

System.out.println(calculator.add(1, 2)); // 3
```

这里，`(a, b) -> a + b` 提供了 `add()` 方法的实现。

注意：函数式接口可以包含多个默认方法、静态方法，以及符合特定规则的其他方法；关键是它只能有一个需要实现的抽象方法。

**（2）编译器必须能够确定 Lambda 表达式的目标类型**

例如：

```java
Runnable task = () -> System.out.println("执行任务");
```

因为变量 `task` 的类型是 `Runnable`，编译器知道 Lambda 表达式需要实现 `run()` 方法。

但是，Lambda 表达式不能脱离上下文随意使用，**编译器需要知道它对应哪个函数式接口**，以及参数和返回值应该是什么类型。

**（3）参数和返回值必须符合函数式接口的抽象方法**

例如：

```java
@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}
```

正确写法：

```java
Calculator calculator = (a, b) -> a + b;
```

因为 `add()` 接收两个 `int` 参数，并返回一个 `int` 值。

如果参数数量、参数类型或返回值不符合接口要求，就可能编译失败。

**（4）Lambda 表达式可以使用不同的简写形式**

```java
// 无参数
Runnable task = () -> System.out.println("执行任务");

// 一个参数，可以省略参数括号
java.util.function.Consumer<String> printer =
        s -> System.out.println(s);

// 多个参数，需要保留参数括号
java.util.function.BiFunction<Integer, Integer, Integer> add =
        (a, b) -> a + b;

// 单个表达式，可以省略大括号和 return
java.util.function.Function<Integer, Integer> square =
        x -> x * x;

// 多条语句，需要使用大括号；有返回值时需要显式 return
java.util.function.Function<Integer, Integer> calculate = x -> {
    int result = x * x;
    return result;
};
```

### 2.1.2 总结

使用 Lambda 表达式时，重点掌握以下几点：

1. **目标类型：** 通常需要有明确的函数式接口类型。
    
2. **抽象方法：** Lambda 表达式提供该抽象方法的实现。
    
3. **参数和返回值：** 必须符合抽象方法的定义。
    
4. **语法简写：** 根据参数数量和方法体内容，可以省略部分括号、大括号和 `return`。
    

核心理解：**Lambda 表达式不是任意一段代码，而是以简洁的方式提供函数式接口所需的行为实现。**

## 2.2 Lambda 表达式的基本语法

```java
// 只有一个表达式
(parameters) -> expression

// 包含多条语句
(parameters) -> {
    statements;
}
```

例如：

```java
// 两个参数相加
(a, b) -> a + b

// 一个参数，判断是否为偶数
n -> n % 2 == 0

// 多条语句
(a, b) -> {
    int sum = a + b;
    return sum;
}
```

当 Lambda 只有一个参数时，可以省略参数括号；当表达式体只有一个表达式时，可以省略大括号和显式的 `return`。

## 2.3 什么是函数式接口？

**函数式接口是指只有一个抽象方法的接口。** 它可以有多个默认方法、静态方法，也可以包含与 `Object` 中公共方法相对应的声明。

例如：

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}
```

使用 Lambda 实现：

```java
Calculator calculator = (a, b) -> a + b;

System.out.println(calculator.calculate(3, 5)); // 8
```

这里的 `Calculator` 只有一个抽象方法 `calculate()`，所以可以使用 Lambda 表达式提供具体实现。

`@FunctionalInterface` 是一个可选注解，用于让编译器检查接口是否符合函数式接口的要求。

Java 中常见的函数式接口包括：

|接口|作用|
|---|---|
|`Runnable`|执行任务，不接收参数，也不返回结果|
|`Consumer<T>`|接收一个参数并进行处理，不返回结果|
|`Supplier<T>`|不接收参数，提供一个结果|
|`Function<T, R>`|接收一个参数并转换为另一个结果|
|`Predicate<T>`|接收一个参数，返回布尔值，常用于条件判断|

例如，`Predicate<Integer>` 可以用于判断数字是否为偶数：

```java
Predicate<Integer> isEven = n -> n % 2 == 0;

System.out.println(isEven.test(4)); // true
System.out.println(isEven.test(5)); // false
```

## 2.4 什么是方法引用？

方法引用是 Lambda 表达式的一种简化写法。当 Lambda 的作用只是调用一个已有方法时，可以考虑使用方法引用。

例如：

```java
// Lambda 表达式
list.forEach(s -> System.out.println(s));

// 方法引用
list.forEach(System.out::println);
```

常见形式包括：

|写法|含义|
|---|---|
|`类名::静态方法`|引用静态方法|
|`对象::实例方法`|引用指定对象的实例方法|
|`类名::实例方法`|引用某个类型的实例方法|
|`类名::new`|引用构造方法|

需要注意，方法引用并不适用于所有 Lambda，只有在方法的参数、返回值等能够匹配目标函数式接口时才能使用。

# 3. Stream API
## 3.1 什么是 Stream API？

Stream API 是 Java 8 引入的数据处理 API，主要用于对集合等数据源进行过滤、转换、排序和聚合等操作。

它可以将**多个数据处理步骤连接起来**，形成一个处理流水线，减少手动遍历和创建中间集合的代码。

例如，筛选出列表中所有长度大于 3 的字符串。

传统方式：

```java
List<String> list =
        Arrays.asList("apple", "fig", "banana", "kiwi");

List<String> result = new ArrayList<>();

for (String s : list) {
    if (s.length() > 3) {
        result.add(s);
    }
}
```

使用 Stream API：

```java
List<String> list =
        Arrays.asList("apple", "fig", "banana", "kiwi");

List<String> result = list.stream()
        .filter(s -> s.length() > 3)
        .collect(Collectors.toList());
```

Stream 通过 `filter()` 筛选满足条件的数据，再通过 `collect()` 将结果收集到新的列表中。

## 3.2 Stream 的执行流程

Stream 操作通常可以分为三个部分：

```text
数据源
  |
  v
中间操作
filter()、map()、sorted()
  |
  v
终端操作
collect()、count()、forEach()
  |
  v
处理结果
```

**中间操作**：对数据进行处理，通常返回另一个 Stream。

常见方法：

|方法|作用|
|---|---|
|`filter()`|筛选符合条件的元素|
|`map()`|将元素转换成其他形式|
|`flatMap()`|将多个流的内容合并展开为一个流|
|`distinct()`|去除重复元素|
|`sorted()`|对元素排序|
|`limit()`|只保留前几个元素|
|`skip()`|跳过前几个元素|

**终端操作**：触发流水线执行，并产生结果或副作用。

常见方法：

|方法|作用|
|---|---|
|`collect()`|将结果收集到集合等容器中|
|`forEach()`|对元素执行操作|
|`count()`|统计元素数量|
|`reduce()`|将多个元素归约为一个结果|
|`anyMatch()`|判断是否至少有一个元素满足条件|
|`allMatch()`|判断是否所有元素都满足条件|
|`noneMatch()`|判断是否没有元素满足条件|

## 3.3 Stream 的特点

**（1）支持链式调用**

多个中间操作可以连接在一起，依次处理数据。

```java
List<Integer> result = Arrays.asList(1, 2, 3, 4, 5, 6)
        .stream()
        .filter(n -> n % 2 == 0)
        .map(n -> n * n)
        .collect(Collectors.toList());

// 结果：[4, 16, 36]
```

先筛选偶数，再计算平方，最后收集结果。

**（2）中间操作具有惰性**

仅仅调用 `filter()` 或 `map()` 等中间操作，并不会立即完成整个数据处理过程。通常需要终端操作触发执行。

```java
Stream<Integer> stream = Arrays.asList(1, 2, 3)
        .stream()
        .filter(n -> {
            System.out.println(n);
            return n > 1;
        });
```

上面的代码创建了 Stream 流水线，但此时不会打印数字。只有执行终端操作，例如 `stream.count()`，才会触发处理。

**（3）Stream 通常不能重复使用**

一个 Stream 在终端操作后就不能再次使用，否则通常会抛出 `IllegalStateException`。

```java
Stream<Integer> stream = Arrays.asList(1, 2, 3).stream();

System.out.println(stream.count());

// 错误：Stream 已经被消费
// System.out.println(stream.count());
```

如果需要再次处理数据，可以从原始数据源重新创建 Stream。

**（4）Stream 并不等于集合**

集合主要用于存储数据，Stream 主要用于处理数据。一般情况下，使用 Stream 处理集合并不会自动修改原集合，但应避免在流水线中通过副作用修改共享状态。

## 3.4 Stream 如何计算总和？

对于数字集合，可以使用 `mapToInt()` 将 `Stream<Integer>` 转换为专门处理基本类型的 `IntStream`，再调用 `sum()`。

```java
List<Integer> numbers = Arrays.asList(1, 2, 3, 4, 5);

int sum = numbers.stream()
        .mapToInt(Integer::intValue)
        .sum();

System.out.println(sum); // 15
```

`IntStream`、`LongStream` 和 `DoubleStream` 是专门处理基本数值类型的流，可以提供求和、平均值等操作，减少部分装箱和拆箱开销。

# 4. 并行流（Parallel Stream）
## 4.1 什么是并行流？

普通 Stream 默认按照串行方式处理数据，而并行流可以将数据处理任务拆分成多个子任务，利用多个线程并发执行，再汇总处理结果。

例如：

```java
List<Integer> numbers =
        Arrays.asList(1, 2, 3, 4, 5, 6);

int sum = numbers.parallelStream()
        .mapToInt(Integer::intValue)
        .sum();

System.out.println(sum); // 21
```

调用 `parallelStream()` 创建并行流，也可以对已有的 Stream 调用 `parallel()` 切换为并行模式。

## 4.2 并行流的底层原理

并行流通常借助 `ForkJoinPool` 将任务拆分成多个子任务执行，再将结果合并。

```text
原始数据
   |
   v
拆分成多个子任务
   |
   +--------+--------+
   |        |        |
   v        v        v
 任务 A    任务 B    任务 C
   |        |        |
   +--------+--------+
            |
            v
         合并结果
```

默认情况下，并行流通常使用公共 `ForkJoinPool`，因此可能与其他使用公共线程池的任务共享资源。

## 4.3 并行流适合什么场景？

并行流更适合**数据量较大、任务可以独立处理、计算开销较高的 CPU 密集型场景**。

例如，对**大量数字进行计算**或**执行互相独立的数据转换**。

但并行流不一定比串行流快：

- 数据量较小时，拆分任务和合并结果的开销可能超过收益。
    
- 如果任务存在共享可变状态，可能产生线程安全问题。
    
- 如果任务主要等待网络、数据库等 I/O 操作，并行流不一定是合适的选择。
    
- 如果处理顺序很重要，需要注意并行流对执行顺序的影响。
    

**不要认为只要使用并行流，程序就一定能加速。** 应结合数据规模、任务特征和实际测试决定是否使用。

# 5. CompletableFuture：异步编程
## 5.1 什么是 CompletableFuture？

`CompletableFuture` 是 Java 8 引入的异步编程工具，实现了 `Future` 和 `CompletionStage` 接口。

**普通 `Future` 可以表示异步任务的结果，但通常需要通过 `get()` 等待结果。`CompletableFuture` 除了能表示异步结果，还可以注册后续操作，并将多个任务组合起来。**

例如，服务器需要分别查询用户信息和订单数量。如果两个查询互不依赖，就可以同时启动，等结果都完成后再合并。

```text
        同时启动
        /     \
       v       v
 查询用户信息  查询订单数量
       |       |
       v       v
    用户结果  订单结果
        \     /
         v   v
        合并结果
```

这可以减少无依赖任务之间不必要的串行等待。

## 5.2 如何创建异步任务？

`CompletableFuture` 提供了 `runAsync()` 和 `supplyAsync()` 两种常用方法，用于创建异步任务。

### 5.2.1 两种方法的区别

|方法|作用|类似的任务接口|返回类型|
|---|---|---|---|
|`runAsync()`|执行不需要返回结果的任务|`Runnable`|`CompletableFuture<Void>`|
|`supplyAsync()`|执行需要返回结果的任务|`Callable` 的使用场景|`CompletableFuture<T>`|

例如：

```java
// 执行不需要返回结果的任务
CompletableFuture<Void> task = CompletableFuture.runAsync(
        () -> System.out.println("执行异步任务")
);

// 执行需要返回结果的任务
CompletableFuture<String> result = CompletableFuture.supplyAsync(
        () -> "hello"
);
```

这里，两个任务都可以异步执行。第二个任务执行完成后，可以通过 `result.join()` 获取返回值 `"hello"`。

### 5.2.2 它们与 Runnable、Callable 有什么关系？

先看 Java 中的两个任务接口：

```java
// Runnable：没有返回值
Runnable task1 = () -> System.out.println("执行任务");

// Callable：可以返回结果
Callable<String> task2 = () -> "hello";
```

它们的主要区别是：

- `Runnable` 的 `run()` 方法没有返回值。
    
- `Callable<T>` 的 `call()` 方法可以返回类型为 `T` 的结果，也可以抛出受检异常。
    

`CompletableFuture` 则提供了创建异步任务的便捷方法：

```text
Runnable
   |
   v
runAsync()
   |
   v
CompletableFuture<Void>


返回结果的任务逻辑
   |
   v
supplyAsync()
   |
   v
CompletableFuture<T>
```

需要注意，`supplyAsync()` 接收的是 `Supplier<T>`，而不是 `Callable<T>`。`Supplier<T>` 同样可以提供一个返回结果的任务，但它的 `get()` 方法不声明受检异常。

### 5.2.3 如何指定线程池？

两种方法都支持传入自定义 `Executor`，指定任务使用的线程池。

```java
ExecutorService pool = Executors.newFixedThreadPool(4);

CompletableFuture<String> future =
        CompletableFuture.supplyAsync(
                () -> "hello",
                pool
        );
```

如果没有传入线程池，常见的异步方法默认使用公共 `ForkJoinPool.commonPool()`。

实际开发中，对于耗时的阻塞 I/O 任务，通常应考虑使用合适的专用线程池，避免大量阻塞任务影响其他共享线程池中的任务。

**总结：** `Runnable`、`Callable` 和 `Supplier` 主要描述任务的执行逻辑；`CompletableFuture` 则进一步提供异步执行、结果获取、任务组合和异常处理等能力。**

## 5.3 CompletableFuture 的常用方法

|方法|作用|
|---|---|
|`thenApply()`|使用上一步的结果进行转换，并返回新的结果|
|`thenAccept()`|使用上一步的结果执行操作，不返回业务结果|
|`thenRun()`|执行后续操作，不使用上一步的结果|
|`thenCompose()`|根据上一步结果启动另一个异步任务，并展平结果|
|`thenCombine()`|等两个任务都正常完成后，合并它们的结果|
|`allOf()`|等待多个任务全部完成，返回 `CompletableFuture<Void>`|
|`exceptionally()`|发生异常时提供替代结果|
|`handle()`|无论成功还是异常，都可以进行处理并返回新结果|
|`whenComplete()`|观察任务结果或异常，常用于日志记录等操作|

## 5.4 `thenApply()` 与 `thenCompose()` 有什么区别？

两者的核心区别在于：**后续操作返回普通值，还是返回另一个 `CompletableFuture`。**

### 5.4.1 `thenApply()`：转换结果

`thenApply()` 用于对上一个任务的结果进行转换，并返回转换后的结果。

```java
CompletableFuture<Integer> future =
        CompletableFuture.supplyAsync(() -> 10)
                .thenApply(n -> n * 2);
```

执行过程：

```text
异步任务返回 10
      |
      v
thenApply(n -> n * 2)
      |
      v
得到 20
```

最终，`future` 的类型是 `CompletableFuture<Integer>`，结果为 `20`。

### 5.4.2 `thenCompose()`：串联异步任务

`thenCompose()` 适用于后续操作本身会返回另一个 `CompletableFuture` 的情况。它会将后续异步任务接入当前流程，避免产生嵌套的 `CompletableFuture`。

```java
CompletableFuture<Integer> future =
        CompletableFuture.supplyAsync(() -> 10)
                .thenCompose(n ->
                        CompletableFuture.supplyAsync(() -> n * 2)
                );
```

执行过程：

```text
第一个异步任务返回 10
      |
      v
根据 10 启动第二个异步任务
      |
      v
第二个异步任务返回 20
      |
      v
得到最终结果 20
```

最终，`future` 的类型仍然是 `CompletableFuture<Integer>`，结果为 `20`。

### 5.4.3 为什么需要 `thenCompose()`？

假设后续操作会返回一个 `CompletableFuture`，如果使用 `thenApply()`，就会出现嵌套类型。

```java
CompletableFuture<CompletableFuture<Integer>> future =
        CompletableFuture.supplyAsync(() -> 10)
                .thenApply(n ->
                        CompletableFuture.supplyAsync(() -> n * 2)
                );
```

此时，外层 `CompletableFuture` 的结果不是整数 `20`，而是另一个 `CompletableFuture<Integer>`。

类型关系如下：

```java
thenApply()
    |
    v
CompletableFuture<
    CompletableFuture<Integer>
>
```

如果改用 `thenCompose()`，就可以把内层的 `CompletableFuture` 展平，直接得到：

```java
CompletableFuture<Integer>
```

因此，可以这样记忆：

- `thenApply()`：上一步结果 → 普通值。
    
- `thenCompose()`：上一步结果 → 新的 `CompletableFuture`，并将其接入当前异步流程。
    

### 5.4.4 什么是回调地狱？

回调地狱（Callback Hell）是指：当多个异步操作存在依赖关系时，如果不断在一个回调中嵌套另一个回调，代码就会越来越深，难以阅读和维护。

例如，一个业务流程需要：

1. 根据用户 ID 查询用户。
    
2. 根据用户信息查询订单。
    
3. 根据订单查询物流信息。
    

使用嵌套回调时，代码可能类似这样：

```java
getUser(userId, user -> {
    getOrder(user, order -> {
        getDelivery(order, delivery -> {
            System.out.println(delivery);
        });
    });
});
```

随着业务步骤增加，嵌套层级也会增加，还需要分别处理各层的异常，维护起来比较麻烦。

### 5.4.5 如何使用 `CompletableFuture` 改善回调地狱？

如果每一步都返回一个 `CompletableFuture`，就可以使用 `thenCompose()` 将有依赖关系的异步任务串联起来。

```java
CompletableFuture<Delivery> deliveryFuture =
        getUserAsync(userId) // 这里内部调用了 supplyAsync，任务丢给线程池开始并发执行！
                .thenCompose(user -> getOrderAsync(user)) // 注册回调
                .thenCompose(order -> getDeliveryAsync(order)); // 注册回调

deliveryFuture.thenAccept(delivery ->
        System.out.println(delivery)
);
```

这里假设 `getUserAsync()`、`getOrderAsync()` 和 `getDeliveryAsync()` 都返回各自类型的 `CompletableFuture`。

代码从上到下描述业务流程，不需要不断嵌套回调。

如果这些步骤只需要对前一步的结果进行普通计算，而不是启动一个返回 `CompletableFuture` 的异步任务，则可以使用 `thenApply()`。

例如：

```java
CompletableFuture<String> nameFuture =
        getUserAsync(userId)
                .thenApply(user -> user.getName());
```

这里，`thenApply()` 只是从用户对象中提取姓名，不需要再串联另一个异步任务。

### 5.4.6 补充：异常处理

异步流程中的某一步如果发生异常，异常通常会沿着后续阶段传播，导致后续正常处理逻辑无法按预期执行。

可以使用 `exceptionally()` 提供一个异常恢复结果：

```java
CompletableFuture<String> future =
        getNameAsync()
                .exceptionally(ex -> "未知用户");
```

如果上游任务异常完成，`exceptionally()` 可以返回默认值 `"未知用户"`，让后续流程继续处理这个恢复后的结果。

注意：异常处理方式需要根据业务需求选择，不能一概用默认值掩盖真正的错误。

### 总结

|方法|主要用途|后续函数的返回值|
|---|---|---|
|`thenApply()`|转换上一步的结果|普通值|
|`thenCompose()`|串联依赖的异步任务，避免嵌套|`CompletableFuture`|
|`thenAccept()`|消费上一步结果，不需要返回新值|通常为 `void`|

**核心记忆：** `thenApply()` 负责转换结果，`thenCompose()` 负责串联异步任务。面对有依赖关系的多个异步操作，使用 `CompletableFuture` 的链式组合方法，可以减少回调嵌套，让业务流程更清晰。

## 5.5 `thenCombine()`：组合两个独立任务
### 5.5.1 什么是 `thenCombine()`？

`thenCombine()` 用于组合两个**互不依赖的异步任务**。

例如，页面需要同时展示用户姓名和订单数量：

- 任务 A：查询用户姓名，得到 `"小林"`。
    
- 任务 B：查询订单数量，得到 `3`。
    
- 最后：将两个结果合并，生成 `"小林有3笔订单"`。
    

由于查询姓名和查询订单数量互不依赖，因此可以分别执行，不需要等其中一个完成后才开始另一个。

### 5.5.2 代码示例

```java
// 任务 A：查询用户姓名
CompletableFuture<String> userFuture =
        CompletableFuture.supplyAsync(() -> "小林");

// 任务 B：查询订单数量
CompletableFuture<Integer> orderFuture =
        CompletableFuture.supplyAsync(() -> 3);

// 等两个任务都完成后，合并它们的结果
CompletableFuture<String> resultFuture =
        userFuture.thenCombine(
                orderFuture,
                (user, count) -> user + "有" + count + "笔订单"
        );

// 获取最终结果
System.out.println(resultFuture.join());
```

输出：

```text
小林有3笔订单
```

### 5.5.3 代码是如何执行的？

```text
                 +--> 任务 A：查询姓名 --> "小林" --+
开始执行 ---------|                                |--> thenCombine() --> 最终结果
                 +--> 任务 B：查询订单 --> 3 ------+
```

这里需要注意：

1. `userFuture` 表示查询姓名的任务及其结果。
    
2. `orderFuture` 表示查询订单数量的任务及其结果。
    
3. `thenCombine()` 等待两个任务都正常完成，然后将它们的结果传入合并函数。
    
4. `(user, count) -> ...` 中，`user` 接收第一个任务的结果，`count` 接收第二个任务的结果。
    
5. 合并后的结果由 `resultFuture` 表示，调用 `join()` 可以获取最终结果。
    

这里的两个任务没有先后依赖关系，因此可以并发执行。不过，`thenCombine()` 本身并不负责启动这两个任务，它负责组合已有的 `CompletableFuture`。

### 5.5.4 什么时候用 `thenCombine()`，什么时候用 `thenCompose()`？

关键看：**第二个任务是否需要第一个任务的结果才能执行。**

|场景|使用方法|原因|
|---|---|---|
|查询用户姓名，同时查询订单数量|`thenCombine()`|两个任务互不依赖，可以分别执行，最后合并结果|
|先查询用户，再根据用户 ID 查询订单|`thenCompose()`|第二个任务需要第一个任务的结果才能执行|

例如，先查询用户，再查询该用户的订单：

```java
CompletableFuture<List<Order>> orderFuture =
        getUserAsync(userId)
                .thenCompose(user ->
                        getOrdersAsync(user.getId())
                );
```

这里必须先获得 `user`，才能调用 `getOrdersAsync(user.getId())`，所以使用 `thenCompose()`。

**总结：**

- `thenCombine()`：两个任务分别执行，最后合并两个结果。
    
- `thenCompose()`：先获得一个任务的结果，再用这个结果衔接下一个异步任务。
    

可以简单记成：**独立任务用 `thenCombine()` 合并结果，有依赖关系的任务用 `thenCompose()` 串联。**

## 5.7 get() 与 join() 的区别？（`CompletableFuture` 类方法）

**两者都可以获取任务结果**；如果任务尚未完成，调用它们通常会等待结果。

| 方法       | 特点                                                     |
| -------- | ------------------------------------------------------ |
| `get()`  | 可能抛出 `InterruptedException`、`ExecutionException` 等受检异常 |
| `join()` | 任务异常通常通过 `CompletionException` 传播，不要求捕获上述受检异常          |

需要注意，**调用 `get()` 或 `join()` 可能阻塞当前线程**。因此，使用 `CompletableFuture` 时，通常应先组合异步任务，在确实需要结果的地方再等待，避免每启动一个任务就立即调用 `get()`，从而让原本可以并行执行的任务变成串行执行。

# 6. Java 21 有哪些重要新特性？

Java 21 是一个长期支持版本（LTS）。相比只关注语法变化，更值得了解的是虚拟线程、模式匹配和集合 API 等改进。

## 6.1 虚拟线程（Virtual Thread）

Java 21 正式发布了虚拟线程。

虚拟线程由 JVM 管理和调度，可以由较少的平台线程承载和执行，因此能够以相对较低的资源开销支持大量并发任务。

例如：

```java
try (var executor =
         Executors.newVirtualThreadPerTaskExecutor()) {

    executor.submit(() -> {
        System.out.println("执行任务");
    });
}
```

`newVirtualThreadPerTaskExecutor()` 会为提交的每个任务创建一个新的虚拟线程。

虚拟线程尤其适合大量阻塞等待的任务，例如 HTTP 请求、数据库访问等 I/O 密集型场景。

需要注意：

- 虚拟线程不是为了加快单个 CPU 密集型任务，而是为了更高效地承载大量并发任务。
    
- 虚拟线程仍然占用内存，也受到 CPU、数据库连接池和外部服务能力的限制。
    
- 虚拟线程与平台线程不同，不需要始终与一个独立的操作系统线程一一对应。
    

## 6.2 switch 的模式匹配

Java 21 正式支持在 `switch` 中使用模式匹配，可以根据对象的实际类型进行分支判断，并直接获取对应类型的变量。

例如：

```java
static String describe(Object obj) {
    return switch (obj) {
        case Integer i -> "整数：" + i;
        case String s -> "字符串：" + s;
        case null -> "空值";
        default -> "其他类型";
    };
}
```

传统方式通常需要先判断类型，再进行强制类型转换。

模式匹配可以将类型判断和变量绑定结合起来，让代码更加简洁。

## 6.3 Record Patterns：记录模式

记录模式可以对 `record` 对象进行解构，直接提取其中的组件值。

例如：

```java
record Point(int x, int y) {}

Object obj = new Point(3, 5);

if (obj instanceof Point(int x, int y)) {
    System.out.println(x + y); // 8
}
```

这里不需要先将对象转换为 `Point`，再分别调用 `x()` 和 `y()` 获取值。

记录模式也可以与 `switch` 的模式匹配结合使用，方便处理复杂的数据结构。

## 6.4 Sequenced Collections：有序集合接口

Java 21 引入了 `SequencedCollection`、`SequencedSet` 和 `SequencedMap` 等接口，用于统一表示具有明确 encounter order（遍历顺序）的集合。

相关接口提供了统一的首尾元素访问和逆序视图等操作，例如：

- `getFirst()`：获取首元素。
    
- `getLast()`：获取末元素。
    
- `reversed()`：获取逆序视图。
    

这些 API 让具有顺序的集合可以通过更加统一的方式访问首尾元素和反向遍历。

注意：具体实现是否支持相关操作、是否允许修改，仍取决于集合实现本身。

## 6.5 Scoped Values：范围值

Scoped Values 是 Java 21 引入的预览 API，用于在一定范围内向执行任务共享不可变数据，例如用户身份、请求上下文等。

它的目标之一是在适合的场景下提供 `ThreadLocal` 的替代方式，尤其值得结合虚拟线程理解。

但在 Java 21 中，它仍然属于预览功能，不应与正式稳定的语言和 API 特性混为一谈。

## 6.6 字符串模板

字符串模板曾在 Java 21 中作为预览功能出现，用于在字符串中嵌入表达式，并通过模板处理器生成结果。

但该功能后来被撤回，因此**不应将 Java 21 的字符串模板记为已经稳定发布的标准特性**。面试复习时，优先掌握虚拟线程、switch 模式匹配、记录模式和有序集合等正式特性。

# 7. Optional

**`Optional<T>` 是 Java 提供的一个容器类，用于表示一个值可能存在，也可能不存在。

在 Java 中，方法可能返回 `null`，如果调用者没有检查就直接访问该对象的属性或方法，就可能引发 `NullPointerException`（空指针异常）。

`Optional<T>` 将这种“可能有值，也可能没有值”的情况显式地表示出来，让开发者能够通过 `orElse()`、`orElseGet()` 等方法**提供默认值**，或通过 `orElseThrow()` 在**值不存在时抛出异常**，从而**更清晰**地处理空值情况，减少空指针异常。

**注意：** Optional 并不能完全消除 `null`，也不意味着所有变量都需要使用 Optional，通常适合用于需要明确表达返回值可能缺失的场景。

## 7.1 常用方法

|方法|作用|
|---|---|
|`Optional.of(value)`|创建包含非空值的 Optional，传入 `null` 会抛出异常|
|`Optional.ofNullable(value)`|创建 Optional，允许传入 `null`|
|`Optional.empty()`|创建一个不包含值的 Optional|
|`orElse(value)`|值不存在时，返回默认值|
|`orElseGet(supplier)`|值不存在时，通过函数获取默认值|
|`orElseThrow()`|值不存在时，抛出异常|
|`map(function)`|值存在时，对值进行转换|

## 7.2 简单示例

```java
String name = Optional.ofNullable(userName)
        .orElse("未知用户");
```

- 如果 `userName` 不为 `null`，就使用原值。
    
- 如果 `userName` 为 `null`，就使用 `"未知用户"`。
    

## 7.3 `orElse()` 和 `orElseGet()` 的区别

- `orElse()`：无论 Optional 中是否有值，都会先计算默认值。
    
- `orElseGet()`：只有值不存在时，才会执行函数获取默认值。
    

**注意：** Optional 主要用于更清晰地处理可能为空的返回值，不代表所有变量都需要使用 Optional，也不能完全替代 `null` 判断。
