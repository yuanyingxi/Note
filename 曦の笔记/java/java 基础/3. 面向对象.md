# 1. 什么是面向对象？

面向对象（Object-Oriented Programming，OOP）是一种**编程范式**，核心思想是将程序中的事物抽象为对象，通过对象之间的交互完成业务功能。

对象通常包含：

- **属性（字段）**：描述对象的状态。
    
- **方法**：描述对象能够执行的行为。
    

例如，在一个用户管理系统中，可以将用户抽象为 `User` 类：

```java
public class User {
    private String name;
    private int age;

    public void introduce() {
        System.out.println("我是" + name);
    }
}
```

其中，`name` 和 `age` 是属性，`introduce()` 是方法。

面向对象的主要优势：

1. **封装性**：隐藏内部实现，控制外部对数据的访问。
    
2. **复用性**：通过合理的继承、组合等方式复用代码。
    
3. **扩展性**：通过接口、抽象类和多态，降低新增功能对原有代码的影响。
    
4. **可维护性**：将不同职责组织到不同类中，方便理解、测试和修改。
    

Java 面向对象的三大特性是：**封装、继承、多态**。

# 2. 面向对象的三大特性
### 2.1 封装

**封装是指将数据与操作数据的方法组织在一起，并隐藏内部实现细节，通过对外提供的方法控制访问。**

即给数据加上 `private`（私有化），外部代码**直接看不见也摸不到**了。同时，提供 `public` 的方法作为“安检口”。

例如，用户年龄不应该被任意设置为负数，可以通过方法控制：

```java
public class User {
    private int age;

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age < 0) {
            throw new IllegalArgumentException("年龄不能为负数");
        }
        this.age = age;
    }
}
```

使用：

```java
User user = new User();
user.setAge(20);
```

这里的 `private` 限制外部直接访问 `age`，而 `setAge()` 可以在修改数据前进行校验。

封装的关键不是简单地把字段设为 `private`，而是**保护对象自身的数据和业务规则，避免外部随意破坏对象状态**。

### 2.2.1 常见访问修饰符

Java 使用访问修饰符控制类的成员（属性、方法等）可以被哪些代码访问。

常见的访问修饰符有 `private`、默认（不写）、`protected` 和 `public`。

#### 先理解什么是包（package）

**包是 Java 用来组织类的一种机制，可以理解为类的分类目录。**

例如，一个项目可以按照功能划分为不同的包：

```text
src/main/java/
├── com/example/user/
│   ├── User.java
│   └── UserService.java
└── com/example/order/
    └── OrderService.java
```

这里：

- `User.java` 和 `UserService.java` 属于 `com.example.user` 包。
    
- `OrderService.java` 属于 `com.example.order` 包。
    
- `com.example.user` 和 `com.example.order` 是两个不同的包。
    

Java 文件通常通过开头的 `package` 声明所属的包：

```java
package com.example.user;

public class User {
}
```

**判断两个类是否在同一个包中，主要看它们声明的包名是否相同，而不是看它们是否在同一个项目中。**

例如：

```java
package com.example.user;
```

和：

```java
package com.example.order;
```

属于不同的包。

如果没有写 `package` 声明，该类属于未命名包（默认包）。实际项目中通常建议使用命名包。

#### 四种访问修饰符

| 修饰符         | 同一个类 | 同一个包 | 不同包的子类    | 不同包的非子类 |
| ----------- | ---- | ---- | --------- | ------- |
| `private`   | 可以   | 不可以  | 不可以       | 不可以     |
| 默认（不写）      | 可以   | 可以   | 不可以       | 不可以     |
| `protected` | 可以   | 可以   | 可以（有访问限制） | 不可以     |
| `public`    | 可以   | 可以   | 可以        | 可以      |

这里的“同一个类”是指访问代码位于声明该成员的类内部；“同一个包”是指访问代码位于同一个包中的其他类。

注意：`protected` 在不同包的子类中有特殊限制。子类可以通过继承关系访问父类的 `protected` 成员，但不能在任意位置通过父类对象访问这些成员。

#### 分别理解四种修饰符

**①** `**private**`**：仅当前类可以访问**

```java
package com.example.user;

public class User {
    private String password;

    public void setPassword(String password) {
        this.password = password; // 可以访问
    }
}
```

**`password` 只能在 `User` 类内部直接访问，其他类不能直接访问它。**

常见用途：**隐藏对象内部的数据**，避免外部随意修改。

**② 默认（不写）：同一个包内可以访问**

```java
package com.example.user;

public class User {
    String name;
}
```

这里的 `name` 没有写访问修饰符，因此它具有包级访问权限。

同一个 `com.example.user` 包中的其他类可以访问 `name`，但其他包中的类不能直接访问。

常见用途：只允许同一个包中的相关类访问某个成员。

**③** `**protected**`**：同一个包内可以访问，不同包的子类也可以访问**

```java
package com.example.user;

public class User {
    protected String name;
}
```

同一个包中的类可以访问 `name`。

如果其他包中的类继承了 `User`，也可以通过继承关系访问该成员。例如：

```java
package com.example.admin;

import com.example.user.User;

public class Admin extends User {
    public void printName() {
        System.out.println(name); // 可以访问继承来的 protected 成员
    }
}
```

但是，`protected` 并不意味着不同包中的任何类都可以访问它；不同包的非子类仍然不能直接访问。

常见用途：允许子类使用或扩展父类提供的成员，同时限制普通外部类的访问。

**④** `**public**`**：任何能够访问该类的代码都可以访问**

```java
package com.example.user;

public class User {
    public String name;
}
```

其他包中的类只要能够访问 `User` 类，就可以访问它的 `public` 成员。

常见用途：对外提供公开的方法或功能，例如公共 API。

#### 如何选择访问修饰符？

可以记住以下原则：

- `private`：只供当前类内部使用。
    
- 默认（不写）：只供同一个包中的类使用。
    
- `protected`：供同一个包中的类和符合访问规则的子类使用。
    
- `public`：作为对外公开的功能。
    

实际开发中，通常优先使用尽可能小的访问范围：不需要对外公开的成员，不要随意设置为 `public`。

这样可以减少外部代码对类内部实现的依赖，使代码更容易维护和修改。

补充：对于顶层类（直接定义在文件中、没有嵌套在其他类内部的类），访问修饰符只能使用 `public` 或默认（不写），不能使用 `private` 和 `protected`。

## 2.2 继承

**继承是指子类在已有父类的基础上获得其可继承的成员，并可以增加自己的属性和方法，或重写父类允许重写的方法。**

例如：

```java
class Animal {
    public void eat() {
        System.out.println("动物进食");
    }
}

class Dog extends Animal {
    public void bark() {
        System.out.println("狗叫");
    }
}
```

使用：

```java
Dog dog = new Dog();

dog.eat();  // 继承自 Animal
dog.bark(); // Dog 自己的方法
```

继承的主要作用：

- 复用父类中已有的代码。
    
- 建立类之间的层次关系。
    
- 配合方法重写实现运行时多态。
    

需要注意：

1. **Java 类只能直接继承一个父类，但可以实现多个接口。**
    
2. 构造方法不会被子类继承。
    
3. `private` 成员不会被子类直接访问。
    
4. 子类可以通过 `super` 调用父类的构造方法或访问允许访问的父类成员。
    
5. 继承不一定是最佳复用方式。如果两个类只是需要使用对方的功能，而不存在合理的 `is-a` 关系，通常应该考虑组合。
    

例如，`Dog is an Animal` 是合理的继承关系；汽车拥有发动机，但汽车不是发动机，因此通常使用组合表示汽车与发动机的关系。

## 2.3 多态

**多态是指通过父类或接口类型的引用操作不同的具体对象时，可以执行各自对应的实现。**

例如：

```java
class Animal {
    public void sound() {
        System.out.println("动物发出声音");
    }
}

class Dog extends Animal {
    @Override
    public void sound() {
        System.out.println("汪汪");
    }
}

class Cat extends Animal {
    @Override
    public void sound() {
        System.out.println("喵喵");
    }
}
```

使用：

```java
Animal animal1 = new Dog();
Animal animal2 = new Cat();

animal1.sound(); // 汪汪
animal2.sound(); // 喵喵
```

理解这段代码，需要区分两个概念：

- **引用的声明类型**：例如 `Animal`，决定编译时可以通过该引用调用哪些成员。
    
- **对象的实际类型**：例如 `Dog`，决定普通可重写实例方法在运行时执行哪个实现。
    

因此，虽然 `animal1` 的声明类型是 `Animal`，但它指向的是 `Dog` 对象，所以调用 `sound()` 时执行的是 `Dog` 的实现。

这就是运行时多态。

#### 多态解决了什么问题？

多态的核心价值是**让调用方依赖统一的抽象，而不必针对每一种具体实现编写不同的调用逻辑**。

假设支付系统支持支付宝和微信支付。

如果没有利用多态，代码可能是：

```java
if (type.equals("alipay")) {
    // 调用支付宝支付
} else if (type.equals("wechat")) {
    // 调用微信支付
}
```

每增加一种支付方式，都可能需要修改这段判断逻辑。

可以改为统一接口：

```java
interface Payment {
    void pay();
}

class Alipay implements Payment {
    @Override
    public void pay() {
        System.out.println("支付宝支付");
    }
}

class WechatPay implements Payment {
    @Override
    public void pay() {
        System.out.println("微信支付");
    }
}
```

调用方只需要：

```java
public void processPayment(Payment payment) {
    payment.pay();
}
```

传入 `Alipay` 或 `WechatPay` 对象，就会执行对应的实现。

这样新增支付方式时，通常只需要新增实现类，而不必修改统一的调用逻辑。

多态是接口编程、策略模式、依赖倒置等设计思想的重要基础。

# 3. 多态的体现形式

理解时要区分：**方法重载和方法重写是两种不同的机制；接口实现和向上转型则是运行时多态常见的使用方式。**

## 3.1 方法重载（Overloading）

方法重载是指同一作用域中存在多个同名方法，但参数列表不同，编译器根据调用时的参数选择匹配的方法。

```java
class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public double add(double a, double b) {
        return a + b;
    }

    public int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

调用：

```java
Calculator calculator = new Calculator();

calculator.add(1, 2);
calculator.add(1.0, 2.0);
calculator.add(1, 2, 3);
```

重载的特点：

- 方法名相同。
    
- 参数列表必须不同，可以是**参数数量、类型或类型顺序不同**。
    
- 不能只靠返回类型不同来实现重载。
    
- 编译器在编译时根据方法签名和参数匹配规则选择方法。
    

## 3.2 方法重写（Overriding）

方法重写是指子类重新实现父类中允许重写的实例方法。

```java
class Parent {
    public void show() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    @Override
    public void show() {
        System.out.println("Child");
    }
}
```

调用：

```java
Parent obj = new Child();
obj.show(); // Child
```

重写的特点：

1. 发生在继承关系中。
    
2. 方法名和参数列表必须一致。
    
3. 返回类型必须相同，或者在引用类型的情况下满足协变返回类型规则。
    
4. 子类方法的访问权限不能比父类更严格。
    
5. `final` 方法不能重写。
    
6. `private` 方法不被子类继承，因此不能被重写。
    
7. `static` 方法属于类，子类定义同名同参数的静态方法属于隐藏，不是重写。
    
8. `@Override` 用于让编译器检查是否正确重写，建议使用。
    

#### 重载与重写的区别

|对比维度|重载|重写|
|---|---|---|
|英文|Overloading|Overriding|
|主要目的|同一功能支持不同参数形式|子类改变继承方法的实现|
|参数列表|必须不同|必须相同|
|返回类型|不能只通过返回类型区分|必须相同或满足协变返回类型规则|
|发生位置|同一作用域中可有重载方法，也可能涉及继承|子类重写父类的实例方法|
|方法选择|编译时根据参数匹配规则确定|运行时根据对象实际类型确定实例方法实现|

记忆方法：

- **重载看参数。**
    
- **重写看实际对象。**
    

## 3.3 向上转型与向下转型

**向上转型：子类对象赋值给父类引用。**

```java
Dog dog = new Dog();
Animal animal = dog;
```

向上转型通常可以自动完成，适合统一处理不同子类对象。

**向下转型：父类引用转换为子类引用。**

```java
Animal animal = new Dog();

Dog dog = (Dog) animal;
dog.bark();
```

向下转型需要显式转换，而且实际对象必须与目标类型兼容，否则会抛出 `ClassCastException`。

```java
Animal animal = new Animal();

Dog dog = (Dog) animal; // 运行时异常
```

可以使用 `instanceof` 检查：

```java
if (animal instanceof Dog dog) {
    dog.bark();
}
```

这里的 `instanceof` 模式匹配写法适用于 Java 16 及之后的版本。

# 4. 面向对象的设计原则

常见的面向对象设计原则包括 SOLID 五大原则，以及最少知识原则（迪米特法则）。

## 4.1 单一职责原则（SRP）

**一个类应该只有一个引起它变化的原因。**

也就是说，一个类应尽量只**承担一类职责**。

例如，不应该让一个用户类同时负责用户数据管理、发送邮件、生成报表和连接数据库。

可以将这些职责拆分到不同的类中，**降低类之间的耦合**。

## 4.2 开放封闭原则（OCP）

**软件实体应该对扩展开放，对修改封闭。**

**新增功能**时，尽量通过**新增实现、扩展接口等方式完成，而不是不断修改稳定的已有代码**。

例如，支付系统通过 `Payment` 接口支持不同支付方式，新增支付渠道时可以新增实现类。

## 4.3 里氏替换原则（LSP）

**子类对象应该能够替换父类对象，而不破坏程序原本依赖父类行为的正确性。**

继承不只是为了复用代码，子类还应该**遵守**父类对行为的**约定**。

如果子类改变了父类方法原本承诺的行为，使得调用方无法正常工作，就可能违反里氏替换原则。

## 4.4 接口隔离原则（ISP）

**客户端不应该被迫依赖自己不需要的接口。**

**接口**应当尽可能**小而专**，**避免**将大量**无关方法放进一个接口**。

例如，将打印、扫描和传真分别设计成独立能力，比要求所有设备都实现一个包含所有功能的大接口更加灵活。

## 4.5 依赖倒置原则（DIP）

**高层模块不应该直接依赖低层模块的具体实现，双方都应该依赖抽象。**

例如，订单服务依赖 `Payment` 接口，而不是直接依赖某个具体的支付宝支付实现。

这样更换支付实现时，订单服务通常不需要跟着修改。

注意：依赖倒置原则关注的是依赖关系；依赖注入（DI）则是一种常见的实现手段，两者不是同一个概念。

## 4.6 最少知识原则（迪米特法则）

**一个对象应当尽量少了解其他对象的内部细节，只与直接相关的对象交互。**

例如，订单服务只调用支付服务公开的方法，而不直接操作支付服务内部的数据库访问对象、缓存对象和其他内部组件。

这样可以减少耦合，避免一个模块的内部结构变化影响大量其他模块。

# 5. 抽象类与普通类
## 5.1 什么是抽象类？

**使用 `abstract` 修饰的类称为抽象类。**

抽象类通常用于描述多个子类共同具有的属性和行为，并允许将部分行为留给子类实现。

```java
abstract class Animal {
    public abstract void sound();

    public void eat() {
        System.out.println("进食");
    }
}
```

这里：

- `sound()` 是抽象方法，没有方法体，需要由具体子类实现。
    
- `eat()` 是普通方法，具有具体实现，可以被子类继承使用。
    

## 5.2 抽象类和普通类的区别

|对比维度|抽象类|普通类|
|---|---|---|
|能否直接实例化|不能|可以，前提是类本身不是其他受限情况|
|是否能包含抽象方法|可以|不可以|
|是否能包含具体方法|可以|可以|
|是否能有构造方法|可以|可以|
|是否能继承父类、实现接口|可以|可以|

抽象类不能直接通过 `new` 创建对象，但可以有构造方法。

创建子类对象时，父类构造方法仍然会参与初始化过程。

```java
abstract class Animal {
    public Animal() {
        System.out.println("Animal 初始化");
    }

    public abstract void sound();
}

class Dog extends Animal {
    @Override
    public void sound() {
        System.out.println("汪汪");
    }
}

Dog dog = new Dog();
```

这里创建的是 `Dog` 对象，而不是直接实例化 `Animal`。

## 5.3 抽象类能加 final 修饰吗？

不能。

- `abstract` 类需要允许被继承，以便子类实现抽象方法。
    
- `final` 类禁止被继承。
    

两者的语义冲突，因此不能同时修饰同一个类。

# 6. 抽象类与接口的区别
## 6.1 什么是接口？

接口主要用于定义一组行为规范，告诉实现类需要提供哪些能力。

```java
interface Payment {
    void pay();
}
```

实现接口：

```java
class Alipay implements Payment {
    @Override
    public void pay() {
        System.out.println("支付宝支付");
    }
}
```

## 6.2 抽象类与接口的对比

| 对比维度    | 抽象类              | 接口                              |
| ------- | ---------------- | ------------------------------- |
| 关键字     | `abstract class` | `interface`                     |
| 继承或实现方式 | `extends`        | `implements`                    |
| 类的关系    | 一个类只能直接继承一个类     | 一个类可以实现多个接口                     |
| 构造方法    | 可以有              | 不可以有                            |
| 实例字段    | 可以有              | 不能定义普通实例字段                      |
| 常量      | 可以定义             | 字段隐式为 `public static final`（常量） |
| 抽象方法    | 可以有              | 可以有                             |
| 具体方法    | 可以有              | 可以有默认、静态和私有方法                   |
| 主要用途    | 表达共同的基础状态和实现     | 定义行为规范或能力                       |

选择时可以这样理解：

- 如果多个类具有共同的状态和基础实现，可以考虑抽象类。
    
- 如果多个类需要遵守统一的行为规范，但它们不一定具有相同的继承关系，可以考虑接口。
    

例如，`Dog` 和 `Cat` 可以继承 `Animal`；而 `Dog`、`Robot` 都可以实现 `Runnable`，表示它们具有可运行的能力。

## 6.3 接口可以定义哪些方法？

Java 接口可以定义以下几种方法：

**（1）抽象方法**

接口中未提供方法体的普通实例方法，默认是 `public abstract`。

```java
interface Animal {
    void sound();
}
```

**（2）默认方法**

Java 8 引入，使用 `default` 修饰，允许接口提供默认实现。

```java
interface Animal {
    default void sleep() {
        System.out.println("睡觉");
    }
}
```

实现类可以直接使用，也可以重写。

**（3）静态方法**

Java 8 引入，属于接口本身，通过接口名调用。

```java
interface Animal {
    static void info() {
        System.out.println("动物信息");
    }
}

// 调用
Animal.info();
```

**（4）私有方法**

Java 9 开始，接口可以定义 `private` 实例方法和 `private static` 静态方法，主要用于**提取** `default` 方法或静态方法中的**重复逻辑**。私有方法只能在**接口内部使用**，不能被实现类直接调用，也不会成为接口对外公开的 API。

```java
interface Animal {
    default void sleep() {
        log();
    }

    private void log() {
        System.out.println("记录行为");
    }
}
```

## 6.4 接口可以有构造方法吗？

不可以。

**接口不能直接实例化**，因此不能定义构造方法。实现接口的类可以有自己的构造方法。

# 7. static：静态变量与静态方法

`static` 用于声明与类关联的成员，而不是与某一个对象实例关联的成员。

## 7.1 静态变量与实例变量

**静态变量（类变量）**：由类的所有实例共享。

**实例变量**：每个对象分别持有自己的实例状态。

```java
class Student {
    static String school = "A大学";

    String name;
}
```

使用：

```java
Student s1 = new Student();
Student s2 = new Student();

s1.name = "小明";
s2.name = "小红";

Student.school = "B大学";
```

这里：

- `s1.name` 和 `s2.name` 分别属于不同对象。
    
- `school` 是共享的类变量，通过类名访问更清晰。
    

## 7.2 静态方法与实例方法

**静态方法属于类，可以不创建对象直接调用。**

```java
class MathUtils {
    public static int add(int a, int b) {
        return a + b;
    }
}
```

调用：

```java
int result = MathUtils.add(2, 3);
```

静态方法不能直接访问实例成员，因为它没有默认对应的具体对象。

```java
class User {
    private String name;

    public void sayHello() {
        System.out.println(name);
    }

    public static void printInfo() {
        // System.out.println(name); // 编译错误
    }
}
```

如果静态方法确实需要操作某个对象的实例成员，可以通过参数传入对象。

```java
public static void printName(User user) {
    user.sayHello();
}
```

## 7.3 静态方法能重写吗？

不能。

静态方法属于类，不遵循实例方法的运行时动态分派机制。

如果子类声明了同名、同参数的静态方法，这属于**静态方法隐藏**，不是方法重写。

## 7.4 静态代码块

静态代码块用于执行类级别的初始化逻辑。

```java
class Config {
    static String name;

    static {
        name = "MiniChat";
        System.out.println("类初始化");
    }
}
```

**静态代码块在类初始化阶段执行，通常用于初始化静态数据。**

注：静态代码块不是每创建一个对象就执行一次；**一个类在同一个类加载器下通常只初始化一次**。

## 7.5 静态代码与普通代码的区别

静态代码和普通代码在编译阶段没有本质区别，都会经过编译并生成字节码，主要区别在于**运行时的执行时机和执行次数**。

| 对比项  | 静态代码            | 普通实例代码                |
| ---- | --------------- | --------------------- |
| 所属   | 类               | 对象                    |
| 执行时机 | 类初始化时           | 创建对象时                 |
| 执行次数 | 同一个类加载器下通常只执行一次 | 每创建一个对象，实例初始化逻辑通常执行一次 |

**总结：编译阶段没有本质区别，运行阶段的执行时机不同。静态代码属于类，只会在类初始化的时候执行一次；普通实例代码属于对象，每创建一个对象，实例初始化逻辑通常执行一次。**

# 8. 静态内部类与非静态内部类

**内部类是定义在另一个类内部的类。**

## 8.1 非静态内部类

非静态内部类依赖外部类的实例。

```java
class Outer {
    private int value = 10;

    class Inner {
        public void print() {
            System.out.println(value);
        }
    }
}
```

创建方式：

```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();

inner.print();
```

**非静态内部类能够直接访问外部类实例的成员，因为它与一个具体的外部类对象关联。**

## 8.2 静态内部类

静态内部类使用 `static` 修饰，不依赖外部类的实例。

```java
class Outer {
    private static int staticValue = 10;
    private int value = 20;

    static class Inner {
        public void print() {
            System.out.println(staticValue);

            // System.out.println(value); // 编译错误
        }
    }
}
```

创建方式：

```java
Outer.Inner inner = new Outer.Inner();
inner.print();
```

**如果静态内部类需要访问外部类的实例成员，必须先取得外部类对象，再通过该对象访问。**

## 8.3 两者的区别

| 对比维度          | 非静态内部类              | 静态内部类               |
| ------------- | ------------------- | ------------------- |
| 是否依赖外部类实例     | 是                   | 否                   |
| 能否直接访问外部类实例成员 | 可以                  | 不可以                 |
| 能否直接访问外部类静态成员 | 可以                  | 可以                  |
| 创建方式          | `outer.new Inner()` | `new Outer.Inner()` |
| 是否隐式持有外部类实例引用 | 通常是                 | 否                   |

补充：Java 16 之前，非静态内部类不能声明除编译期常量等特殊情况外的静态成员；Java 16 起，这一限制已放宽。

## 8.4 非静态内部类为什么能直接访问外部类成员？

编译器会为非静态内部类生成与外部类实例关联的引用，使其能够访问对应外部对象的成员。

可以把它理解为：**非静态内部类对象内部隐含着一个指向外部类实例的引用。**

因此，非静态内部类需要先有外部类对象才能创建。
