# 1 什么是注解？

**注解是一种用于给程序元素添加元数据的机制**，可以修饰类、方法、字段、参数等。

**注解（Annotation）可以理解为给代码添加额外的说明信息。**

例如：

```java
@Override
public String toString() {
    return "Hello";
}
```

这里的 `@Override` 就是一个注解，它告诉编译器：这个方法是用来重写父类或接口中的方法的，编译器可以据此检查写法是否正确。

注解可以添加在不同的代码元素上，例如：

- **类**：说明这个类具有某种特征。
    
- **方法**：说明这个方法的用途或需要遵守的规则。
    
- **字段**：说明这个字段的相关信息。
    
- **参数**：说明参数的相关信息。
    

这些**额外信息**可以供编译器、开发工具或程序运行时读取和处理。

简单来说，**注解就是给代码贴上特定的标签，让编译器或程序知道这些代码有什么特点，或者应该如何处理它们。**

注意：**注解本身通常不直接执行具体业务逻辑，而是由编译器或框架等读取并处理注解信息。**

# 2 Java 注解的原理是什么？
## 2.1 注解的本质

注解通过 `@interface` 定义，本质上是一种特殊的接口，编译后会生成继承自 `java.lang.annotation.Annotation` 的接口类型。

例如：

```java
public @interface MyAnnotation {
    String value();
}
```

这里定义了一个名为 `MyAnnotation` 的注解，其中 `value()` 是注解的一个属性。

使用方式：

```java
@MyAnnotation(value = "hello")
public class User {
}
```

注解中的属性主要用于保存配置信息，属性值可以在后续解析时被读取。

## 2.2 注解的底层实现

#### 注解信息是怎么保存的？

注解本质上是一种为代码添加额外信息的机制。例如：

```java
@Retention(RetentionPolicy.RUNTIME)
@interface MyAnnotation {
    String value();
}

@MyAnnotation("hello")
class User {
}
```

这里，`@MyAnnotation("hello")` 为 `User` 类添加了一个注解，属性 `value` 的值是 `"hello"`。

Java 编译器编译代码时，会根据注解的保留策略决定如何处理注解信息：

|保留策略|含义|
|---|---|
|`SOURCE`|只保留在源代码中，编译后不保留在 `.class` 文件中|
|`CLASS`|保留在 `.class` 文件中，但运行时不要求 JVM 将其作为运行时注解提供给反射|
|`RUNTIME`|保留在 `.class` 文件中，运行时可以通过反射读取|

因此，上面的注解使用了 `RUNTIME`，运行时就可以通过反射获取它。

#### 反射是怎么读取注解的？

例如：

```java
MyAnnotation annotation =
        User.class.getAnnotation(MyAnnotation.class);

if (annotation != null) {
    System.out.println(annotation.value());
}
```

可以分成三个步骤理解：

1. `User.class`：获取 `User` 类对应的 `Class` 对象。
    
2. `getAnnotation(MyAnnotation.class)`：查询 `User` 类上是否存在指定类型的注解，并获取该注解的运行时表示。
    
3. `annotation.value()`：读取注解的 `value` 属性，输出 `hello`。
    

可以把整个过程理解为：

```text
User 类上的注解信息
        |
        v
保存在 User.class 文件中
        |
        v
反射读取注解信息
        |
        v
得到 MyAnnotation 类型的注解实例
        |
        v
调用 value() 获取属性值
        |
        v
输出 hello
```

这里的关键是：**反射读取的不是源代码中的注解文本，而是编译后保留在** `**.class**` **文件中的注解信息。**

#### 为什么还会涉及动态代理？

这是常见 OpenJDK 实现中的底层细节，不是理解注解使用方式的前提。

当通过反射获取运行时注解时，常见的 **OpenJDK** 实现会根据读取到的注解信息，**构造一个能够表示该注解的对象**。这个对象通常通过 JDK 动态代理实现。

例如：

```java
MyAnnotation annotation =
        User.class.getAnnotation(MyAnnotation.class);

System.out.println(annotation.value());
```

虽然 `MyAnnotation` 是一个注解类型，但获取到的 `annotation` 可以像普通对象一样调用 `value()`。

在常见的 OpenJDK 实现中，这个对象的属性访问大致经过以下过程：

```text
调用 annotation.value()
          |
          v
动态代理接收方法调用
          |
          v
AnnotationInvocationHandler 处理调用
          |
          v
根据属性名 value 查找对应的属性值
          |
          v
返回 "hello"
```

其中：

- **动态代理**：在运行时创建一个代理对象，让它能够按照指定规则处理方法调用。
    
- `AnnotationInvocationHandler`：常见 OpenJDK 实现中负责处理注解代理对象方法调用的类。
    
- **属性值映射**：内部保存注解属性名称及其对应值的数据结构，例如 `value` 对应 `"hello"`。
    

所以，调用 `annotation.value()` 时，看起来像是在调用一个普通对象的方法，实际上在常见实现中可能是由代理对象拦截调用，再返回保存的注解属性值。

#### 需要掌握到什么程度？

对于 Java 基础和面试，建议记住以下几点：

1. 注解可以为**类、方法、字段**等程序元素添加元信息。
    
2. `@Retention` 决定注解信息保留到什么阶段；需要运行时反射读取时，通常使用 `RetentionPolicy.RUNTIME`。
    
3. **反射**可以通过 `getAnnotation()` 等方法获取运行时注解，并调用注解属性方法读取属性值。
    
4. 常见 OpenJDK 实现会使用动态代理表示运行时注解，但这是具体实现细节，不是 Java 注解机制必须采用的唯一方案。
    

**核心理解：** 注解信息先由编译器按照保留策略写入编译结果，运行时再由反射读取；动态代理只是常见 OpenJDK 实现用来表示注解实例的一种方式。

# 3 注解如何保存和解析？

注解信息的保存与读取，主要涉及 `@Retention`、`.class` 文件和反射机制。

## 3.1 注解的保留策略

Java 使用元注解 `@Retention` 指定一个注解的**保留策略**，也就是注解信息会保留到哪个阶段。

`@Retention` 有三种策略：

| 策略        | 保留阶段                         | 能否通过反射读取 | 典型用途                                              |
| --------- | ---------------------------- | -------- | ------------------------------------------------- |
| `SOURCE`  | 仅在源码中保留，编译后不保留               | 不能       | **编译期间的检查和提示**，例如 `@Override`、`@SuppressWarnings` |
| `CLASS`   | 保留在 `.class` 文件中，运行时反射不可见    | 不能       | 供**字节码分析**、**处理**等工具读取注解信息                        |
| `RUNTIME` | 保留在 `.class` 文件中，运行时可以通过反射读取 | 可以       | **供运行时框架读取和处理**，例如 Spring 根据注解进行组件扫描和依赖注入         |

例如：

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME)
public @interface MyAnnotation {
    String value();
}
```

这里使用 `@Retention(RetentionPolicy.RUNTIME)`，表示 `MyAnnotation` 注解需要保留到运行时，因此可以通过反射获取注解信息。

**三种策略的核心区别：**

- `SOURCE`：编译后不保留注解信息，适合只在编写代码或编译时发挥作用的注解。
    
- `CLASS`：编译后仍保留注解信息，但普通反射无法读取，适合需要将信息保存在字节码中、供相关工具处理的场景。
    
- `RUNTIME`：运行时仍保留注解信息，可以通过反射读取，适合需要在程序运行期间处理注解的场景。
    

**注意：** 如果没有显式指定 `@Retention`，默认策略是 `CLASS`。

## 3.2 注解信息保存在什么地方？

编译后，符合相应保留策略的注解信息会记录在 `.class` 文件的属性表中。

常见的字节码属性包括：

- `RuntimeVisibleAnnotations`：记录运行时可见的注解。
    
- `RuntimeInvisibleAnnotations`：记录运行时反射不可见的注解。
    
- `RuntimeVisibleParameterAnnotations` 等：记录方法参数上的注解信息。
    

可以使用 `javap -v` 查看编译后的类文件及相关注解信息。

## 3.3 如何通过反射读取注解？

常用方法包括：

| 方法                        | 作用                                         |
| ------------------------- | ------------------------------------------ |
| `getAnnotation()`         | 获取指定注解；对于类上的注解，可能包含通过 `@Inherited` 继承的父类注解 |
| `getDeclaredAnnotation()` | 仅获取当前元素直接声明的指定注解                           |
| `getAnnotations()`        | 获取当前元素上可见的注解，可能包含符合继承规则的父类注解               |
| `isAnnotationPresent()`   | 判断是否存在指定注解，判断类上的注解时也会考虑 `@Inherited`       |

例如：

```java
MyAnnotation annotation =
        User.class.getAnnotation(MyAnnotation.class);

if (annotation != null) {
    System.out.println(annotation.value());
}
```

这里通过 `User.class` 获取类对象，再通过反射获取注解实例，最后调用 `value()` 读取属性值。

**核心原理：注解信息被保存在字节码中，在运行时可以通过反射进行解析和读取。**

# 4 Java 注解的使用范围是什么？

注解的使用范围需要区分两个概念：

- **`@Target`：规定注解可以使用在哪些程序元素上。**
    
- **`@Retention`：规定注解可以保留到哪个阶段。**
    

## 4.1 `@Target` 指定注解的使用位置

`@Target` 配合 `ElementType` 使用，决定一个注解允许修饰哪些程序元素。

|类型|含义|
|---|---|
|`TYPE`|类、接口、枚举、注解类型|
|`FIELD`|字段，包括枚举常量|
|`METHOD`|方法|
|`PARAMETER`|方法或构造方法的参数|
|`CONSTRUCTOR`|构造方法|
|`LOCAL_VARIABLE`|局部变量|
|`ANNOTATION_TYPE`|注解类型本身|
|`PACKAGE`|包|
|`TYPE_PARAMETER`|泛型类型参数的声明|
|`TYPE_USE`|使用类型的地方，例如变量类型、泛型类型参数等|
|`MODULE`|模块|
|`RECORD_COMPONENT`|Record 类的组件|

例如：

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Target;

@Target(ElementType.METHOD)
public @interface MyAnnotation {
}
```

该注解只能用于方法：

```java
public class User {

    @MyAnnotation
    public void test() {
    }
}
```

如果将 `@MyAnnotation` 用于不允许的位置，编译器就会报错。

如果没有显式指定 `@Target`，注解通常可以用于各种声明位置，但不能因此认为它可以用于任意类型使用位置。

## 4.2 其他常见元注解

**元注解就是用于修饰其他注解的注解。**

| 元注解           | 作用                    |
| ------------- | --------------------- |
| `@Target`     | 指定注解的使用位置             |
| `@Retention`  | 指定注解的保留策略             |
| `@Documented` | 指示该注解应出现在 Javadoc 文档中 |
| `@Inherited`  | 允许类上的注解沿父类继承链被继承      |
| `@Repeatable` | 允许在同一位置重复使用某种注解       |

注意：`@Inherited` 只影响类上注解的继承，不会让方法、字段上的注解自动继承，也不代表实现接口时会自动继承接口上的注解。

# 5 总结

- **注解是什么？** 一种为程序元素**提供元数据的机制**，由编译器、注解处理器或框架等读取和处理。
    
- **注解的本质是什么？** 通过 **`@interface`** 定义的特殊接口，继承自 `Annotation`。
    
- **注解如何解析？** 注解信息保存在字节码中，运行时可以通过反射读取；常见 JDK 实现会使用动态代理表示注解实例。
    
- `@Retention` **的作用是什么？** 控制注解保留到源码、编译后的类文件还是运行时。
    
- `@Target` **的作用是什么？** 限制注解可以用于哪些程序元素。
    
- **注解为什么常用于框架？** 注解可以声明配置信息，让框架根据这些信息执行相应处理，例如 Spring 的组件扫描和事务管理。
