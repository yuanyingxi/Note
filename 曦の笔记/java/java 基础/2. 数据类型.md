# 1. Java 的数据类型有哪些？

Java 的数据类型分为两大类：

- **基本数据类型（Primitive Type）**：直接表示数值、字符或布尔值。
    
- **引用数据类型（Reference Type）**：包括类、接口、数组等，变量保存的是对象引用，而不是对象的全部内容。
    

Java 有 8 种基本数据类型，可以分为三类：

1. 整数类型：`byte`、`short`、`int`、`long`
    
2. 浮点类型：`float`、`double`
    
3. 其他类型：`char`、`boolean`
     

## 1.1 八种基本数据类型

| 类型        | 大小          | 取值范围                      | 默认值        |
| --------- | ----------- | ------------------------- | ---------- |
| `byte`    | 1 字节        | -2⁷ 到 2⁷ - 1，即 -128 到 127 | `0`        |
| `short`   | 2 字节        | -2¹⁵ 到 2¹⁵ - 1            | `0`        |
| `int`     | 4 字节        | -2³¹ 到 2³¹ - 1            | `0`        |
| `long`    | 8 字节        | -2⁶³ 到 2⁶³ - 1            | `0L`       |
| `float`   | 4 字节        | 约 ±3.4 × 10³⁸             | `0.0f`     |
| `double`  | 8 字节        | 约 ±1.8 × 10³⁰⁸            | `0.0d`     |
| `char`    | 2 字节        | 0 到 65535                 | `'\u0000'` |
| `boolean` | 规范未规定固定存储大小 | `true`、`false`            | `false`    |

注意：

- 上表中的默认值是**类的成员变量、数组元素**等在默认初始化时使用的值。局部变量没有默认值，必须先赋值才能使用。
    
- `boolean` 只有 `true` 和 `false` 两种取值，但 Java 语言规范没有规定它必须占多少位或多少字节。
    
- `char` 是无符号的 16 位类型，表示一个 UTF-16 代码单元，不一定能独立表示所有 Unicode 字符。例如，一些 emoji 需要两个 `char` 才能表示。
    
- 整数字面量默认是 `int`，浮点数字面量默认是 `double`。
    
- 声明 `long` 常量时可以加 `L`，声明 `float` 常量时需要加 `f` 或 `F`。
    

示例：

```java
int age = 20;
long population = 8_000_000_000L;

double price = 3.14;
float rate = 3.14f;

char letter = 'A';
boolean passed = true;
```

## 1.2 int 和 long 有什么区别？

- `int`：32 位，4 字节，适用于大多数普通整数计算。
    
- `long`：64 位，8 字节，适用于数值范围超过 `int` 的场景。
    

例如，`int` 的最大值为 `2147483647`。当计数值可能超过这个范围时，应考虑使用 `long`。

```java
int a = 100;
long b = a; // 自动转换

long c = 3_000_000_000L;
```

注意：整数溢出不会自动报错，计算结果可能出现意料之外的值。

```java
int max = Integer.MAX_VALUE;
System.out.println(max + 1); // -2147483648
```

# 2. Java 的数据类型转换

Java 的类型转换主要包括基本数据类型之间的转换、引用类型之间的转换，以及字符串与数值之间的转换。

## 2.1 自动类型转换

当数值类型之间的转换可以由 Java 自动完成时，称为自动类型转换。

例如：

```java
int a = 10;
long b = a;

float c = b;
double d = c;
```

常见的数值类型转换方向为：

```text
byte → short → int → long → float → double
                  ↑
                 char
```

其中，`char` 可以自动转换为 `int`、`long`、`float`、`double`，但不能直接转换为 `short` 或 `byte`。

注意：**自动类型转换不代表一定不会丢失精度。**

例如，`int` 转 `float` 虽然可以自动完成，但 `float` 只有约 24 位二进制有效精度，不能精确表示所有 32 位整数。

```
int a = 16_777_217;
float b = a;

System.out.println(b); // 16777216.0，发生精度损失
```

## 2.2 强制类型转换

当需要将数值转换为较小范围的类型，或者显式转换为其他类型时，可以使用强制类型转换。

语法：

```text
目标类型 变量名 = (目标类型) 原始值;
```

示例：

```java
long a = 100L;
int b = (int) a;

double c = 3.14;
int d = (int) c;

System.out.println(b); // 100
System.out.println(d); // 3
```

强制转换可能出现两类问题：

**（1）整数溢出**

当目标整数类型无法容纳原始值时，转换结果可能发生变化。

```java
int a = 300;
byte b = (byte) a;

System.out.println(b); // 44
```

原因：转换为 `byte` 时只保留低 8 位，超出范围的高位被丢弃。

**（2）精度损失**

浮点数转换为整数时，小数部分会被直接截去，不会自动进行四舍五入。

```java
double a = 3.99;
int b = (int) a;

System.out.println(b); // 3
```

### 2.3 引用类型转换

引用类型之间的转换主要分为向上转型和向下转型。

**向上转型：子类转为父类**

向上转型通常可以自动完成。

```java
class Animal {}

class Dog extends Animal {}

Dog dog = new Dog();
Animal animal = dog;
```

此时，引用变量 `animal` 的声明类型是 `Animal`，但它指向的实际对象仍然是 `Dog`。

**向下转型：父类引用转为子类引用**

向下转型需要显式转换，并且必须满足对象的实际类型与目标类型兼容的条件，否则会抛出 `ClassCastException`。

```java
Animal animal = new Dog();

Dog dog = (Dog) animal; // 正确
```

错误示例：

```java
Animal animal = new Animal();

Dog dog = (Dog) animal; // 运行时抛出 ClassCastException
```

可以使用 `instanceof` 进行检查：

```java
if (animal instanceof Dog) {
    Dog dog = (Dog) animal;
}
```

Java 16 及之后的版本还支持模式匹配写法：

```java
if (animal instanceof Dog dog) {
    // 这里可以直接使用 dog
}
```

### 2.4 字符串与数值之间的转换

字符串转数值时，可以使用包装类提供的解析方法：

```java
int a = Integer.parseInt("123");
double b = Double.parseDouble("3.14");
long c = Long.parseLong("1000");
```

数值转字符串时，可以使用：

```java
String a = Integer.toString(123);
String b = String.valueOf(3.14);
```

注意：如果字符串不是合法的数值格式，解析方法会抛出 `NumberFormatException`。

# 3. 为什么金额计算通常使用 BigDecimal，而不是 double？
## 3.1 double 为什么会产生精度误差？

`float` 和 `double` 使用二进制浮点数表示数值。

有些十进制小数无法用有限位数的二进制小数精确表示，因此存储时只能使用近似值，计算时就可能产生误差。

示例：

```java
System.out.println(0.1 + 0.2);
// 0.30000000000000004
```

对于图形计算、科学计算等允许一定误差的场景，浮点数通常足够使用。

但是，对于金额、账单和精确计费等业务，精度误差可能造成实际问题，因此一般使用 `BigDecimal` 或整数最小货币单位进行计算。

## 3.2 BigDecimal 的使用

`BigDecimal` 可以表示任意精度的十进制数值，并支持指定精度和舍入规则。

推荐使用字符串创建：

```java
BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");

System.out.println(a.add(b)); // 0.3
```

也可以使用：

```java
BigDecimal value = BigDecimal.valueOf(0.1);
```

不推荐直接使用：

```java
BigDecimal value = new BigDecimal(0.1);
```

原因：`0.1` 先被表示为 `double` 近似值，再传入 `BigDecimal`，无法恢复原本想表达的精确十进制数值。

注意：`BigDecimal.valueOf(0.1)` 适合从 `double` 的字符串表示构造十进制数，但无法修复之前已经发生的浮点运算误差。

## 3.3 BigDecimal 的常见注意事项

**（1）除法需要考虑精度和舍入规则**

例如，1 除以 3 的结果是无限循环小数，无法用有限位数精确表示。

```java
BigDecimal result = BigDecimal.ONE.divide(
    new BigDecimal("3"),
    2,
    RoundingMode.HALF_UP
);

System.out.println(result); // 0.33
```

其中：

- `2` 表示保留两位小数。
    
- `RoundingMode.HALF_UP` 表示采用常见的四舍五入规则。
    

实际业务应根据金额规则确定保留位数和舍入方式。

**（2）equals 和 compareTo 的区别**

`equals()` 同时比较数值和 scale（小数位数）；`compareTo()` 比较数值大小。

```java
BigDecimal a = new BigDecimal("1.0");
BigDecimal b = new BigDecimal("1.00");

System.out.println(a.equals(b));        // false
System.out.println(a.compareTo(b));    // 0
```

因此，如果只关心金额数值是否相等，通常使用：

```java
a.compareTo(b) == 0
```

**（3）BigDecimal 是不可变对象**

`add()`、`subtract()`、`multiply()` 等方法会返回新的 `BigDecimal` 对象，不会直接修改原对象。

```java
BigDecimal a = new BigDecimal("10");
BigDecimal b = new BigDecimal("5");

a.add(b); // 没有保存返回值，a 仍然是 10

a = a.add(b); // a 变成 15
```

# 4. 什么是装箱和拆箱？

装箱和拆箱是基本数据类型与对应包装类之间的转换。

- **装箱（Boxing）**：基本类型转换为对应的包装类。
    
- **拆箱（Unboxing）**：包装类转换为对应的基本类型。
    

|基本类型|对应包装类|
|---|---|
|`byte`|`Byte`|
|`short`|`Short`|
|`int`|`Integer`|
|`long`|`Long`|
|`float`|`Float`|
|`double`|`Double`|
|`char`|`Character`|
|`boolean`|`Boolean`|

## 4.1 自动装箱和自动拆箱

Java 5 开始支持自动装箱和自动拆箱。

```java
Integer a = 10; // 自动装箱
int b = a;      // 自动拆箱
```

可以近似理解为：

```java
Integer a = Integer.valueOf(10);
int b = a.intValue();
```

自动装箱和拆箱也会发生在方法调用等场景中。

```java
public static Integer getValue(Integer value) {
    return value;
}

int result = getValue(10);
```

调用时，`10` 被装箱为 `Integer`；返回值赋给 `int` 时，又发生了拆箱。

### 4.2 自动装箱有什么问题？

自动装箱和拆箱虽然方便，但会带来额外的对象操作。

例如：

```java
Integer sum = 0;

for (int i = 1000; i < 5000; i++) {
    sum += i;
}
```

`sum += i` 可以理解为：

```java
sum = sum + i;
```

执行时需要：

1. 将 `sum` 自动拆箱为 `int`。
    
2. 完成整数加法。
    
3. 将结果重新装箱为 `Integer`。
    

循环过程中可能产生大量临时对象，增加内存分配和垃圾回收的开销。

因此，普通数值计算、循环计数等场景通常优先使用 `int` 或 `long`。

## 4.3 自动拆箱的空指针问题

包装类是引用类型，可以为 `null`；基本数据类型不能为 `null`。

如果对值为 `null` 的包装类进行自动拆箱，就会抛出 `NullPointerException`。

```java
Integer value = null;

int number = value; // NullPointerException
```

因此，在使用包装类时，要特别注意空值检查。

# 5. Java 为什么需要 Integer？

`Integer` 是 `int` 的包装类，可以把整数表示为对象。

## 5.1 支持集合和泛型

Java 的泛型类型参数不能直接使用基本数据类型。

不能写：

```java
List<int> list = new ArrayList<>(); // 编译错误
```

应该写：

```java
List<Integer> list = new ArrayList<>();

list.add(10); // 自动装箱
int number = list.get(0); // 自动拆箱
```

集合中存储的是 `Integer` 对象，而不是 `int` 基本类型。

## 5.2 可以表示没有值的情况

`int` 的默认值是 `0`，`Integer` 作为成员变量时默认值是 `null`。

例如，用户年龄尚未填写时：

```java
Integer age = null;
```

这样可以区分“没有填写年龄”和“年龄为 0”。

但 `null` 也意味着使用前需要进行空值检查，否则自动拆箱可能抛出空指针异常。

## 5.3 提供常用工具方法

`Integer` 提供了许多静态工具方法：

```java
int number = Integer.parseInt("123");

String text = Integer.toString(123);

String hex = Integer.toHexString(255); // "ff"
```

## 5.4 Integer 和 int 有什么区别？

| 对比维度       | int            | Integer                     |
| ---------- | -------------- | --------------------------- |
| 类型         | 基本数据类型         | 引用数据类型                      |
| 是否可以为 null | 不可以            | 可以                          |
| 默认值        | 成员变量默认为 `0`    | 成员变量默认为 `null`              |
| 存储与操作      | 通常更节省空间，数值操作直接 | 对象和引用带来额外开销，可能发生装箱拆箱        |
| 泛型集合       | 不能直接作为泛型参数     | 可以作为泛型参数                    |
| 比较注意事项     | `==` 比较数值      | 两个 `Integer` 使用 `==` 比较对象身份 |

## 5.5 为什么还要保留 int？

虽然 `Integer` 使用方便，但 `int` 在普通数值计算中通常更加高效。

主要原因：

1. `int` 不需要为每个数值创建包装对象。
    
2. `int` 不涉及装箱和拆箱。
    
3. 使用大量整数时，基本类型通常能够节省内存。
    

例如，普通计数器优先使用 `int`：

```java
int count = 0;
count++;
```

而当需要把整数放进集合、表示空值，或者使用需要对象类型的 API 时，可以使用 `Integer`。

# 6. Integer 的缓存机制
## 6.1 什么是 IntegerCache？

`Integer` 内部有一个缓存机制，用来复用一部分常用整数对应的 `Integer` 对象。

通过 `Integer.valueOf()` 创建缓存范围内的数值时，可以直接复用缓存对象，减少重复创建对象的开销。

至少缓存的范围是 `-128` 到 `127`。HotSpot JVM 默认缓存这个范围，缓存上限还可能根据 JVM 配置进行调整。

**即：只要是通过自动装箱（例如 `Integer a = 10;`）或者调用 `Integer.valueOf(10)`，只要数值在 `-128` 到 `127` 之间，Java 都会从预先创建好的缓存池（数组）**里，直接把这同一个对象的地址交给你。**

自动装箱通常也会使用 `Integer.valueOf()`，因此同样可能命中缓存。

## 6.2 Integer 缓存的示例

```java
Integer a = 127;
Integer b = 127;

System.out.println(a == b); // true
```

因为 `127` 位于默认缓存范围内，`a` 和 `b` 通常指向同一个缓存对象。

再看一个例子：

```java
Integer c = 128;
Integer d = 128;

System.out.println(c == d);      // 默认配置下通常为 false
System.out.println(c.equals(d)); // true
```

默认缓存范围不包含 `128`，因此这**两个变量通常引用不同对象，但它们表示的整数值相同**。

注意：`128` 是否被缓存并不是绝对的，因为缓存上限可以调整。

## 6.3 为什么 Integer 不能随便使用 == 比较数值？

对于引用类型，`==` 比较的是两个引用是否指向同一个对象，而不是对象中的数值是否相同。

**在 Java 里，`==` 到底比较什么取决于比较的是“基本类型”还是“引用类型”。**

- **基本类型（如 `int`, `double`, `boolean`）**：`==` 比较的是**数值本身**。
    
- **引用类型（如 `Integer`, `String`, `User` 对象）**：`==` 比较的是**内存地址（是不是同一个对象）**。

因此：

```java
Integer a = 1000;
Integer b = 1000;

System.out.println(a == b);      // 通常为 false
System.out.println(a.equals(b)); // true
```

即使某个值命中了缓存，导致 `==` 返回 `true`，也不能把这种行为当作数值比较的依据。

比较两个 `Integer` 的数值时，通常使用：

```java
a.equals(b)
```

如果还需要安全处理 `null`，可以使用：

```java
Objects.equals(a, b)
```

## 6.4 Integer 和 int 使用 == 比较时会怎样？

当 `Integer` 和 `int` 使用 `==` 比较时，`Integer` 会**自动拆箱**，然后比较两个整数值。

```java
Integer number = 128;

System.out.println(number == 128); // true
```

但是，如果 `number` 为 `null`，自动拆箱时会抛出 `NullPointerException`。

## 6.5 Integer 缓存的目的是什么？

**主要目的是复用常用整数对象，减少重复的对象分配和内存开销。**

需要记住：

- 缓存会影响某些情况下的对象身份比较结果。
    
- 缓存不改变整数的数值含义。
    
- 判断两个 `Integer` 数值是否相等，不应该依赖 `==`。
    
- 日常使用中优先采用自动装箱或 `Integer.valueOf()`，不需要手动维护缓存。
    
- `new Integer(int)` 自 Java 9 起已被标记为过时，不建议使用。
    

# 7. 本节重点总结

1. Java 有 8 种基本数据类型，其余常见类型如 `String`、数组和自定义类都属于引用类型。
    
2. `int` 为 32 位，`long` 为 64 位；整数溢出不会自动报错。
    
3. 自动类型转换不一定完全精确，强制类型转换可能导致溢出或精度损失。
    
4. 金额等需要精确十进制运算的场景通常使用 `BigDecimal`，创建时优先使用字符串。
    
5. 自动装箱和拆箱可以简化代码，但可能带来对象开销；对 `null` 进行拆箱会产生空指针异常。
    
6. `Integer` 可以用于集合、泛型和需要表示空值的场景；普通数值计算通常优先使用 `int`。
    
7. `IntegerCache` 会缓存至少 `-128` 到 `127` 的整数对象，缓存范围外的对象身份不应依赖。
    
8. 比较两个 `Integer` 的数值通常使用 `equals()`；需要兼容 `null` 时可以使用 `Objects.equals()`。
