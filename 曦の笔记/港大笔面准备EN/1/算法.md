## 算法设计思想

### 1 Greedy Algorithm（贪心算法）

**题目方向：** 贪心算法在什么情况下会失效？

面经没有提供具体题目，因此只整理核心知识点。

**知识点：Greedy Algorithm**

（1）什么是贪心算法？

贪心算法是一种算法思想，每一步都选择当前看起来最优的方案，希望通过局部最优得到全局最优。

（2）贪心算法的两个重要性质

- Greedy Choice Property（贪心选择性质）：每一步的局部最优选择能够导向全局最优解。
- Optimal Substructure（最优子结构）：原问题的最优解包含子问题的最优解。

（3）贪心算法什么时候可能失效？

当每一步的局部最优选择不能保证最终得到全局最优解时，贪心算法可能失效。

例如：

假设硬币面值为 1、3、4，需要凑出金额 6。

贪心算法每次选择最大面值：

- 第一步：选择 4。
- 第二步：剩余 2，选择 1。
- 第三步：剩余 1，再选择 1。

最终使用 3 枚硬币。

但最优方案是：

- 选择 3。
- 再选择 3。

只需要 2 枚硬币。

因此，贪心算法不一定能够得到全局最优解。

（4）贪心算法与动态规划的区别

| 对比       | Greedy       | Dynamic Programming |
| -------- | ------------ | ------------------- |
| 中文       | 贪心算法         | 动态规划                |
| 核心思想     | 每一步选择局部最优    | 保存并利用子问题的结果         |
| 是否考虑后续影响 | 通常不重新考虑之前的选择 | 通过状态转移综合考虑          |
| 是否保证最优   | 需要满足特定性质     | 正确设计状态和转移时可以保证      |

**所属知识点：** 数据结构与算法 / 算法设计思想 / 贪心算法。

### 2 Dynamic Programming（动态规划）

**题目方向：** 使用动态规划求斐波那契数列。

这部分可以根据面经复现一道基础编程题。

**模拟英文题目：**

Given an integer n, calculate the n-th Fibonacci number using dynamic programming.

The Fibonacci sequence is defined as follows:

```text
F(0) = 0
F(1) = 1

F(n) = F(n - 1) + F(n - 2), for n >= 2
```

Write a program to calculate F(n).

**Example:**

```text
Input:
6

Output:
8
```

**知识点：Dynamic Programming**

（1）什么是动态规划？

动态规划（Dynamic Programming，DP）是一种算法思想，通过将原问题拆分成多个子问题，保存已经计算过的结果，避免重复计算。

（2）动态规划的三个基本要素

- State（状态）：定义每个子问题代表什么。
- State Transition（状态转移）：描述状态之间的关系。
- Initial State（初始状态）：确定最开始的状态值。

（3）斐波那契数列的状态定义

定义：

```text
dp[i] 表示第 i 个斐波那契数。
```

初始状态：

```text
dp[0] = 0
dp[1] = 1
```

状态转移方程：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

（4）Python 代码

```python
n = int(input())

if n == 0:
    print(0)
elif n == 1:
    print(1)
else:
    dp = [0] * (n + 1)
    dp[0] = 0
    dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    print(dp[n])
```

（5）复杂度分析

- 时间复杂度：O(n)，每个状态只计算一次。
- 空间复杂度：O(n)，使用数组保存每个状态。

**所属知识点：** 数据结构与算法 / 动态规划 / 线性 DP。

### 3 分治（Divide and Conquer）与减治（Decrease and Conquer）

**题目方向：** 哪些算法采用分治思想？分治与减治的区别？

**知识点：Divide and Conquer**

（1）分治的三步

```text
Divide   把原问题拆成若干规模更小的子问题（通常 2 个）
Conquer  递归求解每个子问题
Combine  把子问题的解合并成原问题的解
```

（2）减治：每轮只留一个子问题

| 对比    | 分治 Divide and Conquer | 减治 Decrease and Conquer |
| ----- | --------------------- | ----------------------- |
| 子问题个数 | 通常 2 个，**都要解**        | 每轮只解 **1 个**            |
| 递归式   | T(n) = 2T(n/2) + f(n) | T(n) = T(n/2) + f(n)    |
| 复杂度   | O(n log n) 常见         | O(log n) 常见             |
| 例子    | 归并排序、快速排序             | 二分查找、快速选择（quickselect）  |

（3）常见算法的归类

| 算法                 | 思想                     |
| ------------------ | ---------------------- |
| 归并排序               | 分治（分区易、合并难）            |
| 快速排序               | 分治（分区难、合并易——分区完即有序）    |
| 二分查找               | 减治                     |
| 快速选择（求第 k 大）       | 减治                     |
| 大整数乘法、Strassen 矩阵乘 | 分治                     |
| 汉诺塔                | 分治（T(n) = 2T(n−1) + 1） |

（4）分治与动态规划的分界线

**子问题是否重叠**。分治的子问题互相独立（归并排序的左右两半各排各的）；DP 的子问题相互重叠，所以要「存表复用」。

**需要记住：**

Divide and conquer splits into **overlapping-free** subproblems; DP is needed when subproblems **overlap**.

### 4 Backtracking（回溯法）

**题目方向：** 哪类问题用回溯？回溯与 DFS 的关系？

**知识点：Backtracking**

（1）什么是回溯？

回溯是「**系统地枚举所有候选解 + 剪枝**」的搜索方法。它沿着一条路径尝试，走不通就撤销上一步（backtrack），换下一个候选。

（2）与 DFS 的关系

回溯通常**用 DFS 实现**：DFS 是「遍历方式」，回溯是「带撤销与剪枝的遍历策略」。

（3）通用模板

```text
def backtrack(path, choices):
    if 满足结束条件:
        记录 path
        return
    for choice in choices:
        if 不合法: continue        # 剪枝
        做出选择（path.append）
        backtrack(path, 剩余选择)
        撤销选择（path.pop）        # 回溯的关键一步
```

（4）典型问题

| 问题      | 候选       | 剪枝条件      |
| ------- | -------- | --------- |
| 全排列     | 每个未使用的数  | 已使用则跳过    |
| N 皇后    | 每行选一列    | 同列、同对角线冲突 |
| 子集 / 幂集 | 每个元素选或不选 | —         |
| 数独      | 每格填 1–9  | 行、列、宫冲突   |
| 组合总和    | 每个数可选多次  | 和超过目标则停   |

（5）复杂度

最坏是指数级（枚举所有组合），剪枝只能改善常数与平均表现，不能改变最坏阶。

**需要记住：**

Backtracking = DFS + **undo** the choice + **pruning**. It enumerates candidates and is exponential in the worst case.

### 5 算法识别指纹表（Description → Algorithm）

**题目方向：** 给一段文字描述或一段代码，问这是哪个算法。这是 27fall 最典型的「会认」类题目。

**知识点：算法识别**

（1）三步法

```text
Step 1  找「标志性动作」：代码里最独特的那一行
Step 2  看「数据结构」：用了堆？并查集？队列？二维表？
Step 3  看「递归结构」：分成两半都递归？还是只递归一个？
```

（2）文字描述 → 算法

| 描述里的关键词                                                         | 算法               |
| --------------------------------------------------------------- | ---------------- |
| pick a **pivot**, **partition**, recurse on both sides          | **快速排序**         |
| split in half, sort each half, **merge**                        | **归并排序**         |
| build a **heap**, repeatedly **sift down**                      | **堆排序**          |
| repeatedly pick the **smallest** and swap to the front          | 选择排序             |
| insert each element into its correct place in the sorted prefix | 插入排序             |
| swap **adjacent** elements if out of order                      | 冒泡排序             |
| sort edges by weight, use **Union-Find**, avoid cycles          | **Kruskal**      |
| grow a tree from one vertex, always add the **cheapest** edge   | **Prim**         |
| relax **all edges V−1** times                                   | **Bellman-Ford** |
| take the **closest unvisited** vertex, relax its neighbours     | **Dijkstra**     |
| table of size V×V, loop over intermediate vertex k              | **Floyd**        |
| halve the search range each step                                | **二分查找**         |
| **overlapping subproblems**, solve once, **store** results      | **动态规划**         |
| local optimum at each step, never reconsider                    | **贪心**           |
| enumerate candidates, **undo** choices, **prune**               | **回溯**           |
| queue of **zero-indegree** vertices                             | **拓扑排序（Kahn）**   |

（3）代码指纹 → 算法

| 代码里出现                                       | 算法                 |
| ------------------------------------------- | ------------------ |
| `pivot = a[hi]` + 双指针交换 + 两侧递归              | 快排                 |
| `a[:m] + a[m:]`（按**位置**切）+ merge            | 归并                 |
| `for k in range(V): for i: for j:`          | Floyd              |
| `parent[]` + `find()` / `union()`           | Kruskal / 并查集      |
| `dist[u] + w < dist[v]` 松弛                  | 最短路（Dijkstra / BF） |
| `dp[i] = dp[i-1] + dp[i-2]`                 | 线性 DP              |
| `dp[i][j] = dp[i-1][j-1] + 1`（二维表 + 左上角 +1） | LCS                |
| `while lo <= hi: mid = ...`                 | 二分                 |

（4）两个最需要区分的组合

| 看起来像       | 区分点                                            |
| ---------- | ---------------------------------------------- |
| 快排 vs 归并   | **按值切**（`x < pivot`）→ 快排；**按位置切**（`a[:m]`）→ 归并 |
| 快排 vs 选择排序 | 快排有**递归 + 分区**；选择排序只有「每轮选最小」                   |

**英文例题：**

An algorithm works as follows: pick an element as the pivot, partition the array so that elements smaller than the pivot come before it and larger come after it, then recursively sort the two parts. Which algorithm is being described?

A. Merge sort

B. Insertion sort

C. Quick sort

D. Heap sort

E. Selection sort

**答案：C**

**解析：** `pivot + partition + 双侧递归` 是快排的标志性动作。归并是「对半切 + 合并」；堆排是「建堆 + 反复取堆顶」；选择排序没有递归和分区（「选基准」与「选择排序」是两个概念）。

**所属知识点：** 数据结构与算法 / 算法设计思想 / 算法识别。

### 6 循环复杂度速判

**题目方向：** 给一段嵌套循环，问时间复杂度。

**知识点：复杂度分析**

（1）七种基本形态（看到就能报答案）

| 代码形态                                      | 复杂度            | 说明              |
| ----------------------------------------- | -------------- | --------------- |
| for i in 1..n                             | O(n)           | 单层线性            |
| for i: for j in 1..n                      | O(n²)          | 全嵌套（矩形）         |
| for i: for j in 1..i                      | O(n²)          | 三角循环，共 n(n+1)/2 |
| for i: for j in 1..n step i（外层 +1）        | **O(n log n)** | 调和级数 n·H(n)     |
| **while i ≤ n: … i *= 2**（外层 ×2，内层步长 = i） | **O(n)**       | 等比收敛，总和 < 2n    |
| while n > 1: n //= 2                      | O(log n)       | 每次减半            |
| while i*i ≤ n: i++                        | O(√n)          | 判素数、试除          |

（2）判复杂度的三步法

```text
Step 1  写出循环变量的取值范围
Step 2  写出内层执行次数的求和式 Σ
Step 3  用求和公式化简，取最高阶
```

常用求和公式（纯文本形式）：

```text
Σ(i = 1..n) i        = n(n+1)/2      = O(n²)
Σ(i = 1..n) n/i      = n·H(n)        = O(n log n)      ← 调和，发散
Σ(i = 0..log n) n/2^i = n(1+1/2+1/4+…) < 2n = O(n)      ← 等比，收敛
Σ(i = 1..n) i²       = O(n³)
```

（3）最值钱的四句口诀

| 外层走法         | 内层步长          | 复杂度        |
| ------------ | ------------- | ---------- |
| i = 1..n（+1） | j 跑到 i        | O(n²)      |
| i = 1..n（+1） | j += i（n/i 次） | O(n log n) |
| i ×2         | j 跑满 n        | O(n log n) |
| i ×2         | j += i        | **O(n)**   |

（4）五个「看起来更慢、其实更快」的陷阱

- 双指针：外层 while (i < j)，内层可能移动多次，但**总移动次数 ≤ n** → O(n)。
- 建堆 heapify 自底向上 → O(n)，不是 O(n log n)。
- 字符串循环拼接 s = s + c → O(n²)。
- 递归 T(n) = 2T(n/2) + n → O(n log n)，不是 O(n²)。
- 快排平均 O(n log n)、最坏 O(n²)（已有序或大量重复时退化）。

**英文例题：**

```c
int i = 1, s = 0;
while (i <= n) {
    for (int j = 1; j <= n; j += i)
        s++;
    i *= 2;
}
```

What is the time complexity with respect to n?

A. O(log n)

B. O(n)

C. O(n log n)

D. O(n²)

E. O(n² log n)

**答案：B**

**解析：** 外层 i 取 1, 2, 4, …，共 log n 轮；第 t 轮内层跑 n/2^t 次。总和 n(1 + 1/2 + 1/4 + …) < 2n，等比级数有常数上界 → O(n)。代入 n = 8 手算：8 + 4 + 2 + 1 = 15 < 16。选 C 的人是「把最坏一轮当成每一轮」。

**所属知识点：** 数据结构与算法 / 复杂度分析 / 循环。

### 7 递归复杂度与主定理

**题目方向：** 给一个递归式，问时间复杂度。

**知识点：主定理（Master Theorem）**

（1）标准形式

```text
T(n) = a·T(n/b) + f(n)     其中 a ≥ 1, b > 1
```

（2）三种情形（比较 f(n) 与 n^(log_b a)）

| 情形 | 条件                                | 结论                            |
| -- | --------------------------------- | ----------------------------- |
| 1  | f(n) = O(n^(log_b a − ε))         | T(n) = Θ(n^(log_b a))         |
| 2  | f(n) = Θ(n^(log_b a))             | T(n) = Θ(n^(log_b a) · log n) |
| 3  | f(n) = Ω(n^(log_b a + ε)) 且满足正则条件 | T(n) = Θ(f(n))                |

（3）必须背的四个结果

| 递归式                | 算法          | 复杂度        |
| ------------------ | ----------- | ---------- |
| T(n) = 2T(n/2) + n | 归并 / 快排（平均） | O(n log n) |
| T(n) = 2T(n/2) + 1 | 遍历二叉树       | O(n)       |
| T(n) = T(n/2) + 1  | 二分查找        | O(log n)   |
| T(n) = 2T(n−1) + 1 | 汉诺塔         | O(2ⁿ)      |

（4）递归调用次数（选择题爱考）

朴素递归斐波那契 fib(n) = fib(n−1) + fib(n−2)，计算 fib(n) 的总调用次数：

```text
C(0) = C(1) = 1
C(n) = C(n−1) + C(n−2) + 1      （+1 是根自己那次调用）
```

```text
n   : 0  1  2  3  4  5   6
C(n): 1  1  3  5  9  15  25
```

闭式：C(n) = 2·Fib(n+1) − 1（Fib 为标准斐波那契，Fib(6) = 8 → C(5) = 15）。

**三个「同阶」结论：调用次数、返回值、时间复杂度三者同阶，都是 O(2ⁿ)。加记忆化后降为 O(n)。**

（5）主定理不适用的情形

T(n) = 2T(n/2) + n log n 这类「差一个 log 因子」的边界情形，主定理的三种情形都不严格满足，需要展开递归树或用 Akra–Bazzi。选择题不会考这么深。

**英文例题：**

How many times is the function called in total (including the initial call) when evaluating fib(5) with naive recursion?

A. 9

B. 12

C. 13

D. 15

E. 25

**答案：D**

**解析：** 逐项推 C(0)=C(1)=1，C(2)=3，C(3)=5，C(4)=9，C(5)=15。闭式验证 2·Fib(6) − 1 = 16 − 1 = 15。选 9 是少算一层（C(4) 的值）。

**所属知识点：** 数据结构与算法 / 复杂度分析 / 递归与主定理。

### 8 均摊分析（Amortized Analysis）

**题目方向：** 动态数组 push 的复杂度为什么是 O(1)？双指针为什么是 O(n)？

**知识点：均摊分析**

（1）什么是均摊分析？

一次操作可能很贵（如扩容要 O(n)），但**连续 m 次操作的总代价**平均下来很小。均摊分析算的是「每次操作的平均代价」，不是「最坏一次」。

（2）三个经典结论

| 场景               | 单次最坏 | 均摊                      |
| ---------------- | ---- | ----------------------- |
| 动态数组 push（满时翻倍）  | O(n) | **O(1)**                |
| 双指针（i 只增、j 只增）   | —    | **O(n)** 总移动            |
| 建堆 heapify（自底向上） | —    | **O(n)**（不是 O(n log n)） |

（3）为什么 push 均摊是 O(1)（聚合分析法）

扩容发生在第 1、2、4、8、…、n 次插入，总拷贝代价：

```text
1 + 2 + 4 + … + n < 2n
```

n 次插入总代价 < 2n → 每次均摊 O(1)。**关键仍是「等比级数收敛」这个工具。**

（4）建堆为什么是 O(n)

第 h 层的节点最多有 n/2^h 个，每个节点下沉最多 h 层：

```text
Σ(h = 0..log n) (n/2^h)·h = O(n)      ← 级数收敛，不是 n log n
```

直觉：绝大多数节点在底层、根本不用下沉；只有根可能下沉 log n 层。

**英文例题：**

A dynamic array (like C++ `vector` or Java `ArrayList`) doubles its capacity whenever it becomes full. Starting from empty, we perform n `push_back` operations. What is the **amortized** time complexity of a single push?

A. O(1)

B. O(log n)

C. O(n)

D. O(n log n)

E. O(n²)

**答案：A（O(1)）**

**解析：** 扩容发生在第 1、2、4、8、…、n 次插入，每次要把旧元素全部搬走，拷贝总代价为

```text
1 + 2 + 4 + … + n < 2n
```

n 次插入的总代价 < 2n，均摊到每次就是 O(1)。**注意区分「单次最坏」与「均摊」**：某一次 push 的最坏代价是 O(n)（正好触发扩容），但均摊是 O(1)——选项 C 是把「最坏一次」当成了「平均每次」。


**需要记住：**

Amortized cost of push on a dynamic array is O(1) — the expensive resizes are paid for by all the cheap pushes in between.

**所属知识点：** 数据结构与算法 / 复杂度分析 / 均摊分析。

## 排序

### 1. 排序算法基础

#### 1.1 什么是排序？

**排序（Sorting）** 是指按照某个关键字（Key）的大小或其他规则，将一组数据重新排列，使数据按照指定顺序排列。

排序主要分为两种：

| 类型   | 英文               | 说明     |
| ---- | ---------------- | ------ |
| 升序排序 | Ascending Order  | 从小到大排列 |
| 降序排序 | Descending Order | 从大到小排列 |

#### 1.2 稳定性（Stability）

**稳定性（Stability）** 是指：如果两个元素的关键字相同，那么排序之后，它们原来的相对位置是否保持不变。

例如，原始数据：

```text
(张三, 90)
(李四, 80)
(王五, 90)
```

按照成绩从小到大排序：

```text
(李四, 80)
(张三, 90)
(王五, 90)
```

张三仍然排在王五前面，两个成绩相同的元素保持原来的相对位置，因此该排序算法是**稳定的（Stable）**。

如果排序后变成：

```
(李四, 80)
(王五, 90)
(张三, 90)
```

两个相同元素改变了原来的相对位置，因此该排序算法是**不稳定的（Unstable）**。

**注意：**

- 稳定性关注的是关键字相同的元素。
- 稳定性是排序算法本身的性质。
- 稳定排序不代表排序速度更快。

#### 1.3 时间复杂度（Time Complexity）

时间复杂度用于衡量排序算法执行时间随数据规模增长的变化趋势。

通常需要关注三种情况：

| 类型      | 英文                           | 含义                 |
| ------- | ---------------------------- | ------------------ |
| 最好时间复杂度 | Best-case Time Complexity    | 输入数据处于最有利情况时的时间复杂度 |
| 平均时间复杂度 | Average-case Time Complexity | 一般情况下的时间复杂度        |
| 最坏时间复杂度 | Worst-case Time Complexity   | 输入数据处于最不利情况时的时间复杂度 |

常见时间复杂度：

| 时间复杂度      | 含义     |
| ---------- | ------ |
| O(1)       | 常数时间   |
| O(log n)   | 对数时间   |
| O(n)       | 线性时间   |
| O(n log n) | 线性对数时间 |
| O(n²)      | 平方时间   |

其中，n 表示待排序元素的数量。

#### 1.4 空间复杂度（Space Complexity）

空间复杂度用于衡量算法执行过程中额外需要的存储空间。

通常讨论排序算法时，关注的是**辅助空间复杂度（Auxiliary Space Complexity）**，即排序过程中额外使用的空间，不包含原始输入数组。

例如：

- 直接在原数组中交换元素，辅助空间通常为 O(1)。
- 归并排序需要额外创建数组，辅助空间通常为 O(n)。

#### 1.5 原地排序（In-place Sorting）

原地排序是指主要在原始数组上进行排序，只使用常数级别的额外空间。

例如：

- 冒泡排序
- 直接插入排序
- 简单选择排序
- 堆排序

注意：快速排序虽然通常在原数组上进行划分，但递归调用需要使用栈空间，因此其辅助空间复杂度并不是严格的 O(1)。

### 2. 排序算法的分类

按照排序过程中采用的基本思想，可以将常见排序算法分为以下几类：

#### 2.1 插入排序（Insertion Sort）

核心思想：将未排序元素插入到已经有序的部分。

主要包括：

- 直接插入排序（Straight Insertion Sort）
- 折半插入排序（Binary Insertion Sort）
- 希尔排序（Shell Sort）

#### 2.2 交换排序（Exchange Sort）

核心思想：通过比较元素之间的大小关系，并交换元素的位置，使数据逐渐有序。

主要包括：

- 冒泡排序（Bubble Sort）
- 快速排序（Quick Sort）

#### 2.3 选择排序（Selection Sort）

核心思想：每次从未排序部分中选择最小或最大的元素，放到正确的位置。

主要包括：

- 简单选择排序（Simple Selection Sort）
- 堆排序（Heap Sort）

#### 2.4 归并排序（Merge Sort）

核心思想：使用分治思想，将数据拆分成更小的部分，分别排序后再合并。

### 3. 插入排序（Insertion Sort）

插入排序的基本思想是：

**将待排序的数据分成有序部分和无序部分，每次从无序部分中取出一个元素，插入到有序部分的正确位置。**

#### 3.1 直接插入排序（Straight Insertion Sort）

##### （1）基本思想

直接插入排序是最基本的插入排序算法。

具体过程：

1. 将第一个元素视为已经有序。
2. 从第二个元素开始，依次取出未排序元素。
3. 将当前元素与前面已经有序的元素进行比较。
4. 将比当前元素大的元素向后移动。
5. 找到正确位置后，将当前元素插入进去。
6. 重复上述过程，直到所有元素有序。

##### （2）排序过程

原始数组：

```text
[5, 3, 4, 1]
```

第一轮：第一个元素 5 默认有序。

```text
[5 | 3, 4, 1]
```

取出 3，与 5 比较，将 5 向后移动，再插入 3。

```text
[3, 5 | 4, 1]
```

第二轮：取出 4。

因为 4 小于 5、大于 3，因此插入到 3 和 5 之间。

```text
[3, 4, 5 | 1]
```

第三轮：取出 1。

因为 1 比前面的元素都小，将 3、4、5 依次向后移动。

```text
[1, 3, 4, 5]
```

最终完成排序。

##### （3）核心操作

直接插入排序主要包含两个操作：

- 比较（Comparison）：比较当前待插入元素与有序部分中的元素。
- 移动（Shifting）：将有序部分中比当前元素大的元素向后移动，为当前元素腾出位置。

注意：直接插入排序不是简单地不断交换相邻元素，而是通过移动元素完成插入。

##### （4）时间复杂度

| 情况   | 时间复杂度 | 原因                  |
| ---- | ----- | ------------------- |
| 最好情况 | O(n)  | 原数组已经有序，只需要进行一次线性遍历 |
| 平均情况 | O(n²) | 平均需要进行多次比较和移动       |
| 最坏情况 | O(n²) | 原数组完全逆序，需要大量比较和移动   |

##### （5）空间复杂度与稳定性

| 指标      | 结果         |
| ------- | ---------- |
| 辅助空间复杂度 | O(1)       |
| 稳定性     | 稳定（Stable） |

为什么稳定？

因为插入时只将比当前元素大的元素向后移动，相等元素不会改变相对位置。

##### （6）特点总结

- 实现简单，容易理解。
- 适合数据量较小的情况。
- 对于基本有序的数据，效率较高。
- 是一种稳定的排序算法。
- 最坏和平均时间复杂度为 O(n²)。

#### 3.2 折半插入排序（Binary Insertion Sort）

##### （1）基本思想

折半插入排序也叫二分插入排序，是直接插入排序的改进版本。

它主要优化的是**寻找插入位置的过程**。

- 直接插入排序：使用顺序查找（Sequential Search）。
- 折半插入排序：使用折半查找（Binary Search）。

具体过程：

1. 将数组分成有序部分和无序部分。
2. 从无序部分取出一个元素。
3. 使用二分查找，在有序部分中寻找正确的插入位置。
4. 将该位置之后的元素依次向后移动。
5. 将当前元素插入正确位置。
6. 重复上述过程。

##### （2）排序过程

原始数组：

```
[2, 4, 6, 8 | 5]
```

前面的 `[2, 4, 6, 8]` 已经有序，现在需要插入 5。

第一步：使用二分查找，比较中间元素 6。

```
5 < 6
```

因此在左半部分继续查找。

第二步：比较 4。

```
5 > 4
```

因此插入位置在 4 和 6 之间。

第三步：将 6 和 8 向后移动，将 5 插入。

```
[2, 4, 5, 6, 8]
```

##### （3）与直接插入排序的区别

| 对比       | 直接插入排序 | 折半插入排序   |
| -------- | ------ | -------- |
| 插入位置查找方式 | 顺序查找   | 折半查找     |
| 查找时间     | O(n)   | O(log n) |
| 元素移动     | 需要     | 需要       |
| 辅助空间     | O(1)   | O(1)     |
| 稳定性      | 稳定     | 稳定       |

##### （4）时间复杂度

| 情况   | 时间复杂度      | 原因             |
| ---- | ---------- | -------------- |
| 最好情况 | O(n log n) | 每次插入都需要进行折半查找  |
| 平均情况 | O(n²)      | 查找较快，但仍然需要移动元素 |
| 最坏情况 | O(n²)      | 需要移动大量元素       |

**重点：折半插入排序减少的是比较次数，并没有减少大量移动元素的操作。**

因此整体时间复杂度仍然可能达到 O(n²)。

##### （5）空间复杂度与稳定性

| 指标      | 结果         |
| ------- | ---------- |
| 辅助空间复杂度 | O(1)       |
| 稳定性     | 稳定（Stable） |

注意：折半查找确定插入位置时，应将新元素插入已有相同元素的后面，才能保持稳定性。

##### （6）特点总结

- 使用二分查找减少比较次数。
- 仍然需要移动元素。
- 平均和最坏时间复杂度仍然是 O(n²)。
- 是一种稳定的排序算法。

#### 3.3 希尔排序（Shell Sort）

##### （1）基本思想

希尔排序又称**缩小增量排序（Diminishing Increment Sort）**，是对直接插入排序的一种改进。

直接插入排序对于基本有序的数据效率较高，但对于大量无序的数据，可能需要移动很多次。

希尔排序通过设置间隔（Gap），将数组中的元素分成若干组，对每组分别进行插入排序。

然后逐渐缩小间隔，直到间隔为 1，最后进行一次直接插入排序。

核心思想：

**先让元素进行较大跨度的移动，使整个数组逐渐接近有序，最后通过直接插入排序完成整体排序。**

##### （2）排序过程

原始数组：

```
[8, 5, 3, 7, 6, 2, 1, 4]
```

假设初始间隔：

```
Gap = 4
```

按照间隔 4 分组：

```
第一组：[8, 6]
第二组：[5, 2]
第三组：[3, 1]
第四组：[7, 4]
```

对每组进行插入排序：

```
第一组：[6, 8]
第二组：[2, 5]
第三组：[1, 3]
第四组：[4, 7]
```

数组调整为：

```
[6, 2, 1, 4, 8, 5, 3, 7]
```

接下来缩小间隔：

```
Gap = 2
```

继续分组并进行插入排序。

最后：

```
Gap = 1
```

此时整个数组成为一个组，进行一次直接插入排序，完成最终排序。

##### （3）核心概念：增量（Gap）

增量（Gap）表示参与同一组排序的元素之间的距离。

例如：

```
Gap = 3
```

分组方式：

```
a[0]、a[3]、a[6]……
a[1]、a[4]、a[7]……
a[2]、a[5]、a[8]……
```

随着 Gap 不断缩小，分组数量减少，每组包含的元素逐渐增多。

最终 Gap = 1，相当于对整个数组执行直接插入排序。

##### （4）时间复杂度

希尔排序的时间复杂度与**增量序列（Gap Sequence）**&#x5BC6;切相关。

不同的增量序列会得到不同的时间复杂度，因此没有一个适用于所有实现的统一复杂度。

常见教材中的简化结论：

| 情况   | 时间复杂度                   |
| ---- | ----------------------- |
| 最好情况 | 与增量序列有关                 |
| 平均情况 | 部分教材估算为 O(n^1.3)，并非统一结论 |
| 最坏情况 | 常见简单增量序列下为 O(n²)        |

##### （5）空间复杂度与稳定性

| 指标      | 结果            |
| ------- | ------------- |
| 辅助空间复杂度 | O(1)          |
| 稳定性     | 不稳定（Unstable） |

为什么不稳定？

希尔排序允许相隔较远的元素直接交换或移动，这可能改变相同元素之间的相对顺序。

##### （6）特点总结

- 是直接插入排序的改进算法。
- 通过增量分组进行插入排序。
- 增量逐渐缩小，最后 Gap 为 1。
- 不稳定排序。
- 时间复杂度取决于增量序列。

### 4. 交换排序（Exchange Sort）

交换排序的核心思想是：

**通过比较元素之间的大小关系，并交换位置，使整个数组逐渐达到有序状态。**

主要包括：

- 冒泡排序（Bubble Sort）
- 快速排序（Quick Sort）

#### 4.1 冒泡排序（Bubble Sort）

##### （1）基本思想

冒泡排序是一种最简单的交换排序算法。

它通过比较相邻两个元素的大小，如果顺序不符合要求，就交换它们的位置。

每一轮排序结束后，当前未排序部分中的最大元素会移动到最后面。

##### （2）排序过程

原始数组：

```
[5, 3, 8, 2, 1]
```

按照从小到大排序。

第一轮：

比较相邻元素，如果前面的元素大于后面的元素，就交换。

```
[5, 3, 8, 2, 1]
[3, 5, 8, 2, 1]
[3, 5, 8, 2, 1]
[3, 5, 2, 8, 1]
[3, 5, 2, 1, 8]
```

第一轮结束，最大元素 8 已经到达最后面。

第二轮：

不再比较最后面的 8。

```
[3, 5, 2, 1 | 8]
```

经过一轮比较和交换：

```
[3, 2, 1, 5 | 8]
```

第二轮结束，第二大的元素 5 也到达正确位置。

第三轮：

```
[2, 1, 3 | 5, 8]
```

第四轮：

```
[1, 2, 3, 5, 8]
```

最终完成排序。

##### （3）优化：提前结束（Early Termination）

如果某一轮排序过程中，没有发生任何交换，说明整个数组已经有序。

此时不需要继续执行后续轮次，可以直接结束排序。

例如：

```
[1, 2, 3, 4, 5]
```

第一轮比较过程中没有发生交换，说明数组已经有序。

##### （4）时间复杂度

| 情况   | 时间复杂度 | 原因                |
| ---- | ----- | ----------------- |
| 最好情况 | O(n)  | 数组已经有序，第一轮比较后直接结束 |
| 平均情况 | O(n²) | 通常需要多轮比较和交换       |
| 最坏情况 | O(n²) | 数组完全逆序，需要大量比较和交换  |

注意：最好情况为 O(n) 的前提是使用了提前结束的优化版本。

##### （5）空间复杂度与稳定性

| 指标      | 结果         |
| ------- | ---------- |
| 辅助空间复杂度 | O(1)       |
| 稳定性     | 稳定（Stable） |

为什么稳定？

冒泡排序只在前面的元素严格大于后面的元素时才交换。

相等的元素不会因为相邻比较而交换位置。

##### （6）特点总结

- 通过比较相邻元素进行排序。
- 每一轮将当前最大元素放到未排序部分的末尾。
- 可以通过提前结束优化算法。
- 稳定排序。
- 平均和最坏时间复杂度均为 O(n²)。

#### 4.2 快速排序（Quick Sort）

##### （1）基本思想

快速排序是一种经典的交换排序算法，也是非常重要的分治算法（Divide and Conquer）。

核心思想：

**每次选择一个基准元素（Pivot），通过一轮划分，将数组分成左右两个部分，使左边元素不大于基准元素，右边元素不小于基准元素，然后递归处理左右两个部分。**

主要包含三个过程：

1. 选择基准元素（Pivot）。
2. 划分（Partition）。
3. 递归排序（Recursion）。

##### （2）排序过程

原始数组：

```
[6, 3, 8, 2, 5, 1, 7]
```

选择第一个元素 6 作为基准元素：

```
Pivot = 6
```

通过划分操作，将数组调整为：

```
[3, 2, 5, 1]  6  [8, 7]
```

此时：

- 左边元素都不大于 6。
- 右边元素都不小于 6。
- 基准元素 6 已经位于最终位置。

接下来分别对左右两部分递归执行快速排序。

最终：

```
[1, 2, 3, 5, 6, 7, 8]
```

##### （3）分治思想（Divide and Conquer）

分治通常包含三个过程：

| 过程 | 英文      | 含义            |
| -- | ------- | ------------- |
| 分解 | Divide  | 将原问题划分为较小的子问题 |
| 解决 | Conquer | 递归解决子问题       |
| 合并 | Combine | 将子问题的结果组合起来   |

快速排序有一个特点：

**它主要通过划分操作完成排序，划分完成后不需要额外的合并操作。**

##### （4）时间复杂度

| 情况   | 时间复杂度      | 原因           |
| ---- | ---------- | ------------ |
| 最好情况 | O(n log n) | 每次划分都比较均匀    |
| 平均情况 | O(n log n) | 大多数情况下划分相对均衡 |
| 最坏情况 | O(n²)      | 每次划分都极不均衡    |

为什么最坏情况是 O(n²)？

假设数组已经有序，而且每次都选择第一个元素作为基准元素。

每次划分可能得到：

```
1 个元素 + n-1 个元素
```

递归过程：

```
T(n) = T(n-1) + O(n)
```

最终得到 O(n²)。

##### （5）空间复杂度

快速排序通常使用递归实现，因此需要考虑递归调用栈（Recursion Stack）的空间。

| 情况   | 空间复杂度    |
| ---- | -------- |
| 平均情况 | O(log n) |
| 最坏情况 | O(n)     |

原因：

| 平均情况下，递归深度约为                      | English    |
| --------------------------------- | ---------- |
| Object-Oriented Programming (OOP) | 面向对象编程     |
| Abstract Class                    | 抽象类        |
| Abstract Method                   | 抽象方法       |
| Concrete Method                   | 具体方法       |
| Interface                         | 接口         |
| Implementation                    | 实现         |
| Implement an Interface            | 实现接口       |
| Inheritance                       | 继承         |
| Multiple Inheritance              | 多重继承       |
| Single Inheritance                | 单继承        |
| Multiple Interfaces               | 多个接口       |
| Static Keyword                    | static 关键字 |
| Static Variable                   | 静态变量       |
| Class Variable                    | 类变量        |
| Instance Variable                 | 实例变量       |
| Static Method                     | 静态方法       |
| Instance Method                   | 实例方法       |
| Static Block                      | 静态代码块      |
| Method Overriding                 | 方法重写       |
| Method Hiding                     | 方法隐藏       |
| Runtime Polymorphism              | 运行时多态      |
| Dynamic Binding                   | 动态绑定       |
| Static Binding                    | 静态绑定       |
| Access Modifier                   | 访问修饰符      |
| Constructor                       | 构造方法       |
| Default Method                    | 默认方法       |
| Multiple Implementation           | 多接口实现      |

##### （2）排序过程

原始数组：

```
[5, 3, 8, 2, 1]
```

第一轮：

在整个数组中寻找最小元素 1。

将 1 与第一个元素 5 交换：

```
[1, 3, 8, 2, 5]
```

第二轮：

第一个元素已经有序，在剩余部分寻找最小元素 2。

将 2 与当前未排序部分的第一个元素 3 交换：

```
[1, 2, 8, 3, 5]
```

第三轮：

找到最小元素 3，与 8 交换：

```
[1, 2, 3, 8, 5]
```

第四轮：

找到最小元素 5，与 8 交换：

```
[1, 2, 3, 5, 8]
```

最终完成排序。

##### （3）与冒泡排序的区别

冒泡排序：

```
比较相邻元素 → 交换 → 比较相邻元素 → 交换
```

简单选择排序：

```
遍历未排序部分 → 找到最小元素 → 交换一次
```

冒泡排序通过相邻交换逐步移动最大元素，而简单选择排序是先找到最小元素，再进行交换。

##### （4）时间复杂度

| 情况   | 时间复杂度 | 原因                   |
| ---- | ----- | -------------------- |
| 最好情况 | O(n²) | 即使数组已经有序，仍然需要遍历未排序部分 |
| 平均情况 | O(n²) | 需要多轮寻找最小元素           |
| 最坏情况 | O(n²) | 仍然需要大量比较             |

注意：

即使原数组已经有序，简单选择排序也需要寻找每一轮未排序部分中的最小元素，因此最好时间复杂度仍然是 O(n²)。

##### （5）空间复杂度与稳定性

| 指标      | 结果            |
| ------- | ------------- |
| 辅助空间复杂度 | O(1)          |
| 稳定性     | 不稳定（Unstable） |


为什么不稳定？

因为简单选择排序可能交换距离较远的元素。

例如：

```
[5a, 5b, 1]
```

找到最小元素 1，将它与第一个元素 5a 交换：

```
[1, 5b, 5a]
```

两个相同元素 5a 和 5b 的相对位置发生改变。

##### （6）特点总结

- 每一轮选择未排序部分中的最小元素。
- 每一轮最多进行一次交换。
- 最好、平均和最坏时间复杂度都是 O(n²)。
- 辅助空间复杂度为 O(1)。
- 不稳定排序。

#### 5.2 堆排序（Heap Sort）

##### （1）基本思想

堆排序是一种基于堆（Heap）这种数据结构实现的选择排序算法。

**堆是一种特殊的完全二叉树（Complete Binary Tree）。**

堆主要分为两种：

| 类型  | 英文       | 特点                |
| --- | -------- | ----------------- |
| 大顶堆 | Max Heap | 每个父节点的值都大于或等于其子节点 |
| 小顶堆 | Min Heap | 每个父节点的值都小于或等于其子节点 |

大顶堆示例：

```
          9
        /   \
       7     8
      / \   /
     3   2 5
```

特点：

```
父节点 ≥ 左子节点
父节点 ≥ 右子节点
```

因此，大顶堆的根节点一定是整个堆中的最大元素。

小顶堆示例：

```
          1
        /   \
       3     2
      / \   /
     8   5 6
```

特点：

```
父节点 ≤ 左子节点
父节点 ≤ 右子节点
```

因此，小顶堆的根节点一定是整个堆中的最小元素。

##### （2）堆排序的基本过程

如果需要按照从小到大的顺序排序，通常使用**大顶堆（Max Heap）**。

基本步骤：

1. 将原始数组构建成一个大顶堆。
2. 此时堆顶元素就是整个堆中的最大元素。
3. 将堆顶元素与当前堆的最后一个元素交换。
4. 将最后一个元素移出当前堆的范围，它已经处于最终位置。
5. 对剩余元素重新进行调整，使其继续满足大顶堆的性质。
6. 重复上述过程，直到所有元素有序。

##### （3）排序过程

原始数据：

```
[4, 6, 8, 5, 2]
```

第一步：建立大顶堆。

```
[8, 6, 4, 5, 2]
```

对应的堆结构：

```
          8
        /   \
       6     4
      / \
     5   2
```

第二步：交换堆顶元素和最后一个元素。

```
[2, 6, 4, 5 | 8]
```

最大元素 8 已经处于最终位置。

第三步：重新调整剩余部分。

```
[6, 5, 4, 2 | 8]
```

第四步：继续交换和调整。

```
[2, 5, 4 | 6, 8]
```

重新调整：

```
[5, 2, 4 | 6, 8]
```

然后继续：

```
[4, 2 | 5, 6, 8]
```

最终：

```
[2, 4, 5, 6, 8]
```

##### （4）重要概念：堆调整（Heapify）

堆调整（Heapify）是堆排序中的重要操作。

作用：

**调整某个节点及其子树，使其重新满足大顶堆或小顶堆的性质。**

例如，大顶堆中，某个节点比它的子节点小，就需要将它与较大的子节点交换，然后继续向下调整。

需要掌握：

- 构建大顶堆（Build Max Heap）。
- 堆调整（Heapify）。
- 堆顶元素（Root）。
- 完全二叉树（Complete Binary Tree）。

##### （5）数组表示堆

堆通常可以使用数组进行存储。

对于下标从 0 开始的数组，假设某个节点的下标为 i：

| 节点  | 下标           |
| --- | ------------ |
| 父节点 | (i - 1) // 2 |
| 左孩子 | 2 * i + 1    |
| 右孩子 | 2 * i + 2    |

例如：

```
数组：[8, 6, 4, 5, 2]

          8 (0)
        /       \
      6 (1)     4 (2)
      / \
   5 (3) 2 (4)
```

##### （6）时间复杂度

| 情况   | 时间复杂度      |
| ---- | ---------- |
| 最好情况 | O(n log n) |
| 平均情况 | O(n log n) |
| 最坏情况 | O(n log n) |

堆排序主要包含两个过程：

① 建立初始堆：

```
O(n)
```

② 反复取出堆顶元素：

每次取出最大元素后，需要重新调整堆，调整一次的时间复杂度为：

```
O(log n)
```

总共需要进行约 n 次调整，因此整体时间复杂度为：

```
O(n log n)
```

注意：建立堆的时间复杂度是 O(n)，而不是 O(n log n)。

##### （7）空间复杂度与稳定性

| 指标      | 结果            |
| ------- | ------------- |
| 辅助空间复杂度 | O(1)          |
| 稳定性     | 不稳定（Unstable） |

这里的 O(1) 按照常见的迭代式堆调整实现计算。

为什么不稳定？

因为堆排序过程中，堆顶元素需要与堆尾元素交换，可能改变相同元素之间的相对位置。

##### （8）特点总结

- 基于完全二叉树实现。
- 大顶堆的根节点是最大元素。
- 小顶堆的根节点是最小元素。
- 使用大顶堆可以实现升序排序。
- 使用小顶堆可以实现降序排序。
- 时间复杂度最好、平均、最坏都是 O(n log n)。
- 辅助空间复杂度为 O(1)。
- 不稳定排序。

### 6. 归并排序（Merge Sort）

#### 6.1 基本思想

归并排序是一种典型的分治算法（Divide and Conquer）。

核心思想：

**先将数组不断拆分成更小的部分，直到每个部分只剩下一个元素，然后将这些有序部分逐步合并，最终得到完整的有序数组。**

归并排序主要分为两个过程：

1. 拆分（Split）。
2. 合并（Merge）。

其中，合并是归并排序最重要的操作。

#### 6.2 排序过程

原始数组：

```
[8, 4, 5, 7, 1, 3, 6, 2]
```

##### 第一步：不断拆分

先将数组分成左右两个部分：

```
[8, 4, 5, 7]    [1, 3, 6, 2]
```

继续拆分：

```
[8, 4] [5, 7]    [1, 3] [6, 2]
```

继续拆分：

```
[8] [4] [5] [7] [1] [3] [6] [2]
```

直到每个部分只剩下一个元素。

##### 第二步：合并

将相邻的单个元素进行合并，并按照从小到大的顺序排列。

```
[8] [4] → [4, 8]

[5] [7] → [5, 7]

[1] [3] → [1, 3]

[6] [2] → [2, 6]
```

继续合并：

```
[4, 8] [5, 7]
      ↓
[4, 5, 7, 8]
```

```
[1, 3] [2, 6]
      ↓
[1, 2, 3, 6]
```

最后合并两个较大的有序部分：

```
[4, 5, 7, 8] [1, 2, 3, 6]
```

得到：

```
[1, 2, 3, 4, 5, 6, 7, 8]
```

最终完成排序。

#### 6.3 核心操作：合并（Merge）

归并排序最重要的过程就是将两个已经有序的数组合并成一个新的有序数组。

例如：

```
A = [2, 5, 8]
B = [1, 4, 6]
```

比较两个数组当前尚未处理的第一个元素：

第一步：

比较 2 和 1，选择较小的 1。

```
结果：[1]
```

第二步：

比较 2 和 4，选择较小的 2。

```
结果：[1, 2]
```

第三步：

比较 5 和 4，选择较小的 4。

```
结果：[1, 2, 4]
```

继续比较，最终得到：

```
[1, 2, 4, 5, 6, 8]
```

注意：

**归并操作要求参与合并的两个部分本身已经有序。**

#### 6.4 时间复杂度

| 情况   | 时间复杂度      |
| ---- | ---------- |
| 最好情况 | O(n log n) |
| 平均情况 | O(n log n) |
| 最坏情况 | O(n log n) |

为什么归并排序的时间复杂度是 O(n log n)？

① 拆分层数：

每次将数组拆分成两部分，数组规模每次减半。

因此拆分层数约为：

```
log₂ n
```

② 每一层合并的工作量：

每一层都需要处理全部 n 个元素，因此每一层的合并总工作量为：

```
O(n)
```

因此：

```
O(n) × O(log n) = O(n log n)
```

#### 6.5 空间复杂度与稳定性

| 指标      | 结果         |
| ------- | ---------- |
| 辅助空间复杂度 | O(n)       |
| 稳定性     | 稳定（Stable） |

为什么需要 O(n) 的辅助空间？

因为在合并两个有序数组时，通常需要额外创建临时数组（Temporary Array），用于保存合并后的结果。

为什么稳定？

因为在合并时，如果左右两部分当前元素相等，可以优先选择左边的元素。

这样就能保持相同元素之间的原始相对顺序。

#### 6.6 特点总结

- 是典型的分治算法。
- 先拆分，再合并。
- 需要两个已经有序的部分才能进行归并。
- 最好、平均和最坏时间复杂度都是 O(n log n)。
- 辅助空间复杂度为 O(n)。
- 稳定排序。
- 适合处理较大规模的数据。

### 7. 八种常见排序算法对比

#### 7.1 时间复杂度、空间复杂度和稳定性

| 排序类别 | 排序算法   | 最好时间复杂度    | 平均时间复杂度    | 最坏时间复杂度    | 辅助空间复杂度             | 稳定性 |
| ---- | ------ | ---------- | ---------- | ---------- | ------------------- | --- |
| 插入排序 | 直接插入排序 | O(n)       | O(n²)      | O(n²)      | O(1)                | 稳定  |
| 插入排序 | 折半插入排序 | O(n log n) | O(n²)      | O(n²)      | O(1)                | 稳定  |
| 插入排序 | 希尔排序   | 依赖增量序列     | 依赖增量序列     | 依赖增量序列     | O(1)                | 不稳定 |
| 交换排序 | 冒泡排序   | O(n)       | O(n²)      | O(n²)      | O(1)                | 稳定  |
| 交换排序 | 快速排序   | O(n log n) | O(n log n) | O(n²)      | 平均 O(log n)，最坏 O(n) | 不稳定 |
| 选择排序 | 简单选择排序 | O(n²)      | O(n²)      | O(n²)      | O(1)                | 不稳定 |
| 选择排序 | 堆排序    | O(n log n) | O(n log n) | O(n log n) | O(1)                | 不稳定 |
| 归并排序 | 归并排序   | O(n log n) | O(n log n) | O(n log n) | O(n)                | 稳定  |

**注意：**

1. 折半插入排序使用二分查找减少比较次数，但元素移动仍然可能需要 O(n²)。
2. 希尔排序的复杂度与增量序列有关，不存在适用于所有增量序列的统一复杂度。
3. 快速排序的空间复杂度需要考虑递归栈，平均为 O(log n)，最坏为 O(n)。
4. 冒泡排序最好情况为 O(n)，前提是使用提前结束优化。
5. 堆排序的 O(1) 辅助空间按照常见的迭代式堆调整实现计算。

#### 7.2 稳定性总结

##### 稳定排序（Stable Sort）

- 直接插入排序
- 折半插入排序
- 冒泡排序
- 归并排序

##### 不稳定排序（Unstable Sort）

- 希尔排序
- 快速排序
- 简单选择排序
- 堆排序

**记忆方法：**

稳定的四种：

```
直接插入、折半插入、冒泡、归并
```

其余四种不稳定：

```
希尔、快速、简单选择、堆
```

#### 7.3 各种排序算法的核心思想对比

| 排序算法   | 核心思想             | 关键词     |
| ------ | ---------------- | ------- |
| 直接插入排序 | 将元素插入前面已经有序的部分   | 插入      |
| 折半插入排序 | 使用二分查找确定插入位置     | 二分查找    |
| 希尔排序   | 按增量分组，对各组进行插入排序  | 缩小增量    |
| 冒泡排序   | 比较相邻元素，满足条件时交换   | 相邻交换    |
| 快速排序   | 选择基准元素，划分左右部分    | 基准、分治   |
| 简单选择排序 | 从未排序部分选择最小元素     | 选择最小值   |
| 堆排序    | 利用堆顶元素最大或最小的特点排序 | 大顶堆、小顶堆 |
| 归并排序   | 不断拆分，再将有序部分合并    | 分治、合并   |

### 8. 排序算法常见考点总结

#### 8.1 哪些排序算法的时间复杂度是 O(n²)？

常见的平方级排序算法：

- 直接插入排序：平均、最坏 O(n²)。
- 折半插入排序：平均、最坏 O(n²)。
- 希尔排序：部分增量序列下最坏 O(n²)。
- 冒泡排序：平均、最坏 O(n²)。
- 简单选择排序：最好、平均、最坏均为 O(n²)。
- 快速排序：最坏 O(n²)。

#### 8.2 哪些排序算法的时间复杂度是 O(n log n)？

- 快速排序：最好、平均 O(n log n)。
- 堆排序：最好、平均、最坏 O(n log n)。
- 归并排序：最好、平均、最坏 O(n log n)。

#### 8.3 哪些排序算法的空间复杂度是 O(1)？

按照常见的迭代式原地排序实现：

- 直接插入排序
- 折半插入排序
- 希尔排序
- 冒泡排序
- 简单选择排序
- 堆排序

注意：

- 快速排序通常需要递归栈空间。
- 归并排序通常需要额外数组。

#### 8.4 哪些排序算法适合处理基本有序的数据？

**直接插入排序和优化后的冒泡排序。**

原因：

- 直接插入排序在数据基本有序时，需要移动的元素较少。
- 冒泡排序在数据已经有序时，可以通过提前结束机制减少不必要的比较。

#### 8.5 哪些排序算法采用分治思想？

主要包括：

- 快速排序（Quick Sort）
- 归并排序（Merge Sort）

二者的区别：

| 对比      | 快速排序          | 归并排序                    |   |
| ------- | ------------- | ----------------------- | - |
| 核心思想    | 分区（Partition） | 分割和合并（Divide and Merge） |   |
| 主要操作    | 选择基准，划分左右部分   | 拆分数组，再合并有序部分            |   |
| 最好时间复杂度 | O(n log n)    | O(n log n)              |   |
| 平均时间复杂度 | O(n log n)    | O(n log n)              |   |
| 最坏时间复杂度 | O(n²)         | O(n log n)              |   |
| 辅助空间复杂度 | 平均 O(log n)   | O(n)                    |   |
| 稳定性     | 不稳定           | 稳定                      |   |

#### 8.6 哪些排序算法每一轮选择最大或最小元素？

| 算法     | 每一轮主要操作              |
| ------ | -------------------- |
| 冒泡排序   | 将当前未排序部分的最大元素移动到末尾   |
| 简单选择排序 | 找到当前未排序部分的最小元素，放到最前面 |
| 堆排序    | 取出堆顶最大元素，放到末尾        |

### 9. 真题视角：按条件筛选排序算法

**题目方向：** 27fall 的排序题不直接问「快排复杂度是多少」，而是给**若干条件**让你筛。条件一多，凭印象就容易错。

**知识点：三条件筛选法**

#### 9.1 三个筛选键

```text
Step 1  题目有没有提「稳定 / stable」？
          有 → 候选收缩到：冒泡、插入、归并、计数、基数、桶（口诀「插冒归基」）
          没有 → 跳过
Step 2  有没有提「最坏 O(n log n)」？
          有 → 候选里只剩：归并、堆排（再加上非比较排序）
Step 3  有没有提「原地 / in-place / O(1) 额外空间」？
          有 → 归并出局（它要 O(n) 辅助数组），只剩堆排
```

#### 9.2 五种组合问法与唯一答案

| 题目条件                           | 唯一答案                   | 被淘汰的原因                 |
| ------------------------------ | ---------------------- | ---------------------- |
| stable                         | 冒泡 / 插入 / 归并（看选项里出现哪个） | 快排、堆排、选择、希尔**都不稳定**    |
| stable **且** worst O(n log n)  | **归并排序**               | 冒泡、插入最坏 O(n²)          |
| worst O(n log n) **且** O(1) 空间 | **堆排序**                | 归并要 O(n) 空间；快排最坏 O(n²) |
| worst O(n log n)（不限稳定与空间）      | 归并 / 堆排                | 快排最坏退化到 O(n²)          |
| 已基本有序时最快                       | **插入排序**（O(n)）         | 快排此时反而退化到 O(n²)        |

#### 9.3 每个算法「为什么不稳定」

| 算法     | 不稳定的根源                           |
| ------ | -------------------------------- |
| 快速排序   | partition 的交换是**远距离**的，相等元素会被跨过去 |
| 堆排序    | 「堆顶换到末尾」这个操作把相等元素的相对位置打乱         |
| 简单选择排序 | 每轮把最小值**换到前面**，一次远距离交换跨过多个相等元素   |
| 希尔排序   | 分组插入，**跨间隔**移动，相等元素可能被换组         |

**记忆锚点：** 稳定的都是「**相邻比较、相邻移动**」的（冒泡、插入），或者「**另开空间按顺序搬**」的（归并、基数）。一旦出现「远距离交换」，就不稳定。

#### 9.4 英文例题

Which of the following sorting algorithms is **stable**?

A. Quick Sort

B. Heap Sort

C. Selection Sort

D. Shell Sort

E. Bubble Sort

**答案：E**

**解析：** 冒泡只在相邻元素之间交换，相等元素不跨越 → 稳定。快排（分区远距离交换）、堆排（堆顶换末尾）、选择（远距离交换）、希尔（跨间隔分组）都不稳定。

Which of the following sorting algorithms is **stable** and guarantees O(n log n) time in the **worst case**?

A. Quick Sort

B. Heap Sort

C. Merge Sort

D. Selection Sort

E. Shell Sort

**答案：C**

**解析：** 两个条件同时满足的只有归并排序（最好/平均/最坏都是 O(n log n)，且稳定），代价是 O(n) 辅助空间。堆排最坏也是 O(n log n) 且原地，但**不稳定**；快排最坏退化到 O(n²)。

**所属知识点：** 数据结构与算法 / 排序 / 稳定性与复杂度条件组合。

### 10. 排序算法的识别与三个易错细节

**题目方向：** 给一段文字描述，问这是哪种排序；或者给出一个「看起来对」的结论让你判断。

**知识点：排序算法识别**

#### 10.1 描述 → 算法指纹

| 描述里出现                                                                   | 算法     |
| ----------------------------------------------------------------------- | ------ |
| pick a **pivot**, **partition**, recurse on both sides                  | 快速排序   |
| split in half, sort each half, **merge**                                | 归并排序   |
| build a **heap**, repeatedly **sift down / heapify**                    | 堆排序    |
| repeatedly pick the **smallest**, swap to the front                     | 简单选择排序 |
| insert each element into its correct place in the sorted prefix         | 直接插入排序 |
| swap **adjacent** elements if out of order                              | 冒泡排序   |
| group by a **gap**, do insertion sort within each group, shrink the gap | 希尔排序   |

#### 10.2 快排与归并的对称性

| 对比        | 快速排序                        | 归并排序                       |
| --------- | --------------------------- | -------------------------- |
| 切分方式      | **按值切**（比 pivot 小的在左）       | **按位置切**（对半）               |
| 难点在哪      | **分区难**（partition 是核心）      | **合并难**（merge 要 O(n) 辅助数组） |
| 递归后是否还要合并 | **不需要**（分区完成时 pivot 已在最终位置） | **需要**（切完毫无顺序）             |
| 最坏        | O(n²)（已有序 / 大量重复）           | O(n log n)                 |

#### 10.3 三个易错细节

（1）快排最坏 O(n²) 的触发条件

已排序（正序或逆序）+ 固定取首元素为枢轴 → 每次分区都退化成「一边空、一边 n−1」。随机化选枢轴或三数取中可以避免（期望仍是 O(n log n)）。

（2）归并的空间是 O(n)，不是 O(1)

合并两个有序段必须借一份临时数组，所以归并**不是原地排序**。这也是「最坏 O(n log n) 且原地」只能选堆排的原因。

（3）希尔排序的复杂度取决于增量序列

希尔排序的复杂度不是一个确定值，取决于 gap 序列（Shell 原序列 O(n²)，Hibbard 序列 O(n^1.5)，Sedgewick 序列更快）。题目若问「希尔的复杂度」，正确选项通常是「取决于增量序列」或「介于 O(n log n) 与 O(n²) 之间」。


**英文例题：**

An algorithm splits the array in half, recursively sorts each half, then merges the two sorted halves using an auxiliary array. Which algorithm is it?

A. Quick Sort

B. Merge Sort

C. Heap Sort

D. Insertion Sort

E. Selection Sort

**答案：B**

**解析：** 「按位置对半切 + 递归 + 用辅助数组合并」三个特征同时指向归并排序。快排是按值与 pivot 比较来分区，且分区后不需要合并。

**所属知识点：** 数据结构与算法 / 排序 / 算法识别。

### 0. 三个必须先在脑子里建立的概念

图论这一节的很多混乱，不是算法本身难，而是三个基础概念没说清楚就开始讲算法。先花三分钟把下面三条看懂，后面的内容会顺很多。

#### 0.1 记号约定

| 记号 | 含义 |
|---|---|
| V | 顶点（vertex）个数，也常直接写 V 表示顶点集合 |
| E | 边（edge）个数 |
| w(u,v) | 边 u→v 的权值（weight）；无权图可以认为每条边权都是 1 |
| dist[v] | **当前**从源点到 v 的最短距离估计值（注意是「估计」，见 0.2） |
| 邻接表 | 每个点存一张「我能到谁」的清单，空间 O(V+E) |
| 邻接矩阵 | V × V 的表，空间 O(V²)，适合稠密图 |

#### 0.2 `dist[v]` 是「估计值」，不是「最终答案」

这是最容易误解的一点。所有最短路算法（BFS 除外）都是这样运作的：

1. 一开始什么都不知道，所以 `dist[源点] = 0`，其余全是 ∞；
2. 每发现一条更好的路，就把 `dist` **往下调**（调小）；
3. 当算法结束时，`dist` 才变成真正的答案。

所以 `dist` 在过程中会**反复变小**。看到「某个点的距离从 4 变成 3」不要觉得是算错了——那正是算法在起作用。

#### 0.3 「松弛（relaxation）」到底在干什么

松弛这个名字很唬人，其实就是一句大白话：

> 我本来认为从源点到 v 要走 `dist[v]`；现在发现可以先到 u（花 `dist[u]`），再从 u 走一条边 w(u,v) 到 v。如果这样走更近，就改主意。

```text
if dist[u] + w(u, v) < dist[v]:     // 绕道更近
    dist[v] = dist[u] + w(u, v)     // 改主意
```

举个数：`dist[u] = 3`，边 u→v 权为 5，而当前 `dist[v] = 10`。
那么 3+5=8 < 10，于是把 `dist[v]` 改成 8。**这一次操作就叫「对边 (u,v) 做了一次松弛」。**

**所有最短路算法的区别，只是「按什么顺序去做松弛」：**

| 算法 | 松弛顺序 |
|---|---|
| BFS | 按「层」——先处理离源点边数少的 |
| Dijkstra | 按「当前 dist 最小的点」——贪心 |
| Bellman-Ford | 把所有边**从头到尾扫一遍算一轮**，扫 V-1 轮 |
| Floyd | 按「允许使用哪些中转点」——动态规划 |

#### 0.4 贯穿全节的例图 G

后面 BFS / DFS / Dijkstra / Prim / Kruskal / Floyd 全部用**这一张图**，这样你不用每次重新理解图的结构。

```text
            S
         4 / \ 2
          /   \
         A-----B
         |  1  |
       5 |     | 7
         |     |
         C-----D
             3
```

顶点：V={S,A,B,C,D}，共 5 个；边共 6 条（无向）：

| 边 | 权 |
|---|---|
| S–A | 4 |
| S–B | 2 |
| A–B | 1 |
| A–C | 5 |
| B–D | 7 |
| C–D | 3 |

**先自己看一眼**：从 S 到 D，直觉上最省的走法是 S→B→D = 2+7=9；走 S→A→C→D = 4+5+3=12，更贵。记住这个直觉，后面用来验算。

### 1. BFS（Breadth-First Search，广度优先搜索）

**解决什么问题**：无权图（或所有边权相等）中，从源点到其他每个点的**最少边数**；以及「两个点连通不连通」。

#### 1.1 一句话说清它在干嘛

> 像往水里丢石头，波纹**一圈一圈往外扩**。先看所有距离 1 的点，再看所有距离 2 的点……

「一圈一圈」是 BFS 的灵魂。它不是「随便找个点往下走」，而是**严格按距离排队**。

#### 1.2 为什么必须用队列（Queue）

队列是**先进先出（FIFO）**：先被发现的点，先被处理。

假设源点 S 在第 0 层，S 的邻居在第 1 层。S 把邻居全部塞进队列；由于 FIFO，这**一整批第 1 层的点会全部排在**它们各自的邻居（第 2 层）**前面**被处理。于是层与层之间不会交叉——这就是「逐层」的机械保证。

如果换成栈（LIFO），最后塞进去的点会先被处理，那就会沿着一条路猛冲到底——那是 DFS。

#### 1.3 在例图 G 上手动走一遍（从 S 出发）

```text
队列 Queue = [S]        visited = {S}

Step 1  弹出 S        → 邻居 A、B 没访问过 → 入队
        Queue = [A, B]  visited = {S, A, B}
Step 2  弹出 A        → 邻居 S(已访问)、B(已访问)、C(新) → C 入队
        Queue = [B, C]  visited = {S, A, B, C}
Step 3  弹出 B        → 邻居 S、A(已访问)、D(新) → D 入队
        Queue = [C, D]  visited = {S, A, B, C, D}
Step 4  弹出 C        → 邻居 A、D 都已访问 → 无事发生
        Queue = [D]
Step 5  弹出 D        → 全访问过 → 结束
```

出队顺序：**S, A, B, C, D**。
BFS 树（每个点记录「我是从谁那儿第一次被发现的」）：

```text
        S
       / \
      A   B
      |   |
      C   D
```

注意：图中 A–B、C–D 这两条边**没有进 BFS 树**，因为 B 被 S 先发现了（距离 1），A–B 只是让两个已在同层/相邻层的点连了一下，不影响距离。

**层号 = 距离**：S=0，A=1，B=1，C=2，D=2。

#### 1.4 为什么 BFS 给出的就是「最少边数」

因为队列保证了「距离 k 的点全部处理完之前，距离 k+1 的点一个都不会被处理」。

于是任何点 v **第一次**被访问时，一定是从某个距离 d 的点扩展出来的，所以它的距离是 d+1，而这是「能到达 v 的最小层数」——因为更小层数的点早就处理完了，那时候都没能到 v。

这就是**「第一次见就是最短」**。DFS 没有这个性质：DFS 可能先沿着一条绕远的路径摸到 v，之后再也没机会改了。

#### 1.5 复杂度

每个顶点入队一次、出队一次（O(V)），每条边被检查一到两次（O(E)）。总共 **O(V+E)**。
用邻接矩阵实现则是 O(V²)，因为每个点都要扫一整行。

#### 1.6 反过来看：BFS 什么时候会出错

- **边权不全相等时，BFS 直接失效。** 它只数边数，不看权值。
  例：S→D 一条边权 100，S→A→B→D 三条边权各为 1。BFS 会说「S 到 D 距离 1」，但真正的代价最小路径是 3 条边、总权 3。这时候要用 Dijkstra。
- 边权**全相等**时，BFS 就等价于「退化的 Dijkstra」，因为此时「边数最少」= 「权值和最小」。

#### 1.7 BFS 与 DFS 的区别

| 对比 | BFS | DFS |
|---|---|---|
| 英文全称 | Breadth-First Search | Depth-First Search |
| 中文 | 广度优先搜索 | 深度优先搜索 |
| 核心数据结构 | **Queue（队列）** | **Stack / 递归** |
| 搜索方式 | 一圈一圈往外扩（逐层） | 一条路走到黑，走不通再回头 |
| 无权图最短路径 | **保证最短** | 不保证 |
| 空间开销 | O(V)（最坏要存一整层） | O(h)（只存当前这条路径，h 为最大深度） |
| 典型用途 | 最短步数、层序遍历、连通性 | 连通性、拓扑排序、找环、回溯 |

**需要记住：**

BFS uses a **queue** and is suitable for finding the shortest path in an **unweighted** graph.

#### 1.8 英文例题

In a graph where **every edge has the same weight**, which algorithm computes the minimum number of edges from a source vertex to all other vertices in O(V+E) time using a FIFO queue?

A. Depth-First Search
B. Breadth-First Search
C. Bellman-Ford
D. Kruskal's algorithm
E. Floyd-Warshall

**答案：B**

**解析：** 三个线索同时指向 BFS：① FIFO queue；② O(V+E)；③ 边权相同（即「边数最少」等价于「代价最小」）。DFS 用的是栈、且不保证最短；Bellman-Ford 是 O(V·E) 且为带权图设计；Kruskal 求最小生成树，与单源最短路无关；Floyd 是 O(V³) 全源最短路。

**所属知识点：** 数据结构与算法 / 图论 / BFS 与无权图最短路。

### 2. DFS（Depth-First Search，深度优先搜索）

**解决什么问题**：连通性判断、找环、拓扑排序、以及所有「回溯」类问题（全排列、N 皇后、数独、迷宫）。

#### 2.1 一句话说清它在干嘛

> 沿着一条路一直往前走，**撞墙了才回头**，回到最近的一个「还有岔路没走」的路口，换一条继续。

#### 2.2 为什么用栈（或用递归）

递归函数调用本身就是栈：`dfs(u)` 里调用 `dfs(v)`，`dfs(u)` 的现场被压在栈底，等 `dfs(v)` 全部返回后才继续。所以「递归实现 DFS」和「显式用 Stack 实现 DFS」是同一件事，只是写法不同。

#### 2.3 在例图 G 上手动走一遍（从 S 出发，邻居按字母序）

```text
dfs(S)   → 标记 S
  dfs(A) → 标记 A
    dfs(B) → 标记 B            （S 已标记，跳过；A 已标记，跳过）
      dfs(D) → 标记 D          （B 已标记，跳过）
        dfs(C) → 标记 C        （D 已标记；A 已标记，跳过）
        C 无新邻居 → 返回
      D 无新邻居 → 返回
    B 无新邻居 → 返回
  A 的 C 已标记 → 返回
S 的 B 已标记 → 返回
```

访问顺序：**S, A, B, D, C**。
对比 BFS 的 S, A, B, C, D：同为「S A B」开头，之后 BFS 走「按层」去 C，DFS 走「按深度」去 D。**这就是两者最直观的差别。**

#### 2.4 DFS 的三种用途，分别记清楚

**（1）连通性**：从 S 出发 DFS 一遍，能标记到的点就是与 S 连通的。O(V+E)。

**（2）有向图找环——三色标记法（这个必须会）**

给每个点三种状态：

| 颜色 | 含义 |
|---|---|
| 白（white） | 还没访问过 |
| 灰（gray） | **正在**它的递归栈里（我还在处理它，或者它的后代） |
| 黑（black） | 它和它的所有后代都处理完了 |

规则：DFS 过程中，如果从 u 出发遇到一个**灰色**的邻居 v，说明 v 是 u 的「祖先」，形成**回边（back edge）**，即存在环。

为什么灰=环：灰色意味着「v 还没从栈里出来」，也就是「v → … → u 这条祖先链还在。现在又发现 u → v，于是 v → … → u → v 闭环了。

反例体会：图 A→B, B→C, C→A。走到 C 时发现邻居 A 是灰色 → 有环。
而如果是 A→B, A→C, B→D, C→D（菱形，无环），走到 D 的第二次时 D 已经是**黑色**，不是灰色，所以不报环。**「黑色不算环」这一点是很多人做错的地方。**

**（3）拓扑排序**：见 §7.3，DFS 的后序取逆序。

#### 2.5 复杂度与空间

时间 O(V+E)（邻接表）。空间 O(h)，h 是搜索树的最大深度——因为只需要压住当前这条路径，不需要像 BFS 那样存一整层。

#### 2.6 英文例题

Which traversal detects a cycle in a **directed** graph by checking whether the search reaches a vertex that is still on the current recursion stack?

A. Breadth-First Search
B. Depth-First Search
C. Dijkstra's algorithm
D. Prim's algorithm
E. Binary search

**答案：B**

**解析：** 关键短语 `on the current recursion stack` 就是「灰色顶点」的定义，只有 DFS 有「递归栈」这个结构，BFS 只有队列、没有祖先链的概念。BFS 虽然也能判环（无向图用「遇到已访问且不是父节点」），但它判的不是「回边」。Dijkstra / Prim 与判环无关。

**所属知识点：** 数据结构与算法 / 图论 / DFS 与环检测。

### 3. Dijkstra 算法（单源最短路，边权非负）

**解决什么问题**：给定一个**所有边权 ≥ 0** 的带权图和一个源点 s，求 s 到**所有其他点**的最短距离。

这是图论里最常考、也最容易「背了不会用」的算法。下面把它拆到能自己手算的程度。

#### 3.1 核心思路：把点分成两堆

维护一个集合 S，含义是「**我已经百分之百确定它最短距离**的点」。

每轮做两件事：

1. **挑**：从「还没确定的点」里，挑 `dist` 最小的那个 u，宣布它确定（放进 S）；
2. **松**：用 u 去松弛它的所有邻居。

重复 V 轮，所有点都进 S，`dist` 就是答案。

**注意这个「确定」的语义**：一旦进 S，它的 `dist` 就**再也不改了**。这是 Dijkstra 与 Bellman-Ford 的根本区别——Bellman-Ford 是反复改到不再变为止，Dijkstra 是「认定了就不回头」。

#### 3.2 为什么用优先队列

「挑 dist 最小的点」如果每轮都线性扫一遍所有点，是 O(V)，V 轮就是 O(V²)——这叫朴素实现。
用**优先队列（最小堆）**，每次取最小是 O(log V)，一共取 V 次；每次松弛可能触发一次入堆/减键，总共 O(E) 次。所以 O((V+E)log V)。

**关键辨析**：Dijkstra 用的是**优先队列**，不是普通队列。普通队列（BFS）是「谁先被发现谁先出」，优先队列是「谁当前距离最小谁先出」。这一点是选择题的高频陷阱。

#### 3.3 在例图 G 上手动走一遍（源点 S）—— 表要会自己填

初始：`dist[S]=0`，其余 ∞。

| 轮次 | 出队并「确定」的点 | dist[S] | dist[A] | dist[B] | dist[C] | dist[D] | 本轮做了什么松弛 |
|---|---|---|---|---|---|---|---|
| 初始 | — | **0** | ∞ | ∞ | ∞ | ∞ | — |
| 1 | **S**（0） | 0 | **4** | **2** | ∞ | ∞ | S→A 得 4；S→B 得 2 |
| 2 | **B**（2） | 0 | **3** | 2 | ∞ | **9** | B→A：2+1=3<4 ⇒ A 改成 3；B→D 得 9 |
| 3 | **A**（3） | 0 | 3 | 2 | **8** | 9 | A→C 得 8（A→S、A→B 已成定局，跳过） |
| 4 | **C**（8） | 0 | 3 | 2 | 8 | 9 | C→D：8+3=11>9，**不改** |
| 5 | **D**（9） | 0 | 3 | 2 | 8 | 9 | 全部结束 |

最终：dist(S)=0, dist(B)=2, dist(A)=3, dist(C)=8, dist(D)=9。

**两个要盯住的细节：**

- 第 2 轮 `dist[A]` 从 4 **降到** 3。这就是 §0.2 说的「估计值会变小」——绕道 S→B→A（2+1=3）比直达 S→A（4）更省。
- 第 4 轮 `dist[D]` **没有被改进**（11 > 9）。松弛不一定成功，这正是「松弛」是个 `if` 判断的原因。

**验算**：S 到 D 最省的确实是 S→B→D = 2+7=9，与直觉一致。

#### 3.4 为什么「一取出来就定死」是对的（贪心的正确性）

拍脑袋想会担心：万一我先取了某个点，后来发现绕一圈更近呢？

Dijkstra 的论证是这样的：

> 设当前要取出的是 u，它的 `dist[u]` 是所有未确定点里**最小**的。
> 假设存在一条更短的真实路径 P 通往 u。这条路径必然在某处**第一次从「已确定区域」跨到「未确定区域」**，跨越的那条边记作 (x,y)，其中 x 已确定、y 未确定。
> 那么 P 的总长 ≥ dist[x] + w(x,y) ≥ dist[u] + w(x,y)（因为 dist[u] 是未确定里最小的，dist[y] ≥ dist[u]）。
> 而 w(x,y) ≥ 0，所以 P 的长度 ≥ dist[u]，与「更短」矛盾。

**这个论证里 `w(x,y) ≥ 0` 是硬性条件。** 一旦允许负权，最后那步「 ≥ dist[u]」就不成立了，整个证明崩塌——见下一节。

#### 3.5 负权为什么会让它给出**错误答案**（给一个具体反例）

图：A→B 权 1，A→C 权 2，**C→B 权 −2**。源点 A。

真实最短：A→C→B = 2 + (-2) = 0。正确答案是 `dist[B] = 0`。

Dijkstra 跑一遍：

```text
初始      dist[A]=0,  dist[B]=∞,  dist[C]=∞
第1轮  取 A(0) → 松弛：dist[B]=1, dist[C]=2
第2轮  取 B(1) ← 问题就在这！B 的 1 < C 的 2，所以 B 先被「确定」
        B 已进 S，之后再也不会被修改
第3轮  取 C(2) → 松弛 C→B：2 + (−2) = 0 < 1，本该改成 0
        但 B 已经「确定」，Dijkstra 不会再动它
结果    dist[B] = 1   ← 错的（正确是 0）
```

**错误的根源在 3.4 的证明**：那里假设「先确定的一定不会更差」，但负权边让「绕远路反而更省」成为可能。所以 Dijkstra 只能处理**非负权**。

#### 3.6 复杂度汇总

| 实现方式 | 复杂度 | 说明 |
|---|---|---|
| 朴素（每轮线性扫最小值） | O(V²) | 适合稠密图，E 接近 V² 时反而不亏 |
| 优先队列（二叉堆） | O((V+E)log V) | 最常用，稀疏图首选 |
| 斐波那契堆 | O(E + Vlog V) | 理论最优，实际常数大 |

**需要记住：**

Dijkstra works only with **non-negative** edge weights; it uses a **priority queue**, not a plain queue. Negative weights require Bellman-Ford.

#### 3.7 英文例题

Which algorithm finds the shortest paths from a single source in a weighted graph with **non-negative** edge weights?

A. BFS
B. DFS
C. Dijkstra's algorithm
D. Kruskal's algorithm
E. Topological sorting

**答案：C**

**解析：** 题干两个关键词 `single source` + `non-negative` 直接锁定 Dijkstra。BFS 只处理无权（或等权）图；DFS 与最短路无关；Kruskal 求最小生成树；拓扑排序只解决 DAG 的先后顺序。注意：如果题干把 `non-negative` 换成 `possibly negative`，答案就要变成 Bellman-Ford。

**所属知识点：** 数据结构与算法 / 图论 / 最短路与最小生成树。

### 4. Bellman-Ford 算法（可处理负权 + 检测负环）

**解决什么问题**：边权**可能为负**的图中求单源最短路；以及判断图里**有没有负环**。

#### 4.1 一句话说清它和 Dijkstra 的分工

> Dijkstra 是「聪明但挑剔」：挑最小的点，认定了不回头，所以快，但不能有负权。
> Bellman-Ford 是「笨但稳」：不管三七二十一，**把所有边反复扫好几轮**，总能收敛，还能顺便抓出负环。

#### 4.2 核心动作：一轮 = 把所有边扫一遍

```text
for k in 1..V-1:                 // 一共 V-1 轮
    for each edge (u,v,w):       // 每轮扫遍所有边
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
```


就这一个双重循环，没有队列、没有优先队列、没有集合 S。

#### 4.3 为什么是 V-1 轮（这是重点，别只背结论）

**第一步，先想清楚「一条最短路最多有几条边」。**

如果一条最短路里有 V 条边，那它经过了 V+1 个顶点。但总共只有 V 个顶点，由抽屉原理必有重复——有重复就意味着里面有个环。如果这个环的权和 ≥ 0，把环去掉只会更短（或不变），所以「真正的最短路」不会绕这种环；如果环的权和 < 0，那最短路根本不存在（可以无限绕）。

所以：**最短路径一定可以取成一条简单路径，最多 V-1 条边。**

**第二步，再看「扫一轮」能推进多少。**

用归纳法：假设第 k 轮结束时，所有「边数 ≤ k 的最短路」都已经算对了（第 0 轮 = 只有源点自己）。
第 k+1 轮里，考虑一条边数恰好为 k+1 的最短路 s → … → u → v。它的前一段 s→…→u 边数是 k，按假设已经对了，所以 `dist[u]` 正确；这一轮扫到边 (u,v) 时就会把 `dist[v]` 也修正。因此第 k+1 轮结束时，「边数 ≤ k+1 的最短路」全对。

**第三步，合起来。** 最短路最多 V-1 条边，所以 V-1 轮之后，所有最短路都被覆盖。**多扫也没用，少扫一轮就不保证对。**

> 直觉版：每扫一轮，正确信息就往外「传染」一层。信息最多传染 V-1 层，所以要 V-1 轮。

#### 4.4 手算一遍（这个例子里恰好一轮就收敛，正好用来说明「轮数是上界」）

图（**有向**）：A→B 权 5，A→C 权 2，C→B 权 -4，B→D 权 3，C→D 权 6。源点 A。

| 轮次 | dist[A] | dist[B] | dist[C] | dist[D] | 说明 |
|---|---|---|---|---|---|
| 初始 | 0 | ∞ | ∞ | ∞ | — |
| 第 1 轮 | 0 | ∞→**5**→**−2** | **2** | **1** | 扫边顺序：A→B 得 5；A→C 得 2；C→B 得 2−4=−2 覆盖 5；B→D 得 1；C→D 2+6=8>1 不改 |
| 第 2 轮 | 0 | −2 | 2 | 1 | 再扫一遍，没有任何改进 |
| 第 3 轮 | 0 | −2 | 2 | 1 | 已经是 V-1=3 轮，同样无改进 |
| 第 4 轮（判定轮） | 0 | −2 | 2 | 1 | **仍无改进 ⇒ 没有负环** |

答案：dist(A)=0, dist(C)=2, dist(B)=-2, dist(D)=1。

**两处要体会：**

- `dist[B]` 先被算成 **5**（走 A→B），随后被 **−2**（走 A→C→B）覆盖。**值变小是正常的**，这正是 Bellman-Ford 相对 Dijkstra 的「可反悔」。
- 在第 1 轮里，`C→B` 这条边的松弛之所以能成功，是因为**它在 `A→C` 之后被扫到**。如果这一轮里 `C→B` 排到 `A→C` 前面，那这一轮 `dist[C]` 还是 ∞，`C→B` 就松不动，得等第 2 轮。**这就是为什么最坏情况需要 V-1 轮**——链条长 k 条边、且边的扫描顺序恰好事与愿违时，一轮只能推进一条边。

#### 4.5 负环检测：为什么「第 V 轮还能松弛」就等于有负环

第 V 轮是在 V-1 轮之后做的。按 4.3，正常图此时已经全部收敛，**再扫一遍应该一个都改不动**。

如果居然还能改，说明存在一条路径，其边数 ≥ V 却比已求出的更短。边数 ≥ V 必然含环（V 个点走 V 条边），而「边数更多反而更短」说明这个环的权和是**负**的。

并且：一旦有负环，`dist` 会**每一轮都继续变小，永不收敛**——所以这个检测是可靠的。

具体例子：A→B 权 3，B→C 权 -5，C→B 权 -5。
环 B→C→B 的权和是 -10 < 0。于是 `dist[B]` 会依次变成 3、-7、-17、-27……每轮掉 10，永远掉不完 → 最短路**不存在**（可以说成 -∞）。

#### 4.6 复杂度

V-1 轮 × 每轮扫 E 条边 = **O(V·E)**。
稀疏图（E ≈ V）时是 O(V²)；稠密图（E ≈ V²）时退化到 O(V³)，这是它比 Dijkstra 慢的地方。

#### 4.7 与 Dijkstra 的对比

| 对比 | Dijkstra | Bellman-Ford |
|---|---|---|
| 负权边 | ❌ 不支持（见 §3.5 反例） | ✅ 支持 |
| 负环检测 | ❌ 不能 | ✅ 第 V 轮仍能松弛即有负环 |
| 复杂度 | O((V+E)log V) | O(V·E) |
| 核心动作 | 取当前最小 + 松弛它的邻边 | **所有边**反复松弛 V-1 轮 |
| 为什么能/不能 | 贪心：认定不回头 → 需要非负权 | 动态规划：允许反复修正 |
| 数据结构 | 优先队列 | 不需要额外结构 |

**需要记住：**

Bellman-Ford relaxes **all** edges **V − 1** times; if the **V-th** round still relaxes, there is a **negative cycle**.

#### 4.8 英文例题

A directed graph may contain **negative** edge weights. Which algorithm both computes single-source shortest paths and detects negative cycles, and what is its running time?

A. Dijkstra, O((V+E)log V)
B. Bellman-Ford, O(V·E)
C. Floyd-Warshall, O(V³)
D. Prim, O(Elog V)
E. BFS, O(V+E)

**答案：B**

**解析：** 只要题干出现 `negative weights` 且是 `single source`，就只能是 Bellman-Ford。Dijkstra 在负权下会出错（§3.5）；Floyd 虽然也允许负权，但它是**全源**（O(V³)），不符合 `single source` 且代价更高；Prim 求 MST；BFS 不处理权值。

**所属知识点：** 数据结构与算法 / 图论 / 负权最短路与负环检测。

### 5. Floyd-Warshall 算法（全源最短路）

**解决什么问题**：求**任意两点之间**的最短距离（all-pairs shortest paths）。允许负权边，但不允许负环。

#### 5.1 和前面两个算法的定位差别

| | 单源 | 全源 |
|---|---|---|
| 非负权 | Dijkstra O((V+E)log V) | 跑 V 次 Dijkstra |
| 有负权 | Bellman-Ford O(VE) | **Floyd O(V³)** |

Floyd 的价值：**写起来只有三行**，常数小，V 在几百以内时几乎必胜。

#### 5.2 核心思想：动态规划，逐步放宽「允许用哪些中转点」

定义状态：

> dist_k[i][j] = 「只允许把 {1,2,…,k} 这些点当作**中转站**」时，i 到 j 的最短距离。

**递推（这是整个算法的全部）：**

```text
dist_k[i][j] = min( dist_(k-1)[i][j],   dist_(k-1)[i][k] + dist_(k-1)[k][j] )
```

读成人话：

> 从 i 到 j，就两种可能——**要么完全不碰点 k**（第一种，沿用上一阶段的结果），**要么就是「先到 k，再从 k 到 j」**（第二种）。二选一取小的。

因为 dist 数组可以原地更新（右边的 dist[i][k]、dist[k][j] 在 k 这一轮里不会变，见 5.4），所以三维压成二维，代码就是：

```text
for k in 1..V:              // 阶段：允许用前 k 个点当中转
    for i in 1..V:          // 起点
        for j in 1..V:      // 终点
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
```

#### 5.3 手算一个小例子

图（有向）：1→2 权 4，2→3 权 -2，1→3 权 5。

初始矩阵（∞ 表示不直接相连）：

| dist | →1 | →2 | →3 |
|---|---|---|---|
| **1** | 0 | 4 | 5 |
| **2** | ∞ | 0 | −2 |
| **3** | ∞ | ∞ | 0 |

- k=1：没有边指向 1，dist[i][1] 全是 ∞，加任何东西都比原来大，**表不变**。
- k=2：检查「i→2→j」。关键是 dist[1][3]：min(5, 4+(-2)=2) = 2。
  **含义**：1 到 3 与其直达（5），不如先到 2 再转（4-2=2）。表变成 dist[1][3]=2。
- k=3：没有点出边，表不变。

结果 dist[1][3]=2，与手算一致。

#### 5.4 为什么 k 必须在最外层（最容易考的实现细节）

因为 k 不是「一个循环变量」，它是**DP 的阶段**：k=1 是「允许用第 1 个点」，k=2 是「允许用前 2 个点」……阶段只能**一层层往上加**，不能跳。

如果写成 i,j 在外、k 在内，等于「同一个阶段里反复来回改动」，后面的计算用到的可能是「还没被定义好」或者「已经被本阶段污染」的值，DP 的递推关系就断了。

还有一个附带的技术原因：**原地更新（in-place）之所以合法，恰恰是因为 k 在最外层**。更新 dist[i][j] 时，用到的 dist[i][k] 和 dist[k][j] 在这一轮里不会被修改：

- dist[i][k]：终点是 k，本轮里 j 走遍所有值也包括 k，但 dist[k][k]=0 恒成立，dist[i][k] = min(dist[i][k], dist[i][k]+0) 不会变；
- dist[k][j]：起点是 k，同理不变。

> 实践提示：k 放内层的写法**在某些图上碰巧也能算出正确答案**，但没有任何保证，属于经典错误写法。考试问「哪个循环必须在最外层」，答案永远是 k（中间点）。

#### 5.5 顺带两个性质

- **负环判定**：跑完 Floyd 后，如果存在 i 使 dist[i][i] < 0，说明 i 能绕回自己且总权为负 → 有负环。
- **不需要单独处理「经过多个中转点」**：因为 k 逐层放宽，i→a→b→j 这种多跳路径会在 k=b 那一阶段自动被组合出来。

#### 5.6 复杂度与适用规模

时间 O(V³)，空间 O(V²)。
V=100 时约 10⁶ 次操作，很快；V=1000 时是 10⁹，就太慢了。所以适合**稠密图 + 小规模**。

#### 5.7 英文例题

For all-pairs shortest paths on a graph with V vertices, which statement about **Floyd-Warshall** is correct?

A. Its time complexity is O(V²), and the loop over the source vertex must be outermost.
B. Its time complexity is O(V³), and the loop over the intermediate vertex k must be outermost.
C. Its time complexity is O(V³), and the loop over the destination vertex must be outermost.
D. It cannot handle negative edge weights.
E. It finds the minimum spanning tree of the graph.

**答案：B**

**解析：** 时间 O(V³)（三重循环），且 k（中间点/中转站）必须是最外层——k 是 DP 的阶段。C 错在最外层是谁；A 复杂度错；D 错，Floyd **允许**负权边（只是不允许负环）；E 把最短路和 MST 搞混了。

**所属知识点：** 数据结构与算法 / 图论 / 全源最短路与动态规划。

### 6. Prim 与 Kruskal（最小生成树 MST）

**解决什么问题**：用最小的总代价把所有点**连成一片**。

#### 6.1 先分清：MST 求的是「连通」，不是「最短路径」

这是本节最容易被混淆的地方，先立规矩：

> **最短路**问的是：「从 A 到 B 怎么走最省？」
> **MST** 问的是：「花最少的钱，把全部点用边连起来（保证任意两点能互通）。」

两者目标完全不同，得到的边集也通常不同。**MST 上 A、B 两点之间的那条路，往往不是 A 到 B 的最短路。**

**MST 的严格定义**：在**连通无向带权图**中，选出一棵包含**全部**顶点、边权之和最小的树。

- 「树」⟹ 无环；
- V 个点的树恰好有 V-1 条边 ⟹ MST 一定是 V-1 条边。

**为什么一定是 V-1 条**：V 个点的连通图至少 V-1 条边（少一条就断开）；多一条必有环（有环就可以删掉环上最贵的边让总权更小）。所以最优解恰好 V-1 条。

#### 6.2 Prim：从一个点「长」出一棵树

**思路**：维护一个「已在树内」的集合。每次从「一端在树内、一端在树外」的所有边里，挑**最便宜**的那条，把外面的点拉进来。

```text
Step 1  任选一个起点加入树
Step 2  在所有「一端在树内、一端在树外」的边中，选权最小的那条
Step 3  把该边和树外端点一起加入树
Step 4  重复 Step 2-3，共 V-1 次
```

**在例图 G 上手动走一遍（从 S 出发）：**

| 轮次 | 树内顶点 | 候选边（一端内一端外） | 选中的边 | 累计权 |
|---|---|---|---|---|
| 1 | {S} | S–A 4，S–B 2 | **S–B 2** | 2 |
| 2 | {S,B} | S–A 4，A–B 1，B–D 7 | **A–B 1** | 3 |
| 3 | {S,B,A} | A–C 5，B–D 7 | **A–C 5** | 8 |
| 4 | {S,B,A,C} | B–D 7，C–D 3 | **C–D 3** | 11 |
| — | {S,B,A,C,D} | 已 5 个点，共 4 条边，结束 | | **11** |

MST 边集 = {S–B(2), A–B(1), A–C(5), C–D(3)}，总权 **11**。

注意第 3 轮：此时 S–A 这条边两端都在树内了，**它不再进入候选**。Prim 只关心「怎么把外面的点拉进来」，树内部的边毫无意义。这一点想通了，Prim 就没有难点了。

#### 6.3 Kruskal：按边权从小到大加，不成环就加

**思路**：把**所有边**从小到大排序，一条条试着加；如果这条边的两个端点**已经连通**（加了就成环），就跳过；否则加进来。加到 V-1 条为止。

「两个端点是否已连通」用**并查集（Union-Find）**判断：同一集合 ⇒ 已连通 ⇒ 会成环。

**在同一张例图上走一遍：**

边按权排序：A–B 1，S–B 2，C–D 3，S–A 4，A–C 5，B–D 7。

| 顺序 | 边 | 权 | 两端是否已连通 | 动作 | 已选边数 |
|---|---|---|---|---|---|
| 1 | A–B | 1 | 否（{A},{B}） | ✅ 加入，合并 {A,B} | 1 |
| 2 | S–B | 2 | 否（{S} vs {A,B}） | ✅ 加入，合并 {S,A,B} | 2 |
| 3 | C–D | 3 | 否（{C},{D}） | ✅ 加入，合并 {C,D} | 3 |
| 4 | S–A | 4 | **是**（S、A 都在 {S,A,B}） | ❌ 跳过（会成环 S–A–B–S） | 3 |
| 5 | A–C | 5 | 否（{S,A,B} vs {C,D}） | ✅ 加入，全图连通 | 4 |
| 6 | B–D | 7 | **是**（早已连通） | ❌ 跳过 | 4 |

总权 = 1 + 2 + 3 + 5 = 11，与 Prim **一致**——这不是巧合，两种算法都正确，只是顺序不同（这张图恰好只有一个 MST，所以边集相同）。

**体会 Kruskal 的判环逻辑**：第 4 步 S–A 权为 4，比 A–C 的 5 更小，但因为 S 和 A 已经通过 S–B–A 连通了，加它会形成环，所以**必须跳过**。Kruskal 不是「贪心地取最小的」，而是「贪心地取最小的**不构成环的**」——后半句不能丢。

#### 6.4 为什么这两种贪心都是对的（一句话版）

- **Prim 的正确性 = 割性质（cut property）**：「把点任意分成两堆，横跨这两堆的最便宜的边，一定属于某个 MST。」Prim 每一步就是在做这件事（树内 / 树外 就是一个割）。
- **Kruskal 的正确性 = 环性质（cycle property）**：「图里任意一个环上最贵的那条边，一定不属于任何 MST。」Kruskal 加边时跳过成环的边，本质是反过来利用这个性质。

#### 6.5 复杂度与选型

| | Prim | Kruskal |
|---|---|---|
| 做法 | 从一个点长树，每轮挑最小跨界边 | 全局边排序 + 并查集判环 |
| 复杂度 | 朴素 O(V²)；优先队列 O(Elog V) | O(Elog E)（排序主导） |
| 适合 | **稠密图**（E 大，V 小） | **稀疏图**（E 小） |
| 前提 | 图必须连通（否则得不到生成树） | 同左；不连通时得到的是「最小生成森林」 |

记忆抓手：**Prim 盯着点（点集往外长），Kruskal 盯着边（边排序往下筛）。**

#### 6.6 MST ≠ 最短路（给个反例说透）

例图 G 的 MST 边集是 {S–B(2), A–B(1), A–C(5), C–D(3)}。在这棵树上，从 S 到 D **只有一条**路：**S→B→A→C→D**，代价 2+1+5+3 = 11。
但 §3.3 算出 S 到 D 的最短路是 **9**（S→B→D，用的是 B–D 这条边，而 B–D 权 7 太贵，**没被选进 MST**）。

**结论：MST 里没有 B–D，但最短路偏偏要用 B–D。** 这就是「MST ≠ 最短路」最直接的证据。

| 对比 | 最短路（Shortest Path） | 最小生成树（MST） |
|---|---|---|
| 目标 | 两点之间路径最短 | 连通所有点、总权最小 |
| 结果 | 一条路径 | 一棵树（V-1 条边） |
| 算法 | BFS / Dijkstra / Bellman-Ford / Floyd | Prim / Kruskal |
| 是否含最贵边 | 可能含 | 通常不含（环上最贵边必不在 MST 上） |
| 反例 | MST 上两点间的路径往往**不是**最短路（见上） | — |

**需要记住：**

Prim grows the tree **from a vertex**; Kruskal **sorts the edges** and uses **Union-Find** to avoid cycles. MST is **not** the same problem as shortest path.

#### 6.7 英文例题

Which algorithm builds a minimum spanning tree by repeatedly adding the **cheapest edge that does not create a cycle**, using a **union-find** structure?

A. Prim's algorithm
B. Kruskal's algorithm
C. Dijkstra's algorithm
D. Bellman-Ford
E. Floyd-Warshall

**答案：B**

**解析：** `cheapest edge that does not create a cycle` + `union-find` 是 Kruskal 的两个签名。Prim 是「从一个点往外长，挑最便宜的**跨界边**」，不需要并查集（用 visited 数组就行）。Dijkstra 求最短路；Bellman-Ford 求负权最短路；Floyd 求全源最短路。

**所属知识点：** 数据结构与算法 / 图论 / 最小生成树。

### 7. Topological Sort（拓扑排序）

**解决什么问题**：把一堆「有先后依赖」的任务排成一个合法顺序。

典型场景：课程先修关系、编译依赖、任务调度、包管理器的安装顺序。

#### 7.1 定义与前提

**定义**：把 DAG 的所有顶点排成一个线性序列，使得对**每一条**有向边 u→v，u 都排在 v 前面。

**前提：必须是 DAG（有向无环图）。** 如果有环（A 依赖 B，B 依赖 A），那么「A 在 B 前」和「B 在 A 前」同时被要求，无解。

#### 7.2 实现一：Kahn 算法（BFS 式，用队列）

**思路**：入度（in-degree）= 有多少条边指向它 = 「还有几个前置任务没完成」。

```text
Step 1  统计每个点的入度
Step 2  把所有入度为 0 的点入队（这些点没有前置，可以立刻做）
Step 3  出队一个点 u，输出它；对它每条出边 u→v，把 indeg[v] 减 1
Step 4  若某个 v 的入度减到 0，v 入队
Step 5  队列空了就结束
```

**例 DAG**：A→B，A→C，B→D，C→D，D→E。

初始入度：A 0，B 1，C 1，D 2，E 1。

| 步骤 | 队列 | 输出序列 | 动作 |
|---|---|---|---|
| 初始 | [A] | — | A 入度为 0 入队 |
| 1 | [] | **A** | 出队 A；B 的入度 1→0 入队；C 的入度 1→0 入队 |
| 2 | [B, C] | A, **B** | 出队 B；D 的入度 2→1（还没到 0） |
| 3 | [C] | A, B, **C** | 出队 C；D 的入度 1→0 入队 |
| 4 | [D] | A, B, C, **D** | 出队 D；E 的入度 1→0 入队 |
| 5 | [E] | A, B, C, D, **E** | 出队 E，队列空，结束 |

输出：**A, B, C, D, E**（合法，因为每条边都是前→后）。

**注意**：拓扑序**不唯一**。第 2 步队列是 [B, C]，如果先出 C 再出 B，会得到 A, C, B, D, E——同样合法。**考试里问「下列哪个是合法拓扑序」，逐个检查「每条边的起点是否都在终点前面」即可。**

#### 7.3 实现二：DFS 逆后序


**思路**：DFS 一个点，等它的**所有后代都访问完**（即它「后序」完成）之后，才把它加入结果；最后把结果**整个反转**。

```text
dfs(A)：A → B → D → E
   E 先完成（后序第 1 个）
   D 完成（第 2）
   B 完成（第 3）
   C 完成（第 4，此时 D 已访问）
   A 完成（第 5）
后序 = [E, D, B, C, A]
逆序 = [A, C, B, D, E]   ← 合法的拓扑序
```

**为什么逆后序就是拓扑序**：如果存在边 u→v，DFS 里 v 一定是 u 的**后代**（要么还没访问被递归进去，要么已访问——已访问也必然是后代，因为在 DAG 里不可能是「已完成的祖先」）。后代一定比祖先**先**完成，即后序里 v 在 u 之前。反转后 u 就在 v 之前。**每条边都满足，即为拓扑序。**

（这也顺带解释了为什么要求 DAG：若有环，v 既是后代又是祖先，自相矛盾。）

#### 7.4 用 Kahn 检测环（很实用的副产品）

如果最后**输出的顶点数 < V**，说明有点始终没能把入度降到 0 —— 这些点互相依赖，构成环。

例：A→B，B→C，C→A。三者的入度都是 1，初始队列就是**空的**，一个都输出不了，输出数 0 < 3 ⇒ 有环。

#### 7.5 复杂度

每个点入队出队各一次（O(V)），每条边被处理一次（O(E)）⇒ **O(V+E)**。DFS 版同理。

#### 7.6 英文例题

Which statement about **topological sorting** is correct?

A. It can be applied to any directed graph, including graphs with cycles.
B. It requires O(V²) time and uses a priority queue.
C. It is possible only for a DAG, and Kahn's algorithm uses a queue of vertices with in-degree zero.
D. It computes the shortest path from a single source.
E. It produces a unique ordering for every graph.

**答案：C**

**解析：** C 两个断言都对：前提必须是 DAG（有环则无解），Kahn 用「入度为 0 的队列」。A 错在「任意有向图」；B 错，时间 O(V+E) 且不涉及优先队列；D 把拓扑排序和最短路搞混；E 错，拓扑序通常**不唯一**（§7.2 已给出两个合法序列）。

**所属知识点：** 数据结构与算法 / 图论 / 拓扑排序与 DAG。

### 8. 图算法选型对照表（这张表覆盖所有图论选择题）

看到题干里的关键词，直接查表定位算法。

| 题干关键词 | 算法 | 适用图 | 复杂度 |
|---|---|---|---|
| shortest path, **unweighted** / minimum number of edges | **BFS** | 无权或等权 | O(V+E) |
| shortest path, single source, **non-negative** | **Dijkstra** | 边权 ≥ 0 | O((V+E)log V) |
| shortest path, **negative** weights / detect negative cycle | **Bellman-Ford** | 允许负权 | O(V·E) |
| shortest paths **between all pairs** | **Floyd** | 允许负权、无负环 | O(V³) |
| **minimum spanning tree** / connect all with min cost | **Prim / Kruskal** | 连通无向带权 | O(Elog V) / O(Elog E) |
| **DAG** / prerequisites / dependency order | **拓扑排序** | 有向无环 | O(V+E) |
| 连通性 / 有没有路径 / 找环 | **DFS**（或 BFS） | 任意 | O(V+E) |

#### 8.1 七个高频陷阱，逐条对照

1. **BFS 只看边数。** 边权不全相等时，BFS 给的**不是**最短路。边权全相等时，BFS 才等价于退化的 Dijkstra。
2. **Dijkstra 用优先队列，不是普通队列。** 它按「当前距离最小」出队，不是「最早发现」。写「queue」的选项是陷阱。
3. **Dijkstra 不能有负权。** 原因不是实现问题，而是贪心正确性依赖 w ≥ 0（§3.4、§3.5）。
4. **Bellman-Ford 是 V-1 轮，判定负环看第 V 轮。** 不要记成 V 轮松弛。
5. **Floyd 的 k 在最外层**，且它允许负权边（只是不允许负环）。
6. **Kruskal / Prim 求 MST，不是最短路。** 两者目标不同，MST 上的路径不是最短路（§6.6 有例图反例）。
7. **拓扑排序处理「顺序」，与距离无关**，且结果通常不唯一；有环则无解。

#### 8.2 四个算法按「能否反悔」分类（记这个比记表格快）

| 能不能反悔 | 算法 | 代价 |
|---|---|---|
| 不反悔（认定即定死） | BFS、DFS、Dijkstra、Prim、Kruskal | 快（O(V+E) 或 O(Elog V)） |
| 允许反悔（反复修正） | Bellman-Ford、Floyd | 慢（O(VE)、O(V³)） |

「可不可以反悔」这条线把 7 个算法串成两组，本质上是「贪心」与「动态规划」的分界：**贪心快但要求条件（非负权 / 无环），DP 慢但鲁棒（接受负权）。**

#### 8.3 一道综合例题

A network of V routers and E links must be connected so that every pair of routers can communicate, using the minimum total cost of links. Which algorithm should be used?

A. Dijkstra's algorithm
B. Breadth-First Search
C. Kruskal's algorithm
D. Bellman-Ford
E. Floyd-Warshall

**答案：C**

**解析：** 关键词 `every pair can communicate` + `minimum total cost of links` = 把全部点连起来且总代价最小 = **最小生成树**。A 求的是「单源到其余各点」的最短路，不是「把所有点连起来」；B 只数边数；D 处理负权最短路；E 求全源最短路。这三者都能让路由器通信，但**代价不是最小**——这正是 MST 与最短路最本质的区别。

**所属知识点：** 数据结构与算法 / 图论 / 最小生成树与最短路辨析。

### 9. 一页速查：每个算法的「一句话 + 一个抓手」

| 算法 | 一句话 | 抓手 |
|---|---|---|
| BFS | 一圈一圈往外扩，第一次见即最短（无权） | 队列 |
| DFS | 一条路走到底再回头 | 栈 / 递归；灰点=环 |
| Dijkstra | 每次认领当前最近的点，认领后不再改 | 优先队列；非负权 |
| Bellman-Ford | 所有边反复扫 V-1 轮 | 第 V 轮还能松 ⇒ 负环 |
| Floyd | 逐个放开中转站，三行代码 | k 最外层；O(V³) |
| Prim | 从点往外长，挑最便宜的跨界边 | 点集扩张 |
| Kruskal | 边排序，不成环就加 | 并查集 |
| 拓扑排序 | 入度归零者先走 | DAG；Kahn 用队列 |
