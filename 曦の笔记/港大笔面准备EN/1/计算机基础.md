## 进程与线程

### 1. 进程与线程

**题目方向：** 关于进程与线程，下列说法正确的是？（选项涉及地址空间、共享资源、切换开销、进程内的线程数）

**知识点：Process vs Thread**

（1）一句话定位

> **进程（process）是资源分配的基本单位；线程（thread）是 CPU 调度的基本单位。**

一个进程 = 一块独立的**地址空间** + 若干线程；同一进程内的线程**共享**这块地址空间。

（2）共享什么、私有什么（本题唯一考点）

| 资源                       | 同进程的线程之间    | 不同进程之间 |
| ------------------------ | ----------- | ------ |
| 地址空间（代码段、数据段）            | ✅ **共享**    | ❌ 隔离   |
| 堆 Heap（new / malloc 出来的） | ✅ **共享**    | ❌ 隔离   |
| 全局变量 / 静态变量              | ✅ 共享        | ❌ 隔离   |
| 打开的文件描述符                 | ✅ 共享        | ❌ 各自一份 |
| **栈 Stack**              | ❌ **每线程私有** | ❌ 私有   |
| **寄存器 / 程序计数器 PC**       | ❌ **每线程私有** | ❌ 私有   |
| 线程局部存储 TLS               | ❌ 私有        | —      |

记忆钩子：**「堆共享、栈私有」。** 堆是「进程的资源」，栈是「一条执行流的现场」——每个线程在跑不同的函数，现场当然不能共用。

（3）这直接解释了两个现象

- 多线程同时写同一个全局变量会出**竞态条件（race condition）**，因为它们共享堆和全局区；
- 每个线程的**局部变量**不会冲突，因为栈是私有的。

（4）切换开销：进程切换 > 线程切换

|切换类型|要做什么|开销|
|---|---|---|
|线程切换（同进程内）|保存/恢复寄存器、栈指针、PC；**地址空间不变**|小|
|进程切换|上面全部 **＋ 换页表、刷新 TLB**|**大**|

换页表之所以贵：切换进程后虚拟地址到物理地址的映射整套换掉，TLB 里缓存的映射全部失效，之后每次访存都要重新走页表。

（5）隔离性带来的差别

| |进程|线程|
|---|---|---|
|崩溃影响|通常不影响其他进程|**可能拖垮整个进程**（共享地址空间）|
|通信方式|管道、消息队列、共享内存、socket（需要 IPC）|直接读写共享变量（需要加锁）|
|创建开销|大|小|

**所属知识点：** 计算机基础 / 操作系统 / 进程与线程。

### 2. 英文例题

## 内存管理

### 1 Memory Management（内存管理）
#### 1.1 Memory Management Basics（内存管理基础）

内存管理（Memory Management）是操作系统和程序运行时对内存进行分配、使用、释放和回收的过程。

程序运行时，通常会使用以下几类内存：

|Memory Area|中文|主要作用|
|---|---|---|
|Stack|栈|存储局部变量、函数调用信息等|
|Heap|堆|存储动态分配的内存|
|Static Memory|静态内存区|存储全局变量、静态变量等|

##### 1.1.1 Stack（栈）

**栈**主要用于存储**局部变量**和**函数调用**信息。

特点：

- 内存通常由系统自动管理。
    
- 函数调用时分配相关空间。
    
- 函数返回后，局部变量对应的栈空间通常自动释放。
    
- 分配和释放速度较快。
    

示例：

```cpp
void test() {
    int a = 10;
}
```

变量 `a` 是局部变量，通常存储在栈中。函数执行结束后，其对应的栈空间会自动回收。

##### 1.1.2 Heap（堆）

**堆**主要用于**动态内存分配**（Dynamic Memory Allocation）。

特点：

- 程序可以根据需要申请内存。
    
- 生命周期不一定与函数调用绑定。
    
- 在 C/C++ 中，通常需要程序员手动释放。
    
- 如果申请的内存不再使用，却没有被释放，可能造成内存泄漏。
    

C 语言示例：

```cpp
int *p = (int *)malloc(sizeof(int));

*p = 10;

free(p);
p = NULL;
```

说明：

- `malloc()`：动态申请内存。
    
- `free()`：释放动态申请的内存。
    
- `p = NULL`：避免指针继续指向已经释放的内存。
    

##### 1.1.3 Static Memory（静态内存）

**静态内存**主要用于存储**全局变量**和**静态变量**。

示例：

```cpp
static int count = 0;

int main() {
    return 0;
}
```

特点：

- 生命周期通常持续到程序结束。
    
- 不需要程序员手动释放。
    
- 正常使用静态内存不会直接造成传统意义上的内存泄漏。
    

### 2 Memory Leak（内存泄漏）
#### 2.1 什么是内存泄漏？

内存泄漏（Memory Leak）是指：

**程序申请了内存，但在不再需要这部分内存时，没有正确释放，导致这部分内存无法被有效回收或重新利用。**

例如：

```cpp
int *p = (int *)malloc(sizeof(int));

p = NULL;
```

这里申请了一块动态内存，但是在释放之前，就让指针 `p` 指向了 `NULL`。

结果：

- 原来申请的内存仍然存在。
    
- 程序失去了访问这块内存的指针。
    
- 无法通过原来的指针释放这块内存。
    
- 造成内存泄漏。
    

正确写法：

```cpp
int *p = (int *)malloc(sizeof(int));

free(p);
p = NULL;
```

#### 2.2 常见的内存泄漏原因

| Cause                                 | 中文解释           |
| ------------------------------------- | -------------- |
| Failure to free allocated memory      | 未释放已经申请的内存     |
| Repeated memory allocation            | 反复申请内存但没有释放    |
| Losing references to allocated memory | 丢失指向动态内存的引用或指针 |
| Improper resource management          | 没有正确管理内存等资源    |

#### 2.3 循环中反复申请内存

这是非常典型的内存泄漏场景。

错误示例：

```cpp
for (int i = 0; i < 100; i++) {
    int *p = (int *)malloc(sizeof(int));
}
```

问题：

- 每次循环都会申请一块新的内存。
    
- 旧的内存没有释放。
    
- 指针 `p` 被重新赋值，之前申请的内存失去访问途径。
    
- 最终可能产生大量内存泄漏。
    

正确示例：

```cpp
for (int i = 0; i < 100; i++) {
    int *p = (int *)malloc(sizeof(int));

    free(p);
    p = NULL;
}
```

注意：实际编程中还应检查 `malloc()` 是否申请成功。

#### 2.4 内存泄漏的影响

| Impact                 | 中文解释     |
| ---------------------- | -------- |
| Increased Memory Usage | 内存占用不断增加 |
| Reduced Performance    | 程序性能下降   |
| Out of Memory          | 内存耗尽     |
| Program Crash          | 程序可能崩溃   |

内存泄漏通常不会在发生的瞬间导致程序崩溃，但如果长期积累，可能导致系统可用内存减少。

### 3 Garbage Collection（垃圾回收）
#### 3.1 什么是垃圾回收？

垃圾回收（Garbage Collection，GC）是一种自动内存管理机制。

它能够识别不再被程序使用的对象，并在适当的时候回收其占用的内存。

例如 Java：

```java
public class Main {
    public static void main(String[] args) {
        Object obj = new Object();

        obj = null;
    }
}
```

当 `obj` 不再引用原来的对象时，该对象可能成为垃圾回收的候选对象。

注意：成为垃圾回收候选对象，不代表立即被回收。GC 的执行时间由 JVM 管理。

#### 3.2 哪些语言具有垃圾回收机制？

|Language|Garbage Collection|
|---|---|
|C|通常没有自动垃圾回收|
|C++|通常没有自动垃圾回收，但可以使用智能指针等机制管理资源|
|Java|有自动垃圾回收|
|Python|有自动垃圾回收|
|JavaScript|有自动垃圾回收|

#### 3.3 GC 能完全避免内存泄漏吗？

**不能。**

即使使用垃圾回收机制，仍然可能发生内存泄漏。

例如 Java：

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    static List<Object> list = new ArrayList<>();

    public static void main(String[] args) {
        while (true) {
            list.add(new Object());
        }
    }
}
```

问题：

- 每次循环都会创建一个新对象。
    
- 对象被添加到静态集合 `list` 中。
    
- `list` 一直持有这些对象的引用。
    
- GC 认为这些对象仍然可能被使用，因此不会回收它们。
    

这说明：

**垃圾回收只能回收符合回收条件的对象，不能自动判断程序是否还需要某个对象。**

#### 3.4 GC 与 Memory Leak 的关系

|Concept|中文|说明|
|---|---|---|
|Garbage Collection|垃圾回收|自动回收不再被使用的对象|
|Memory Leak|内存泄漏|不再需要的内存或对象长期无法被有效回收|
|Reachability|可达性|对象是否仍然能从 GC Roots 等根引用到达|
|GC Roots|垃圾回收根对象|用于判断对象是否可达的起点|

### 4 Memory Allocation（内存分配）
#### 4.1 Static Allocation（静态分配）

静态分配是指在程序运行前或程序启动阶段确定内存空间。

例如：

```cpp
static int arr[100];
```

特点：

- 内存大小通常固定。
    
- 生命周期通常持续到程序结束。
    
- 不需要手动释放。
    
- 正常使用不会直接造成传统意义上的内存泄漏。
    

#### 4.2 Dynamic Allocation（动态分配）

动态分配是指程序运行过程中，根据实际需要申请内存。

C 语言常见函数：

| Function    | 中文     | 作用          |
| ----------- | ------ | ----------- |
| `malloc()`  | 内存分配   | 申请指定大小的内存   |
| `calloc()`  | 连续内存分配 | 申请内存并初始化为 0 |
| `realloc()` | 重新分配   | 调整已分配内存的大小  |
| `free()`    | 释放内存   | 释放动态申请的内存   |

示例：

```cpp
int *arr = (int *)malloc(10 * sizeof(int));

if (arr != NULL) {
    free(arr);
    arr = NULL;
}
```

#### 4.3 Fixed-size Buffer（固定大小缓冲区）

固定大小缓冲区是指预先确定容量的内存区域，用于临时存储数据。

示例：

```cpp
char buffer[100];
```

特点：

- 缓冲区大小固定。
    
- 不一定需要动态分配。
    
- 正常使用固定大小缓冲区本身不会造成内存泄漏。
    
- 但如果没有做好边界检查，可能产生缓冲区溢出（Buffer Overflow）。
    

注意区分：

|Concept|中文|主要问题|
|---|---|---|
|Memory Leak|内存泄漏|内存没有被正确释放|
|Buffer Overflow|缓冲区溢出|数据超出缓冲区边界|
|Array Out of Bounds|数组越界|访问数组有效范围之外的位置|

数组越界不一定导致内存泄漏，两者是不同的概念。

### 6 四类内存错误的辨析

**题目方向：** 下列哪一项最准确地描述了内存泄漏？（四个错项分别对应悬垂指针、栈溢出、重复释放、OOM）

**知识点：内存错误的分类**

#### 6.1 四类错误对照表（这是本题的全部考点）

|名称|英文|发生了什么|后果|属于泄漏？|
|---|---|---|---|---|
|**内存泄漏**|**memory leak**|已分配的内存**不再可达**（程序丢了指向它的引用），却没有被释放|内存持续累积，长期运行后耗尽|✅ 就是它|
|悬垂指针 / 释放后使用|dangling pointer / **use-after-free**|读取**已释放**的内存|读到脏数据、可能崩溃|❌ 内存已回收|
|栈溢出|**stack overflow**|调用栈超过 OS 允许大小（递归过深、局部数组过大）|程序崩溃|❌|
|重复释放|**double free**|对同一块内存释放两次|破坏堆管理结构，可能崩溃|❌ 属非法操作|
|内存不足|**OOM (out of memory)**|申请的内存超过上限|立即失败/崩溃|❌ 是结果不是定义|

#### 6.2 泄漏的精确定义（一句话）

> **Allocated memory becomes unreachable but is never released.**
> 已分配的内存不再可达，却没有被释放。

判别要点是「**不可达 + 未释放**」两个条件同时成立。只是「用得多」不算泄漏，「已经释放」也不算。

#### 6.3 泄漏 vs 溢出（最常混的一对）

|对比|内存泄漏 Memory Leak|内存溢出 Memory Overflow / OOM|
|---|---|---|
|本质|该释放的没释放|申请的量超过可用上限|
|表现|占用**缓慢增长**，几小时甚至几天才出问题|**立即**失败或崩溃|
|关系|泄漏**可能导致**溢出|溢出**不一定**由泄漏引起（也可能是一次申请太大）|

#### 6.4 常见泄漏场景

- 静态集合（static List / Map）不断 add，永不清理。
- 监听器注册后未注销。
- 打开的文件 / 数据库连接 / 网络流未关闭。
- 缓存无淘汰策略。
- 内部类（匿名内部类）持有外部类引用。
- ThreadLocal 未 remove（线程池复用线程时尤其严重）。

**所属知识点：** 计算机基础 / 内存管理 / 内存错误的分类。

### 7 有垃圾回收也会泄漏

**题目方向：** 有 GC 的语言还会内存泄漏吗？

**知识点：GC 与泄漏的关系**

#### 7.1 结论

**会。** GC 只回收「**不可达**」的对象。只要对象**仍然可达**（还能从 GC Root 顺着引用找到它），GC 就绝不会回收——哪怕程序逻辑上已经不再需要它。

#### 7.2 GC 判断可达性的两种思路

|方法|思路|缺点|
|---|---|---|
|**引用计数** Reference Counting|记录被引用次数，归零即回收|**无法处理循环引用**（A↔B 互相引用，计数永不为 0）|
|**可达性分析** Reachability / Tracing|从 **GC Roots**（栈上局部变量、静态变量等）出发标记，不可达的回收|需要暂停（stop-the-world）|

#### 7.3 语言对照（选择题常考）

|语言|回收方式|
|---|---|
|Java / C# / Go / JavaScript / Python|运行时 GC 自动回收|
|C / C++|程序员手动 free / delete（智能指针是补救，不是 GC）|
|**Rust**|**所有权 + 借用检查，编译期决定释放，没有 GC**|
|汇编|全部显式|

**Rust 是「第三条路」：既不是手动，也不是运行时 GC。**

#### 7.4 一句话

> **GC 解决的是「忘了释放」，解决不了「一直持有」。**

**所属知识点：** 计算机基础 / 内存管理 / 垃圾回收。

## 数据表示与编码

### 1. 补码（Two's Complement）

**题目方向：** −5 的 8 位补码表示是什么？

**知识点：补码**

（1）求负数的补码：三步，顺序不能变

以 −5 的 8 位补码为例：

```text
Step 1  写出绝对值的二进制        5 → 0000 0101
Step 2  按位取反（0↔1）           1111 1010
Step 3  末位加 1                  1111 1011   ← 这就是 −5 的补码
```

**验算（反向操作，必做）：** 对 `1111 1011` 再取反加 1 → `0000 0101` = 5，说明它确实表示 −5。

口诀：**「绝对值 → 取反 → 加一」**。

（2）另一个等价写法（更快，不写减法）

从右往左找**第一个 1**，这个 1 及其右边的 0 保持不变，**左边全部取反**。

```text
−5: 0000 0101 → 从右数第一个 1 在倒数第三位
    保留 ...101，左边 00000 全部取反成 11111
    → 1111 1011
```

（3）符号位与表示范围

8 位补码的最高位是符号位：`0` 表示非负、`1` 表示负（但它**同时参与运算**，不是独立的标志位）。

$$  
-2^{7}\le x\le 2^{7}-1\quad\Longrightarrow\quad -128\sim127  
$$

推广：n 位补码的范围是 $-2^{n-1}\sim2^{n-1}-1$。

（4）两个高频「陷阱值」

|位模式|含义|
|---|---|
|`1111 1111`|**−1**（不是 −127）|
|`1000 0000`|**−128**（不是 −0）|

（5）为什么计算机用补码

- 补码下减法可以统一按加法处理：a − b = a + (−b)补，硬件只需要一个加法器；
- 补码的 0 只有一种表示，不需要为「+0 / −0」做额外判断。

**所属知识点：** 计算机基础 / 数据表示 / 补码。

### 2. 原码、反码、移码

**题目方向：** 补码题的错误选项往往就是原码或反码，必须能一眼认出来。

**知识点：原码 / 反码 / 移码**

（1）四种码的对照（8 位，以 ±5 为例）

| 编码                           | +5         | −5         | 规则                                 | 8 位范围       | 零的个数    |
| ---------------------------- | ---------- | ---------- | ---------------------------------- | ----------- | ------- |
| **原码** True / Sign-magnitude | `00000101` | `10000101` | 最高位是**符号位**（0 正 1 负），其余是绝对值        | −127 ~ +127 | **2 个** |
| **反码** Ones' complement      | `00000101` | `11111010` | 正数同原码；负数 = 原码**符号位不变**，其余按位取反      | −127 ~ +127 | **2 个** |
| **补码** Two's complement      | `00000101` | `11111011` | 正数同原码；负数 = 反码 **+1**               | −128 ~ +127 | **1 个** |
| **移码** Excess / bias（偏移码）    | `10000101` | `01111011` | 补码的**符号位取反**；等价于「真值 + 偏移量 2^(n−1)」 | −128 ~ +127 | 1 个     |

（2）四个必须知道的结论

- **只有补码的 0 是唯一的。** 原码和反码都有 +0 和 −0 两种写法，这是它们被淘汰的根本原因——两个零会让「比较是否相等」多一步判断。
- **补码比原码/反码多表示一个负数**（8 位能到 −128），因为原码里 `1000 0000`（−0）这个位置被补码征用来表示 −128。
- **补码把减法变成加法**，硬件只需一个加法器。
- **移码用于浮点数的阶码**（IEEE 754 的 exponent 就是偏移码），因为移码单调，可以直接按无符号数比较大小。

（3）五种选项的诊断（做补码题时对着看）

|选项长什么样|它是什么|
|---|---|
|符号位改了、其余位没动（`1000 0101`）|**原码**（只改符号位）|
|全取反但没加 1（`1111 1010`）|**反码**（少加 1）|
|取反加 1（`1111 1011`）|✅ **补码**|
|和正数一模一样（`0000 0101`）|忘了这是负数|
|某一位算错（`1111 1001` = −7）|计算失误|

**所属知识点：** 计算机基础 / 数据表示 / 原码反码补码移码。

### 3. 无符号整数的回绕与位运算

**题目方向：** 代码里 `x & (x - 1)` 用来判断什么？

**知识点：无符号运算与位运算技巧**

（1）无符号回绕（wrap-around）

```c
unsigned int x = 0;
x - 1;          // 得到 4294967295（= 2³² − 1，UINT_MAX），不是 −1
```

无符号减法溢出时会「从 0 绕回最大值」，不会报错。这解释了两个反直觉结论：

```c
-1 < 1u        // false！−1 会先转成无符号的大数
0u - 1 == UINT_MAX   // true
```

（2）三个必背的位运算技巧

| 写法                          | 作用                | 原理                                  |
| --------------------------- | ----------------- | ----------------------------------- |
| `x & (x - 1) == 0`（且 x ≠ 0） | 判断 x 是否为 **2 的幂** | 2 的幂只有一位 1；减 1 后该位变 0、其后全变 1，与运算为 0 |
| `x & (x - 1)` 反复执行          | 统计二进制中 **1 的个数**  | 每执行一次消掉最低位的 1                       |
| `x & (-x)`                  | 取出**最低位的 1**      | 补码性质，-x = ~x + 1                    |

（3）`x != 0` 这个前置判断不能省

x = 0 时 x − 1 在无符号下回绕成全 1，0 & 全 1 = 0 同样成立 —— 若不排除，会把 0 误判为 2 的幂。

（4）移位

| 运算              | 含义         | 注意                |
| --------------- | ---------- | ----------------- |
| `x << 1`        | 左移一位 = 乘 2 | 高位溢出丢弃            |
| `x >> 1`（无符号）   | 右移一位 = 除 2 | 逻辑右移，高位补 0        |
| `x >> 1`（有符号负数） | —          | 算术右移，高位补符号位（实现相关） |

**所属知识点：** 计算机基础 / 数据表示 / 位运算。

### 4. 英文例题

**（1）补码**

What is the 8-bit **two's complement** representation of −5?

A. 10000101

B. 11111010

C. 11111011

D. 00000101

E. 11111001

**答案：C**

**解析：** 5 = `00000101` → 取反 `11111010` → 加 1 `11111011`。验算：`11111011` 取反加一得 `00000101` = 5。逐位验算：−128 + 64 + 32 + 16 + 8 + 0 + 2 + 1 = −5 ✓

**（2）位运算**

What does the following code segment determine? (x is declared as `unsigned int`)

```c
if (x != 0 && (x & (x - 1)) == 0) { /* ... */ }
```

A. Whether x is an odd number

B. Whether x is a power of 2

C. Whether all bits of x are 1

D. Whether x is a multiple of 4

E. Whether x is divisible by 3

**答案：B**

**解析：** 2 的幂的二进制只有一位是 1；x − 1 把这一位变 0、其后全变 1，与运算必为 0。若 x 中有两个及以上的 1，结果不为 0。`x != 0` 是必需的，否则 0 会被误判（0 − 1 在无符号下回绕成全 1）。

**所属知识点：** 计算机基础 / 数据表示 / 综合应用。

## 网络协议

### 1. 网络分层与常见协议

**题目方向：** 下列哪个协议能在不可靠的网络之上提供可靠、按序的字节流传输？

**知识点：Network Protocols**

（1）一张分层表（所有网络选择题都在这张表里找答案）

| 层                   | 协议                               | 职责           | 可靠？            |
| ------------------- | -------------------------------- | ------------ | -------------- |
| **应用层** Application | HTTP / HTTPS、DNS、FTP、SMTP        | 面向具体应用的数据交换  | 取决于下层          |
| **传输层** Transport   | **TCP**、**UDP**                  | 端到端（进程到进程）传输 | TCP 可靠、UDP 不可靠 |
| **网络层** Network     | **IP**、ICMP、路由协议（OSPF/BGP）、ARP\* | 逐跳转发、寻址      | **不可靠**（尽力而为）  |
| **链路层** Link        | Ethernet、Wi-Fi                   | 相邻结点间的帧传输    | 局部校验           |

ARP 的归属各教材不一：国内 408 教材多放在**网络层**，也有教材放在链路层。考试只需知道它是「IP → MAC 的地址解析」。

（2）五个协议各干什么

|协议|一句话职责|关键英文词|
|---|---|---|
|**TCP**|在不可靠网络上提供**可靠、按序的字节流**|connection-oriented, reliable, in-order, byte stream, ACK, retransmission|
|**UDP**|无连接、不保证送达与顺序，**开销小、时延低**|connectionless, best-effort, datagram|
|IP|逐跳转发数据包，**本身不可靠**|best-effort delivery, routing|
|ARP|**IP 地址 → MAC 地址**的解析|address resolution|
|ICMP|差错报告与探测（**ping** 的底层）|error reporting, echo request/reply|

（3）TCP 靠什么做到「可靠 + 按序」

|机制|解决什么|
|---|---|
|**序号 + 确认（ACK）**|知道哪些字节到了、哪些没到|
|**超时重传**|丢了就再发|
|**三次握手 / 四次挥手**|建立与释放连接（同步初始序号）|
|**滑动窗口 + 流量控制**|别把接收方灌爆（接收方能力）|
|**拥塞控制**（慢启动、拥塞避免）|别把网络灌爆（网络状况）|
|**按序号重组**|乱序到达也能拼回原顺序|

一句话：**流量控制看接收方，拥塞控制看网络。**

（4）什么时候用 UDP

**实时音视频、在线游戏、DNS 查询、直播**——宁可丢一帧也不要等重传（等到了也过期了）。「可靠」不是免费的：重传与拥塞控制会带来延迟抖动。

（5）题干关键词 → 答案（比背协议栈更快）

| 题干说                                                  | 答案       |
| ---------------------------------------------------- | -------- |
| reliable, in-order, byte stream, connection-oriented | **TCP**  |
| connectionless, low latency, best-effort, datagram   | **UDP**  |
| resolves IP to MAC                                   | **ARP**  |
| ping / error reporting                               | **ICMP** |
| best-effort packet forwarding, routing               | **IP**   |
| application-level, request-response, stateless       | **HTTP** |

**所属知识点：** 计算机基础 / 计算机网络 / 协议分层。

### 2. 英文例题

Which protocol provides **reliable, in-order** delivery of a **byte stream** over an unreliable network?

A. UDP

B. IP

C. TCP

D. ARP

E. ICMP

**答案：C**

**解析：** 题干三个关键词 `reliable`、`in-order`、`byte stream` 每一个都指向 TCP。UDP 不保证送达与顺序；IP 只做尽力而为的转发；ARP 做地址解析；ICMP 做差错报告。

**所属知识点：** 计算机基础 / 计算机网络 / 传输层协议。

## 数据库与 SQL

### 1. SQL 子句与逻辑执行顺序

**题目方向：** 聚合完成后用于过滤分组结果的子句是哪个？

**知识点：SQL 子句**

（1）逻辑执行顺序（**不是书写顺序**）

```text
FROM / JOIN  →  ON  →  WHERE  →  GROUP BY  →  HAVING  →  SELECT  →  DISTINCT  →  ORDER BY  →  LIMIT
   ①              ②       ③          ④           ⑤          ⑥           ⑦            ⑧         ⑨
```

记忆主线：**先找表（FROM）→ 再连表（ON）→ 再筛行（WHERE）→ 再分组（GROUP BY）→ 再筛组（HAVING）→ 再选列（SELECT）→ 排序（ORDER BY）→ 截断（LIMIT）。**

（2）五个子句的分工

|子句|作用|能否用聚合函数|例|
|---|---|---|---|
|`WHERE`|**分组前**筛**行**|❌ 不能|`WHERE age > 18`|
|`GROUP BY`|按列分组|—|`GROUP BY class`|
|**`HAVING`**|**分组后**筛**组**|✅ 能|`HAVING COUNT(*) > 5`|
|`ORDER BY`|排序输出|✅ 能（对结果排序）|`ORDER BY cnt DESC`|
|`LIMIT`|限制返回行数|❌|`LIMIT 10`|
|`DISTINCT`|去重|❌|`SELECT DISTINCT class`|

（3）为什么 `WHERE` 里不能写聚合函数

执行到 `WHERE` 时**还没分组**，`COUNT(*)` 无从算起。这不是「语法规定」，而是**执行顺序的必然结果**——理解了顺序就不用背这条规则。

（4）标准写法示例

```sql
SELECT class, COUNT(*) AS cnt
FROM Student
WHERE grade >= 60          -- 先筛行
GROUP BY class             -- 再分组
HAVING COUNT(*) > 5        -- 再筛组
ORDER BY cnt DESC;         -- 最后排序
```

（5）一句话

**`WHERE` 管行，`HAVING` 管组；先 `WHERE` 后 `GROUP`，先 `GROUP` 后 `HAVING`。**

**所属知识点：** 计算机基础 / 数据库 / SQL 子句。

### 2. 英文例题

Which SQL clause is used to filter **groups** after an aggregation has been performed?

A. WHERE

B. HAVING

C. ORDER BY

D. DISTINCT

E. LIMIT

**答案：B**

**解析：** 题干两个关键词 `groups`（分组后）与 `after an aggregation`（聚合已发生）直接锁定 `HAVING`。`WHERE` 在分组前过滤行，且不能用聚合函数。

**所属知识点：** 计算机基础 / 数据库 / SQL 子句。

## 死锁与饥饿

### 1. 死锁的四个必要条件

**题目方向：** 下列哪一项不属于死锁的四个必要条件？

**知识点：Deadlock**

（1）四个必要条件（**必须同时成立**）

| 条件        | 英文               | 含义             | 破坏它的方法           |
| --------- | ---------------- | -------------- | ---------------- |
| **互斥**    | Mutual exclusion | 资源一次只能被一个进程占用  | 尽量让资源可共享（如只读文件）  |
| **占有并等待** | Hold and wait    | 已占着一些资源，又去等另一些 | **一次性申请全部资源**    |
| **不可抢占**  | No preemption    | 已分配的资源不能被强行夺走  | 允许抢占（CPU、内存页可换出） |
| **循环等待**  | Circular wait    | 存在一个进程的环形等待链   | **资源统一编号，按序申请**  |

（2）「必要」二字的含义

四个条件是「**可能死锁**」的必要条件：**同时满足才可能死锁，破坏任意一个就一定不死锁**。

这是「预防（prevention）」的全部理论基础。注意条件是「必要」不是「充分」——四个都满足也**不一定真的死锁**（要看实际申请时序），但只要缺一个就**一定不会**死锁。

（3）死锁的处理策略（也常考）

| 策略                  | 做法                    | 代价       |
| ------------------- | --------------------- | -------- |
| **预防** Prevention   | 破坏四个条件之一              | 资源利用率下降  |
| **避免** Avoidance    | 银行家算法，运行时判断「这次分配是否安全」 | 需要预知最大需求 |
| **检测与恢复** Detection | 定期检测环路，杀死或回滚进程        | 实现复杂     |
| **鸵鸟策略** Ostrich    | 不管（很多通用 OS 的做法）       | 可能死机     |

**所属知识点：** 计算机基础 / 操作系统 / 死锁。

### 2. 死锁与饥饿的区别

**题目方向：** 死锁与饥饿有什么区别？（常作为死锁题的干扰项出现）

**知识点：Deadlock vs Starvation**

（1）核心区别在「状态」

| |**死锁 Deadlock**|**饥饿 Starvation**|
|---|---|---|
|进程状态|**全部永久阻塞**，互相等|**就绪但一直排不上**（能跑却没机会）|
|是否涉及环|一定存在**循环等待**|不一定有环|
|谁能解除|**没人**，除非外力干预|有可能**自己等到**（资源释放后）|
|典型原因|资源竞争 + 申请顺序不当|**调度策略不公平**（低优先级长期被抢占）|
|类比|四个人各拿一根筷子，谁也不放|排队永远被插队|

（2）一句话

**死锁是「全都卡死」，饥饿是「能跑但排不上队」。** 饥饿与死锁没有必然联系，不属于死锁的必要条件。

（3）概念题的「4 + 1」结构

这类题的标准出法是：四个正确项 + 一个「相关但不同」的干扰项。

|干扰项类型|例子|
|---|---|
|相关但不同的概念|死锁 ↔ 饥饿、进程 ↔ 线程、泄漏 ↔ 溢出|
|方向反了的表述|「进程切换更便宜」、「线程有独立地址空间」|
|程度夸大的表述|「必须」、「一定」、「永远」|
|机制混淆|把「流量控制」说成「拥塞控制」|

看到「下列哪项**不属于**」时，先在四个选项里找「成套的那一组」，剩下的就是答案。

**所属知识点：** 计算机基础 / 操作系统 / 死锁与饥饿。

### 3. 英文例题

Which of the following is **NOT** one of the four necessary conditions for deadlock?

A. Mutual exclusion

B. Hold and wait

C. No preemption

D. Circular wait

E. Starvation

**答案：E**

**解析：** 四个必要条件是 mutual exclusion / hold and wait / no preemption / circular wait。饥饿是指进程长期得不到调度或资源，可能由不公平的调度策略引起，与死锁无必然联系。

**所属知识点：** 计算机基础 / 操作系统 / 死锁。

## 逻辑与命题

### 1. 四种命题：原、逆、否、逆否

**题目方向：** 已知命题「如果下雨，那么地面湿的」，下列哪个命题与它逻辑等价？

**知识点：Logical Equivalence**

（1）四种命题（设原命题为 P → Q）

| 名称       | 英文                       | 形式      | 与原命题等价？  |
| -------- | ------------------------ | ------- | -------- |
| **原命题**  | **original implication** | P → Q   | —        |
| **逆命题**  | **converse**             | Q → P   | ❌        |
| **否命题**  | **inverse**              | ¬P → ¬Q | ❌        |
| **逆否命题** | **contrapositive**       | ¬Q → ¬P | ✅ **等价** |

**只有一组等价关系：原命题 ⇔ 逆否命题，逆命题 ⇔ 否命题。**

记忆：**「逆否等价」**——把箭头两边**同时否定并交换位置**，真假不变。

（2）真值表验证

|P|Q|P → Q|Q → P（逆）|¬P → ¬Q（否）|¬Q → ¬P（逆否）|
|---|---|---|---|---|---|
|T|T|**T**|T|T|**T**|
|T|F|**F**|T|T|**F**|
|F|T|**T**|F|F|**T**|
|F|F|**T**|T|T|**T**|

- 第 2 行（P 真 Q 假）：原命题为 F，逆否也为 F → 同真同假；而逆、否在这一行都是 T，与原命题不一致。
- 第 3 行（P 假 Q 真）：原命题为 T，逆、否都是 F，再次不一致。

因此 P → Q 与 ¬Q → ¬P 在**所有**行都相同 → 逻辑等价。

（3）日常例子：为什么逆命题不等价

原命题：「如果下雨，那么地面湿」（P → Q）

- **逆命题**「地面湿 → 下雨」不成立：洒水车、洗车、管道漏水都能让地面湿。
- **否命题**「不下雨 → 地面不湿」不成立：同上，洒水也会湿。
- **逆否命题**「地面不湿 → 没下雨」成立：如果下过雨地面必然湿，现在不湿，所以必定没下雨。✅

一句话：**逆否是「同一个事实的另一种说法」，逆和否是「另一个事实」。**

（4）五类选项的固定结构

|选项|形式|名称|
|---|---|---|
|「不湿 → 没下雨」|¬Q → ¬P|✅ **逆否（contrapositive）**|
|「湿 → 下雨」|Q → P|逆命题（converse）|
|「不下雨 → 不湿」|¬P → ¬Q|否命题（inverse）|
|「当且仅当」|P ↔ Q|双条件（biconditional），**比原命题强**|
|「可能下雨而地不湿」|直接否定原命题|与原命题**矛盾**|

（5）考场秒判

把原命题写成 P → Q，正确的等价项一定是「**先否定 Q，再否定 P**」——**两个否定都出现、且顺序反过来**。任何只否定一个的、或没否定只交换的，一律排除。

**所属知识点：** 计算机基础 / 逻辑 / 命题等价。

### 2. 英文例题

Consider the statement: "If it rains, then the ground is wet." Which of the following is **logically equivalent** to it?

A. If the ground is wet, then it rained.

B. If it does not rain, then the ground is not wet.

C. If the ground is not wet, then it did not rain.

D. It rains if and only if the ground is wet.

E. It is possible that it rains while the ground is not wet.

**答案：C**

**解析：** P = rains，Q = ground is wet。P → Q 只与逆否 ¬Q → ¬P 等价。A 是逆命题（converse，洒水也能弄湿地面）；B 是否命题（inverse）；D 是双条件，比原命题强得多；E 直接就是原命题的反例。

**所属知识点：** 计算机基础 / 逻辑 / 命题等价。

## Java OOP and Class Members

### 1 Abstract Class（抽象类）
#### 1.1 什么是抽象类？

抽象类（Abstract Class）是使用 `abstract` 关键字修饰的类。

它主要用于定义一类对象的共同属性和行为，并允许子类继承后实现具体功能。

语法：

```java
abstract class Animal {
    String name;

    // 抽象方法：只有声明，没有方法体
    abstract void makeSound();

    // 普通方法：有具体实现
    void eat() {
        System.out.println("Eating...");
    }
}
```

抽象类的特点：

1. 使用 `abstract` 关键字定义。
    
2. 可以包含抽象方法（Abstract Method）。
    
3. 可以包含普通方法（Concrete Method）。
    
4. 可以包含成员变量、构造方法等。
    
5. 不能直接创建抽象类的对象。
    
6. 子类继承抽象类后，需要实现其所有未实现的抽象方法，否则子类也必须声明为抽象类。
    

#### 1.2 Abstract Method（抽象方法）

抽象方法只有方法声明，没有具体实现。

```java
abstract class Animal {
    abstract void makeSound();
}
```

子类需要实现抽象方法：

```java
class Dog extends Animal {
    @Override
    void makeSound() {
        System.out.println("Woof!");
    }
}
```

#### 1.3 Concrete Method（具体方法）

具体方法是具有方法体、能够执行具体功能的方法。

```java
abstract class Animal {
    void eat() {
        System.out.println("Eating...");
    }
}
```

注意：抽象类不等于所有方法都是抽象方法。它可以同时包含抽象方法和具体方法。

### 2 Interface（接口）
#### 2.1 什么是接口？

接口（Interface）是一种定义行为规范的机制。

它主要用于规定实现类应该具备哪些功能。

语法：

```java
interface Flyable {
    void fly();
}
```

实现接口：

```java
class Bird implements Flyable {
    @Override
    public void fly() {
        System.out.println("Flying...");
    }
}
```

#### 2.2 接口的主要特点

1. 使用 `interface` 关键字定义。
    
2. 类通过 `implements` 关键字实现接口。
    
3. 一个类可以实现多个接口。
    
4. 接口不能直接实例化。
    
5. 接口中的普通抽象方法默认是 `public abstract`。
    
6. 接口中的变量默认是 `public static final`，必须初始化。
    

例如：

```java
interface Flyable {
    int MAX_SPEED = 100;

    void fly();
}
```

其中：

```java
int MAX_SPEED = 100;
```

实际上相当于：

```java
public static final int MAX_SPEED = 100;
```

#### 2.3 Java 8 之后接口可以包含具体方法

在 Java 8 之前，接口主要通过抽象方法定义行为规范。

从 Java 8 开始，接口可以包含：

|Method Type|中文|是否有方法体|说明|
|---|---|---|---|
|Abstract Method|抽象方法|否|默认是 `public abstract`|
|Default Method|默认方法|是|使用 `default` 修饰|
|Static Method|静态方法|是|使用 `static` 修饰|

示例：

```java
interface MyInterface {

    // 抽象方法
    void test();

    // 默认方法
    default void show() {
        System.out.println("Default method");
    }

    // 静态方法
    static void print() {
        System.out.println("Static method");
    }
}
```

调用接口中的静态方法：

```java
MyInterface.print();
```

注意：

- 接口中的静态方法必须有具体实现。
    
- 接口中的静态方法通过接口名调用。
    
- 实现类不能通过普通的实例方法重写接口的静态方法。
    

#### 2.4 Abstract Class vs Interface（抽象类与接口的区别）

| Comparison           | Abstract Class   | Interface                    |
| -------------------- | ---------------- | ---------------------------- |
|                      | 抽象类              | 接口                           |
| Definition           | `abstract class` | `interface`                  |
| Inheritance          | 使用 `extends`     | 使用 `implements`              |
| Multiple Inheritance | 一个类只能继承一个类       | 一个类可以实现多个接口                  |
| Instance Variables   | 可以有普通成员变量        | 字段默认是 `public static final`  |
| Constructor          | 可以有构造方法          | 不能定义普通构造方法                   |
| Abstract Methods     | 可以有              | 可以有                          |
| Concrete Methods     | 可以有              | 可以有 `default`、`static` 等具体方法 |
| Purpose              | 提供共同状态和行为        | 定义行为规范                       |

#### 2.5 Java 的单继承与多接口实现

Java 中：

**一个类只能直接继承一个类，但可以实现多个接口。**

例如：

```java
abstract class Animal {
}

interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck extends Animal implements Flyable, Swimmable {

    @Override
    public void fly() {
        System.out.println("Flying");
    }

    @Override
    public void swim() {
        System.out.println("Swimming");
    }
}
```

这里：

- `Duck extends Animal`：继承一个抽象类。
    
- `Duck implements Flyable, Swimmable`：实现两个接口。
    

注意：抽象类本质上也是类，因此 Java 不允许一个类同时继承多个抽象类。

### 3 Static Keyword（static 关键字）
#### 3.1 什么是 static？

`static` 是 Java 中的一个关键字，用于修饰类成员。

被 `static` 修饰的成员属于类（Class），而不是某个具体对象（Object）。

主要包括：

- Static Variable（静态变量）
    
- Static Method（静态方法）
    
- Static Block（静态代码块）
    
- Static Nested Class（静态嵌套类）
    

#### 3.2 Static Variable（静态变量）

静态变量也称为类变量（Class Variable）。

它属于类，所有该类的实例共享同一份静态变量。

示例：

```java
class Student {
    static int count = 0;

    Student() {
        count++;
    }
}
```

测试：

```java
public class Main {
    public static void main(String[] args) {
        Student s1 = new Student();
        Student s2 = new Student();
        Student s3 = new Student();

        System.out.println(Student.count);
    }
}
```

输出：

```text
3
```

原因：

- `count` 是静态变量。
    
- 所有 Student 对象共享同一个 `count`。
    
- 每创建一个对象，`count` 就增加 1。
    

可以理解为：

```text
Student Class
    |
    |-- static int count = 3
    |
    |-- Object s1
    |-- Object s2
    |-- Object s3
```

注意：静态变量只有一份逻辑上的类级别变量，不会因为创建多个对象而为每个对象分别创建一份。

#### 3.3 Instance Variable（实例变量）

实例变量属于对象，每创建一个对象，就有自己独立的实例变量。

示例：

```java
class Student {
    String name;
}
```

测试：

```java
Student s1 = new Student();
Student s2 = new Student();

s1.name = "Tom";
s2.name = "Jerry";

System.out.println(s1.name);
System.out.println(s2.name);
```

输出：

```text
Tom
Jerry
```

对比：

| Comparison       | Static Variable | Instance Variable |
| ---------------- | --------------- | ----------------- |
|                  | 静态变量            | 实例变量              |
| Belongs to       | Class           | Object            |
| Number of Copies | 类级别共享一份         | 每个对象各自一份          |
| Access           | 类名或对象名          | 对象名               |
| Lifetime         | 随类的生命周期管理       | 随对象生命周期管理         |

#### 3.4 Static Method（静态方法）

静态方法属于类，而不是某个对象。

示例：

```java
class MathUtils {
    static int add(int a, int b) {
        return a + b;
    }
}
```

调用：

```java
int result = MathUtils.add(10, 20);
```

输出：

```text
30
```

静态方法的特点：

1. 可以直接通过类名调用。
    
2. 不需要创建对象。
    
3. 不能直接访问非静态成员变量。
    
4. 不能直接调用非静态方法。
    
5. 不能使用 `this` 和 `super`。
    

原因：

静态方法属于类，在没有创建对象时就可以调用；而非静态成员属于具体对象，需要通过对象访问。

#### 3.5 Static Method vs Instance Method（静态方法与实例方法）

| Comparison              | Static Method | Instance Method |
| ----------------------- | ------------- | --------------- |
|                         | 静态方法          | 实例方法            |
| Belongs to              | Class         | Object          |
| Invocation              | 类名调用          | 对象调用            |
| Requires Object         | 不需要           | 需要              |
| Access Static Members   | 可以            | 可以              |
| Access Instance Members | 不能直接访问        | 可以              |
| Use `this`              | 不可以           | 可以              |

### 4 Method Overriding vs Method Hiding（方法重写与方法隐藏）

这是本题非常重要的考点。

#### 4.1 Method Overriding（方法重写）

方法重写是指子类重新实现父类中继承而来的实例方法。

要求：

- 子类方法名相同。
    
- 参数列表相同。
    
- 返回类型相同或满足协变返回类型要求。
    
- 子类方法不能降低访问权限。
    
- 通常使用 `@Override` 注解。
    

示例：

```java
class Parent {
    void show() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    @Override
    void show() {
        System.out.println("Child");
    }
}
```

测试：

```java
Parent p = new Child();
p.show();
```

输出：

```text
Child
```

这是因为 Java 的实例方法支持运行时多态（Runtime Polymorphism），实际执行哪个方法取决于对象的实际类型。

#### 4.2 Method Hiding（方法隐藏）

静态方法不能被真正重写。

如果子类定义了与父类同名、参数列表相同的静态方法，这种情况称为方法隐藏（Method Hiding）。

示例：

```java
class Parent {
    static void show() {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    static void show() {
        System.out.println("Child");
    }
}
```

测试：

```java
Parent p = new Child();
p.show();
```

输出：

```text
Parent
```

原因：

静态方法属于类，调用哪个方法主要取决于**引用变量的声明类型**，而不是对象的实际类型。

如果写成：

```java
Child.show();
```

则输出：

```text
Child
```

#### 4.3 Overriding vs Hiding

| Comparison           | Method Overriding     | Method Hiding        |
| -------------------- | --------------------- | -------------------- |
|                      | 方法重写                  | 方法隐藏                 |
| Applicable To        | 实例方法                  | 静态方法                 |
| Keyword              | 不需要特殊关键字              | `static`             |
| Binding              | Dynamic Binding（动态绑定） | Static Binding（静态绑定） |
| Depends On           | 对象的实际类型               | 引用变量的声明类型（或调用时指定的类名） |
| Runtime Polymorphism | 支持                    | 不支持                  |

**考试重点：**

- Instance Methods（实例方法）可以被重写。
    
- Static Methods（静态方法）不能被真正重写，只能被隐藏。
    
- `@Override` 不能用于重写父类静态方法。

### 6 Practice Question（例题）

##### Question: Abstract Classes, Interfaces and Static Keyword

**English Question:**

Which of the following statements about abstract classes, interfaces and the `static` keyword is correct?

**中文题目：**

关于抽象类、接口和 `static` 关键字，以下说法正确的是：

**Options:**

A) A class can implement multiple interfaces and inherit multiple abstract classes.

B) Static methods can be overridden.

C) Static variables have only one copy in memory, shared by all instances.

D) Interfaces can contain concrete implementations of static methods.

**Answer: C**

##### 解析

**A) 错误**

一个类可以实现多个接口，但只能直接继承一个类，包括抽象类。

```java
class A extends B implements C, D {
}
```

其中 `B` 可以是普通类或抽象类，`C` 和 `D` 是接口。

**B) 错误**

静态方法不能被真正重写（Overriding），只能被隐藏（Hiding）。

**C) 正确**

静态变量属于类，而不是某个具体对象。

同一个类的所有实例共享同一份静态变量。

**D) 正确性需要注意题目中的 Java 版本。**

Java 8 开始，接口允许定义具有具体实现的静态方法。

例如：

```java
interface Test {
    static void show() {
        System.out.println("Hello");
    }
}
```

因此，按照 Java 8 及之后的规则，D 也是正确的。

**重要：原题给出的答案 C 并不严谨。**

如果题目没有限定 Java 8 之前，那么 C 和 D 都正确。若按照 Java 7 及以前的规则，D 才是错误的。

### 7 Inheritance：继承什么、不继承什么

**题目方向：** 关于类的继承，下列说法正确的是？（选项常涉及多继承、private 可见性、构造器是否被调用）

**知识点：Inheritance**

#### 7.1 子类到底继承了什么

|成员|是否被继承|说明|
|---|---|---|
|public / protected 字段与方法|✅ 继承|直接可用|
|private 字段与方法|⚠️ 存在于对象中，但**不可直接访问**|内存里确实有（父类部分必须初始化），但编译器禁止子类直接引用；只能通过父类的 public/protected 方法间接操作|
|**构造器**|❌ **不继承**|构造器不是成员方法；子类必须自己声明，或依赖默认构造器|
|static 成员|⚠️ 共享但**不参与多态**|属于类，通过类名访问；子类同名 static 方法是**隐藏**，不是重写|
|final 方法|✅ 继承但**不能重写**|—|

#### 7.2 访问修饰符与可见性

|修饰符|本类|同包|子类（不同包）|任何地方|
|---|---|---|---|---|
|private|✅|❌|❌|❌|
|（default）|✅|✅|❌|❌|
|protected|✅|✅|✅|❌|
|public|✅|✅|✅|✅|

**protected 的细节（易错）：** 子类**跨包**时，只能通过「子类类型的引用」访问 protected 成员，不能通过父类类型的引用访问。

#### 7.3 单继承、多实现

|语言|类的继承|接口|
|---|---|---|
|Java / C#|**单继承**|多实现|
|C++|**多继承**|用纯虚函数模拟接口|
|Python|**多继承**（MRO / C3 线性化）|抽象基类 ABC|

**所以「一个类可以继承多个类」这句话，只在 C++/Python 成立。** 题目未指明语言时，按 Java/C# 规则作答。

#### 7.4 继承与多态的关系

不是「有了继承就不需要多态」，而是**继承是多态的前提**：

```java
Parent p = new Child();   // 向上转型
p.show();                 // 若 Child 重写了，运行期调用 Child 的版本
```

没有继承（或接口实现），就没有「父类型引用指向子类型对象」，也就没有运行期动态分派。

**所属知识点：** 计算机基础 / Java OOP / 继承。

### 8 Initialization Order（初始化顺序）

**题目方向：** 给出父类、子类的静态块、实例块、构造器，问输出顺序。

**知识点：Initialization Order**

#### 8.1 固定顺序

```text
父类 static 块  →  子类 static 块  →  父类实例初始化块  →  父类构造器
                                        →  子类实例初始化块  →  子类构造器
```

一句话：**先父后子，先静态后实例。**

#### 8.2 为什么 static 最先

static 属于**类**，在类加载/初始化阶段执行，与对象无关；而 `{ }` 实例块和构造器属于**对象**，在 new 时才跑。**谁属于类谁先跑。**

#### 8.3 为什么父类在子类之前

子类构造器第一行隐式调用 `super()`，所以「父类部分先初始化完，才能初始化子类部分」——对象是一个整体，父类部分是它的地基。

#### 8.4 示例

```java
class Parent {
    static { System.out.print("1"); }
    { System.out.print("2"); }
    Parent() { System.out.print("3"); }
}
class Child extends Parent {
    static { System.out.print("4"); }
    { System.out.print("5"); }
    Child() { System.out.print("6"); }
}
public class Main {
    public static void main(String[] args) { new Child(); }
}
```

输出：

```text
142356
```

#### 8.5 构造器链的两个细节

- 子类构造器第一行若不是 `super(...)`，编译器自动插入**无参** `super()`；
- 若父类**没有无参构造器**（只写了带参的），子类必须**显式**写 `super(参数)`，否则编译错误；
- `this(...)` 与 `super(...)` 不能同时出现在第一行。

**所属知识点：** 计算机基础 / Java OOP / 对象初始化。

### 9 Polymorphism 的三条边界

**题目方向：** 哪些方法能被重写？字段会不会多态？

**知识点：Polymorphism 的边界**

#### 9.1 不能重写的情况

|成员|能否重写|实际发生的是|
|---|---|---|
|static 方法|❌|**隐藏（hiding）**，编译期绑定|
|final 方法|❌|编译报错|
|private 方法|❌（子类不可见）|子类写同名方法是**新方法**|
|构造器|❌|不属于可继承成员|
|**字段（field）**|❌|**字段不多态**：编译期看引用类型|

#### 9.2 字段不多态（最容易错的一条）

```java
class Parent { int x = 1; }
class Child extends Parent { int x = 2; }

Parent p = new Child();
System.out.println(p.x);   // 输出 1，不是 2
```

原因：字段的访问在**编译期**就按「引用变量的声明类型」确定了，不走动态分派。**只有方法才多态。**

#### 9.3 overload vs override 再对照

|对比|Overload（重载）|Override（重写）|
|---|---|---|
|位置|同一个类（或父子类）|子类重写父类|
|签名|方法名同、**参数不同**|方法名 + 参数**完全相同**|
|绑定时机|**编译期**（静态绑定）|**运行期**（动态分派）|
|返回类型|可不同|必须相同或协变|
|能否多态|❌|✅|

**所属知识点：** 计算机基础 / Java OOP / 多态。

### 10 英文例题

**（1）继承**

Which of the following statements about class inheritance is correct?

A. A subclass can extend multiple superclasses in Java.

B. Private members of the superclass are directly accessible inside the subclass.

C. A subclass inherits the fields and methods of its superclass and can override them to change behavior.

D. The superclass constructor is never invoked when a subclass object is created.

E. Inheritance makes polymorphism unnecessary.

**答案：C**

**解析：** A 错——Java 类只能单继承（接口才可多实现），只有 C++/Python 支持多继承类；B 错——private 成员对子类不可见；D 错——子类构造器会（显式或隐式）先调用父类构造器；E 错——继承正是多态的基础。

**（2）static**

Which of the following statements about the `static` keyword is correct?

A. A static method can be overridden.

B. A static variable has a single copy in memory shared by all instances.

C. A new copy of a static variable is created for each object.

D. A static method can directly access the instance variables of its class.

E. Static variables are stored on the stack.

**答案：B**

**解析：** static 属于类，整个类只有一份。A 错——static 方法只能被**隐藏**，不能重写（编译期绑定）；C 与 B 互斥；D 错——static 方法里没有 `this`；E 错——static 变量在方法区/元空间（Java）或静态存储区（C/C++），不在栈上。

**（3）初始化顺序**

```java
class Parent {
    static { System.out.print("1"); }
    { System.out.print("2"); }
    Parent() { System.out.print("3"); }
}
class Child extends Parent {
    static { System.out.print("4"); }
    { System.out.print("5"); }
    Child() { System.out.print("6"); }
}
new Child();
```

What is the output?

A. 123456

B. 142356

C. 132456

D. 142536

E. 124356

**答案：B**

**解析：** 父静态(1) → 子静态(4) → 父实例块(2) → 父构造(3) → 子实例块(5) → 子构造(6)，即 142356。

**所属知识点：** 计算机基础 / Java OOP / 综合应用。

## 前端

### 1. UI 和 UX（User Interface & User Experience）

**题目方向：** UI 和 UX 的概念，以及它们与前端开发（Frontend Development）的关系。

这部分可以复现为一道概念辨析题。

**模拟英文题目：**

What is the main difference between User Interface (UI) and User Experience (UX)?

A. UI focuses on how a product looks, while UX focuses on the overall experience of using the product.

B. UI focuses on database design, while UX focuses on server performance.

C. UI and UX are exactly the same.

D. UX is only related to frontend programming.

**知识点：UI/UX 与前端开发**

（1）UI（User Interface，用户界面）

- 关注产品界面的外观和交互元素。
    
- 包括按钮、菜单、图标、颜色、布局等。
    
- 主要考虑用户如何与界面进行交互。
    

（2）UX（User Experience，用户体验）

- 关注用户使用产品时的整体体验。
    
- 包括易用性、操作流程、交互效率和用户满意度等。
    
- 主要考虑产品是否容易使用、是否满足用户需求。
    

（3）Frontend Development（前端开发）

- 负责将 UI 设计转化为实际可交互的网页或应用界面。
    
- 常用技术包括 HTML、CSS、JavaScript 和 Vue、React 等框架。
    

**答案：A**

**所属知识点：** 软件工程基础 / UI 与 UX / 前端开发基础。
