# 港大 CS 笔试笔记 · 数据结构

## 1. Stack（栈）的简单计算

**题目方向：** 栈的基本操作或简单计算。

面经没有说明具体是栈操作模拟、括号匹配还是表达式计算，因此不模拟具体题目。

**知识点：Stack**

（1）什么是栈？

Stack 是一种后进先出（Last In, First Out，LIFO）的数据结构。

即：最后放入栈中的元素，最先被取出。

（2）基本操作

|操作|英文|作用|
|---|---|---|
|入栈|Push|将元素放入栈顶|
|出栈|Pop|删除栈顶元素|
|查看栈顶|Peek / Top|获取栈顶元素，不删除|
|判空|isEmpty|判断栈是否为空|

（3）简单操作示例

初始栈为空：

```text
Push(1)
Push(2)
Push(3)
Pop()
Push(4)
Pop()
```

操作过程：

```text
Push(1): [1]
Push(2): [1, 2]
Push(3): [1, 2, 3]
Pop():   [1, 2]
Push(4): [1, 2, 4]
Pop():   [1, 2]
```

最终栈中剩余：

```text
[1, 2]
```

（4）栈的常见应用

- 括号匹配（Parentheses Matching）。
    
- 表达式求值（Expression Evaluation）。
    
- 函数调用与递归。
    
- 深度优先搜索（DFS）。
    
- 字符串反转。
    

**所属知识点：** 数据结构 / 线性数据结构 / 栈。
## 2. Queue（队列）

**题目方向：** BFS 用哪种数据结构存放待访问的节点？队列的基本特性与变体。

**知识点：Queue**

（1）什么是队列？

Queue 是一种先进先出（First In, First Out，FIFO）的数据结构。

即：最先放入队列的元素，最先被取出（与栈正好相反）。

（2）基本操作

|操作|英文|作用|
|---|---|---|
|入队|Enqueue / Push|将元素放入队尾（rear）|
|出队|Dequeue / Pop|删除队头（front）元素|
|查看队头|Front / Peek|获取队头元素，不删除|
|判空|isEmpty|判断队列是否为空|

（3）队列的变体

|变体|英文|特点|典型用途|
|---|---|---|---|
|循环队列|Circular Queue|用取模复用数组空间，避免「假溢出」|固定大小缓冲区|
|双端队列|Deque (Double-Ended Queue)|两端都可进出|0-1 BFS、滑动窗口最大值|
|优先队列|Priority Queue|按优先级出队，通常用堆实现|Dijkstra、A*、Prim、Huffman|

（4）五种容器与它们的典型使用者（选择题的核心对照）

|容器|出队规则|谁在用|为什么|
|---|---|---|---|
|Stack 栈|LIFO|DFS、括号匹配、表达式求值、递归|一条路走到底再回溯|
|Queue 队列|FIFO|**BFS**、Kahn 拓扑排序、层序遍历|按发现顺序处理，保证「层」不被打乱|
|Priority Queue 优先队列|按优先级|Dijkstra、A*、Prim、Huffman|每轮要「当前最小」，不是「最早」|
|Deque 双端队列|两端皆可|0-1 BFS、滑动窗口最大值|0 权边从队头入、1 权边从队尾入|
|Hash Table 哈希表|O(1) 查存|visited 集合、去重|判断「访问过没有」，不是「下一个访问谁」|

**需要记住：**

BFS uses a queue; DFS uses a stack (or the recursion call stack). Dijkstra uses a priority queue, not a plain queue.

**英文例题：**

Which data structure does breadth-first search (BFS) use to store the set of nodes waiting to be visited?

A. Stack

B. Queue

C. Priority queue

D. Deque

E. Hash table

**答案：B**

**解析：** BFS 按「层」扩展，先发现先访问，符合 FIFO，因此用队列。DFS 用栈（递归本身即调用栈）；Dijkstra 用优先队列（每轮取距离最小的点，靠的是优先级而非到达顺序）；哈希表用于 visited 集合。

**所属知识点：** 数据结构 / 线性数据结构 / 队列。

## 3. Linked List vs Array（链表与数组）

**题目方向：** 与数组相比，链表的优点是什么？

**知识点：Linked List**

（1）什么是链表？

Linked List 由一系列节点（node）组成，每个节点包含数据域和指针域（指向下一个节点）。节点在内存中**不连续**。

（2）与数组的完整对比

|操作 / 性质|Array 数组|Linked List 链表|谁更优|
|---|---|---|---|
|按下标随机访问 a[k]|O(1)|O(k)（必须从头走）|**数组**|
|已知位置插入 / 删除|O(n)（后面全体搬移）|**O(1)**（改指针）|**链表**|
|查找某个值|O(n)；有序则 O(log n)|O(n)|数组（有序时）|
|二分查找|可以|**不行**（定位中点要 O(n)）|**数组**|
|内存布局|连续|分散|**数组**|
|缓存局部性（cache locality）|好（预取命中率高）|差（指针跳转，cache miss 多）|**数组**|
|每个元素的内存开销|只有数据|数据 + 1~2 个指针（64 位下 8~16 字节）|**数组**|
|容量扩展|需扩容 + 拷贝（动态数组均摊 O(1)）|天然可增长|链表|

（3）注意「已知位置」这个前提

「链表插入删除是 O(1)」**只在已经拿到该位置指针时成立**。如果要「按值插入」，链表先要 O(n) 找到位置，整体仍是 O(n)。

（4）链表的变体

|类型|英文|特点|
|---|---|---|
|单链表|Singly Linked List|每个节点一个 next 指针|
|双链表|Doubly Linked List|prev + next，可 O(1) 删除已知节点|
|循环链表|Circular Linked List|尾节点指回头节点|

**英文例题：**

Which of the following is an advantage of a linked list over an array?

A. Constant-time random access by index.

B. Better cache locality.

C. Insertion or deletion at a known position takes O(1) time.

D. Each element occupies less memory.

E. Binary search can be performed directly.

**答案：C**

**解析：** 找到位置后只改指针，不搬移元素 → O(1)。其余四项都是数组的优势：随机访问 O(1)、内存连续带来高缓存命中、无需额外指针域、有序数组可二分。题干里「known position」四个字是 C 唯一成立的前提。

**所属知识点：** 数据结构 / 线性数据结构 / 链表；与数组的复杂度对比。

## 4. Hash Table（哈希表）

**题目方向：** 哈希冲突怎么处理？删除元素时为什么不能直接置空？

**知识点：Hash Table**

（1）什么是哈希表？

Hash Table 通过哈希函数 h(k) 把键映射到槽位（slot），从而实现平均 O(1) 的插入、查找、删除。

（2）冲突处理的两大流派

|方法|英文|做法|删除时的问题|
|---|---|---|---|
|链地址法|Separate Chaining|每个槽挂一条链表（或红黑树）|从链表摘除即可，**没有问题**|
|开放定址法|Open Addressing|按探测序列找下一个空槽|**不能直接置空**，要用墓碑|

开放定址的三种探测方式：

- 线性探测（Linear Probing）：h(k), h(k)+1, h(k)+2 … 容易产生「一次聚集（primary clustering）」。
- 二次探测（Quadratic Probing）：h(k)+1², h(k)+2² … 缓解聚集。
- 双重哈希（Double Hashing）：再用第二个哈希函数决定步长。

（3）删除为什么必须用墓碑（tombstone）

哈希函数 h(k) = k mod 7，线性探测依次插入 1、8、15：分别落在槽 1、槽 2、槽 3。

此时删除 8。若把槽 2 直接标成 EMPTY，再查找 15：

```text
查 15：h(15)=1 → 槽 1 是 1，不是 15 → 探测槽 2
       槽 2 是 EMPTY → 判定「不存在」→ 返回 not found   ← 错！
```

原因：查找规则是「沿探测序列逐个比较，**遇到空槽即判定不存在**」。直接置空等于在探测簇中间砌了一道墙。

墓碑标记（DELETED）的语义是「这里曾有人，请继续往后找」，它既不阻断探测，又能在插入时被复用。

（4）三种槽位状态

|状态|含义|查找时|插入时|
|---|---|---|---|
|EMPTY|从未使用|停止，判定不存在|可用|
|OCCUPIED|有效元素|比较|跳过|
|DELETED（墓碑）|曾被占用、已删除|**继续探测**|**可复用**|

（5）负载因子与复杂度

$$\text{load factor } \alpha=\frac{n}{m}\quad(\text{元素数} / \text{槽位数})$$

- 平均查找 O(1 + α)；
- α 越大冲突越多，通常超过 0.75 就扩容（Java HashMap 的阈值就是 0.75）；
- 墓碑过多时探测变慢，**标准补救是重哈希（rehash）**。

**英文例题：**

In a hash table that resolves collisions by open addressing with linear probing, why is a deleted slot usually marked with a special "deleted" (tombstone) flag rather than being reset to empty?

A. Because resetting the slot would invalidate the hash function.

B. Because an empty slot would break the probe sequence and make later elements unreachable.

C. Because the slot will be immediately reused by the next insertion.

D. Because an empty slot cannot be distinguished from a key whose value is 0.

E. Because the whole table must be rehashed after every deletion.

**答案：B**

**解析：** A 错——哈希函数只由键决定，与槽内存什么无关；C 错——墓碑确实可被复用，但那是**结果**不是**理由**（因果倒置）；D 错——槽位有独立的状态标记，与键值无关；E 错——避免「每次删除都重哈希」正是墓碑存在的意义。

**所属知识点：** 数据结构 / 哈希表 / 冲突处理与删除。

## 5. Tree、BST 与遍历（Tree / BST / Traversal）

**题目方向：** 二叉搜索树查找的最坏复杂度？给定二叉树求中序遍历？

**知识点：Tree**

（1）基本术语

|术语|英文|含义|
|---|---|---|
|根|Root|最顶层节点|
|叶子|Leaf|没有子节点的节点|
|高度|Height|根到最深叶子的边数（或节点数，看教材约定）|
|度|Degree|一个节点的子节点个数（图论口径下还要算上父边，见第 9 章）|

> **度数求和与结点计数**（Σdeg = 2(n−1)、n0 = n2 + 1、满 m 叉树、完全二叉树叶子数）见 **第 9 章**，那是独立的一套计数公式，不依赖遍历。

（2）二叉搜索树（Binary Search Tree, BST）的性质

对任意节点：**左子树所有键 < 根 < 右子树所有键**；中序遍历得到**升序序列**。

（3）BST 的查找代价只看树高 h

|树的形态|树高 h|查找|
|---|---|---|
|完全平衡（AVL / 红黑树）|⌊log₂n⌋ + 1|O(log n)|
|随机插入的 BST|≈ 1.39 log₂n（期望）|O(log n)|
|退化成链的 BST|n|**O(n)**|

退化怎么发生：依次插入 1,2,3,4,5，每次新元素都比已插入的大，于是永远往右走：

```text
1
 \
  2
   \
    3
     \
      4
       \
        5
```

**题目问「worst case」→ 答 O(n)；问「average case」或「balanced BST」→ 答 O(log n)。**

（4）三种深度优先遍历：名字就是「根」的位置

|遍历|英文|顺序|性质|
|---|---|---|---|
|前序|Preorder|根 → 左 → 右|第一个元素是根|
|中序|Inorder|左 → 根 → 右|**BST 的中序是升序**|
|后序|Postorder|左 → 右 → 根|最后一个元素是根|
|层序|Level-order|逐层从左到右|用队列（BFS）|

（5）遍历示例

```text
        A
       / \
      B   C
     / \  /
    D  E F
```

- 前序：A B D E C F
- 中序：D B E A F C
- 后序：D E B F C A
- 层序：A B C D E F

（6）能不能唯一还原一棵二叉树？

|已知|能否唯一确定|
|---|---|
|前序 + 中序|✅ 可以|
|后序 + 中序|✅ 可以|
|前序 + 后序|❌ 不行（分不清「只有左孩子」还是「只有右孩子」）|

还原四步：前序首元素 = 根 → 在中序里定位根，左边是左子树、右边是右子树 → 按长度切出前序的两段 → 递归。

**英文例题：**

What is the worst-case time complexity of searching for a key in a binary search tree with n nodes?

A. O(1)

B. O(log n)

C. O(n)

D. O(n log n)

E. O(n²)

**答案：C**

**解析：** 查找代价 = O(h)。按递增（或递减）顺序插入时 BST 退化成单链，h = n，退化为顺序查找。只有在平衡的情况下（AVL、红黑树）才保证 O(log n)——这是本题最大的陷阱：记住「BST 查找是 log n」却忘了前提是平衡。

**所属知识点：** 数据结构 / 树 / 二叉搜索树与遍历。

## 6. Valid Pop Sequence（合法出栈序列）

**题目方向：** 元素依次入栈，哪个出栈序列不可能出现？

**知识点：栈的应用——出栈序列判定**

（1）两种判定法

**方法一：逐个模拟（最稳）**

按目标序列走，每步：① 把还没入栈的元素一直 push 到栈顶 = 当前要的那个；② 若栈顶 ≠ 当前要的，则此序列非法。

**方法二：降序法则（3 秒判断）**

序列中任取一个元素 x，**在 x 之后出现的、所有比 x 小的元素，必须按从大到小排列**。

（2）为什么降序法则成立

当 x 出栈时，比 x 小且尚未出栈的元素**全被压在 x 下面**，而栈只能从顶部弹——所以它们只能后进先出，即从大到小弹出。

（3）示例：1,2,3,4 依次入栈，判断 3,1,2,4

取 x = 3，其后比 3 小的有 1、2，出现顺序是 **1 然后 2（升序）** → 违规，不可能。

模拟验证：

```text
想要 3 → push1,push2,push3 → pop3    栈: [1,2]
想要 1 → 栈顶是 2，不是 1 → 非法
```

（4）合法序列总数：卡特兰数（Catalan number）

$$C_n=\frac{1}{n+1}\binom{2n}{n}:\quad C_3=5,\ C_4=14,\ C_5=42$$

n = 4 共有 14 种合法序列，而全部排列有 4! = 24 种——**近一半的排列都是非法的**。

**英文例题：**

Elements 1, 2, 3, 4 are pushed onto an initially empty stack in this order, with pushes and pops interleaved arbitrarily. Which of the following pop sequences is NOT possible?

A. 1, 2, 3, 4

B. 4, 3, 2, 1

C. 1, 3, 2, 4

D. 3, 1, 2, 4

E. 2, 4, 3, 1

**答案：D**

**解析：** 先弹 3 说明 1、2 仍在栈内且 2 压在 1 上面，此后栈顶只能是 2，不可能先弹 1 再弹 2。用降序法则：取 x = 3，其后比 3 小的为 1、2，呈升序 → 违规。

**所属知识点：** 数据结构 / 栈 / 出栈序列与卡特兰数。

## 7. Binary Search（二分查找）

**题目方向：** 二分查找的复杂度？边界怎么写才不会死循环？

**知识点：Binary Search**

（1）两个前提，缺一不可

- 数组**已排序**；
- 支持 **O(1) 随机访问**——链表即使有序也不能二分（定位中点本身就要 O(n)）。

（2）复杂度

$$T(n)=T\!\left(\frac{n}{2}\right)+O(1)\;\Longrightarrow\;T(n)=O(\log n)$$

最多比较次数：

$$\left\lfloor\log_2 n\right\rfloor+1$$

直觉：n 每翻一倍，只多比较 1 次。n = 1000 时 2⁹ = 512 < 1000 ≤ 1024 = 2¹⁰，所以最多 10 次。

（3）两套模板（写代码题时才用，选择题考「哪个不会死循环」）

|模板|区间表示|循环条件|更新|
|---|---|---|---|
|闭区间|lo, hi 都**包含**|while (lo <= hi)|lo = mid + 1 / hi = mid − 1|
|左闭右开|hi **不包含**|while (lo < hi)|lo = mid + 1 / hi = mid|

要点：**两套模板内部的「循环条件」和「更新方式」必须配套**，混用才会死循环或漏元素。

（4）mid 的防溢出写法

```java
int mid = lo + (hi - lo) / 2;   // 安全
// int mid = (lo + hi) / 2;      // lo + hi 可能溢出成负数
```

（5）lower_bound / upper_bound

|函数|返回|含义|
|---|---|---|
|lower_bound(x)|第一个 **≥ x** 的位置|插入 x 的最左位置|
|upper_bound(x)|第一个 **> x** 的位置|插入 x 的最右位置|

**英文例题：**

An array of n = 1000 elements is sorted in ascending order. What is the maximum number of comparisons binary search needs in the worst case?

A. 9

B. 10

C. 11

D. 100

E. 500

**答案：B**

**解析：** ⌊log₂1000⌋ + 1 = 9 + 1 = 10。A 是漏掉「+1」（只剩一个元素时仍要比较一次）；C 是又多加一次；D 是线性查找；E 是「每次查一半元素」。

**所属知识点：** 数据结构 / 查找 / 二分查找。

## 9. 树的度数与结点计数（Degree & Node Counting）

**题目方向：** 已知一棵树各结点的度数分布，求叶子数；或已知二叉树叶子数，求度为 2 的结点数。

**知识点：树的度数性质**

（1）先统一「度」的定义（口径不同，答案差很多）

| 语境 | 度的定义 | 例：根有 2 个孩子 |
|---|---|---|
| 图论（把树看成无向图） | 与该顶点相连的**边数** | 度 = **3**（2 条孩子边 + 1 条父边） |
| 数据结构（根树 / 有序树） | 结点的**孩子数** | 度 = **2** |
| 有向树 | 出度 = 孩子数；入度除根外都是 1 | 出度 = 2 |

判据：题干说 "a tree with n nodes, the sum of degrees" 一般指**图论口径**；说 "binary tree / full m-ary tree" 一般指**孩子数**。

（2）树的两条基本关系

```text
边数：      E = n − 1
握手定理：  Σdeg = 2E = 2(n − 1)
```

含义：每条边被两个端点各贡献 1 度，所以度数总和恒为 2(n−1)。这是「已知度数分布求结点数」的唯一钥匙。

（3）二叉树：n0 = n2 + 1

设 n0、n1、n2 分别是度为 0（叶子）、1、2 的结点数：

```text
结点数：    n = n0 + n1 + n2
孩子总数：  n1 + 2·n2 = n − 1        （孩子数之和 = 边数）
联立：       n0 = n2 + 1
```

推导中 n1 被消掉了，所以这条公式**对任意二叉树都成立**，与有没有单孩子结点无关——这是它最容易被误用的地方（很多人以为只对满二叉树成立）。

（4）满 m 叉树：n = m·i + 1

每个内部结点恰好 m 个孩子，i 为内部结点数：

```text
总结点数：  n = m·i + 1
叶子数：    n − i = (m − 1)·i + 1
```

（5）完全二叉树的三条常用结论

```text
叶子数 = ⌈n/2⌉  =  n − ⌊n/2⌋      （结点 1..⌊n/2⌋ 有孩子，其余是叶子）
n1 只能是 0 或 1： n 偶 → n1 = 1；n 奇 → n1 = 0
高度 = ⌊log₂n⌋ + 1
```

（6）解题四步模板

```text
Step 1  按度数把结点分类，设未知数（叶子数 L、度 1 个数、度 2 个数…）
Step 2  写结点数方程：n = 各类之和
Step 3  写度数方程：Σdeg = 2(n − 1)（或 Σ孩子数 = n − 1）
Step 4  联立求解，并用「边数 = n − 1」验算
```

**英文例题：**

**（1）由度数分布求叶子数**

A tree has 2 vertices of degree 3, 1 vertex of degree 2, and all remaining vertices are leaves. How many leaves does the tree have?

A. 2

B. 3

C. 4

D. 5

E. 6

**答案：C（4）**

**解析：** 设叶子数 L。结点数 n = L + 3；度数总和 = 3×2 + 2×1 + L = 8 + L。由 Σdeg = 2(n−1) 得 8 + L = 2(L+2)，解得 L = 4。验算：n = 7，边数 6，3+3+2+1+1+1+1 = 12 = 2×6 ✓

**易错：** 忘掉「叶子也贡献 1 度」。

**（2）叶子数与双孩子结点**

A binary tree has 20 leaves. How many nodes have exactly two children?

A. 18

B. 19

C. 20

D. 21

E. Cannot be determined

**答案：B（19）**

**解析：** 由 n0 = n2 + 1 得 n2 = 20 − 1 = 19。因为该公式与 n1 无关，所以「无法确定」是错的。

**（3）满 m 叉树**

A full ternary (3-ary) tree has 10 internal nodes. How many leaves does it have?

A. 20

B. 21

C. 30

D. 31

E. 40

**答案：B（21）**

**解析：** n = 3×10 + 1 = 31，叶子 = 31 − 10 = 21（或 (3−1)×10 + 1 = 21）。验算：孩子总数 30 = 边数 31−1 ✓

**（4）完全二叉树的叶子数**

A complete binary tree has 1000 nodes. How many leaves does it have?

A. 499

B. 500

C. 501

D. 512

E. 999

**答案：B（500）**

**解析：** 有孩子的结点是 1..⌊1000/2⌋ = 1..500，其余为叶子 → 1000 − 500 = 500。因 n 为偶数，n1 = 1，故 n2 = 499，校验 500 + 1 + 499 = 1000 ✓ 且 n0 = n2 + 1 ✓。高度 = ⌊log₂1000⌋ + 1 = 10。

（7）六个易错点

| # | 错误 | 正确 |
|---|---|---|
| 1 | 用「孩子数」去算 Σdeg | 图论口径下根还有 1 条父边，Σdeg = 2(n−1) |
| 2 | 算度数总和时漏掉叶子 | 每个叶子也贡献 1 度 |
| 3 | 以为 n0 = n2 + 1 只对满二叉树成立 | 对任意二叉树都成立 |
| 4 | 用 n0 = n2 + 1 时把 n1 也算进去 | 公式里没有 n1；n1 只影响总数 n |
| 5 | 混淆 full / complete / perfect | full = 每点 0 或 2 个孩子；complete = 除末层外全满且末层靠左；perfect = 全满且叶同层 |
| 6 | 满 m 叉树当成「最多 m 个孩子」 | full 是**恰好** m 个 |

**需要记住：**

In any tree with n vertices, the sum of all degrees is 2(n − 1). In any binary tree, the number of leaves equals the number of two-child nodes plus one: n0 = n2 + 1.

**所属知识点：** 数据结构 / 树 / 度数性质与结点计数。
