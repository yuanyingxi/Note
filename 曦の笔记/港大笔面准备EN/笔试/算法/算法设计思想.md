# 1 Greedy Algorithm（贪心算法）

**题目方向：** 贪心算法在什么情况下会失效？

面经没有提供具体题目，因此只整理核心知识点。

**知识点：Greedy Algorithm**

（1）什么是贪心算法？

贪心算法是一种算法思想，每一步都选择当前看起来最优的方案，希望通过局部最优得到全局最优。

（2）贪心算法的两个重要性质

- Greedy Choice Property（贪心选择性质）：每一步的局部最优选择能够导向全局最优解。
    
- Optimal Substructure（最优子结构）：原问题的最优解包含子问题的最优解。
    

（3）贪心算法什么时候可能失效？

当每一步的局部最优选择不能保证最终得到全局最优解时，贪心算法可能失效。

例如：

假设硬币面值为 1、3、4，需要凑出金额 6。

贪心算法每次选择最大面值：

- 第一步：选择 4。
    
- 第二步：剩余 2，选择 1。
    
- 第三步：剩余 1，再选择 1。
    

最终使用 3 枚硬币。

但最优方案是：

- 选择 3。
    
- 再选择 3。
    

只需要 2 枚硬币。

因此，贪心算法不一定能够得到全局最优解。

（4）贪心算法与动态规划的区别

|对比|Greedy|Dynamic Programming|
|---|---|---|
|中文|贪心算法|动态规划|
|核心思想|每一步选择局部最优|保存并利用子问题的结果|
|是否考虑后续影响|通常不重新考虑之前的选择|通过状态转移综合考虑|
|是否保证最优|需要满足特定性质|正确设计状态和转移时可以保证|

**所属知识点：** 数据结构与算法 / 算法设计思想 / 贪心算法。

# 2 Dynamic Programming（动态规划）

**题目方向：** 使用动态规划求斐波那契数列。

这部分可以根据面经复现一道基础编程题。

**模拟英文题目：**

Given an integer n, calculate the n-th Fibonacci number using dynamic programming.

The Fibonacci sequence is defined as follows:

```text
F(0) = 0
F(1) = 1

F(n) = F(n - 1) + F(n - 2), for n >= 2
```

Write a program to calculate F(n).

**Example:**

```text
Input:
6

Output:
8
```

**知识点：Dynamic Programming**

（1）什么是动态规划？

动态规划（Dynamic Programming，DP）是一种算法思想，通过将原问题拆分成多个子问题，保存已经计算过的结果，避免重复计算。

（2）动态规划的三个基本要素

- State（状态）：定义每个子问题代表什么。
    
- State Transition（状态转移）：描述状态之间的关系。
    
- Initial State（初始状态）：确定最开始的状态值。
    

（3）斐波那契数列的状态定义

定义：

```text
dp[i] 表示第 i 个斐波那契数。
```

初始状态：

```text
dp[0] = 0
dp[1] = 1
```

状态转移方程：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

（4）Python 代码

```python
n = int(input())

if n == 0:
    print(0)
elif n == 1:
    print(1)
else:
    dp = [0] * (n + 1)
    dp[0] = 0
    dp[1] = 1

    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]

    print(dp[n])
```

（5）复杂度分析

- 时间复杂度：O(n)，每个状态只计算一次。
    
- 空间复杂度：O(n)，使用数组保存每个状态。

**所属知识点：** 数据结构与算法 / 动态规划 / 线性 DP。

# 3 分治（Divide and Conquer）与减治（Decrease and Conquer）

**题目方向：** 哪些算法采用分治思想？分治与减治的区别？

**知识点：Divide and Conquer**

（1）分治的三步

```text
Divide   把原问题拆成若干规模更小的子问题（通常 2 个）
Conquer  递归求解每个子问题
Combine  把子问题的解合并成原问题的解
```

（2）减治：每轮只留一个子问题

|对比|分治 Divide and Conquer|减治 Decrease and Conquer|
|---|---|---|
|子问题个数|通常 2 个，**都要解**|每轮只解 **1 个**|
|递归式|T(n) = 2T(n/2) + f(n)|T(n) = T(n/2) + f(n)|
|复杂度|O(n log n) 常见|O(log n) 常见|
|例子|归并排序、快速排序|二分查找、快速选择（quickselect）|

（3）常见算法的归类

|算法|思想|
|---|---|
|归并排序|分治（分区易、合并难）|
|快速排序|分治（分区难、合并易——分区完即有序）|
|二分查找|减治|
|快速选择（求第 k 大）|减治|
|大整数乘法、Strassen 矩阵乘|分治|
|汉诺塔|分治（T(n) = 2T(n−1) + 1）|

（4）分治与动态规划的分界线

**子问题是否重叠**。分治的子问题互相独立（归并排序的左右两半各排各的）；DP 的子问题相互重叠，所以要「存表复用」。

**需要记住：**

Divide and conquer splits into **overlapping-free** subproblems; DP is needed when subproblems **overlap**.

# 4 Backtracking（回溯法）

**题目方向：** 哪类问题用回溯？回溯与 DFS 的关系？

**知识点：Backtracking**

（1）什么是回溯？

回溯是「**系统地枚举所有候选解 + 剪枝**」的搜索方法。它沿着一条路径尝试，走不通就撤销上一步（backtrack），换下一个候选。

（2）与 DFS 的关系

回溯通常**用 DFS 实现**：DFS 是「遍历方式」，回溯是「带撤销与剪枝的遍历策略」。

（3）通用模板

```text
def backtrack(path, choices):
    if 满足结束条件:
        记录 path
        return
    for choice in choices:
        if 不合法: continue        # 剪枝
        做出选择（path.append）
        backtrack(path, 剩余选择)
        撤销选择（path.pop）        # 回溯的关键一步
```

（4）典型问题

|问题|候选|剪枝条件|
|---|---|---|
|全排列|每个未使用的数|已使用则跳过|
|N 皇后|每行选一列|同列、同对角线冲突|
|子集 / 幂集|每个元素选或不选|—|
|数独|每格填 1–9|行、列、宫冲突|
|组合总和|每个数可选多次|和超过目标则停|

（5）复杂度

最坏是指数级（枚举所有组合），剪枝只能改善常数与平均表现，不能改变最坏阶。

**需要记住：**

Backtracking = DFS + **undo** the choice + **pruning**. It enumerates candidates and is exponential in the worst case.

# 5 算法识别指纹表（Description → Algorithm）

**题目方向：** 给一段文字描述或一段代码，问这是哪个算法。这是 27fall 最典型的「会认」类题目。

**知识点：算法识别**

（1）三步法

```text
Step 1  找「标志性动作」：代码里最独特的那一行
Step 2  看「数据结构」：用了堆？并查集？队列？二维表？
Step 3  看「递归结构」：分成两半都递归？还是只递归一个？
```

（2）文字描述 → 算法

| 描述里的关键词                                                         | 算法               |
| --------------------------------------------------------------- | ---------------- |
| pick a **pivot**, **partition**, recurse on both sides          | **快速排序**         |
| split in half, sort each half, **merge**                        | **归并排序**         |
| build a **heap**, repeatedly **sift down**                      | **堆排序**          |
| repeatedly pick the **smallest** and swap to the front          | 选择排序             |
| insert each element into its correct place in the sorted prefix | 插入排序             |
| swap **adjacent** elements if out of order                      | 冒泡排序             |
| sort edges by weight, use **Union-Find**, avoid cycles          | **Kruskal**      |
| grow a tree from one vertex, always add the **cheapest** edge   | **Prim**         |
| relax **all edges V−1** times                                   | **Bellman-Ford** |
| take the **closest unvisited** vertex, relax its neighbours     | **Dijkstra**     |
| table of size V×V, loop over intermediate vertex k              | **Floyd**        |
| halve the search range each step                                | **二分查找**         |
| **overlapping subproblems**, solve once, **store** results      | **动态规划**         |
| local optimum at each step, never reconsider                    | **贪心**           |
| enumerate candidates, **undo** choices, **prune**               | **回溯**           |
| queue of **zero-indegree** vertices                             | **拓扑排序（Kahn）**   |

（3）代码指纹 → 算法

|代码里出现|算法|
|---|---|
|`pivot = a[hi]` + 双指针交换 + 两侧递归|快排|
|`a[:m] + a[m:]`（按**位置**切）+ merge|归并|
|`for k in range(V): for i: for j:`|Floyd|
|`parent[]` + `find()` / `union()`|Kruskal / 并查集|
|`dist[u] + w < dist[v]` 松弛|最短路（Dijkstra / BF）|
|`dp[i] = dp[i-1] + dp[i-2]`|线性 DP|
|`dp[i][j] = dp[i-1][j-1] + 1`（二维表 + 左上角 +1）|LCS|
|`while lo <= hi: mid = ...`|二分|

（4）两个最需要区分的组合

|看起来像|区分点|
|---|---|
|快排 vs 归并|**按值切**（`x < pivot`）→ 快排；**按位置切**（`a[:m]`）→ 归并|
|快排 vs 选择排序|快排有**递归 + 分区**；选择排序只有「每轮选最小」|

**英文例题：**

An algorithm works as follows: pick an element as the pivot, partition the array so that elements smaller than the pivot come before it and larger come after it, then recursively sort the two parts. Which algorithm is being described?

A. Merge sort

B. Insertion sort

C. Quick sort

D. Heap sort

E. Selection sort

**答案：C**

**解析：** `pivot + partition + 双侧递归` 是快排的标志性动作。归并是「对半切 + 合并」；堆排是「建堆 + 反复取堆顶」；选择排序没有递归和分区（「选基准」与「选择排序」是两个概念）。

**所属知识点：** 数据结构与算法 / 算法设计思想 / 算法识别。

# 6 循环复杂度速判

**题目方向：** 给一段嵌套循环，问时间复杂度。

**知识点：复杂度分析**

（1）七种基本形态（看到就能报答案）

|代码形态|复杂度|说明|
|---|---|---|
|for i in 1..n|O(n)|单层线性|
|for i: for j in 1..n|O(n²)|全嵌套（矩形）|
|for i: for j in 1..i|O(n²)|三角循环，共 n(n+1)/2|
|for i: for j in 1..n step i（外层 +1）|**O(n log n)**|调和级数 n·H(n)|
|**while i ≤ n: … i *= 2**（外层 ×2，内层步长 = i）|**O(n)**|等比收敛，总和 < 2n|
|while n > 1: n //= 2|O(log n)|每次减半|
|while i*i ≤ n: i++|O(√n)|判素数、试除|

（2）判复杂度的三步法

```text
Step 1  写出循环变量的取值范围
Step 2  写出内层执行次数的求和式 Σ
Step 3  用求和公式化简，取最高阶
```

常用求和公式（纯文本形式）：

```text
Σ(i = 1..n) i        = n(n+1)/2      = O(n²)
Σ(i = 1..n) n/i      = n·H(n)        = O(n log n)      ← 调和，发散
Σ(i = 0..log n) n/2^i = n(1+1/2+1/4+…) < 2n = O(n)      ← 等比，收敛
Σ(i = 1..n) i²       = O(n³)
```

（3）最值钱的四句口诀

|外层走法|内层步长|复杂度|
|---|---|---|
|i = 1..n（+1）|j 跑到 i|O(n²)|
|i = 1..n（+1）|j += i（n/i 次）|O(n log n)|
|i ×2|j 跑满 n|O(n log n)|
|i ×2|j += i|**O(n)**|

（4）五个「看起来更慢、其实更快」的陷阱

- 双指针：外层 while (i < j)，内层可能移动多次，但**总移动次数 ≤ n** → O(n)。
- 建堆 heapify 自底向上 → O(n)，不是 O(n log n)。
- 字符串循环拼接 s = s + c → O(n²)。
- 递归 T(n) = 2T(n/2) + n → O(n log n)，不是 O(n²)。
- 快排平均 O(n log n)、最坏 O(n²)（已有序或大量重复时退化）。

**英文例题：**

```c
int i = 1, s = 0;
while (i <= n) {
    for (int j = 1; j <= n; j += i)
        s++;
    i *= 2;
}
```

What is the time complexity with respect to n?

A. O(log n)

B. O(n)

C. O(n log n)

D. O(n²)

E. O(n² log n)

**答案：B**

**解析：** 外层 i 取 1, 2, 4, …，共 log n 轮；第 t 轮内层跑 n/2^t 次。总和 n(1 + 1/2 + 1/4 + …) < 2n，等比级数有常数上界 → O(n)。代入 n = 8 手算：8 + 4 + 2 + 1 = 15 < 16。选 C 的人是「把最坏一轮当成每一轮」。

**所属知识点：** 数据结构与算法 / 复杂度分析 / 循环。

# 7 递归复杂度与主定理

**题目方向：** 给一个递归式，问时间复杂度。

**知识点：主定理（Master Theorem）**

（1）标准形式

```text
T(n) = a·T(n/b) + f(n)     其中 a ≥ 1, b > 1
```

（2）三种情形（比较 f(n) 与 n^(log_b a)）

|情形|条件|结论|
|---|---|---|
|1|f(n) = O(n^(log_b a − ε))|T(n) = Θ(n^(log_b a))|
|2|f(n) = Θ(n^(log_b a))|T(n) = Θ(n^(log_b a) · log n)|
|3|f(n) = Ω(n^(log_b a + ε)) 且满足正则条件|T(n) = Θ(f(n))|

（3）必须背的四个结果

|递归式|算法|复杂度|
|---|---|---|
|T(n) = 2T(n/2) + n|归并 / 快排（平均）|O(n log n)|
|T(n) = 2T(n/2) + 1|遍历二叉树|O(n)|
|T(n) = T(n/2) + 1|二分查找|O(log n)|
|T(n) = 2T(n−1) + 1|汉诺塔|O(2ⁿ)|

（4）递归调用次数（选择题爱考）

朴素递归斐波那契 fib(n) = fib(n−1) + fib(n−2)，计算 fib(n) 的总调用次数：

```text
C(0) = C(1) = 1
C(n) = C(n−1) + C(n−2) + 1      （+1 是根自己那次调用）
```

```text
n   : 0  1  2  3  4  5   6
C(n): 1  1  3  5  9  15  25
```

闭式：C(n) = 2·Fib(n+1) − 1（Fib 为标准斐波那契，Fib(6) = 8 → C(5) = 15）。

**三个「同阶」结论：调用次数、返回值、时间复杂度三者同阶，都是 O(2ⁿ)。加记忆化后降为 O(n)。**

（5）主定理不适用的情形

T(n) = 2T(n/2) + n log n 这类「差一个 log 因子」的边界情形，主定理的三种情形都不严格满足，需要展开递归树或用 Akra–Bazzi。选择题不会考这么深。

**英文例题：**

How many times is the function called in total (including the initial call) when evaluating fib(5) with naive recursion?

A. 9

B. 12

C. 13

D. 15

E. 25

**答案：D**

**解析：** 逐项推 C(0)=C(1)=1，C(2)=3，C(3)=5，C(4)=9，C(5)=15。闭式验证 2·Fib(6) − 1 = 16 − 1 = 15。选 9 是少算一层（C(4) 的值）。

**所属知识点：** 数据结构与算法 / 复杂度分析 / 递归与主定理。

# 8 均摊分析（Amortized Analysis）

**题目方向：** 动态数组 push 的复杂度为什么是 O(1)？双指针为什么是 O(n)？

**知识点：均摊分析**

（1）什么是均摊分析？

一次操作可能很贵（如扩容要 O(n)），但**连续 m 次操作的总代价**平均下来很小。均摊分析算的是「每次操作的平均代价」，不是「最坏一次」。

（2）三个经典结论

|场景|单次最坏|均摊|
|---|---|---|
|动态数组 push（满时翻倍）|O(n)|**O(1)**|
|双指针（i 只增、j 只增）|—|**O(n)** 总移动|
|建堆 heapify（自底向上）|—|**O(n)**（不是 O(n log n)）|

（3）为什么 push 均摊是 O(1)（聚合分析法）

扩容发生在第 1、2、4、8、…、n 次插入，总拷贝代价：

```text
1 + 2 + 4 + … + n < 2n
```

n 次插入总代价 < 2n → 每次均摊 O(1)。**关键仍是「等比级数收敛」这个工具。**

（4）建堆为什么是 O(n)

第 h 层的节点最多有 n/2^h 个，每个节点下沉最多 h 层：

```text
Σ(h = 0..log n) (n/2^h)·h = O(n)      ← 级数收敛，不是 n log n
```

直觉：绝大多数节点在底层、根本不用下沉；只有根可能下沉 log n 层。

**英文例题：**

A dynamic array (like C++ `vector` or Java `ArrayList`) doubles its capacity whenever it becomes full. Starting from empty, we perform n `push_back` operations. What is the **amortized** time complexity of a single push?

A. O(1)

B. O(log n)

C. O(n)

D. O(n log n)

E. O(n²)

**答案：A（O(1)）**

**解析：** 扩容发生在第 1、2、4、8、…、n 次插入，每次要把旧元素全部搬走，拷贝总代价为

```text
1 + 2 + 4 + … + n < 2n
```

n 次插入的总代价 < 2n，均摊到每次就是 O(1)。**注意区分「单次最坏」与「均摊」**：某一次 push 的最坏代价是 O(n)（正好触发扩容），但均摊是 O(1)——选项 C 是把「最坏一次」当成了「平均每次」。

**需要记住：**

Amortized cost of push on a dynamic array is O(1) — the expensive resizes are paid for by all the cheap pushes in between.

**所属知识点：** 数据结构与算法 / 复杂度分析 / 均摊分析。
