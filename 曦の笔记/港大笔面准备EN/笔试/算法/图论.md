# 0. 三个必须先在脑子里建立的概念

图论这一节的很多混乱，不是算法本身难，而是三个基础概念没说清楚就开始讲算法。先花三分钟把下面三条看懂，后面的内容会顺很多。

## 0.1 记号约定

| 记号 | 含义 |
|---|---|
| V | 顶点（vertex）个数，也常直接写 V 表示顶点集合 |
| E | 边（edge）个数 |
| w(u,v) | 边 u→v 的权值（weight）；无权图可以认为每条边权都是 1 |
| dist[v] | **当前**从源点到 v 的最短距离估计值（注意是「估计」，见 0.2） |
| 邻接表 | 每个点存一张「我能到谁」的清单，空间 O(V+E) |
| 邻接矩阵 | V × V 的表，空间 O(V²)，适合稠密图 |

## 0.2 `dist[v]` 是「估计值」，不是「最终答案」

这是最容易误解的一点。所有最短路算法（BFS 除外）都是这样运作的：

1. 一开始什么都不知道，所以 `dist[源点] = 0`，其余全是 ∞；
2. 每发现一条更好的路，就把 `dist` **往下调**（调小）；
3. 当算法结束时，`dist` 才变成真正的答案。

所以 `dist` 在过程中会**反复变小**。看到「某个点的距离从 4 变成 3」不要觉得是算错了——那正是算法在起作用。

## 0.3 「松弛（relaxation）」到底在干什么

松弛这个名字很唬人，其实就是一句大白话：

> 我本来认为从源点到 v 要走 `dist[v]`；现在发现可以先到 u（花 `dist[u]`），再从 u 走一条边 w(u,v) 到 v。如果这样走更近，就改主意。

```text
if dist[u] + w(u, v) < dist[v]:     // 绕道更近
    dist[v] = dist[u] + w(u, v)     // 改主意
```

举个数：`dist[u] = 3`，边 u→v 权为 5，而当前 `dist[v] = 10`。
那么 3+5=8 < 10，于是把 `dist[v]` 改成 8。**这一次操作就叫「对边 (u,v) 做了一次松弛」。**

**所有最短路算法的区别，只是「按什么顺序去做松弛」：**

| 算法 | 松弛顺序 |
|---|---|
| BFS | 按「层」——先处理离源点边数少的 |
| Dijkstra | 按「当前 dist 最小的点」——贪心 |
| Bellman-Ford | 把所有边**从头到尾扫一遍算一轮**，扫 V-1 轮 |
| Floyd | 按「允许使用哪些中转点」——动态规划 |

## 0.4 贯穿全节的例图 G

后面 BFS / DFS / Dijkstra / Prim / Kruskal / Floyd 全部用**这一张图**，这样你不用每次重新理解图的结构。

```text
            S
         4 / \ 2
          /   \
         A-----B
         |  1  |
       5 |     | 7
         |     |
         C-----D
             3
```

顶点：V={S,A,B,C,D}，共 5 个；边共 6 条（无向）：

| 边 | 权 |
|---|---|
| S–A | 4 |
| S–B | 2 |
| A–B | 1 |
| A–C | 5 |
| B–D | 7 |
| C–D | 3 |

**先自己看一眼**：从 S 到 D，直觉上最省的走法是 S→B→D = 2+7=9；走 S→A→C→D = 4+5+3=12，更贵。记住这个直觉，后面用来验算。

# 1. BFS（Breadth-First Search，广度优先搜索）

**解决什么问题**：无权图（或所有边权相等）中，从源点到其他每个点的**最少边数**；以及「两个点连通不连通」。

## 1.1 一句话说清它在干嘛

> 像往水里丢石头，波纹**一圈一圈往外扩**。先看所有距离 1 的点，再看所有距离 2 的点……

「一圈一圈」是 BFS 的灵魂。它不是「随便找个点往下走」，而是**严格按距离排队**。

## 1.2 为什么必须用队列（Queue）

队列是**先进先出（FIFO）**：先被发现的点，先被处理。

假设源点 S 在第 0 层，S 的邻居在第 1 层。S 把邻居全部塞进队列；由于 FIFO，这**一整批第 1 层的点会全部排在**它们各自的邻居（第 2 层）**前面**被处理。于是层与层之间不会交叉——这就是「逐层」的机械保证。

如果换成栈（LIFO），最后塞进去的点会先被处理，那就会沿着一条路猛冲到底——那是 DFS。

## 1.3 在例图 G 上手动走一遍（从 S 出发）

```text
队列 Queue = [S]        visited = {S}

Step 1  弹出 S        → 邻居 A、B 没访问过 → 入队
        Queue = [A, B]  visited = {S, A, B}
Step 2  弹出 A        → 邻居 S(已访问)、B(已访问)、C(新) → C 入队
        Queue = [B, C]  visited = {S, A, B, C}
Step 3  弹出 B        → 邻居 S、A(已访问)、D(新) → D 入队
        Queue = [C, D]  visited = {S, A, B, C, D}
Step 4  弹出 C        → 邻居 A、D 都已访问 → 无事发生
        Queue = [D]
Step 5  弹出 D        → 全访问过 → 结束
```

出队顺序：**S, A, B, C, D**。
BFS 树（每个点记录「我是从谁那儿第一次被发现的」）：

```text
        S
       / \
      A   B
      |   |
      C   D
```

注意：图中 A–B、C–D 这两条边**没有进 BFS 树**，因为 B 被 S 先发现了（距离 1），A–B 只是让两个已在同层/相邻层的点连了一下，不影响距离。

**层号 = 距离**：S=0，A=1，B=1，C=2，D=2。

## 1.4 为什么 BFS 给出的就是「最少边数」

因为队列保证了「距离 k 的点全部处理完之前，距离 k+1 的点一个都不会被处理」。

于是任何点 v **第一次**被访问时，一定是从某个距离 d 的点扩展出来的，所以它的距离是 d+1，而这是「能到达 v 的最小层数」——因为更小层数的点早就处理完了，那时候都没能到 v。

这就是**「第一次见就是最短」**。DFS 没有这个性质：DFS 可能先沿着一条绕远的路径摸到 v，之后再也没机会改了。

## 1.5 复杂度

每个顶点入队一次、出队一次（O(V)），每条边被检查一到两次（O(E)）。总共 **O(V+E)**。
用邻接矩阵实现则是 O(V²)，因为每个点都要扫一整行。

## 1.6 反过来看：BFS 什么时候会出错

- **边权不全相等时，BFS 直接失效。** 它只数边数，不看权值。
  例：S→D 一条边权 100，S→A→B→D 三条边权各为 1。BFS 会说「S 到 D 距离 1」，但真正的代价最小路径是 3 条边、总权 3。这时候要用 Dijkstra。
- 边权**全相等**时，BFS 就等价于「退化的 Dijkstra」，因为此时「边数最少」= 「权值和最小」。

## 1.7 BFS 与 DFS 的区别

| 对比 | BFS | DFS |
|---|---|---|
| 英文全称 | Breadth-First Search | Depth-First Search |
| 中文 | 广度优先搜索 | 深度优先搜索 |
| 核心数据结构 | **Queue（队列）** | **Stack / 递归** |
| 搜索方式 | 一圈一圈往外扩（逐层） | 一条路走到黑，走不通再回头 |
| 无权图最短路径 | **保证最短** | 不保证 |
| 空间开销 | O(V)（最坏要存一整层） | O(h)（只存当前这条路径，h 为最大深度） |
| 典型用途 | 最短步数、层序遍历、连通性 | 连通性、拓扑排序、找环、回溯 |

**需要记住：**

BFS uses a **queue** and is suitable for finding the shortest path in an **unweighted** graph.

## 1.8 英文例题

In a graph where **every edge has the same weight**, which algorithm computes the minimum number of edges from a source vertex to all other vertices in O(V+E) time using a FIFO queue?

A. Depth-First Search
B. Breadth-First Search
C. Bellman-Ford
D. Kruskal's algorithm
E. Floyd-Warshall

**答案：B**

**解析：** 三个线索同时指向 BFS：① FIFO queue；② O(V+E)；③ 边权相同（即「边数最少」等价于「代价最小」）。DFS 用的是栈、且不保证最短；Bellman-Ford 是 O(V·E) 且为带权图设计；Kruskal 求最小生成树，与单源最短路无关；Floyd 是 O(V³) 全源最短路。

**所属知识点：** 数据结构与算法 / 图论 / BFS 与无权图最短路。

# 2. DFS（Depth-First Search，深度优先搜索）

**解决什么问题**：连通性判断、找环、拓扑排序、以及所有「回溯」类问题（全排列、N 皇后、数独、迷宫）。

## 2.1 一句话说清它在干嘛

> 沿着一条路一直往前走，**撞墙了才回头**，回到最近的一个「还有岔路没走」的路口，换一条继续。

## 2.2 为什么用栈（或用递归）

递归函数调用本身就是栈：`dfs(u)` 里调用 `dfs(v)`，`dfs(u)` 的现场被压在栈底，等 `dfs(v)` 全部返回后才继续。所以「递归实现 DFS」和「显式用 Stack 实现 DFS」是同一件事，只是写法不同。

## 2.3 在例图 G 上手动走一遍（从 S 出发，邻居按字母序）

```text
dfs(S)   → 标记 S
  dfs(A) → 标记 A
    dfs(B) → 标记 B            （S 已标记，跳过；A 已标记，跳过）
      dfs(D) → 标记 D          （B 已标记，跳过）
        dfs(C) → 标记 C        （D 已标记；A 已标记，跳过）
        C 无新邻居 → 返回
      D 无新邻居 → 返回
    B 无新邻居 → 返回
  A 的 C 已标记 → 返回
S 的 B 已标记 → 返回
```

访问顺序：**S, A, B, D, C**。
对比 BFS 的 S, A, B, C, D：同为「S A B」开头，之后 BFS 走「按层」去 C，DFS 走「按深度」去 D。**这就是两者最直观的差别。**

## 2.4 DFS 的三种用途，分别记清楚

**（1）连通性**：从 S 出发 DFS 一遍，能标记到的点就是与 S 连通的。O(V+E)。

**（2）有向图找环——三色标记法（这个必须会）**

给每个点三种状态：

| 颜色 | 含义 |
|---|---|
| 白（white） | 还没访问过 |
| 灰（gray） | **正在**它的递归栈里（我还在处理它，或者它的后代） |
| 黑（black） | 它和它的所有后代都处理完了 |

规则：DFS 过程中，如果从 u 出发遇到一个**灰色**的邻居 v，说明 v 是 u 的「祖先」，形成**回边（back edge）**，即存在环。

为什么灰=环：灰色意味着「v 还没从栈里出来」，也就是「v → … → u 这条祖先链还在。现在又发现 u → v，于是 v → … → u → v 闭环了。

反例体会：图 A→B, B→C, C→A。走到 C 时发现邻居 A 是灰色 → 有环。
而如果是 A→B, A→C, B→D, C→D（菱形，无环），走到 D 的第二次时 D 已经是**黑色**，不是灰色，所以不报环。**「黑色不算环」这一点是很多人做错的地方。**

**（3）拓扑排序**：见 §7.3，DFS 的后序取逆序。

## 2.5 复杂度与空间

时间 O(V+E)（邻接表）。空间 O(h)，h 是搜索树的最大深度——因为只需要压住当前这条路径，不需要像 BFS 那样存一整层。

## 2.6 英文例题

Which traversal detects a cycle in a **directed** graph by checking whether the search reaches a vertex that is still on the current recursion stack?

A. Breadth-First Search
B. Depth-First Search
C. Dijkstra's algorithm
D. Prim's algorithm
E. Binary search

**答案：B**

**解析：** 关键短语 `on the current recursion stack` 就是「灰色顶点」的定义，只有 DFS 有「递归栈」这个结构，BFS 只有队列、没有祖先链的概念。BFS 虽然也能判环（无向图用「遇到已访问且不是父节点」），但它判的不是「回边」。Dijkstra / Prim 与判环无关。

**所属知识点：** 数据结构与算法 / 图论 / DFS 与环检测。

# 3. Dijkstra 算法（单源最短路，边权非负）

**解决什么问题**：给定一个**所有边权 ≥ 0** 的带权图和一个源点 s，求 s 到**所有其他点**的最短距离。

这是图论里最常考、也最容易「背了不会用」的算法。下面把它拆到能自己手算的程度。

## 3.1 核心思路：把点分成两堆

维护一个集合 S，含义是「**我已经百分之百确定它最短距离**的点」。

每轮做两件事：

1. **挑**：从「还没确定的点」里，挑 `dist` 最小的那个 u，宣布它确定（放进 S）；
2. **松**：用 u 去松弛它的所有邻居。

重复 V 轮，所有点都进 S，`dist` 就是答案。

**注意这个「确定」的语义**：一旦进 S，它的 `dist` 就**再也不改了**。这是 Dijkstra 与 Bellman-Ford 的根本区别——Bellman-Ford 是反复改到不再变为止，Dijkstra 是「认定了就不回头」。

## 3.2 为什么用优先队列

「挑 dist 最小的点」如果每轮都线性扫一遍所有点，是 O(V)，V 轮就是 O(V²)——这叫朴素实现。
用**优先队列（最小堆）**，每次取最小是 O(log V)，一共取 V 次；每次松弛可能触发一次入堆/减键，总共 O(E) 次。所以 O((V+E)log V)。

**关键辨析**：Dijkstra 用的是**优先队列**，不是普通队列。普通队列（BFS）是「谁先被发现谁先出」，优先队列是「谁当前距离最小谁先出」。这一点是选择题的高频陷阱。

## 3.3 在例图 G 上手动走一遍（源点 S）—— 表要会自己填

初始：`dist[S]=0`，其余 ∞。

| 轮次 | 出队并「确定」的点 | dist[S] | dist[A] | dist[B] | dist[C] | dist[D] | 本轮做了什么松弛 |
|---|---|---|---|---|---|---|---|
| 初始 | — | **0** | ∞ | ∞ | ∞ | ∞ | — |
| 1 | **S**（0） | 0 | **4** | **2** | ∞ | ∞ | S→A 得 4；S→B 得 2 |
| 2 | **B**（2） | 0 | **3** | 2 | ∞ | **9** | B→A：2+1=3<4 ⇒ A 改成 3；B→D 得 9 |
| 3 | **A**（3） | 0 | 3 | 2 | **8** | 9 | A→C 得 8（A→S、A→B 已成定局，跳过） |
| 4 | **C**（8） | 0 | 3 | 2 | 8 | 9 | C→D：8+3=11>9，**不改** |
| 5 | **D**（9） | 0 | 3 | 2 | 8 | 9 | 全部结束 |

最终：dist(S)=0, dist(B)=2, dist(A)=3, dist(C)=8, dist(D)=9。

**两个要盯住的细节：**

- 第 2 轮 `dist[A]` 从 4 **降到** 3。这就是 §0.2 说的「估计值会变小」——绕道 S→B→A（2+1=3）比直达 S→A（4）更省。
- 第 4 轮 `dist[D]` **没有被改进**（11 > 9）。松弛不一定成功，这正是「松弛」是个 `if` 判断的原因。

**验算**：S 到 D 最省的确实是 S→B→D = 2+7=9，与直觉一致。

## 3.4 为什么「一取出来就定死」是对的（贪心的正确性）

拍脑袋想会担心：万一我先取了某个点，后来发现绕一圈更近呢？

Dijkstra 的论证是这样的：

> 设当前要取出的是 u，它的 `dist[u]` 是所有未确定点里**最小**的。
> 假设存在一条更短的真实路径 P 通往 u。这条路径必然在某处**第一次从「已确定区域」跨到「未确定区域」**，跨越的那条边记作 (x,y)，其中 x 已确定、y 未确定。
> 那么 P 的总长 ≥ dist[x] + w(x,y) ≥ dist[u] + w(x,y)（因为 dist[u] 是未确定里最小的，dist[y] ≥ dist[u]）。
> 而 w(x,y) ≥ 0，所以 P 的长度 ≥ dist[u]，与「更短」矛盾。

**这个论证里 `w(x,y) ≥ 0` 是硬性条件。** 一旦允许负权，最后那步「 ≥ dist[u]」就不成立了，整个证明崩塌——见下一节。

## 3.5 负权为什么会让它给出**错误答案**（给一个具体反例）

图：A→B 权 1，A→C 权 2，**C→B 权 −2**。源点 A。

真实最短：A→C→B = 2 + (-2) = 0。正确答案是 `dist[B] = 0`。

Dijkstra 跑一遍：

```text
初始      dist[A]=0,  dist[B]=∞,  dist[C]=∞
第1轮  取 A(0) → 松弛：dist[B]=1, dist[C]=2
第2轮  取 B(1) ← 问题就在这！B 的 1 < C 的 2，所以 B 先被「确定」
        B 已进 S，之后再也不会被修改
第3轮  取 C(2) → 松弛 C→B：2 + (−2) = 0 < 1，本该改成 0
        但 B 已经「确定」，Dijkstra 不会再动它
结果    dist[B] = 1   ← 错的（正确是 0）
```

**错误的根源在 3.4 的证明**：那里假设「先确定的一定不会更差」，但负权边让「绕远路反而更省」成为可能。所以 Dijkstra 只能处理**非负权**。

## 3.6 复杂度汇总

| 实现方式 | 复杂度 | 说明 |
|---|---|---|
| 朴素（每轮线性扫最小值） | O(V²) | 适合稠密图，E 接近 V² 时反而不亏 |
| 优先队列（二叉堆） | O((V+E)log V) | 最常用，稀疏图首选 |
| 斐波那契堆 | O(E + Vlog V) | 理论最优，实际常数大 |

**需要记住：**

Dijkstra works only with **non-negative** edge weights; it uses a **priority queue**, not a plain queue. Negative weights require Bellman-Ford.

## 3.7 英文例题

Which algorithm finds the shortest paths from a single source in a weighted graph with **non-negative** edge weights?

A. BFS
B. DFS
C. Dijkstra's algorithm
D. Kruskal's algorithm
E. Topological sorting

**答案：C**

**解析：** 题干两个关键词 `single source` + `non-negative` 直接锁定 Dijkstra。BFS 只处理无权（或等权）图；DFS 与最短路无关；Kruskal 求最小生成树；拓扑排序只解决 DAG 的先后顺序。注意：如果题干把 `non-negative` 换成 `possibly negative`，答案就要变成 Bellman-Ford。

**所属知识点：** 数据结构与算法 / 图论 / 最短路与最小生成树。

# 4. Bellman-Ford 算法（可处理负权 + 检测负环）

**解决什么问题**：边权**可能为负**的图中求单源最短路；以及判断图里**有没有负环**。

## 4.1 一句话说清它和 Dijkstra 的分工

> Dijkstra 是「聪明但挑剔」：挑最小的点，认定了不回头，所以快，但不能有负权。
> Bellman-Ford 是「笨但稳」：不管三七二十一，**把所有边反复扫好几轮**，总能收敛，还能顺便抓出负环。

## 4.2 核心动作：一轮 = 把所有边扫一遍

```text
for k in 1..V-1:                 // 一共 V-1 轮
    for each edge (u,v,w):       // 每轮扫遍所有边
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
```

就这一个双重循环，没有队列、没有优先队列、没有集合 S。

## 4.3 为什么是 V-1 轮（这是重点，别只背结论）

**第一步，先想清楚「一条最短路最多有几条边」。**

如果一条最短路里有 V 条边，那它经过了 V+1 个顶点。但总共只有 V 个顶点，由抽屉原理必有重复——有重复就意味着里面有个环。如果这个环的权和 ≥ 0，把环去掉只会更短（或不变），所以「真正的最短路」不会绕这种环；如果环的权和 < 0，那最短路根本不存在（可以无限绕）。

所以：**最短路径一定可以取成一条简单路径，最多 V-1 条边。**

**第二步，再看「扫一轮」能推进多少。**

用归纳法：假设第 k 轮结束时，所有「边数 ≤ k 的最短路」都已经算对了（第 0 轮 = 只有源点自己）。
第 k+1 轮里，考虑一条边数恰好为 k+1 的最短路 s → … → u → v。它的前一段 s→…→u 边数是 k，按假设已经对了，所以 `dist[u]` 正确；这一轮扫到边 (u,v) 时就会把 `dist[v]` 也修正。因此第 k+1 轮结束时，「边数 ≤ k+1 的最短路」全对。

**第三步，合起来。** 最短路最多 V-1 条边，所以 V-1 轮之后，所有最短路都被覆盖。**多扫也没用，少扫一轮就不保证对。**

> 直觉版：每扫一轮，正确信息就往外「传染」一层。信息最多传染 V-1 层，所以要 V-1 轮。

## 4.4 手算一遍（这个例子里恰好一轮就收敛，正好用来说明「轮数是上界」）

图（**有向**）：A→B 权 5，A→C 权 2，C→B 权 -4，B→D 权 3，C→D 权 6。源点 A。

| 轮次 | dist[A] | dist[B] | dist[C] | dist[D] | 说明 |
|---|---|---|---|---|---|
| 初始 | 0 | ∞ | ∞ | ∞ | — |
| 第 1 轮 | 0 | ∞→**5**→**−2** | **2** | **1** | 扫边顺序：A→B 得 5；A→C 得 2；C→B 得 2−4=−2 覆盖 5；B→D 得 1；C→D 2+6=8>1 不改 |
| 第 2 轮 | 0 | −2 | 2 | 1 | 再扫一遍，没有任何改进 |
| 第 3 轮 | 0 | −2 | 2 | 1 | 已经是 V-1=3 轮，同样无改进 |
| 第 4 轮（判定轮） | 0 | −2 | 2 | 1 | **仍无改进 ⇒ 没有负环** |

答案：dist(A)=0, dist(C)=2, dist(B)=-2, dist(D)=1。

**两处要体会：**

- `dist[B]` 先被算成 **5**（走 A→B），随后被 **−2**（走 A→C→B）覆盖。**值变小是正常的**，这正是 Bellman-Ford 相对 Dijkstra 的「可反悔」。
- 在第 1 轮里，`C→B` 这条边的松弛之所以能成功，是因为**它在 `A→C` 之后被扫到**。如果这一轮里 `C→B` 排到 `A→C` 前面，那这一轮 `dist[C]` 还是 ∞，`C→B` 就松不动，得等第 2 轮。**这就是为什么最坏情况需要 V-1 轮**——链条长 k 条边、且边的扫描顺序恰好事与愿违时，一轮只能推进一条边。

## 4.5 负环检测：为什么「第 V 轮还能松弛」就等于有负环

第 V 轮是在 V-1 轮之后做的。按 4.3，正常图此时已经全部收敛，**再扫一遍应该一个都改不动**。

如果居然还能改，说明存在一条路径，其边数 ≥ V 却比已求出的更短。边数 ≥ V 必然含环（V 个点走 V 条边），而「边数更多反而更短」说明这个环的权和是**负**的。

并且：一旦有负环，`dist` 会**每一轮都继续变小，永不收敛**——所以这个检测是可靠的。

具体例子：A→B 权 3，B→C 权 -5，C→B 权 -5。
环 B→C→B 的权和是 -10 < 0。于是 `dist[B]` 会依次变成 3、-7、-17、-27……每轮掉 10，永远掉不完 → 最短路**不存在**（可以说成 -∞）。

## 4.6 复杂度

V-1 轮 × 每轮扫 E 条边 = **O(V·E)**。
稀疏图（E ≈ V）时是 O(V²)；稠密图（E ≈ V²）时退化到 O(V³)，这是它比 Dijkstra 慢的地方。

## 4.7 与 Dijkstra 的对比

| 对比 | Dijkstra | Bellman-Ford |
|---|---|---|
| 负权边 | ❌ 不支持（见 §3.5 反例） | ✅ 支持 |
| 负环检测 | ❌ 不能 | ✅ 第 V 轮仍能松弛即有负环 |
| 复杂度 | O((V+E)log V) | O(V·E) |
| 核心动作 | 取当前最小 + 松弛它的邻边 | **所有边**反复松弛 V-1 轮 |
| 为什么能/不能 | 贪心：认定不回头 → 需要非负权 | 动态规划：允许反复修正 |
| 数据结构 | 优先队列 | 不需要额外结构 |

**需要记住：**

Bellman-Ford relaxes **all** edges **V − 1** times; if the **V-th** round still relaxes, there is a **negative cycle**.

## 4.8 英文例题

A directed graph may contain **negative** edge weights. Which algorithm both computes single-source shortest paths and detects negative cycles, and what is its running time?

A. Dijkstra, O((V+E)log V)
B. Bellman-Ford, O(V·E)
C. Floyd-Warshall, O(V³)
D. Prim, O(Elog V)
E. BFS, O(V+E)

**答案：B**

**解析：** 只要题干出现 `negative weights` 且是 `single source`，就只能是 Bellman-Ford。Dijkstra 在负权下会出错（§3.5）；Floyd 虽然也允许负权，但它是**全源**（O(V³)），不符合 `single source` 且代价更高；Prim 求 MST；BFS 不处理权值。

**所属知识点：** 数据结构与算法 / 图论 / 负权最短路与负环检测。

# 5. Floyd-Warshall 算法（全源最短路）

**解决什么问题**：求**任意两点之间**的最短距离（all-pairs shortest paths）。允许负权边，但不允许负环。

## 5.1 和前面两个算法的定位差别

| | 单源 | 全源 |
|---|---|---|
| 非负权 | Dijkstra O((V+E)log V) | 跑 V 次 Dijkstra |
| 有负权 | Bellman-Ford O(VE) | **Floyd O(V³)** |

Floyd 的价值：**写起来只有三行**，常数小，V 在几百以内时几乎必胜。

## 5.2 核心思想：动态规划，逐步放宽「允许用哪些中转点」

定义状态：

> dist_k[i][j] = 「只允许把 {1,2,…,k} 这些点当作**中转站**」时，i 到 j 的最短距离。

**递推（这是整个算法的全部）：**

```text
dist_k[i][j] = min( dist_(k-1)[i][j],   dist_(k-1)[i][k] + dist_(k-1)[k][j] )
```

读成人话：

> 从 i 到 j，就两种可能——**要么完全不碰点 k**（第一种，沿用上一阶段的结果），**要么就是「先到 k，再从 k 到 j」**（第二种）。二选一取小的。

因为 dist 数组可以原地更新（右边的 dist[i][k]、dist[k][j] 在 k 这一轮里不会变，见 5.4），所以三维压成二维，代码就是：

```text
for k in 1..V:              // 阶段：允许用前 k 个点当中转
    for i in 1..V:          // 起点
        for j in 1..V:      // 终点
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
```

## 5.3 手算一个小例子

图（有向）：1→2 权 4，2→3 权 -2，1→3 权 5。

初始矩阵（∞ 表示不直接相连）：

| dist | →1 | →2 | →3 |
|---|---|---|---|
| **1** | 0 | 4 | 5 |
| **2** | ∞ | 0 | −2 |
| **3** | ∞ | ∞ | 0 |

- k=1：没有边指向 1，dist[i][1] 全是 ∞，加任何东西都比原来大，**表不变**。
- k=2：检查「i→2→j」。关键是 dist[1][3]：min(5, 4+(-2)=2) = 2。
  **含义**：1 到 3 与其直达（5），不如先到 2 再转（4-2=2）。表变成 dist[1][3]=2。
- k=3：没有点出边，表不变。

结果 dist[1][3]=2，与手算一致。

## 5.4 为什么 k 必须在最外层（最容易考的实现细节）

因为 k 不是「一个循环变量」，它是**DP 的阶段**：k=1 是「允许用第 1 个点」，k=2 是「允许用前 2 个点」……阶段只能**一层层往上加**，不能跳。

如果写成 i,j 在外、k 在内，等于「同一个阶段里反复来回改动」，后面的计算用到的可能是「还没被定义好」或者「已经被本阶段污染」的值，DP 的递推关系就断了。

还有一个附带的技术原因：**原地更新（in-place）之所以合法，恰恰是因为 k 在最外层**。更新 dist[i][j] 时，用到的 dist[i][k] 和 dist[k][j] 在这一轮里不会被修改：

- dist[i][k]：终点是 k，本轮里 j 走遍所有值也包括 k，但 dist[k][k]=0 恒成立，dist[i][k] = min(dist[i][k], dist[i][k]+0) 不会变；
- dist[k][j]：起点是 k，同理不变。

> 实践提示：k 放内层的写法**在某些图上碰巧也能算出正确答案**，但没有任何保证，属于经典错误写法。考试问「哪个循环必须在最外层」，答案永远是 k（中间点）。

## 5.5 顺带两个性质

- **负环判定**：跑完 Floyd 后，如果存在 i 使 dist[i][i] < 0，说明 i 能绕回自己且总权为负 → 有负环。
- **不需要单独处理「经过多个中转点」**：因为 k 逐层放宽，i→a→b→j 这种多跳路径会在 k=b 那一阶段自动被组合出来。

## 5.6 复杂度与适用规模

时间 O(V³)，空间 O(V²)。
V=100 时约 10⁶ 次操作，很快；V=1000 时是 10⁹，就太慢了。所以适合**稠密图 + 小规模**。

## 5.7 英文例题

For all-pairs shortest paths on a graph with V vertices, which statement about **Floyd-Warshall** is correct?

A. Its time complexity is O(V²), and the loop over the source vertex must be outermost.
B. Its time complexity is O(V³), and the loop over the intermediate vertex k must be outermost.
C. Its time complexity is O(V³), and the loop over the destination vertex must be outermost.
D. It cannot handle negative edge weights.
E. It finds the minimum spanning tree of the graph.

**答案：B**

**解析：** 时间 O(V³)（三重循环），且 k（中间点/中转站）必须是最外层——k 是 DP 的阶段。C 错在最外层是谁；A 复杂度错；D 错，Floyd **允许**负权边（只是不允许负环）；E 把最短路和 MST 搞混了。

**所属知识点：** 数据结构与算法 / 图论 / 全源最短路与动态规划。

# 6. Prim 与 Kruskal（最小生成树 MST）

**解决什么问题**：用最小的总代价把所有点**连成一片**。

## 6.1 先分清：MST 求的是「连通」，不是「最短路径」

这是本节最容易被混淆的地方，先立规矩：

> **最短路**问的是：「从 A 到 B 怎么走最省？」
> **MST** 问的是：「花最少的钱，把全部点用边连起来（保证任意两点能互通）。」

两者目标完全不同，得到的边集也通常不同。**MST 上 A、B 两点之间的那条路，往往不是 A 到 B 的最短路。**

**MST 的严格定义**：在**连通无向带权图**中，选出一棵包含**全部**顶点、边权之和最小的树。

- 「树」⟹ 无环；
- V 个点的树恰好有 V-1 条边 ⟹ MST 一定是 V-1 条边。

**为什么一定是 V-1 条**：V 个点的连通图至少 V-1 条边（少一条就断开）；多一条必有环（有环就可以删掉环上最贵的边让总权更小）。所以最优解恰好 V-1 条。

## 6.2 Prim：从一个点「长」出一棵树

**思路**：维护一个「已在树内」的集合。每次从「一端在树内、一端在树外」的所有边里，挑**最便宜**的那条，把外面的点拉进来。

```text
Step 1  任选一个起点加入树
Step 2  在所有「一端在树内、一端在树外」的边中，选权最小的那条
Step 3  把该边和树外端点一起加入树
Step 4  重复 Step 2-3，共 V-1 次
```

**在例图 G 上手动走一遍（从 S 出发）：**

| 轮次 | 树内顶点 | 候选边（一端内一端外） | 选中的边 | 累计权 |
|---|---|---|---|---|
| 1 | {S} | S–A 4，S–B 2 | **S–B 2** | 2 |
| 2 | {S,B} | S–A 4，A–B 1，B–D 7 | **A–B 1** | 3 |
| 3 | {S,B,A} | A–C 5，B–D 7 | **A–C 5** | 8 |
| 4 | {S,B,A,C} | B–D 7，C–D 3 | **C–D 3** | 11 |
| — | {S,B,A,C,D} | 已 5 个点，共 4 条边，结束 | | **11** |

MST 边集 = {S–B(2), A–B(1), A–C(5), C–D(3)}，总权 **11**。

注意第 3 轮：此时 S–A 这条边两端都在树内了，**它不再进入候选**。Prim 只关心「怎么把外面的点拉进来」，树内部的边毫无意义。这一点想通了，Prim 就没有难点了。

## 6.3 Kruskal：按边权从小到大加，不成环就加

**思路**：把**所有边**从小到大排序，一条条试着加；如果这条边的两个端点**已经连通**（加了就成环），就跳过；否则加进来。加到 V-1 条为止。

「两个端点是否已连通」用**并查集（Union-Find）**判断：同一集合 ⇒ 已连通 ⇒ 会成环。

**在同一张例图上走一遍：**

边按权排序：A–B 1，S–B 2，C–D 3，S–A 4，A–C 5，B–D 7。

| 顺序 | 边 | 权 | 两端是否已连通 | 动作 | 已选边数 |
|---|---|---|---|---|---|
| 1 | A–B | 1 | 否（{A},{B}） | ✅ 加入，合并 {A,B} | 1 |
| 2 | S–B | 2 | 否（{S} vs {A,B}） | ✅ 加入，合并 {S,A,B} | 2 |
| 3 | C–D | 3 | 否（{C},{D}） | ✅ 加入，合并 {C,D} | 3 |
| 4 | S–A | 4 | **是**（S、A 都在 {S,A,B}） | ❌ 跳过（会成环 S–A–B–S） | 3 |
| 5 | A–C | 5 | 否（{S,A,B} vs {C,D}） | ✅ 加入，全图连通 | 4 |
| 6 | B–D | 7 | **是**（早已连通） | ❌ 跳过 | 4 |

总权 = 1 + 2 + 3 + 5 = 11，与 Prim **一致**——这不是巧合，两种算法都正确，只是顺序不同（这张图恰好只有一个 MST，所以边集相同）。

**体会 Kruskal 的判环逻辑**：第 4 步 S–A 权为 4，比 A–C 的 5 更小，但因为 S 和 A 已经通过 S–B–A 连通了，加它会形成环，所以**必须跳过**。Kruskal 不是「贪心地取最小的」，而是「贪心地取最小的**不构成环的**」——后半句不能丢。

## 6.4 为什么这两种贪心都是对的（一句话版）

- **Prim 的正确性 = 割性质（cut property）**：「把点任意分成两堆，横跨这两堆的最便宜的边，一定属于某个 MST。」Prim 每一步就是在做这件事（树内 / 树外 就是一个割）。
- **Kruskal 的正确性 = 环性质（cycle property）**：「图里任意一个环上最贵的那条边，一定不属于任何 MST。」Kruskal 加边时跳过成环的边，本质是反过来利用这个性质。

## 6.5 复杂度与选型

| | Prim | Kruskal |
|---|---|---|
| 做法 | 从一个点长树，每轮挑最小跨界边 | 全局边排序 + 并查集判环 |
| 复杂度 | 朴素 O(V²)；优先队列 O(Elog V) | O(Elog E)（排序主导） |
| 适合 | **稠密图**（E 大，V 小） | **稀疏图**（E 小） |
| 前提 | 图必须连通（否则得不到生成树） | 同左；不连通时得到的是「最小生成森林」 |

记忆抓手：**Prim 盯着点（点集往外长），Kruskal 盯着边（边排序往下筛）。**

## 6.6 MST ≠ 最短路（给个反例说透）

例图 G 的 MST 边集是 {S–B(2), A–B(1), A–C(5), C–D(3)}。在这棵树上，从 S 到 D **只有一条**路：**S→B→A→C→D**，代价 2+1+5+3 = 11。
但 §3.3 算出 S 到 D 的最短路是 **9**（S→B→D，用的是 B–D 这条边，而 B–D 权 7 太贵，**没被选进 MST**）。

**结论：MST 里没有 B–D，但最短路偏偏要用 B–D。** 这就是「MST ≠ 最短路」最直接的证据。

| 对比 | 最短路（Shortest Path） | 最小生成树（MST） |
|---|---|---|
| 目标 | 两点之间路径最短 | 连通所有点、总权最小 |
| 结果 | 一条路径 | 一棵树（V-1 条边） |
| 算法 | BFS / Dijkstra / Bellman-Ford / Floyd | Prim / Kruskal |
| 是否含最贵边 | 可能含 | 通常不含（环上最贵边必不在 MST 上） |
| 反例 | MST 上两点间的路径往往**不是**最短路（见上） | — |

**需要记住：**

Prim grows the tree **from a vertex**; Kruskal **sorts the edges** and uses **Union-Find** to avoid cycles. MST is **not** the same problem as shortest path.

## 6.7 英文例题

Which algorithm builds a minimum spanning tree by repeatedly adding the **cheapest edge that does not create a cycle**, using a **union-find** structure?

A. Prim's algorithm
B. Kruskal's algorithm
C. Dijkstra's algorithm
D. Bellman-Ford
E. Floyd-Warshall

**答案：B**

**解析：** `cheapest edge that does not create a cycle` + `union-find` 是 Kruskal 的两个签名。Prim 是「从一个点往外长，挑最便宜的**跨界边**」，不需要并查集（用 visited 数组就行）。Dijkstra 求最短路；Bellman-Ford 求负权最短路；Floyd 求全源最短路。

**所属知识点：** 数据结构与算法 / 图论 / 最小生成树。

# 7. Topological Sort（拓扑排序）

**解决什么问题**：把一堆「有先后依赖」的任务排成一个合法顺序。

典型场景：课程先修关系、编译依赖、任务调度、包管理器的安装顺序。

## 7.1 定义与前提

**定义**：把 DAG 的所有顶点排成一个线性序列，使得对**每一条**有向边 u→v，u 都排在 v 前面。

**前提：必须是 DAG（有向无环图）。** 如果有环（A 依赖 B，B 依赖 A），那么「A 在 B 前」和「B 在 A 前」同时被要求，无解。

## 7.2 实现一：Kahn 算法（BFS 式，用队列）

**思路**：入度（in-degree）= 有多少条边指向它 = 「还有几个前置任务没完成」。

```text
Step 1  统计每个点的入度
Step 2  把所有入度为 0 的点入队（这些点没有前置，可以立刻做）
Step 3  出队一个点 u，输出它；对它每条出边 u→v，把 indeg[v] 减 1
Step 4  若某个 v 的入度减到 0，v 入队
Step 5  队列空了就结束
```

**例 DAG**：A→B，A→C，B→D，C→D，D→E。

初始入度：A 0，B 1，C 1，D 2，E 1。

| 步骤 | 队列 | 输出序列 | 动作 |
|---|---|---|---|
| 初始 | [A] | — | A 入度为 0 入队 |
| 1 | [] | **A** | 出队 A；B 的入度 1→0 入队；C 的入度 1→0 入队 |
| 2 | [B, C] | A, **B** | 出队 B；D 的入度 2→1（还没到 0） |
| 3 | [C] | A, B, **C** | 出队 C；D 的入度 1→0 入队 |
| 4 | [D] | A, B, C, **D** | 出队 D；E 的入度 1→0 入队 |
| 5 | [E] | A, B, C, D, **E** | 出队 E，队列空，结束 |

输出：**A, B, C, D, E**（合法，因为每条边都是前→后）。

**注意**：拓扑序**不唯一**。第 2 步队列是 [B, C]，如果先出 C 再出 B，会得到 A, C, B, D, E——同样合法。**考试里问「下列哪个是合法拓扑序」，逐个检查「每条边的起点是否都在终点前面」即可。**

## 7.3 实现二：DFS 逆后序

**思路**：DFS 一个点，等它的**所有后代都访问完**（即它「后序」完成）之后，才把它加入结果；最后把结果**整个反转**。

```text
dfs(A)：A → B → D → E
   E 先完成（后序第 1 个）
   D 完成（第 2）
   B 完成（第 3）
   C 完成（第 4，此时 D 已访问）
   A 完成（第 5）
后序 = [E, D, B, C, A]
逆序 = [A, C, B, D, E]   ← 合法的拓扑序
```

**为什么逆后序就是拓扑序**：如果存在边 u→v，DFS 里 v 一定是 u 的**后代**（要么还没访问被递归进去，要么已访问——已访问也必然是后代，因为在 DAG 里不可能是「已完成的祖先」）。后代一定比祖先**先**完成，即后序里 v 在 u 之前。反转后 u 就在 v 之前。**每条边都满足，即为拓扑序。**

（这也顺带解释了为什么要求 DAG：若有环，v 既是后代又是祖先，自相矛盾。）

## 7.4 用 Kahn 检测环（很实用的副产品）

如果最后**输出的顶点数 < V**，说明有点始终没能把入度降到 0 —— 这些点互相依赖，构成环。

例：A→B，B→C，C→A。三者的入度都是 1，初始队列就是**空的**，一个都输出不了，输出数 0 < 3 ⇒ 有环。

## 7.5 复杂度

每个点入队出队各一次（O(V)），每条边被处理一次（O(E)）⇒ **O(V+E)**。DFS 版同理。

## 7.6 英文例题

Which statement about **topological sorting** is correct?

A. It can be applied to any directed graph, including graphs with cycles.
B. It requires O(V²) time and uses a priority queue.
C. It is possible only for a DAG, and Kahn's algorithm uses a queue of vertices with in-degree zero.
D. It computes the shortest path from a single source.
E. It produces a unique ordering for every graph.

**答案：C**

**解析：** C 两个断言都对：前提必须是 DAG（有环则无解），Kahn 用「入度为 0 的队列」。A 错在「任意有向图」；B 错，时间 O(V+E) 且不涉及优先队列；D 把拓扑排序和最短路搞混；E 错，拓扑序通常**不唯一**（§7.2 已给出两个合法序列）。

**所属知识点：** 数据结构与算法 / 图论 / 拓扑排序与 DAG。

# 8. 图算法选型对照表（这张表覆盖所有图论选择题）

看到题干里的关键词，直接查表定位算法。

| 题干关键词 | 算法 | 适用图 | 复杂度 |
|---|---|---|---|
| shortest path, **unweighted** / minimum number of edges | **BFS** | 无权或等权 | O(V+E) |
| shortest path, single source, **non-negative** | **Dijkstra** | 边权 ≥ 0 | O((V+E)log V) |
| shortest path, **negative** weights / detect negative cycle | **Bellman-Ford** | 允许负权 | O(V·E) |
| shortest paths **between all pairs** | **Floyd** | 允许负权、无负环 | O(V³) |
| **minimum spanning tree** / connect all with min cost | **Prim / Kruskal** | 连通无向带权 | O(Elog V) / O(Elog E) |
| **DAG** / prerequisites / dependency order | **拓扑排序** | 有向无环 | O(V+E) |
| 连通性 / 有没有路径 / 找环 | **DFS**（或 BFS） | 任意 | O(V+E) |

## 8.1 七个高频陷阱，逐条对照

1. **BFS 只看边数。** 边权不全相等时，BFS 给的**不是**最短路。边权全相等时，BFS 才等价于退化的 Dijkstra。
2. **Dijkstra 用优先队列，不是普通队列。** 它按「当前距离最小」出队，不是「最早发现」。写「queue」的选项是陷阱。
3. **Dijkstra 不能有负权。** 原因不是实现问题，而是贪心正确性依赖 w ≥ 0（§3.4、§3.5）。
4. **Bellman-Ford 是 V-1 轮，判定负环看第 V 轮。** 不要记成 V 轮松弛。
5. **Floyd 的 k 在最外层**，且它允许负权边（只是不允许负环）。
6. **Kruskal / Prim 求 MST，不是最短路。** 两者目标不同，MST 上的路径不是最短路（§6.6 有例图反例）。
7. **拓扑排序处理「顺序」，与距离无关**，且结果通常不唯一；有环则无解。

## 8.2 四个算法按「能否反悔」分类（记这个比记表格快）

| 能不能反悔 | 算法 | 代价 |
|---|---|---|
| 不反悔（认定即定死） | BFS、DFS、Dijkstra、Prim、Kruskal | 快（O(V+E) 或 O(Elog V)） |
| 允许反悔（反复修正） | Bellman-Ford、Floyd | 慢（O(VE)、O(V³)） |

「可不可以反悔」这条线把 7 个算法串成两组，本质上是「贪心」与「动态规划」的分界：**贪心快但要求条件（非负权 / 无环），DP 慢但鲁棒（接受负权）。**

## 8.3 一道综合例题

A network of V routers and E links must be connected so that every pair of routers can communicate, using the minimum total cost of links. Which algorithm should be used?

A. Dijkstra's algorithm
B. Breadth-First Search
C. Kruskal's algorithm
D. Bellman-Ford
E. Floyd-Warshall

**答案：C**

**解析：** 关键词 `every pair can communicate` + `minimum total cost of links` = 把全部点连起来且总代价最小 = **最小生成树**。A 求的是「单源到其余各点」的最短路，不是「把所有点连起来」；B 只数边数；D 处理负权最短路；E 求全源最短路。这三者都能让路由器通信，但**代价不是最小**——这正是 MST 与最短路最本质的区别。

**所属知识点：** 数据结构与算法 / 图论 / 最小生成树与最短路辨析。

# 9. 一页速查：每个算法的「一句话 + 一个抓手」

| 算法 | 一句话 | 抓手 |
|---|---|---|
| BFS | 一圈一圈往外扩，第一次见即最短（无权） | 队列 |
| DFS | 一条路走到底再回头 | 栈 / 递归；灰点=环 |
| Dijkstra | 每次认领当前最近的点，认领后不再改 | 优先队列；非负权 |
| Bellman-Ford | 所有边反复扫 V-1 轮 | 第 V 轮还能松 ⇒ 负环 |
| Floyd | 逐个放开中转站，三行代码 | k 最外层；O(V³) |
| Prim | 从点往外长，挑最便宜的跨界边 | 点集扩张 |
| Kruskal | 边排序，不成环就加 | 并查集 |
| 拓扑排序 | 入度归零者先走 | DAG；Kahn 用队列 |
