# 1. 闭包（Closure）
## 1.1 什么是闭包？

**闭包可以简单理解为：一个函数能够记住并访问它创建时所在作用域中的变量，即使外层函数已经执行结束。**

示例：

```js
function outer() {
  const x = 10;

  function inner() {
    console.log(x);
  }

  return inner;
}

const fn = outer();
fn(); // 10
```

执行过程：

1. 调用 `outer()`，创建局部变量 `x` 和内部函数 `inner`。
    
2. `outer()` 返回 `inner` 函数，并执行结束。
    
3. 变量 `fn` 保存了返回的函数。
    
4. 调用 `fn()` 时，仍然可以访问外层作用域中的 `x`，因此输出 `10`。

正常情况下，函数执行结束后，其局部数据不再被需要时就可以被垃圾回收。但闭包引用的变量仍然被需要时，相关数据就需要继续保留。

## 1.2 为什么闭包能够访问外层变量？

JavaScript 使用**词法作用域**：**函数可以访问哪些变量，取决于函数定义时所处的位置**，而不是调用时的位置。

```js
function outer() {
  const name = "张三";

  return function inner() {
    console.log(name);
  };
}

const fn = outer();
fn(); // 张三
```

虽然 `inner` 在 `outer` 执行结束后才被调用，但它仍然能够访问定义时所在作用域中的 `name`。

可以理解为：

```text
outer() 执行
    |
    | 创建 name = "张三"
    |
    v
返回 inner 函数
    |
    v
outer() 执行结束
    |
    v
调用 inner()
    |
    v
仍然可以访问 name = "张三"
```

注意：不是外层函数一直在重新执行，而是闭包使仍然需要的外层变量可以继续被访问。

## 1.3 闭包的常见应用
### 1.3.0 回调函数
#### （1）什么是回调函数？

**回调函数是指作为参数传递给其他函数，再由其他代码决定何时调用的函数。**

可以简单理解为：**先把函数交给别人，等对方需要时，再由对方调用。**

#### （2）普通函数调用与回调函数

**普通函数调用：自己主动调用。**

```js
function sayHello() {
    console.log("你好");
}

sayHello(); // 主动调用，立即执行
```

**回调函数：把函数交给其他代码调用。**

```js
setTimeout(() => {
    console.log("你好");
}, 1000);
```

这里将箭头函数传给了 `setTimeout()`，由定时器机制在约 1000 毫秒后调用它，因此这个箭头函数就是回调函数。

#### （3）回调函数与闭包

```js
for (var i = 0; i < 3; i++) {
    setTimeout(() => {
        console.log(i);
    }, 100);
}
```

这里的**箭头函数是回调函数**，因为它被传递给 `setTimeout()`，稍后才会执行。

由于 `var` 声明的 `i` 被三个回调函数共享，等回调执行时，循环已经结束，`i` 的值为 `3`，因此输出：

```text
3
3
3
```

#### （4） 注意事项

- 回调函数不是一种特殊的函数，而是函数的一种使用方式。
    
- 回调函数不一定延迟执行，例如 `forEach()` 接收的回调函数通常会在遍历数组时执行。
    
- 回调函数常用于定时器、事件处理、数组遍历和异步操作等场景。

### 1.3.1 保存私有数据

闭包可以将变量保存在函数内部，只通过返回的方法访问或修改，避免外部代码直接访问该变量。

```js
function createCounter() {
  let count = 0;

  return {
    increment() {
      count++;
    },

    getCount() {
      return count;
    }
  };
}

const counter = createCounter();

counter.increment();
counter.increment();

console.log(counter.getCount()); // 2
console.log(counter.count);      // undefined
```

这里的 `count` 是 `createCounter` 内部的局部变量，外部不能直接通过 `counter.count` 读取它，只能调用返回的 `increment()` 和 `getCount()` 方法。

### 1.3.2 防抖函数

**防抖是指：连续触发某个操作时，只在最后一次触发后等待指定时间，再执行函数。简单来说，就是避免一个操作在短时间内被连续触发时，执行很多次真正的业务函数。**

闭包可以用来保存定时器的 ID：

```js
function debounce(fn, delay) {
  let timer;

  return function (...args) {
    clearTimeout(timer);

    timer = setTimeout(() => {
      fn(...args);
    }, delay);
  };
}
```

这里返回的函数形成闭包，可以持续访问 `timer`，从而取消上一次的定时器，并创建新的定时器。

防抖常用于搜索框输入等场景，避免用户每输入一个字符就立即执行一次查询。

## 1.4 闭包与内存管理

闭包会使仍被引用的变量继续保留，但**闭包本身并不意味着内存泄漏**。

如果事件监听器一直存在，而它的回调又引用了不再需要的大对象，那么这些对象可能无法及时被垃圾回收。

```js
function bindEvent() {
  const data = new Array(100000).fill("data");

  function handler() {
    console.log(data.length);
  }

  const button = document.querySelector("#btn");
  button.addEventListener("click", handler);

  // 应在不再需要时移除同一个监听器
  return function cleanup() {
    button.removeEventListener("click", handler);
  };
}

const cleanup = bindEvent();

// 不再需要时执行清理
cleanup();
```

这里通过 `cleanup()` 移除事件监听器，解除不再需要的回调关联。

注意：如果其他地方仍然持有相关对象的引用，移除监听器并不代表这些对象一定会立即被回收。

## 1.5 闭包与类的区别及使用场景

闭包和类都可以用于**保存状态、封装数据**，但实现方式和适用场景有所不同。

#### 闭包

闭包通过函数及其能够访问的外部作用域变量来保存状态，不需要定义一个类。

```js
function createCounter() {
    let count = 0;

    return function () {
        count++;
        return count;
    };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2
```

这里的 `count` 保存在 `createCounter()` 的作用域中，即使外层函数执行结束，返回的函数仍然可以访问它。

**适用场景：**

- 保存少量私有状态，例如计数器。
    
- 防抖、节流等工具函数。
    
- 在回调函数中保留外部变量。
    

#### 类（class）

类通过定义属性和方法来组织数据与行为，适合创建多个具有相同结构和功能的对象。

```js
class Counter {
    #count = 0;

    increment() {
        this.#count++;
    }

    getCount() {
        return this.#count;
    }
}

const counter = new Counter();
counter.increment();
console.log(counter.getCount()); // 1
```

这里的 `#count` 是私有字段，外部不能直接访问。

**适用场景：**

- 创建多个具有相同属性和方法的对象。
    
- 组织较复杂的业务逻辑，例如用户、订单等对象。
    
- 需要继承或扩展对象功能时。
    

#### 两者的主要区别

|对比项|闭包|类|
|---|---|---|
|组织方式|函数与外部作用域变量|属性与方法|
|保存状态|通过闭包保留变量|通过对象属性保存|
|封装数据|外部通常无法直接访问闭包内的局部变量|可以使用 `#` 定义私有字段|
|适用场景|简单状态、回调、工具函数|多个相似对象、复杂业务逻辑|

**记忆：** 简单地保存一些私有状态，通常可以使用闭包；需要创建多个结构相似、具有一组属性和方法的对象时，通常使用类。

两者并不冲突，类的方法内部也可以使用闭包。

# 2. 作用域与作用域链
## 2.1 什么是作用域？

**作用域（Scope）决定了变量在代码的哪些位置可以被访问。**

JavaScript 常见的作用域有以下三种：

| 作用域   | 含义                                              |
| ----- | ----------------------------------------------- |
| 全局作用域 | 在全局范围内声明的变量，可以在符合规则的代码位置访问                      |
| 函数作用域 | 在函数内部声明的变量，通常只能在该函数内部访问                         |
| 块级作用域 | 在 `{}` 代码块内通过 `let` 或 `const` 声明的变量，只能在该块及其内部访问 |

示例：

```js
const a = 1; // 全局作用域

function test() {
  const b = 2; // 函数作用域

  if (true) {
    const c = 3; // 块级作用域
    console.log(a, b, c); // 1 2 3
  }

  console.log(a, b); // 1 2
  // console.log(c); // ReferenceError
}

test();
```

这里的 `c` 在 `if` 代码块外无法访问，因为它使用 `const` 声明，具有块级作用域。

## 2.2 什么是作用域链？

当 JavaScript 需要读取一个变量时，会先在当前作用域中查找。如果没有找到，就沿着外层作用域继续查找，直到找到变量或到达最外层作用域。

这种逐层查找的关系称为**作用域链（Scope Chain）**。

```js
const a = 1;

function outer() {
  const b = 2;

  function inner() {
    const c = 3;

    console.log(a, b, c); // 1 2 3
  }

  inner();
}

outer();
```

查找 `a`、`b`、`c` 时，可以理解为：

```text
inner 的作用域
    |
    | 没找到 a、b 时
    v
outer 的作用域
    |
    | 仍没找到 a 时
    v
全局作用域
```

如果沿着作用域链也找不到变量，就会产生 `ReferenceError`。

需要注意：**作用域链的查找方向是从当前作用域向外层查找，而不是向内层查找。** 外层函数不能直接访问内层函数的局部变量。

# 3. var、let、const 的区别
## 3.1 三者的主要区别

| 对比项       | `var`                  | `let`          | `const`        |
| --------- | ---------------------- | -------------- | -------------- |
| 作用域       | 函数作用域；全局声明还需考虑脚本环境     | 块级作用域          | 块级作用域          |
| 变量提升      | 声明会提升，初始化为 `undefined` | 存在提升，但初始化前不可访问 | 存在提升，但初始化前不可访问 |
| 重复声明      | 同一作用域中通常允许重复声明         | 同一作用域中不允许重复声明  | 同一作用域中不允许重复声明  |
| 重新赋值      | 允许                     | 允许             | 不允许            |
| 声明时是否必须赋值 | 不需要                    | 不需要            | 必须             |

实际开发中，通常优先使用 `const`；需要重新赋值时使用 `let`。一般不建议在新代码中使用 `var`。

## 3.2 var：函数作用域与变量提升
### 3.2.1 函数作用域

`var` 声明的变量不受普通代码块限制，但受函数作用域限制。

```js
function test() {
  if (true) {
    var a = 10;
  }

  console.log(a); // 10
}

test();
```

虽然 `a` 在 `if` 代码块内部声明，但仍然可以在整个 `test()` 函数内部访问。

### 3.2.2 变量提升

`var` 声明会被提升，因此在声明语句之前访问变量时，通常得到 `undefined`，而不是直接报错。

```js
console.log(a); // undefined

var a = 10;
```

可以近似理解为：

```js
var a;

console.log(a); // undefined

a = 10;
```

注意：提升的是声明，不是赋值。执行到 `a = 10` 之前，变量的值仍然是 `undefined`。

## 3.3 let：块级作用域

`let` 用于声明可以重新赋值的变量，具有块级作用域。

```js
if (true) {
  let a = 10;
  a = 20;

  console.log(a); // 20
}

// console.log(a); // ReferenceError
```

变量 `a` 只能在 `if` 代码块内部访问。

同一作用域内不能重复声明：

```js
let a = 10;

// let a = 20; // SyntaxError
```

## 3.4 const：不能重新赋值

`const` 用于声明不能重新赋值的变量，声明时必须初始化。

```js
const a = 10;

// a = 20; // TypeError
```

但是，**const 限制的是变量绑定不能重新赋值，并不意味着对象内部的数据不能修改。**

```js
const user = {
  name: "张三"
};

user.name = "李四"; // 可以修改对象属性

console.log(user.name); // 李四

// user = {}; // TypeError，不能重新赋值
```

这里 `user` 仍然引用原来的对象，因此**可以修改对象内部的属性**，但不能让 `user` 重新指向另一个对象。

## 3.5 暂时性死区（TDZ）

`let` 和 `const` 声明的变量，在代码执行到声明语句之前不能访问。

这段从作用域开始到变量完成初始化之前不可访问的区域，称为**暂时性死区（Temporal Dead Zone，TDZ）**。

```js
// console.log(a); // ReferenceError

let a = 10;
```

与 `var` 不同，`let` 和 `const` 在声明前访问会产生 `ReferenceError`。

注意：不是说 `let` 和 `const` 不存在变量提升，而是它们在初始化前不可访问。

# 4. 循环中的闭包问题

这是闭包、作用域和 `var`、`let` 综合考查的常见题目。

## 4.1 使用 var 为什么会输出 3、3、3？

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}
```

输出：

```text
3
3
3
```

**原因：**

1. `var` 声明的 `i` 不具有块级作用域，**整个循环共享同一个变量**。
    
2. `setTimeout` 的回调不会立即执行。`setTimeout()` 会安排这个函数在约 100 毫秒后执行。因此，循环可以先继续运行，等回调真正执行时，循环中的 `i` 已经变成了 `3`。
    
3. 循环很快结束，此时 `i` 已经变成 `3`。
    
4. 等回调开始执行时，三个回调读取的都是同一个 `i`，因此全部输出 `3`。

## 4.2 使用 let 为什么会输出 0、1、2？

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}
```

输出：

```text
0
1
2
```

原因：

- `let` 在 `for` 循环中具有**特殊的迭代绑定行为**。
    
- **每次迭代都有独立的 `i` 绑定**。
    
- 回调通过闭包访问各自迭代中的 `i`，不会全部读取循环结束后的同一个值。
    

**记忆重点：** 在循环中创建延迟执行的回调时，使用 `let` 通常可以避免 `var` 导致多个回调共享同一个循环变量的问题。

# 5. 面试重点速记
## 5.1 什么是闭包？

闭包是指函数**能够记住并访问其创建时所在词法作用域中的变量**，**即使外层函数已经执行结束**，这些仍被需要的变量也可以继续访问。

## 5.2 闭包有什么用途？

常见用途包括保存私有状态、防抖函数、缓存结果，以及在回调中保留创建时的变量。

## 5.3 什么是作用域链？

读取变量时，JavaScript 从当前作用域开始查找；如果没有找到，就沿着外层作用域逐层查找。

## 5.4 var、let、const 有什么区别？

`var` 具有函数作用域和变量提升特性；`let`、`const` 具有块级作用域，并存在暂时性死区；`const` 还要求声明时初始化，且不允许重新赋值。

## 5.5 const 声明的对象为什么可以修改属性？

因为 `const` 限制的是变量绑定不能重新赋值，而不是冻结对象本身。对象属性仍然可以修改，除非额外采取对象冻结等措施。

## 5.6 为什么循环中的 var 闭包可能输出相同的值？

因为**多个回调共享同一个 `var` 循环变量**，等回调执行时，循环可能已经结束。使用 `let` 可以为每次迭代提供独立的变量绑定。
